## 한 줄 요약
디버거의 레지스터 창(x64dbg) 또는 `info registers`/`print`(GDB)로 실행 중 CPU 레지스터의 실제 값을 언제든 확인할 수 있고, 한 줄씩 스텝하면서 어떤 명령어가 어떤 레지스터를 바꾸는지 색상 강조(x64dbg) 또는 반복 조회(GDB)로 추적하면 정적 분석만으로는 알 수 없는 "실제로 그 순간 이 변수가 무슨 값이었는지"를 확인할 수 있다.

## 언제 검색해야 하나
- IDA에서 `eax`에 어떤 값이 들어가는지 코드만 봐서는 계산이 복잡해 손으로 추적하기 힘들 때
- 조건 분기 직전에 비교 대상 값이 실제로 몇인지 알아야 할 때
- 반복문(loop)이 도는 동안 카운터 레지스터(`ecx` 등)가 어떻게 변하는지 눈으로 확인하고 싶을 때
- 함수 인자나 반환값이 들어있는 레지스터의 값을 스텝마다 확인하고 싶을 때
- x64dbg 레지스터 창에서 빨간색으로 표시된 값이 무슨 뜻인지 모를 때
- GDB에서 특정 레지스터 하나만 계속 보고 싶은데 매번 `info registers`로 전체를 보기 귀찮을 때

## 핵심 개념

### 레지스터 창(x64dbg)이 보여주는 것
x64dbg를 실행하고 브레이크포인트에서 멈추면, 화면 오른쪽(기본 레이아웃 기준)에 레지스터 창이 항상 떠 있다. 여기에는 범용 레지스터(RAX, RBX, RCX, RDX, RSI, RDI, RBP, RSP, R8~R15), 명령어 포인터(RIP), 플래그 레지스터(개별 비트: ZF, CF, SF, OF, PF 등), 세그먼트 레지스터가 실시간으로 표시된다. 한 스텝(F7/F8) 실행할 때마다 **직전 값과 달라진 레지스터는 빨간색으로 강조**되어, 방금 실행한 명령어가 정확히 무엇을 바꿨는지 한눈에 보인다.

### GDB의 `info registers`
GDB에서는 `info registers`(줄여서 `i r`)를 입력하면 그 순간의 모든 범용 레지스터 값과 플래그(`eflags`) 상태가 텍스트로 출력된다. 특정 레지스터 하나만 보고 싶다면 `print`(`p`) 명령에 `$` 접두사를 붙여서 조회한다(예: `p $rax`). Pwndbg를 설치했다면 `context` 명령(또는 브레이크포인트에서 정지할 때마다 자동으로) 레지스터, 디스어셈블리, 스택을 한 화면에 색상별로 정리해서 보여주는데, 이전 값과 달라진 레지스터는 자동으로 강조 색이 붙어 x64dbg의 "변경된 레지스터 빨간 표시"와 거의 같은 효과를 낸다.

### 실행 중 값을 "추적"한다는 것의 의미
레지스터 추적은 단순히 한 번 값을 보는 게 아니라, **여러 스텝에 걸쳐 값이 어떻게 변해가는지 연속적으로 관찰**하는 것이다. 방법은 크게 두 가지다.
1. **수동 스텝 + 매번 확인**: F7/F8(또는 `si`/`ni`)로 한 줄씩 실행하면서 매번 레지스터 창(또는 `info registers`)을 확인한다. 정확하지만 느리다.
2. **조건부 브레이크포인트 활용**: 레지스터 값이 특정 값이 될 때만 멈추도록 조건부 브레이크포인트를 걸어서(REV-0169 참고), 관심 있는 순간만 빠르게 찾는다.

### 32비트 vs 64비트 하위 레지스터 표기 주의
x64 CPU에서 `RAX`(64비트 전체), `EAX`(하위 32비트), `AX`(하위 16비트), `AL`(하위 8비트)은 모두 같은 물리 레지스터의 다른 부분을 가리킨다. 디버거에서 `EAX`만 보고 있는데 명령어가 `RAX` 전체를 쓰는 경우(또는 반대) 값이 안 맞아 보일 수 있다. x64dbg 레지스터 창에서는 RAX 옆의 작은 화살표나 우클릭으로 32/16/8비트 뷰를 전환할 수 있고, GDB에서는 `p $eax`, `p $rax`처럼 원하는 크기를 직접 지정해서 조회하면 된다. **참고**: 32비트 레지스터(EAX 등)에 값을 쓰면 상위 32비트가 자동으로 0으로 채워지지만(zero-extend), 16비트/8비트 레지스터에 값을 쓰면 상위 비트가 그대로 남는다는 차이도 기억해 둘 필요가 있다.

### 어떤 레지스터를 추적해야 하는가
막연히 전체를 다 보려 하지 말고 목적에 맞춰 좁힌다.
- 함수 인자를 보고 싶다 → RDI/RSI/RDX/RCX/R8/R9(SysV) 또는 RCX/RDX/R8/R9(Windows x64) (REV-0175 참고)
- 반환값을 보고 싶다 → RAX/EAX (REV-0176 참고)
- 반복문 카운터나 인덱스를 보고 싶다 → 해당 루프에서 `inc`/`dec`/`add`되는 레지스터(주로 ECX, EDX, 또는 컴파일러가 배정한 레지스터)를 코드에서 먼저 특정한 뒤 그것만 본다.
- 비교/분기 조건을 보고 싶다 → `cmp`/`test` 직전에 관련된 두 레지스터/값 (REV-0174 참고)
- 스택 포인터 이상(스택 불균형)을 의심할 때 → RSP를 계속 관찰한다.

### 값 표시 형식 — 16진수/10진수/문자/부호
레지스터 값은 기본적으로 16진수로 표시된다. x64dbg 레지스터 창에서 값을 우클릭하면 "10진수로 표시", "문자로 표시(ASCII)", "부호 있는 값으로 표시" 등으로 바꿔볼 수 있다. GDB에서는 `p/d $eax`(10진수), `p/x $eax`(16진수), `p/c $eax`(문자)처럼 포맷 지정자를 붙여 원하는 방식으로 즉시 출력할 수 있다. 이 차이는 특히 signed/unsigned 비교(REV-0174, `jg`/`ja` 차이) 문제를 풀 때 중요하다 — 같은 비트 패턴이라도 부호 있는 값으로 해석하면 음수로 보일 수 있다.

## 화면/코드에서 보이는 징후
- x64dbg 레지스터 창에서 값이 빨간 글씨로 강조되어 있으면 직전 한 스텝 사이에 그 레지스터가 바뀌었다는 뜻이다.
- x64dbg에서 레지스터 값 옆에 회색 글씨로 `ASCII "..."` 나 함수 이름이 함께 표시되면, 그 값이 메모리 주소이고 그 주소가 문자열이나 알려진 함수를 가리킨다는 뜻이다(자동 심볼 해석).
- GDB `info registers` 출력에서 `eflags` 줄에 `[ ZF PF ]` 같은 대괄호 목록이 보이면 현재 세팅된 플래그 비트들이다.

## 가장 먼저 할 것
1. 추적하고 싶은 레지스터를 코드(IDA/Ghidra)에서 먼저 특정한다(예: 이 CMP에서 비교되는 두 값이 EAX와 EBX다).
2. 그 레지스터가 마지막으로 쓰이는 지점 근처, 또는 반복문 시작 지점에 브레이크포인트를 건다(REV-0169).
3. 실행해서 멈춘 뒤 레지스터 창/`info registers`로 현재 값을 확인한다.
4. 필요하면 한 스텝씩 진행하며 값의 변화를 계속 관찰한다.

## 단계별 절차

**x64dbg**
1. 원하는 지점에 브레이크포인트를 걸고 `F9`로 실행한다.
2. 오른쪽 레지스터 창에서 전체 레지스터 값을 한눈에 확인한다.
3. `F7`/`F8`로 한 스텝씩 진행하면서, 빨간색으로 강조되는 레지스터를 관찰한다 — 방금 실행한 명령어가 어떤 레지스터를 바꿨는지 바로 알 수 있다.
4. 특정 레지스터 값의 표시 형식을 바꾸려면 그 레지스터를 우클릭 → "Signed"/"Unsigned"/"Hex"/"Follow in Dump"(메모리 주소라면 Dump 창에서 내용 확인) 등을 선택한다.
5. 특정 레지스터가 특정 값이 될 때만 멈추고 싶다면 그 지점에 조건부 브레이크포인트를 건다(REV-0169 참고, 예: `eax==0x1234`).

**GDB / Pwndbg**
1. 브레이크포인트를 걸고 `run`으로 실행한다.
2. 전체 레지스터를 보려면:
   ```
   info registers
   i r
   ```
3. 특정 레지스터 하나만 보려면:
   ```
   print $rax
   p/x $rax
   p/d $eax
   ```
4. Pwndbg를 쓴다면 정지할 때마다 자동으로 레지스터/디스어셈블리/스택이 정리된 `context` 화면이 뜨고, 변경된 레지스터는 색으로 강조된다. 수동으로 다시 보려면:
   ```
   context
   ```
5. 한 스텝씩 진행하며 관찰하려면:
   ```
   si
   p $rax
   si
   p $rax
   ```
   반복이 귀찮다면 GDB의 `display` 명령으로 매 스텝마다 자동 출력되게 등록할 수 있다:
   ```
   display/x $rax
   si
   ```
   (`si`를 칠 때마다 `$rax` 값이 자동으로 함께 출력된다.)

## 명령어/단축키
- x64dbg: 레지스터 창(기본 표시), `F7`/`F8`(스텝하며 변경 관찰), 레지스터 우클릭 → Signed/Unsigned/Hex 전환, "Follow in Dump"(메모리로 이동)
- GDB/Pwndbg: `info registers`(`i r`), `print $rax`(`p $rax`), `p/x`(16진수), `p/d`(10진수), `p/c`(문자), `display/x $rax`(스텝마다 자동 출력 등록), `undisplay <번호>`(해제), Pwndbg `context`(전체 상태 한 화면 정리)

## 출력 해석
- x64dbg에서 `RAX = 0000000000000000` 이고 빨간색이면, 방금 명령어가 RAX를 0으로 만들었다는 뜻(`xor eax, eax` 같은 패턴).
- GDB `p/d $eax`가 `-1`을 출력했는데 `p/x $eax`는 `0xffffffff`를 출력한다면, 같은 비트 패턴을 부호 있는 값(signed)과 부호 없는 값(unsigned/hex)으로 각각 해석한 것 — 실제 값은 동일하고 해석만 다르다.
- GDB `display/x $rax` 등록 후 매 `si`마다 `1: /x $rax = 0x5`처럼 번호와 함께 자동 출력되면, 등록이 잘 된 것이다.

## 흔한 실수
- EAX만 보고 RAX 상위 32비트에 남아있는 값(예: 이전 64비트 연산의 잔여값)을 놓치는 것 — 64비트 함수/포인터를 다룰 때는 RAX 전체를 확인해야 한다.
- 부호 있는 값(signed)과 부호 없는 값(unsigned) 표시를 헷갈려서 "음수인데 왜 큰 양수로 보이지"라고 착각하는 것 — 표시 형식(Signed/Unsigned)을 반드시 확인한다.
- 레지스터 값이 메모리 주소인데 그 주소가 가리키는 실제 데이터(문자열, 구조체)를 안 보고 숫자만 보고 끝내는 것 — x64dbg는 "Follow in Dump", GDB는 `x/s $rax`(문자열로 보기)로 실제 내용까지 확인해야 한다.
- 매 스텝마다 수동으로 `info registers`를 반복 입력하는 비효율 — GDB `display` 등록이나 Pwndbg의 자동 `context` 출력을 활용하면 훨씬 빠르다.

## 막혔을 때 다음 체크
- 레지스터 값이 기대와 다르다면 → 지금 보고 있는 게 정말 관심 있는 그 CALL/CMP 직전/직후 시점이 맞는지, 브레이크포인트 위치를 다시 확인한다.
- 32비트/64비트 뷰가 헷갈린다면 → 명령어가 `mov eax, ...`인지 `mov rax, ...`인지 오퍼랜드 크기를 코드에서 먼저 확인한다.
- 레지스터가 가리키는 메모리 내용이 궁금하다면 → REV-0173(스택 값 추적)이나 Dump 창/`x` 명령으로 넘어간다.
- 특정 값이 될 때까지 스텝하기 너무 번거롭다면 → 조건부 브레이크포인트(REV-0169)로 바로 그 순간까지 건너뛴다.

## 미니 예제

**x64dbg — 반복문 카운터 추적**
```asm
xor     ecx, ecx        ; ECX = 0 (카운터 초기화)
loop_start:
inc     ecx              ; ECX += 1
cmp     ecx, 0Ah         ; ECX와 10 비교
jl      loop_start
```
`loop_start` 줄에 브레이크포인트를 걸고 `F9`를 반복해서 누르면, 매번 멈출 때마다 레지스터 창의 ECX 값이 0→1→2→...→9로 빨간색 강조와 함께 올라가는 것을 볼 수 있다.

**GDB/Pwndbg — display로 자동 추적**
```
(gdb) break *0x401230
(gdb) run
(gdb) display/d $ecx
(gdb) si
1: /d $ecx = 1
(gdb) si
1: /d $ecx = 2
```
