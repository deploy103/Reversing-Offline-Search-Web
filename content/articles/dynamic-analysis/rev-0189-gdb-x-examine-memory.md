## 한 줄 요약
GDB의 `x`(examine) 명령은 `x/개수FMT단위 주소` 형태로 메모리를 원하는 개수, 형식(16진수/문자열/명령어 등), 단위(바이트/워드/더블워드 등)로 직접 들여다보는 명령으로, `x/10xb $rsp`(스택 10바이트를 16진수로), `x/s $rdi`(RDI가 가리키는 문자열)처럼 조합해서 쓰는 것이 동적 분석의 기본기다.

## 언제 검색해야 하나
- 스택 맨 위(`$rsp`)나 특정 버퍼 주소에 실제로 어떤 바이트 값이 들어있는지 확인하고 싶을 때
- 레지스터가 가리키는 곳이 문자열인지 확인하고 싶은데, `print`로는 그냥 숫자만 보여서 답답할 때
- 특정 주소 주변의 어셈블리 명령어들을 미리 몇 개만 훑어보고 싶을 때
- `x/10xb`, `x/s`, `x/i`처럼 자꾸 보이는 `x/` 뒤의 문법이 정확히 무슨 규칙인지 모를 때
- 배열이나 구조체처럼 여러 개의 값이 연속으로 있는 메모리를 한 번에 여러 개 출력하고 싶을 때

## 핵심 개념

### `x` 명령의 문법: `x/NFU 주소`
`x` 명령은 `x/` 뒤에 세 가지 요소를 붙여서 쓴다.
```
x/N F U 주소
```
- **N**: 몇 개를 출력할지(개수). 생략하면 1.
- **F**: 형식(format) 문자 하나.
- **U**: 단위(unit) 크기 문자 하나.
- **주소**: 어디서부터 볼지 — 레지스터(`$rsp`), 심볼(`&buf`), 상수 주소(`0x601040`) 모두 가능.

세 요소 중 F와 U는 순서 상관없이 붙여 써도 되고, 생략하면 직전에 썼던 값이 그대로 재사용된다. 예를 들어 `x/10xb $rsp`는 "`$rsp`부터 시작해서, 16진수(x) 형식으로, 바이트(b) 단위로, 10개를 보여줘"라는 뜻이다.

### 형식(Format) 문자
| 문자 | 의미 |
|---|---|
| `x` | 16진수 |
| `d` | 부호 있는 10진수 |
| `u` | 부호 없는 10진수 |
| `o` | 8진수 |
| `t` | 2진수(binary) |
| `c` | 문자(char)로 해석 |
| `s` | NUL로 끝나는 문자열로 해석 |
| `i` | 어셈블리 명령어로 디스어셈블 |
| `a` | 주소로 해석(가능하면 심볼도 표시) |
| `f` | 부동소수점 |

### 단위(Unit) 문자
| 문자 | 크기 |
|---|---|
| `b` | 1바이트 |
| `h` | 2바이트(halfword) |
| `w` | 4바이트(word, 기본값) |
| `g` | 8바이트(giant word) |

`s`(문자열)와 `i`(명령어) 형식은 자체적으로 길이가 가변이므로 단위 지정이 필요 없다 — `x/s`, `x/3i`처럼 단위 없이 개수만 붙인다.

### 가장 많이 쓰는 조합 예시
```gdb
x/10xb $rsp     # 스택 위 10바이트를 16진수로 (바이트 단위로 세세히)
x/4xg $rsp      # 스택 위 4개의 8바이트(퀴드워드) 값 (64비트 값 단위로 보기 좋음)
x/s $rdi        # RDI가 가리키는 문자열
x/3i $rip       # 현재 명령어부터 3개를 디스어셈블
x/20xw $rsp     # 스택 위 20개의 4바이트 값
```
64비트 환경에서는 포인터/정수 값을 볼 때 `xg`(8바이트, 16진수) 조합이 가장 자연스럽고, 스택에 쌓인 바이트 배열(버퍼 원본 데이터)을 세세히 볼 때는 `xb`가 유용하다.

### 문자열이 안 보일 때
`x/s $rdi`를 쳤는데 이상한 값이 나온다면, `$rdi`가 진짜 문자열의 시작 주소가 아니라 다른 값(예: 정수, 혹은 문자열 포인터를 담은 변수의 주소 자체)일 가능성이 크다. 포인터의 포인터라면 한 번 더 역참조해야 한다:
```gdb
x/gx $rdi        # rdi가 가리키는 곳의 8바이트 값(그게 진짜 포인터일 수 있음)
x/s *(long*)$rdi # 그 값을 다시 주소로 보고 문자열로 해석
```
Pwndbg의 `telescope`(REV-0193 참고)는 이런 포인터 체인을 자동으로 따라가서 보여주므로 훨씬 편하다.

### 반복 사용 — Enter로 이어보기
`x/10xb $rsp`를 친 뒤 그냥 Enter를 누르면, GDB는 **직전 주소 다음부터 이어서** 같은 형식으로 10개를 더 보여준다. 큰 버퍼를 스크롤하듯 훑어볼 때 유용하다.

### 심볼/변수 주소 지정
전역 변수나 함수의 주소는 `&`를 붙여서 얻는다.
```gdb
x/s &global_buf
x/4xg &some_struct
```
지역 변수는 최적화가 없고 디버그 심볼이 있다면 이름 그대로 `x/s buf`처럼 쓸 수 있지만, `buf`가 배열이 아니라 포인터 변수라면 `&buf`와 `buf`의 의미가 다르므로 주의해야 한다.

### `print`와의 차이
`print`(p)는 GDB의 타입 시스템을 활용해 값을 "해석"해서 보여주는 명령이고(`print buf`라고 하면 심볼 타입에 따라 배열 전체를 알아서 보여줄 수도 있다), `x`는 타입과 무관하게 **순수 메모리 바이트를 원하는 형식으로 강제로** 찍어보는 명령이다. 디버그 심볼이 없는 바이너리를 분석할 때는 타입 정보 자체가 없으므로 `x`가 훨씬 더 자주, 그리고 안정적으로 쓰인다.

## 화면/코드에서 보이는 징후
- 스택 버퍼 오버플로우를 확인할 때 `x/40xb $rsp`로 실제 스택 내용을 바이트 단위로 눈으로 확인하는 흐름
- `strcmp` 호출 직전 `x/s $rdi`, `x/s $rsi`로 비교 대상 두 문자열을 각각 확인하는 패턴
- `x/3i $rip`로 지금 명령어와 그다음 두 개를 미리 보고 흐름을 예측하는 습관

## 가장 먼저 할 것
정수/포인터 값을 확인할 땐 `x/gx 주소`(64비트 16진수), 문자열이 예상되면 `x/s 주소`, 명령어를 보고 싶으면 `x/Ni 주소` 형태부터 시도한다.

## 단계별 절차

**1) 확인하려는 값의 성격 파악**
문자열인지, 정수인지, 포인터 배열인지 먼저 추측한다.

**2) 형식에 맞는 `x` 명령 실행**
```gdb
x/s $rdi
x/8xg $rsp
```

**3) 결과가 이상하면 역참조 추가 시도**
```gdb
x/gx $rdi
x/s *(long*)$rdi
```

**4) 넓은 범위를 훑어볼 때는 Enter로 이어보기**

**5) 반복적으로 자주 보는 지점은 display 등록**
```gdb
display/s $rdi
```
`display`로 등록해두면 이후 `stepi`/`continue` 등으로 멈출 때마다 자동으로 다시 출력된다.

## 명령어/단축키
```gdb
x/NFU 주소
x/10xb $rsp
x/4xg $rsp
x/s $rdi
x/3i $rip
x/20xw $rsp
display/s $rdi
```

## 출력 해석
```
0x7fffffffe4a0:	0x74	0x65	0x73	0x74	0x00	0x00	0x00	0x00
```
왼쪽은 시작 주소, 이후 각 칸이 바이트 단위 16진수 값이다. `0x74 0x65 0x73 0x74`는 ASCII로 `t e s t`이므로, 이 스택 위치에 `"test"` 문자열이 있다는 뜻이다.
```
0x7fffffffe4a0:	"test123"
```
`x/s` 형식은 아예 바로 문자열로 해석해서 보여주므로 훨씬 읽기 쉽다.
```
=> 0x555555555185 <main+8>:	mov    DWORD PTR [rbp-0x4],edi
```
`x/i` 결과에서 `=>` 표시는 현재 `$rip`가 가리키는 바로 그 명령어라는 뜻이다.

## 흔한 실수
- 단위(U)를 빼먹고 개수(N)만 크게 줘서 의도보다 훨씬 넓은 범위를 조회하는 것 — 예를 들어 `x/40x $rsp`는 기본 단위가 `w`(4바이트)라서 실제로는 160바이트 범위를 본다. 바이트 단위로 정확히 보고 싶다면 반드시 `b`를 명시해야 한다.
- `x/s`로 봤는데 문자열이 아니라 포인터 값 하나만 있는 경우 — 한 단계 더 역참조가 필요하다는 신호다.
- 형식과 단위 순서를 바꿔 쓰면 안 될 것처럼 걱정하는 것 — `x/xb`와 `x/bx`는 GDB에서 동일하게 동작한다(순서 무관).
- 매핑되지 않은 주소를 조회해서 `Cannot access memory at address 0x...` 에러를 보고 GDB가 고장났다고 오해하는 것 — 실제로 그 주소가 현재 프로세스에 매핑되어 있지 않다는 뜻이다(`info proc mappings`로 확인).

## 막혔을 때 다음 체크
- 지금 명령어 자체를 넓은 범위로 디스어셈블해서 보고 싶다면 → REV-0190 GDB disassemble와 현재 RIP 주변 보기
- 포인터를 자동으로 따라가며 보여주는 더 편한 방법이 궁금하다면 → REV-0193 Pwndbg context telescope vmmap
- 특정 주소 값이 바뀌는 순간을 잡고 싶다면 → REV-0191 GDB watchpoint 기초

## 출처/검증
- `x` 명령의 문법(`x/NFU addr`), 형식/단위 문자 목록: GDB 공식 온라인 문서("Examining Memory") 기준.
- `display` 명령의 자동 재출력 동작: GDB 공식 문서 "Automatic Display" 섹션 기준 (2026-09-08 검증).
