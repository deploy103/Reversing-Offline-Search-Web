## 한 줄 요약
x64dbg의 **Script 탭**은 `msg`, `cmp`, `jmp`(및 `je`/`jne` 계열), `log` 같은 전용 스크립트 명령과 라벨을 한 줄씩 실행하는 미니 프로그래밍 환경으로, "특정 조건이 될 때까지 반복해서 확인하고 자동으로 다음 동작을 하는" 작업을 F9 반복 클릭 없이 자동화할 수 있게 해준다.

## 언제 검색해야 하나
- 같은 루프를 몇 번이고 `F9`(Run)/`F8`(Step over)로 손으로 지나가는 게 지겨울 때
- 언패킹 문제에서 "특정 레지스터가 특정 값이 될 때까지 실행하고 그 순간 멈춰라" 같은 절차를 자동화하고 싶을 때
- 메모리 값이 특정 조건을 만족할 때만 메시지를 띄우거나 로그를 남기고 싶을 때
- CTF에서 같은 크랙미를 입력값만 바꿔가며 반복 검증해야 할 때
- x64dbg 커맨드 바에 입력하는 명령(`bp`, `eax=1` 등)과 Script 탭 전용 명령(`msg`, `jmp`, 라벨)의 차이가 궁금할 때

## 핵심 개념

### Script 탭은 무엇인가
x64dbg 상단 탭 목록에서 `Script`를 클릭하면 나오는 창으로, 한 줄에 하나씩 명령을 적어두고 위에서 아래로 실행하는 **작은 스크립트 파일**을 편집/실행하는 곳이다. 이미 브레이크포인트, 레지스터 조작 등에 쓰던 커맨드 바 명령(`bp`, `eax=1`, `dump 0x401000` 등)을 그대로 쓸 수 있고, 여기에 더해 **Script 전용 명령**(`msg`, `cmp`, `jmp`/`je`/`jne`, `log`, `pause`, `ret`, `call`)이 추가된다. 즉 Script 탭 문법은 "커맨드 바에서 쓰던 명령 + 흐름 제어(라벨과 조건 분기)"의 조합이다.

### 라벨과 분기 — cmp + jxx/ifxx
스크립트에서 흐름을 제어하는 핵심은 **라벨**과 **조건부 점프**다. 라벨은 줄 끝에 콜론을 붙여 만든다.

```text
mainloop:
  ...
  jmp mainloop
```

조건 분기는 어셈블리와 비슷한 이름을 그대로 쓴다. `cmp A, B`로 두 값을 비교하면 그 결과가 내부 플래그(`$_EZ_FLAG`, `$_BS_FLAG` 같은 스크립트 전용 전역 변수)에 저장되고, 바로 다음 줄의 `je`(=`ife`)/`jne`(=`ifne`)/`jb`(=`ifb`)/`ja`(=`ifa`) 등이 이 플래그를 보고 지정한 라벨로 점프할지 결정한다.

```text
cmp eax, 1
je found        ; eax == 1이면 found 라벨로 점프
jmp mainloop     ; 아니면 계속 반복
```

`jxx`(예: `je`)와 `ifxx`(예: `ife`)는 사실상 같은 기능이며, 표기 스타일 차이일 뿐이다.

### 메시지/로그 출력 — msg, log
- `msg "텍스트"` : 메시지 박스를 띄운다. 스크립트가 특정 지점까지 왔음을 눈으로 바로 확인할 때 유용하다. 문자열 포매팅(`{r:eax}`처럼 레지스터 값을 문자열에 끼워 넣는 문법)을 그대로 쓸 수 있다.
- `msgyn "텍스트"` : 예/아니오를 물어보는 메시지 박스. 사용자가 계속 진행할지 스크립트 안에서 직접 선택하게 할 수 있다.
- `log "텍스트"` : 메시지 박스 없이 Log 탭에만 값을 남긴다. 실행 흐름을 끊지 않고 값만 기록하고 싶을 때 `msg` 대신 쓴다.
- `pause` : 스크립트 실행을 일시 정지하고 디버거를 일반 조작 상태로 돌려준다. 중간에 사람이 직접 값을 확인해야 할 때 넣는다.
- `ret` : 스크립트(또는 `call`로 불려 들어온 서브루틴)를 종료한다.

### 서브루틴 호출 — call
`call 라벨`로 다른 라벨 위치를 서브루틴처럼 호출하고, 그 라벨 쪽 코드가 `ret`을 만나면 호출한 지점 바로 다음 줄로 돌아온다. 반복되는 검사 로직(예: "현재 EAX가 유효한 포인터인지 확인")을 한 번만 작성해 여러 곳에서 재사용할 때 쓴다.

### 실행/디버그 조작 명령을 그대로 사용
Script 탭 안에서도 `bp 401000`, `run`(또는 `go`), `StepOver`, `StepInto` 같은 일반 디버거 명령을 그대로 쓸 수 있다. 즉 "브레이크포인트를 걸고 실행하다가, 멈추면 값을 검사하고, 조건에 따라 분기한다"는 흐름 전체를 스크립트 한 개로 표현할 수 있다.

### 저장/불러오기
스크립트는 텍스트 파일(예: `.txt`)로 저장(`File → Save Script` 또는 Script 탭 우클릭)하고 다시 불러올(`Load Script`) 수 있어서, 자주 쓰는 자동화 루틴을 재사용할 수 있다.

## 화면/코드에서 보이는 징후
- Script 탭에 줄 번호와 함께 명령들이 나열되어 있고, 현재 실행 중인 줄은 화살표(→)로 강조 표시된다.
- 스크립트를 실행(F9 계열 스크립트 실행 버튼 또는 Script 메뉴의 Run)하면 CPU 탭이 아니라 Script 탭에서 진행 상황을 볼 수 있다.
- 문법 오류가 있는 줄에서는 스크립트 실행이 그 줄에서 멈추고 에러가 표시된다.
- `msg`가 실행되면 일반적인 Windows 메시지 박스 팝업이 뜬다 — 이게 뜨면 스크립트가 그 지점까지는 정상적으로 도달했다는 뜻이다.

## 가장 먼저 할 것
자동화하려는 절차를 먼저 **손으로 한 번** 끝까지 따라가 본다. 어떤 레지스터/메모리 값을 조건으로 삼아야 하는지, 몇 번째 반복에서 원하는 상태가 되는지 감을 잡은 뒤에 그 판단 기준을 `cmp`/`jxx` 조합으로 옮기는 것이 스크립트 작성 시행착오를 크게 줄인다.

## 단계별 절차

**1) Script 탭 열기**

상단 탭에서 `Script`를 클릭한다. 빈 탭이면 첫 줄부터 바로 입력을 시작할 수 있다.

**2) 라벨과 반복 구조 만들기**

먼저 뼈대를 만든다.

```text
start:
  bp 00401230
  run
loopcheck:
  cmp eax, 5
  je done
  StepOver
  jmp loopcheck
done:
  msg "eax == 5 도달!"
  ret
```

이 스크립트는 `00401230`에 브레이크포인트를 걸고 실행한 뒤, 멈출 때마다 `EAX`가 5인지 검사해서 아니면 한 줄 더 진행(`StepOver`)하고 다시 검사하는 것을 반복하다가, `EAX==5`가 되는 순간 메시지를 띄우고 종료한다.

**3) 실행하기**

Script 탭에서 우클릭 → `Run` 또는 스크립트 실행 단축키를 사용한다. 한 줄씩 확인하고 싶으면 `Step`(스크립트 자체를 한 줄씩 실행)을 쓴다.

**4) 문제 생기면 한 줄씩 디버깅**

스크립트가 의도대로 멈추지 않으면, Script 탭의 `Step` 기능으로 한 줄씩 실행하면서 어느 라벨/조건에서 예상과 다르게 흘러가는지 확인한다.

**5) 저장해서 재사용**

잘 동작하는 스크립트는 파일로 저장해두고, 비슷한 문제를 풀 때 불러와 주소만 바꿔서 재사용한다.

## 명령어/단축키
```text
msg "텍스트"          ; 메시지 박스 출력 (문자열 포매팅 가능, 예: msg "eax={r:eax}")
msgyn "텍스트"        ; 예/아니오 메시지 박스
log "텍스트"          ; Log 탭에만 기록
pause                 ; 스크립트 실행을 잠깐 멈추고 수동 조작으로 전환
cmp A, B              ; A와 B 비교, 결과를 내부 플래그에 저장
jmp label             ; 무조건 분기
je label / ife label  ; 같으면 분기 (jne/ifne: 다르면)
ja label / ifa label  ; A가 크면 분기 (jb/ifb: A가 작으면)
call label            ; 서브루틴 호출
ret                    ; 서브루틴/스크립트 종료
```
Script 탭 우클릭 메뉴: `New Script`, `Open Script`, `Save Script`, `Run`, `Step`, `Abort`.

## 출력 해석
- `msg` 창의 문자열 포매팅(`{r:eax}`, `{p:cip}` 등)은 현재 값을 그대로 문자열로 바꿔 보여주므로, 창에 찍힌 값이 곧 그 시점의 실제 레지스터/주소 값이다.
- 스크립트가 특정 줄에서 멈추고 더 진행하지 않는다면, 그 줄의 조건(`cmp`/`jxx`)이 계속 거짓으로 평가되어 무한 루프에 빠졌거나, `bp`가 걸린 주소에 실행이 아예 도달하지 못하고 있다는 뜻이다. 이럴 때는 `pause`를 그 근처에 임시로 추가해 중간 상태를 눈으로 확인한다.
- `Abort`로 스크립트를 강제 종료했는데도 디버거가 이상하게 멈춰 있다면, 스크립트 중간에 걸어둔 브레이크포인트가 그대로 남아 있을 수 있으니 Breakpoints 탭에서 정리한다.

## 흔한 실수
- 스크립트 안에서 `run`처럼 실행 상태를 바꾸는 명령을 남발하고 바로 다음 줄에서 값을 확인하려다가, 실제로 그 주소에 도달하기 전에 다음 줄이 평가되어 버리는 경우 — `run`/`go` 다음에는 반드시 브레이크포인트 도달을 기다리는 구조로 짜야 한다.
- 라벨 이름에 공백이나 예약어를 써서 파싱 오류가 나는 경우 — 라벨은 영문/숫자/밑줄 조합의 단순한 이름으로 짓는다.
- `cmp` 다음 줄에 조건 분기(`je`/`jne` 등)를 넣지 않고 다른 명령을 먼저 넣어서, 비교 결과 플래그가 다른 값으로 덮어써지는 경우.
- 무한 루프를 만들어 놓고 종료 조건(`je done` 같은 탈출 경로)을 빠뜨려서 스크립트가 영원히 멈추지 않는 경우 — 반드시 하나 이상의 탈출 라벨을 준비한다.
- 조건부 브레이크포인트(REV-0816, REV-0183)로 충분한 상황인데 굳이 Script로 복잡하게 구현하는 경우 — "이 주소에서 이 조건이면 멈춰라"는 조건부 브레이크포인트가 훨씬 간단하고, Script는 "여러 단계에 걸친 절차 자체를 자동화"해야 할 때 쓰는 것이 적합하다.

## 막혔을 때 다음 체크
- 스크립트 안에서 쓸 조건식 문법 자체가 헷갈리면 → REV-0183 x64dbg 조건부 Breakpoint 기초에서 표현식 문법을 먼저 복습한다.
- 반복 실행 중 값이 어떻게 변하는지 전체 흐름을 기록하고 싶다면 → REV-0815 x64dbg Trace 기능으로 실행 흐름 기록하기가 더 적합할 수 있다.
- 조건이 맞는 순간을 잡은 뒤 코드를 바로 고치고 싶다면 → REV-0184 x64dbg CTF용 간단 패치와 저장을 참고한다.
- 기본적인 브레이크포인트 설정법이 헷갈린다면 → REV-0178 x64dbg Breakpoint 설정과 삭제를 먼저 본다.

## 미니 예제
간단한 크랙미에서 입력 비교 루프가 몇 번째 문자에서 실패하는지 자동으로 찾는 상황이다.

```text
start:
  bp 00401450          ; 문자 비교가 일어나는 지점
  run
checkloop:
  cmp al, byte:[edx]
  jne mismatch
  log "match at index={r:ecx}"
  StepOver
  jmp checkloop
mismatch:
  msg "첫 번째 불일치 index={r:ecx}, al={r:al}"
  ret
```

이 스크립트를 실행하면 매 반복마다 일치한 인덱스를 Log 탭에 남기다가, 처음으로 불일치가 발생하는 순간 인덱스와 값을 메시지 박스로 바로 알려준다. 손으로 F8을 수십 번 누르며 매번 `AL`과 `ECX`를 확인하던 작업을 한 번의 실행으로 끝낼 수 있다.

## 출처/검증
- Script 탭의 `msg`/`msgyn`/`log`/`pause`/`ret`/`call` 명령과 `jxx`/`ifxx` 계열 조건 분기, 라벨 문법: 공식 문서 help.x64dbg.com의 Script Commands 레퍼런스(`commands/script/`) 및 GitHub `x64dbg/docs` 저장소의 `commands/script/index.rst` 기준(2026-09-09 조사).
- `cmp` 비교 결과가 내부 플래그(`$_EZ_FLAG`, `$_BS_FLAG` 등)에 저장되고 이후 `jxx`가 이를 참조한다는 동작 방식: 커뮤니티 튜토리얼(n1ghtw0lf.github.io "Writing x64dbg scripts", HackMag "Automating x64dbg") 및 공식 문서의 설명을 교차 확인.
- 문자열 포매팅(`{r:eax}` 등)과 `bp`/`run`/`StepOver` 등 커맨드 바 명령을 Script 탭에서 그대로 재사용할 수 있다는 점: 공식 문서 Script Commands 개요("commands that also exist in a non-scripting context have priority") 기준.
