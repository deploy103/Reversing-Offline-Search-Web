## 한 줄 요약
`Z3`는 "이 조건들을 모두 만족하는 값이 있는가?"를 자동으로 풀어주는 SMT(Satisfiability Modulo Theories) 솔버이며, 리버싱에서는 정수 대신 정확한 비트 폭을 가진 `BitVec`으로 변수를 선언하고 검증 로직을 제약조건으로 옮긴 뒤 `s.check()`/`s.model()`로 정답 입력값을 역산해내는 데 쓴다.

## 언제 검색해야 하나
- 리버싱한 검증 함수(`check(int x)` 같은)가 복잡한 산술/비트 연산을 여러 겹 하고 있어서 손으로 역산하기 너무 번거로울 때
- 브루트포스를 하기엔 입력 공간이 너무 커서(예: 32비트 정수 전체) 현실적인 시간 안에 못 풀 때
- 라이트업에서 `from z3 import *`, `BitVec`, `Solver`, `s.add(...)`, `s.check()` 같은 코드를 봤는데 각각 무슨 역할인지 모를 때
- "이 조건을 만족하는 값 아무거나 하나"를 자동으로 찾고 싶을 때(직접 방정식을 풀 필요 없이)

## 핵심 개념
Z3는 마이크로소프트 리서치에서 만든 SMT 솔버로, "변수들 사이의 제약조건(constraint) 집합"을 입력받아 그 조건을 모두 만족하는 값 조합이 존재하는지(`sat`, satisfiable) 아닌지(`unsat`, unsatisfiable)를 판단하고, 존재한다면 실제 값 하나(모델)를 찾아준다. 이는 수학적으로 정확한 탐색이며, 브루트포스처럼 값을 하나씩 대입해보는 방식이 아니라 제약조건 자체를 분석해서 답을 좁혀나간다. 그래서 32비트, 64비트처럼 브루트포스로는 사실상 불가능한 큰 탐색 공간도 순식간에(또는 적어도 훨씬 빠르게) 풀어내는 경우가 많다.

리버싱에서 가장 먼저 익혀야 할 타입은 **`BitVec`**이다.

```python
from z3 import *
x = BitVec('x', 32)   # 이름이 'x'인 32비트 비트벡터 변수
```

여기서 `32`는 이 변수가 C의 `int`나 `unsigned int`처럼 정확히 32비트 폭을 가진다는 뜻이다. 이것이 왜 중요한가 하면, Z3의 파이썬 정수(`Int`)는 수학적으로 무한히 큰 정수를 표현하지만, 실제 바이너리의 변수는 8/16/32/64비트로 잘려서(truncate) 오버플로우가 발생하는 유한한 값이기 때문이다. 리버싱 자동화에서 `Int` 대신 `BitVec`을 쓰는 이유가 바로 이 "잘림/오버플로우까지 정확히 흉내 내기" 위해서다. 이 주제는 REV-0270에서 더 깊이 다룬다.

Z3 파이썬 바인딩(`z3-solver` 패키지)의 기본 작업 흐름은 다음 네 단계다.

1. **변수 선언** — `BitVec('이름', 비트수)`로 심볼릭 변수를 만든다. 아직 값이 정해지지 않은, "미지수" 상태다.
2. **솔버 생성** — `s = Solver()`로 제약조건을 모아둘 그릇을 만든다.
3. **제약조건 추가** — `s.add(조건식)`으로 리버싱한 검증 로직을 그대로(또는 등가 형태로) 옮겨 담는다. 여러 번 `add()`를 호출하면 모든 조건이 AND로 합쳐진다.
4. **풀이 및 결과 확인** — `s.check()`가 `sat`을 반환하면 조건을 만족하는 값이 존재한다는 뜻이고, `s.model()`로 실제 변수값을 꺼낸다.

## 화면/코드에서 보이는 징후
- 코드 맨 위에 `from z3 import *`가 있고, 이어서 `BitVec(...)` 호출들이 여러 개 보인다.
- `s = Solver()` 다음에 `s.add(x + y == 100)`처럼 파이썬의 비교/산술 연산자를 그대로 쓴 제약조건이 여러 줄 나열되어 있다 — Z3는 연산자 오버로딩으로 `==`, `<`, `+`, `^`, `&` 같은 파이썬 연산자를 심볼릭 수식으로 바꿔준다.
- `if s.check() == sat:` 형태의 분기가 있고, 그 안에서 `s.model()` 결과를 출력한다.
- 결과 출력이 `[x = 1234567]`처럼 대괄호로 감싸진 리스트 형태로 나온다 — 이것이 Z3의 `Model` 객체를 사람이 읽을 수 있게 출력한 형태다.
- `m[x].as_long()`처럼 모델에서 특정 변수의 값을 파이썬 정수로 꺼내는 코드가 붙어 있다.

## 가장 먼저 할 것
Z3를 쓰기 전에 리버싱으로 알아낸 검증 로직을 먼저 "입력 변수가 어떤 산술/비트 연산을 거쳐서 어떤 최종 조건과 비교되는가"의 형태로 종이나 텍스트로 정리한다. Z3 코드를 짜는 작업은 사실 이 논리를 그대로 파이썬 문법으로 옮기는 번역 작업에 가깝다. 로직 파악 없이 Z3부터 열면 어떤 변수를 몇 비트로 선언해야 할지조차 알 수 없다.

## 단계별 절차

**1) 설치 확인**

```bash
pip install z3-solver
python3 -c "import z3; print(z3.get_version_string())"
```

**2) 가장 단순한 예: `x + 5 == 100`을 만족하는 x 찾기**

```python
from z3 import *

x = BitVec('x', 32)
s = Solver()
s.add(x + 5 == 100)

if s.check() == sat:
    m = s.model()
    print(m)              # [x = 95]
    print(m[x].as_long())  # 95
else:
    print('unsat: 조건을 만족하는 값이 없음')
```

**3) 여러 변수, 여러 조건 다루기**

리버싱한 검증 로직이 두 정수 x, y를 함께 검사한다고 가정한다.

```python
from z3 import *

x = BitVec('x', 32)
y = BitVec('y', 32)
s = Solver()

s.add(x + y == 30)
s.add(x - y == 10)
s.add(x > 0)
s.add(y > 0)

if s.check() == sat:
    m = s.model()
    print('x =', m[x].as_long())  # 20
    print('y =', m[y].as_long())  # 10
```

**4) 비트 연산 조건 추가**

Z3 BitVec은 XOR(`^`), AND(`&`), OR(`|`), 시프트(`<<`, `>>`)도 파이썬 연산자로 그대로 표현할 수 있다.

```python
from z3 import *

x = BitVec('x', 32)
s = Solver()

s.add((x ^ 0x1337) == 0xdead)
s.add(x & 0xff == 0x42)

result = s.check()
print(result)
if result == sat:
    print(hex(s.model()[x].as_long()))
```

**5) `unsat`일 때 대응**

조건이 서로 모순되면 `s.check()`는 `unsat`을 반환한다. 이는 대부분 제약조건을 잘못 옮겼거나(부호/비트폭 실수), 원래 검증 로직 자체에 도달 불가능한 분기가 있다는 신호다.

```python
from z3 import *
x = BitVec('x', 8)
s = Solver()
s.add(x > 200)
s.add(x < 100)
print(s.check())  # unsat
```

## 명령어/단축키
- `BitVec('name', n)` : n비트 폭의 심볼릭 변수 선언
- `BitVecVal(v, n)` : n비트 폭의 상수값(구체값) 생성
- `Solver()` : 제약조건 컨테이너 생성
- `s.add(expr)` : 제약조건 추가(여러 번 호출 시 AND로 결합)
- `s.check()` : `sat` / `unsat` / `unknown` 반환
- `s.model()` : 만족 모델(변수 → 값 매핑) 반환
- `m[var].as_long()` : 모델에서 특정 변수 값을 파이썬 정수로 추출
- `s.add(Or(...))`, `s.add(And(...))` : 명시적 논리 결합

## 출력 해석
- `sat` — 조건을 만족하는 값 조합이 적어도 하나 존재한다. 이후 `s.model()`로 실제 값을 얻을 수 있다.
- `unsat` — 조건을 동시에 만족하는 값이 없다. 제약조건을 잘못 옮겼는지(부호 있는 비교를 부호 없는 비교로 잘못 썼는지, 비트폭이 맞는지) 먼저 의심한다.
- `unknown` — Z3가 시간/자원 제한 내에 답을 결론짓지 못했다는 뜻. 조건식이 지나치게 비선형적이거나(나눗셈, 곱셈이 얽힌 복잡한 수식) 탐색 공간이 비정상적으로 크면 나타날 수 있다.
- `[x = 95]` 같은 모델 출력에서 값이 음수처럼 보이면, 부호 있는 비교(`s.add(x > 0)`이 아니라 `x >s 0` 계열의 signed 비교) 함수를 썼는지 확인해야 한다. Z3 BitVec의 기본 비교 연산자는 부호 없는(unsigned) 비교라는 점에 주의한다(부호 있는 비교는 `x > y` 대신 별도 함수를 쓰거나, 필요시 문맥에 맞게 처리해야 한다).
  - **정확한 정정:** 위 문장과 달리, z3py의 `BitVec` 기본 비교 연산자(`<`, `<=`, `>`, `>=`)는 사실 **부호 있는(signed) 비교**다. 부호 없는 비교가 필요하면 반드시 `ULT(a, b)`, `ULE(a, b)`, `UGT(a, b)`, `UGE(a, b)` 함수를 명시적으로 써야 한다(Z3 공식 API 문서 기준). 예를 들어 8비트 `BitVecVal(0xff, 8)`는 기본 `<` 비교에서는 `-1`(음수)로 취급되지만 `ULT`/`ULE` 비교에서는 `255`(양수)로 취급된다. 이 차이를 실제로 확인하고 싶다면 REV-0270 문서의 "실전 예시" 항목에서 `ULT`를 직접 사용해보는 코드를 참고한다.

## 흔한 실수
- 32비트 값인데 `BitVec('x', 8)`처럼 비트폭을 잘못 지정해서 값이 잘리거나 엉뚱한 오버플로우가 생기는 경우 — 원래 C 변수의 타입(`char`, `int`, `long` 등)을 정확히 확인하고 그에 맞는 비트폭을 골라야 한다.
- Z3의 `BitVec` 대신 무심코 `Int`를 써서, C 프로그램이라면 당연히 발생했을 오버플로우가 Z3 모델에서는 발생하지 않아 잘못된(바이너리에서는 실제로 안 통하는) 해를 얻는 경우.
- `s.add()`를 여러 번 호출하면 자동으로 AND로 묶인다는 걸 모르고, `s.add(a == 1, b == 2)`처럼 한 번에 여러 조건을 넣어야 하는지 헷갈리는 경우 — 사실 이 둘은 동일하게 동작하지만, 조건이 복잡해질수록 `Solver()`를 하나만 재사용하지 않고 매번 새로 만들어서 이전 조건이 다 날아가는 실수도 흔하다.
- `s.check()`를 호출하기 전에 `s.model()`을 먼저 부르려다 예외가 나는 경우 — 반드시 `check()`가 `sat`을 반환한 뒤에만 `model()`을 호출할 수 있다.
- 여러 개의 해가 있을 수 있는데 Z3가 찾아준 첫 모델이 "원래 정답"이 아니라고 착각하는 경우 — Z3는 조건을 만족하는 아무 값이나 하나를 찾아줄 뿐, 문제 출제자가 의도한 유일한 정답이라는 보장은 없다. 다만 CTF 검증 로직은 보통 해가 유일하도록 설계되어 있어 실무에서는 문제가 되는 경우가 드물다.

## 막혔을 때 다음 체크
- `unsat`이 계속 나온다면 → 조건을 하나씩 주석 처리하며 어느 조건이 모순을 만드는지 이분 탐색하듯 좁혀본다.
- 문자 단위 조건(패스워드 각 글자에 대한 제약)을 다뤄야 한다면 → REV-0269 문서에서 문자열/문자 배열을 BitVec 배열로 다루는 패턴을 참고한다.
- 8비트/32비트 오버플로우나 부호 확장이 섞인 로직이라면 → REV-0270 문서에서 정확한 비트폭 모델링 방법을 참고한다.
- 검증 로직 자체가 손으로 옮기기엔 너무 복잡한 분기/루프 구조라면 → REV-0271 문서의 `angr` 심볼릭 실행으로 넘어가는 것을 고려한다. angr은 내부적으로 Z3를 백엔드 솔버로 쓰면서 바이너리 실행 자체를 심볼릭하게 시뮬레이션해준다.
- 오프라인 환경에서 `pip install z3-solver`가 막혀 있다면 → 툴킷 카테고리(`../tools/`, 추후 작성)에서 오프라인 설치 절차를 참고한다.

## 미니 예제
간단한 시리얼 검증 로직 `((x * 3) ^ 0x5a) == 0xe1`을 만족하는 32비트 x를 Z3로 구한다.

```python
from z3 import *

x = BitVec('x', 32)
s = Solver()
s.add((x * 3) ^ 0x5a == 0xe1)

if s.check() == sat:
    m = s.model()
    ans = m[x].as_long()
    print('x =', ans, hex(ans))
else:
    print('unsat')
```

이 스크립트를 실행하면 조건을 만족하는 `x` 값을 즉시 얻을 수 있고, 이 값을 REV-0266/REV-0267의 `p32(ans)` + `sendline()` 조합으로 실제 바이너리에 넣어 검증하면 리버싱-역산-검증의 전체 자동화 루프가 완성된다.

## 실전 예시: 변수 세 개, 조건 세 개가 동시에 얽힌 경우
리버싱한 검증 로직이 정수 하나가 아니라 **서로 다른 변수 여러 개가 XOR, 덧셈, 마스킹으로 뒤섞여** 있는 경우도 흔하다. Z3는 변수가 몇 개든 `s.add()`로 조건을 계속 추가하기만 하면 되므로, 사람이 손으로 연립방정식을 푸는 것보다 훨씬 쉽게 답을 구할 수 있다.

리버싱으로 다음과 같은 세 조건을 확인했다고 가정한다(변수 x, y, z 모두 32비트 `unsigned int`).

```c
// 원본 검증 로직(가정)
// cond1: x ^ y == 0x624
// cond2: (x + z) & 0xff == 0xa4
// cond3: y - z == 800
```

이 세 조건을 그대로 Z3 코드로 옮기면 다음과 같다.

```python
from z3 import *

x = BitVec('x', 32)   # unsigned int x
y = BitVec('y', 32)   # unsigned int y
z = BitVec('z', 32)   # unsigned int z
s = Solver()

s.add(x ^ y == 0x624)          # 조건 1: x와 y를 XOR한 결과가 0x624
s.add((x + z) & 0xff == 0xa4)   # 조건 2: x+z의 하위 8비트가 0xa4
s.add(y - z == 800)              # 조건 3: y에서 z를 뺀 값이 800 (32비트 unsigned 뺄셈)
s.add(x > 0, y > 0, z > 0)        # 세 값 모두 양수라는 상식적인 제약도 추가

print(s.check())
if s.check() == sat:
    m = s.model()
    xv, yv, zv = m[x].as_long(), m[y].as_long(), m[z].as_long()
    print('x =', xv)
    print('y =', yv)
    print('z =', zv)
```

이 스크립트를 실행하면 `sat`이 나오고, `x = 34676`, `y = 33104`, `z = 32304`라는 값을 얻는다(직접 z3-solver로 재현 검증됨). 실제로 이 세 값을 손으로 대입해 확인해보면 세 조건이 모두 정확히 성립한다.

```python
xv, yv, zv = 34676, 33104, 32304
print(hex(xv ^ yv))          # 0x624  -> 조건 1 만족
print(hex((xv + zv) & 0xff))  # 0xa4   -> 조건 2 만족
print(yv - zv)                 # 800    -> 조건 3 만족
```

주의할 점은, 이 값이 **문제 출제자가 애초에 정해둔 "원래 정답"과 정확히 같을 필요는 없다**는 것이다(핵심 개념/흔한 실수에서 이미 다룬 대로, Z3는 조건을 만족하는 아무 해나 하나를 찾아준다). 조건 세 개만으로는 여러 개의 `(x, y, z)` 조합이 답이 될 수 있으므로, 실제 CTF 문제라면 보통 조건이 더 추가되어(예: `x`, `y`, `z` 중 하나가 아스키 문자열 범위로 제한되는 등) 해가 사실상 유일하도록 설계되어 있는 경우가 많다.
