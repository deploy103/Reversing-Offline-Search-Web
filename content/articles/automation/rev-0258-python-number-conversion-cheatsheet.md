## 한 줄 요약
리버싱 중 계산기 대용으로 Python을 켰다면 `hex()`, `int(x, 16)`, `bin()`, `chr()`/`ord()`, f-string 서식(`f"{x:#010x}"`)만 기억해도 진법 변환의 90%는 해결된다.

## 언제 검색해야 하나
- 디버거에서 본 16진수 상수를 10진수로 바꾸고 싶을 때
- 반대로 계산해서 나온 10진수 결과를 16진수 상수로 다시 바꿔서 브레이크포인트 조건이나 패치 값으로 써야 할 때
- 바이트 배열을 아스키 문자열로, 혹은 문자를 바이트값으로 즉석에서 바꿔야 할 때
- `%08x`, `%x` 같은 printf 서식을 Python f-string으로 어떻게 쓰는지 매번 까먹을 때

## 핵심 개념
Python의 정수는 내부적으로 진법 구분이 없다 — `10`, `0xa`, `0b1010`, `0o12`는 전부 같은 정수 객체를 가리킨다. 즉 "몇 진법으로 표시할지"는 오직 **출력 시점**의 문제이고, 계산 자체는 항상 10진 정수로 이루어진다. 이 점을 이해하면 변환 함수들이 왜 "문자열 ↔ 정수" 변환기인지 명확해진다.

- `hex(n)`, `bin(n)`, `oct(n)`: 정수를 각각 `'0x..'`, `'0b..'`, `'0o..'` 접두어가 붙은 **문자열**로 변환.
- `int(s, base)`: 문자열을 지정한 진법으로 해석해 정수로 변환. `base=0`이면 접두어(`0x`, `0b`, `0o`)를 보고 자동 판별.
- `chr(n)` / `ord(c)`: 정수 코드포인트 ↔ 1글자 문자열 상호 변환.
- f-string의 `:x`, `:b`, `:o` 서식 지정자는 `hex()`류보다 자릿수/0채움/접두어 유무를 세밀하게 제어할 수 있어 실전에서 더 자주 쓴다.

## 화면/코드에서 보이는 징후
디스어셈블러에서 `cmp eax, 0x1337`처럼 16진 상수가 보이거나, 덤프 창에 `41 42 43 44` 같은 바이트가 나열되어 있는 상황이 전형적이다. 이런 값을 눈으로 계산하지 말고 바로 Python 인터랙티브 셸(`python3` 실행 후 `>>>` 프롬프트)에 붙여넣어 확인하는 것이 실수를 줄인다.

## 가장 먼저 할 것
터미널에서 `python3`를 쳐서 인터랙티브 셸을 띄운다. 이후 모든 변환은 한 줄짜리 REPL 입력으로 끝난다 — 별도 스크립트 파일을 만들 필요가 없다.

## 단계별 절차
**1) 10진수 → 16진수**
```python
>>> hex(4919)
'0x1337'
>>> f"{4919:#06x}"      # 0x 포함 6자리, 부족하면 0으로 채움
'0x1337'
>>> f"{4919:04x}"       # 0x 없이 4자리
'1337'
```

**2) 16진수 문자열 → 정수**
```python
>>> int("1337", 16)
4919
>>> int("0x1337", 16)   # 0x 접두어가 있어도 그대로 됨
4919
>>> int("0x1337", 0)    # base=0이면 접두어를 보고 자동 판별
4919
```

**3) 2진수 변환**
```python
>>> bin(202)
'0b11001010'
>>> int("11001010", 2)
202
>>> f"{202:#010b}"      # 0b + 8자리 이진수
'0b11001010'
```

**4) 문자 ↔ 코드값**
```python
>>> ord('A')
65
>>> chr(65)
'A'
>>> [hex(ord(c)) for c in "flag"]
['0x66', '0x6c', '0x61', '0x67']
>>> "".join(chr(b) for b in [0x66, 0x6c, 0x61, 0x67])
'flag'
```

**5) 바이트 배열 ↔ 문자열/정수**
```python
>>> b"flag".hex()
'666c6167'
>>> bytes.fromhex("666c6167")
b'flag'
>>> list(b"flag")            # 바이트 배열을 정수 리스트로
[102, 108, 97, 103]
>>> bytes([102, 108, 97, 103])
b'flag'
```

**6) 8진수와 진법 자동 판별, 임의 진법**
```python
>>> oct(83)
'0o123'
>>> int("123", 8)
83
>>> int("0o123", 0)      # base=0이면 0o 접두어도 자동 인식
83
>>> int("101", 36)       # 2~36 사이 임의의 진법 지원
1297
```
CTF에서 흔히 쓰이는 36진법(숫자+소문자 알파벳)이나 62진법(대소문자+숫자) 인코딩을 분석할 때도 `int(s, base)`의 `base`를 원하는 값으로 바꾸기만 하면 되므로 별도 변환 로직을 짤 필요가 없다. 다만 `int()`는 base 2~36까지만 지원하며, 62진법처럼 그 이상을 쓰는 커스텀 인코딩은 직접 알파벳 테이블을 만들어 나눗셈/나머지로 변환해야 한다.

## 명령어/단축키
- `python3` : REPL 진입 (Windows에서는 `py` 명령이 더 잘 동작하는 경우도 있음)
- REPL 안에서 위/아래 화살표로 직전 계산 재사용
- `python3 -c "print(hex(4919))"` : 셸을 열지 않고 원라이너로 바로 결과 확인
- x64dbg/IDA에서 값을 복사한 뒤 Python에 그대로 붙여넣기 — 앞의 `0x`는 그대로 두어도 `int(s, 0)`이 알아서 처리

## 출력 해석
- `hex()`/`bin()`/`oct()`의 결과는 **문자열**이다. 다시 산술 연산에 쓰려면 `int(..., 16)` 등으로 되돌려야 한다는 점을 잊지 말 것.
- f-string의 `#` 플래그는 `0x`/`0b`/`0o` 접두어를 붙이라는 뜻이고, 그 뒤 숫자(`06`, `010` 등)는 **접두어를 포함한** 전체 자릿수다. 따라서 `{x:#010x}`는 `0x` 2글자 + 8자리 16진수 = 총 10글자를 의미한다.
- 음수를 `hex()`에 넣으면 `-0x...` 형태로 나온다. C의 부호 없는 32비트 표현을 원한다면 먼저 `x & 0xFFFFFFFF`로 마스킹해야 하며, 이 주제는 REV-0259(부호 변환)와 REV-0264(32비트 오버플로)에서 자세히 다룬다.

## 흔한 실수
- `hex(n)[2:]`로 접두어를 잘라내는 습관 때문에 자릿수가 부족할 때 앞자리 0이 없어져서 바이트 길이가 틀어지는 것 — `f"{n:02x}"` 같은 서식 지정자를 쓰는 편이 안전하다.
- `int("0x1337")`처럼 `base` 인자를 생략해서 `ValueError: invalid literal for int() with base 10`을 만나는 것. 문자열에 `0x`가 있으면 반드시 `base=16` 또는 `base=0`을 명시해야 한다.
- `chr()`에 256 이상의 값을 넣고 아스키 1바이트라고 착각하는 것 — `chr()`은 유니코드 코드포인트 전체를 다루므로 바이트 범위(0~255)를 벗어난 값이 들어가면 깨진 것처럼 보이는 문자가 나올 수 있다.
- 여러 바이트를 한 번에 다룰 때 `ord()`/`chr()`을 반복문으로 돌리는 대신 `bytes.fromhex()`나 `int.to_bytes()`를 쓰는 것이 더 빠르고 실수도 적다(REV-0260, REV-0261 참고).

## 막혔을 때 다음 체크
- 부호 있는 값(음수)과 부호 없는 값 사이의 변환이 헷갈리면 → REV-0259 (Signed/Unsigned 변환).
- 바이트 순서(리틀엔디안/빅엔디안)까지 고려해야 하면 → REV-0260 (Endianness 변환).
- 여러 필드를 한 번에 바이너리로 묶거나 풀어야 하면 → REV-0261 (struct pack/unpack).
- 32비트 연산에서 값이 예상과 다르게 커지거나 음수가 나오면 → REV-0264 (32비트 Overflow 재현).

## 미니 예제
디버거에서 `EAX = 0x1337` 상태로 `cmp eax, 4919`를 만났다고 하자. 두 값이 같은지 눈으로 확인하기 귀찮다면:
```python
>>> hex(4919) == "0x1337"
True
>>> int("1337", 16) == 4919
True
```
또는 메모리 덤프 `41 42 43 44 21`을 본 경우 바로 문자열로 바꿔서 의미를 확인한다:
```python
>>> bytes.fromhex("4142434421")
b'ABCD!'
```
반대로 브레이크포인트 조건식에 넣을 값이 필요하면:
```python
>>> n = 1000
>>> f"{n:#x}"
'0x3e8'
```
이 값을 x64dbg의 조건부 브레이크포인트(`eax == 0x3e8`)에 그대로 붙여넣으면 된다.

또 다른 흔한 상황으로, 여러 바이트로 이루어진 값을 한 번에 사람이 읽기 좋은 형태로 출력하고 싶을 때가 있다. 예를 들어 정수 리스트로 덤프된 배열을 16진수 표로 보고 싶다면:
```python
>>> data = [0x41, 0x13, 0xFF, 0x02]
>>> " ".join(f"{b:02x}" for b in data)
'41 13 ff 02'
```
이 한 줄은 IDA/x64dbg의 헥스 덤프 창과 똑같은 형태의 문자열을 만들어주므로, 스크립트 출력과 디버거 화면을 눈으로 대조할 때 매우 유용하다.

## 참고 — 자주 쓰는 서식 지정자 요약
| 지정자 | 의미 | 예시 (`n = 255`) |
|---|---|---|
| `{n:x}` | 소문자 16진수, 접두어 없음 | `ff` |
| `{n:X}` | 대문자 16진수 | `FF` |
| `{n:#x}` | `0x` 접두어 포함 | `0xff` |
| `{n:04x}` | 4자리, 0으로 채움 | `00ff` |
| `{n:#06x}` | `0x` 포함 총 6자 | `0x00ff` |
| `{n:b}` | 2진수 | `11111111` |
| `{n:o}` | 8진수 | `377` |
이 표 하나만 즐겨찾기 해두면 리버싱 스크립트 작성 중 서식 관련 검색을 다시 할 필요가 거의 없다.
