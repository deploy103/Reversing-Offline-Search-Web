## 한 줄 요약
x86/x64의 범용 레지스터 16개(x86은 8개)는 폭에 따라 64/32/16/8비트 이름이 각각 따로 있고, 여기에 포인터·플래그·세그먼트·명령어 포인터 레지스터까지 합쳐 이 문서 한 장으로 전체 이름을 대조할 수 있다.

## 언제 검색해야 하나
- IDA/GDB/x64dbg에서 낯선 레지스터 이름(`R13D`, `SIL`, `RFLAGS`, `FS` 등)이 나왔는데 이게 정확히 몇 비트짜리이고 무슨 역할인지 바로 찾고 싶을 때
- 레지스터 이름 전체를 한 표로 정리해두고 필요할 때마다 찾아보고 싶을 때
- 세그먼트 레지스터(`FS`, `GS`)나 플래그 레지스터 이름이 범용 레지스터와 헷갈릴 때
- x86과 x64에서 존재하는 레지스터 개수 차이를 빠르게 확인하고 싶을 때

## 핵심 개념
x86/x64 레지스터는 크게 4종류로 나뉜다: 범용 레지스터(GPR), 포인터/인덱스 레지스터(GPR에 포함되지만 특수 용도), 플래그 레지스터, 세그먼트 레지스터, 명령어 포인터. 아래 표들은 각각을 폭/역할별로 정리한 것이다.

### 범용 레지스터 전체 대조표 (64/32/16/8비트)

| 64비트(x64) | 32비트 | 16비트 | 8비트(하위) | 8비트(상위, 레거시) | 전통적 용도 |
|---|---|---|---|---|---|
| RAX | EAX | AX | AL | AH | 누산기(Accumulator), 반환값 |
| RBX | EBX | BX | BL | BH | 베이스(Base) |
| RCX | ECX | CX | CL | CH | 카운터(Counter), 4번째 인자(SysV)/1번째 인자(Win) |
| RDX | EDX | DX | DL | DH | 데이터(Data), 3번째 인자(SysV)/2번째 인자(Win) |
| RSI | ESI | SI | SIL | (없음) | Source Index, 1번째 인자(SysV) |
| RDI | EDI | DI | DIL | (없음) | Destination Index, 2번째 인자(SysV) |
| RBP | EBP | BP | BPL | (없음) | Base Pointer(스택 프레임 기준) |
| RSP | ESP | SP | SPL | (없음) | Stack Pointer |
| R8 | R8D | R8W | R8B | (없음) | 5번째 인자(SysV)/3번째 인자(Win), x64 전용 |
| R9 | R9D | R9W | R9B | (없음) | 6번째 인자(SysV)/4번째 인자(Win), x64 전용 |
| R10 | R10D | R10W | R10B | (없음) | 여분 레지스터, x64 전용 |
| R11 | R11D | R11W | R11B | (없음) | 여분 레지스터, x64 전용 |
| R12 | R12D | R12W | R12B | (없음) | 여분 레지스터, x64 전용 |
| R13 | R13D | R13W | R13B | (없음) | 여분 레지스터, x64 전용 |
| R14 | R14D | R14W | R14B | (없음) | 여분 레지스터, x64 전용 |
| R15 | R15D | R15W | R15B | (없음) | 여분 레지스터, x64 전용 |

**x86(32비트) 모드에는 위 표의 32/16/8비트 열까지만 존재**하며(`R8`~`R15` 계열과 64비트 열은 x64 전용), `SIL`/`DIL`/`BPL`/`SPL`(SI/DI/BP/SP의 8비트 하위 이름)도 x64 모드(REX 프리픽스 필요)에서만 쓸 수 있다.

### 명령어 포인터 / 플래그 레지스터

| 64비트 | 32비트 | 16비트 | 역할 |
|---|---|---|---|
| RIP | EIP | IP | 명령어 포인터(다음에 실행할 명령어 주소) |
| RFLAGS | EFLAGS | FLAGS | 상태 플래그(ZF, CF, SF, OF, PF, AF 등) |

주요 플래그 비트: `ZF`(Zero, 결과가 0이면 1) · `CF`(Carry, 자리올림/빌림 발생) · `SF`(Sign, 결과가 음수면 1) · `OF`(Overflow, signed 오버플로 발생) · `PF`(Parity, 하위 바이트의 1비트 개수가 짝수) · `AF`(Auxiliary Carry, BCD 연산용).

### 세그먼트 레지스터 (x64에서는 역할이 축소됨)

| 이름 | 역할 |
|---|---|
| `CS` | 코드 세그먼트 |
| `DS` | 데이터 세그먼트(레거시) |
| `SS` | 스택 세그먼트 |
| `ES` | 확장 데이터 세그먼트(레거시) |
| `FS` | x64 Windows: TEB(Thread Environment Block) 접근에 사용(`fs:[0x30]` 등) |
| `GS` | x64 Linux: 스레드 로컬 스토리지(TLS) 접근에 사용, x64 Windows: 일부 시스템 구조체 접근 |

x64에서는 플랫(flat) 메모리 모델을 쓰므로 `CS`/`DS`/`SS`/`ES`는 사실상 항상 베이스 주소 0으로 고정되어 실질적 의미가 거의 없고, `FS`/`GS`만 스레드별 특수 데이터 구조 접근용으로 실제 활용된다.

## 화면/코드에서 보이는 징후
- x64dbg/GDB 레지스터 창에 `RAX`~`R15`까지 16개가 표시(x64)되거나 `EAX`~`EDI`까지 8개만 표시(x86)
- 디스어셈블리에 `mov rax, fs:[30h]`(Windows, TEB 접근) 또는 `mov rax, gs:[0]`(Linux, TLS 접근) 형태로 세그먼트 레지스터 사용
- 조건 분기 직전에 `RFLAGS`/`EFLAGS`의 특정 비트(`ZF`, `SF` 등)를 검사하는 `cmp`/`test` 뒤의 `jz`/`js` 등

## 가장 먼저 할 것
낯선 레지스터 이름을 보면 먼저 접두사/접미사로 폭을 판별한다(`R`+없음=64비트, `E`+없음 또는 `D`로 끝남=32비트, `W`로 끝나거나 2글자 레거시=16비트, `B`/`L`/`H`로 끝남=8비트). 그 다음 이 표에서 같은 행을 찾아 전체 폭 계열과 용도를 확인한다.

## 단계별 절차
1. 레지스터 이름의 접두사/접미사만 보고 비트 폭을 먼저 판별한다.
2. 표의 해당 열에서 같은 행(같은 물리 레지스터 계열)을 찾아 다른 폭 이름들도 함께 확인한다.
3. 그 레지스터가 범용(GPR)인지, 플래그인지, 세그먼트인지 표의 구분으로 확인한다.
4. 범용 레지스터라면 호출 규약상 몇 번째 인자에 대응하는지(Windows/SysV 열) 함께 확인한다.
5. `FS`/`GS` 같은 세그먼트 레지스터가 나오면 일반 산술 레지스터가 아니라 TEB/TLS 접근용 특수 레지스터임을 감안하고 문맥을 다시 읽는다.

## 명령어/단축키
```
(gdb) info registers        # 전체 레지스터 한 번에 확인 (x64: rax~r15+rip+eflags)
(gdb) p $eflags              # 플래그 레지스터 값
(gdb) p/x $fs_base            # x64 GDB에서 FS 베이스 주소 확인
```
x64dbg: 레지스터 패널 우클릭 → "Change view" → 32/16/8비트 서브 레지스터 값도 함께 표시 가능.

## 출력 해석
- `info registers`에서 `r8`~`r15`가 보이면 그 프로세스는 확실히 x64(64비트)로 실행 중이다.
- `eflags` 값의 특정 비트가 1인지 확인하려면 표준 비트 위치(`ZF`=bit6, `CF`=bit0, `SF`=bit7, `OF`=bit11)를 기준으로 마스킹해서 읽는다.

## 흔한 실수
- `R8`~`R15`가 x86(32비트) 모드에도 있다고 착각하는 것 — x64 전용이다.
- `AH`/`BH`/`CH`/`DH`(레거시 상위 바이트) 이름 방식이 `R8`~`R15`, `SI`/`DI`/`BP`/`SP` 계열에도 있다고 착각하는 것 — 이 계열은 상위 바이트 별명이 아예 없다.
- 세그먼트 레지스터 `FS`/`GS`를 일반 범용 레지스터처럼 산술 연산에 쓸 수 있다고 착각하는 것 — 이들은 메모리 접근 시 베이스 세그먼트를 지정하는 특수 용도로만 쓰인다(`fs:[...]` 형태).
- `RFLAGS`를 다른 범용 레지스터처럼 직접 `mov`로 자유롭게 읽고 쓸 수 있다고 착각하는 것 — 플래그는 대개 `pushf`/`popf` 또는 개별 조건 분기/`SETcc`/`CMOVcc` 명령어를 통해 간접적으로 다룬다.

## 막혔을 때 다음 체크
- 32/64비트 부분 쓰기가 상위 비트에 미치는 영향(제로 익스텐션 규칙)이 궁금하면 → REV-0022 32비트와 64비트 레지스터 차이
- x86과 x64 아키텍처 전반의 차이가 궁금하면 → REV-0021 x86와 x64를 구분하는 법
- 함수 인자가 어느 레지스터로 전달되는지(Windows/SysV 차이) 궁금하면 → REV-0032 함수 인자와 반환값이 어디에 있는지

## 미니 예제
Windows x64 TEB 접근 코드에서 `FS`/`GS` 대신 `GS`가 쓰이는 예(x64는 `GS` 사용, x86 Windows는 `FS` 사용):
```asm
mov     rax, gs:[30h]     ; x64 Windows: GS 세그먼트 기준 오프셋 0x30 = TEB 주소
```
x86(32비트) Windows에서는 같은 목적으로 `FS`를 쓴다(`mov eax, fs:[30h]`). 아키텍처가 바뀌면서 같은 역할의 세그먼트 레지스터 이름이 바뀐 대표적인 사례이므로, 32비트/64비트 바이너리를 오가며 분석할 때 헷갈리지 않도록 이 표로 확인하는 습관이 유용하다.

## 관련 글
- REV-0022 — 32비트와 64비트 레지스터 차이
- REV-0021 — x86와 x64를 구분하는 법
- REV-0032 — 함수 인자와 반환값이 어디에 있는지

## 출처/검증
- x86/x64 범용 레지스터, 플래그 레지스터, 세그먼트 레지스터 정의: Intel 64 and IA-32 Architectures Software Developer's Manual, Volume 1(Basic Architecture) 기준 (2026-09-09 검증).
- Windows x64에서 GS를 통한 TEB 접근, x86에서 FS를 통한 TEB 접근: Microsoft 공식 문서(Thread Environment Block) 및 Linux `x86_64` ABI의 GS 기반 TLS 관례 기준.
