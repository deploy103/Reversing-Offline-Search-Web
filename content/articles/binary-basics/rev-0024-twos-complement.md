## 한 줄 요약
CPU는 음수를 따로 표현하는 회로가 없고, **모든 비트를 뒤집고 1을 더하는 "2의 보수"** 방식으로 음수를 표현한다. 그래서 `0xFFFFFFFF`가 부호 있는 32비트로 보면 `-1`이 된다.

## 언제 검색해야 하나
- IDA 디컴파일 결과에 `-1`, `-87097619`처럼 갑자기 음수가 나와서 당황했을 때
- 헥스값을 부호 있는(signed) 값으로 바꿔야 하는데 계산법을 모를 때
- `cmp eax, 0FFFFFFFFh`처럼 이상하게 큰 헥스값과 비교하는 코드를 만났을 때

## 핵심 개념
컴퓨터 메모리와 레지스터에는 그냥 0과 1 비트만 저장된다. `+`나 `-` 부호를 저장하는 별도 공간은 없다. 그런데도 우리는 `-5`, `-1` 같은 음수를 다뤄야 한다. 그 해법이 **2의 보수(Two's Complement)** 표현이다.

**핵심 규칙**: N비트 부호 있는 정수에서, 최상위 비트(MSB)가 1이면 음수로 해석한다. 어떤 양수 `x`의 음수 `-x`를 만들려면:
1. `x`의 모든 비트를 뒤집는다 (0↔1, 이것을 1의 보수라 함)
2. 결과에 1을 더한다

**왜 이 방식을 쓰는가**: 2의 보수 표현을 쓰면 CPU가 덧셈 회로 하나만으로 뺄셈까지 처리할 수 있다(`a - b`를 `a + (-b)`로 계산). 별도의 뺄셈 전용 회로나 부호 처리 로직이 필요 없어서 하드웨어가 단순해진다.

**8비트 예시**: `5`는 `0000 0101`. `-5`를 만들려면:
- 비트 반전: `1111 1010`
- +1: `1111 1011` = `0xFB`

즉 8비트에서 `-5`는 `0xFB`(십진수 251)로 저장된다. 부호 없는(unsigned) 관점에서 읽으면 251이고, 부호 있는(signed) 관점에서 읽으면 -5다. **같은 비트 패턴이 해석 방식에 따라 다른 숫자로 보인다**는 게 핵심이다.

**전체 1비트가 모두 1인 값**은 항상 -1이다: 8비트 `0xFF` = -1, 32비트 `0xFFFFFFFF` = -1, 64비트 `0xFFFFFFFFFFFFFFFF` = -1.

## 화면/코드에서 보이는 징후
- IDA 디컴파일 결과에 `if ( result == -1 )` 처럼 나오는데, 어셈블리에서는 `cmp eax, 0FFFFFFFFh`로 되어 있는 경우 — 둘은 완전히 같은 의미다.
- 변수 타입이 `int`(signed)인데 큰 양수를 넣었더니 음수로 출력되는 경우
- `unsigned int` 타입 변수에 음수 리터럴을 대입한 코드가 실제로는 매우 큰 양수로 동작하는 경우

## 가장 먼저 할 것
IDA에서 이상한 음수가 보이면, 그 값을 **부호 없는 헥스값으로 다시 계산**해서 원래 의도를 파악한다. IDA 자체에서도 숫자를 우클릭 → "Hex" 또는 그냥 변수 타입을 unsigned로 바꿔서 보면 원래 헥스 패턴을 바로 확인할 수 있다.

## 단계별 절차

**1) 음수를 헥스(비트 패턴)로 변환하기 — 손으로 계산**

예: 32비트에서 `-87097619`를 헥스로 바꾸고 싶다.
1. 절댓값을 헥스로: `87097619` → `0x0530_something`... (손으로 하기 번거로우면 아래 파이썬 방법 사용을 권장)

**2) 파이썬으로 변환하기 (실전에서 가장 빠른 방법)**
```python
>>> x = -87097619
>>> x & 0xFFFFFFFF          # 32비트 unsigned 값으로
4207869677
>>> hex(x & 0xFFFFFFFF)
'0xfabc1ded'
```
`& 0xFFFFFFFF`(32비트 마스크)를 걸면 파이썬이 자동으로 2의 보수 변환을 해준다. 이 방법이 손으로 비트를 뒤집는 것보다 훨씬 빠르고 안전하다.

**3) 반대로 헥스값을 signed로 해석하기**
```python
>>> v = 0xFABC1DED
>>> if v & 0x80000000:      # 최상위 비트(MSB)가 1이면 음수
...     v -= 0x100000000    # 2^32을 빼면 signed 값이 나옴
>>> v
-87097619
```
이 패턴(`if MSB set: value -= 2**bits`)은 어떤 비트폭에서도 그대로 적용된다.

**4) IDA에서 직접 확인**

숫자 리터럴 위에서 우클릭 → **"Hex"** 또는 숫자 표현 방식을 바꾸는 단축키(`H`)로 헥스/십진 전환이 가능하다. 변수의 타입을 signed↔unsigned로 바꾸고 싶으면 변수 선택 후 **Y**(Set type)로 `int`를 `unsigned int`로 바꿔본다.

## 명령어/단축키
```python
# 파이썬 치트시트
signed_to_hex = lambda x, bits=32: hex(x & ((1 << bits) - 1))
def hex_to_signed(v, bits=32):
    if v & (1 << (bits - 1)):
        v -= (1 << bits)
    return v
```
IDA: 숫자 리터럴에서 `H` (10진/16진 전환)

## 출력 해석
- `0xFFFFFFFF` (32비트) → signed로 읽으면 `-1`
- `0x80000000` (32비트) → signed로 읽으면 `-2147483648` (32비트 signed의 최솟값)
- `0x7FFFFFFF` (32비트) → signed로 읽으면 `2147483647` (32비트 signed의 최댓값, 여기서 1을 더하면 오버플로로 최솟값이 됨)
- 최상위 비트가 0이면 항상 양수, 1이면 항상 음수(2의 보수, N비트 signed 기준)

## 흔한 실수
- 헥스값을 볼 때마다 "이건 그냥 큰 양수겠지"라고 단정하는 것 — 변수 타입이 signed라면 최상위 비트를 반드시 확인해야 한다.
- 32비트 마스크(`& 0xFFFFFFFF`)를 안 걸고 파이썬에서 음수를 그대로 다뤄서, 64비트로 계산되어 결과가 어긋나는 것 — 파이썬 정수는 임의 정밀도라 비트폭을 명시하지 않으면 C와 다르게 동작한다.
- 1의 보수(비트만 반전)와 2의 보수(반전 후 +1)를 헷갈리는 것 — CPU와 C 언어는 2의 보수를 쓴다.

## 막혔을 때 다음 체크
- 여러 비트폭(8/16/24/32/64비트)에서 마스크가 헷갈리면 → REV-0026(비트별 마스크)로 이동.
- `& 0xFF`, `& 0xFFFFFFFF` 같은 AND 연산의 의미가 궁금하면 → REV-0055(AND 명령어)로 이동.
- 오버플로가 왜 일어나는지 궁금하면 → REV-0027(정수 Overflow와 Wraparound, 예정)로 이동.

## 미니 예제
IDA 디컴파일에서 다음 코드를 봤다고 하자:
```c
if ( v4 == -1 )
    goto fail;
```
어셈블리로 내려가 보면:
```asm
cmp     eax, 0FFFFFFFFh
je      fail
```
`v4`가 `unsigned int`로 선언되어 있었다면 이 값은 `4294967295`(즉 `0xFFFFFFFF`)와 비교하는 것과 완전히 동일한 코드다. 디컴파일러가 변수 타입을 `int`(signed)로 추론해서 `-1`로 "예쁘게" 보여준 것뿐이다. 이럴 때는 "아, 이건 그냥 모든 비트가 1인 값(0xFFFFFFFF)을 검사하는 거구나"라고 해석하면 된다 — 예를 들어 함수가 실패 시 `-1`(즉 `0xFFFFFFFF`)을 반환하는 관례적 패턴이다.
