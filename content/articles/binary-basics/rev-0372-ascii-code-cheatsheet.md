## 한 줄 요약
디스어셈블리나 헥스덤프에 나오는 `0x41`, `0x30`, `0x0A` 같은 작은 상수는 산술 계산값이 아니라 **아스키 문자 코드**일 가능성이 높으며, 특히 `0x30`~`0x39`(숫자), `0x41`~`0x5A`(대문자), `0x61`~`0x7A`(소문자) 범위와 `0x0A`(개행), `0x00`(널)은 리버싱에서 매일 마주치는 값이라 외워두면 즉시 알아볼 수 있다.

## 언제 검색해야 하나
- 디스어셈블리에서 `cmp al, 41h` 같은 비교 명령어를 봤는데 `0x41`이 그냥 숫자인지 문자인지 확신이 안 설 때
- 헥스덤프에서 `48 65 6C 6C 6F`처럼 규칙성 있어 보이는 바이트열을 보고 문자열인지 의심될 때
- 입력값 검증 로직에서 특정 범위(`0x30`~`0x39` 등)를 확인하는 코드가 "숫자 문자인지 검사하는 것"인지 판단해야 할 때
- 파일 안의 제어 문자(개행, 탭, 널 등)의 정확한 헥스값이 헷갈릴 때

## 핵심 개념
아스키(ASCII, American Standard Code for Information Interchange)는 문자 하나를 0~127 범위의 정수(7비트, 실제로는 1바이트에 저장) 하나로 대응시키는 표준이다. 리버싱에서는 이 표를 암기하고 있으면 헥스값만 보고도 즉시 "이건 문자 비교/문자열 처리 코드"라고 알아챌 수 있어 매우 유용하다.

### 숫자 문자 (0x30 ~ 0x39)

| 문자 | 10진수 | 16진수 |
|---|---|---|
| `'0'` | 48 | 0x30 |
| `'1'` | 49 | 0x31 |
| `'2'` | 50 | 0x32 |
| `'3'` | 51 | 0x33 |
| `'4'` | 52 | 0x34 |
| `'5'` | 53 | 0x35 |
| `'6'` | 54 | 0x36 |
| `'7'` | 55 | 0x37 |
| `'8'` | 56 | 0x38 |
| `'9'` | 57 | 0x39 |

**핵심 공식**: 숫자 문자의 헥스값에서 `0x30`을 빼면 그 숫자의 실제 값이 나온다. 예: `'7'`(0x37) - 0x30 = 7. `atoi`류 함수의 파싱 루프에서 이 패턴(`sub`, `and 0Fh`)이 반복적으로 나온다.

### 알파벳 (대문자 0x41~0x5A, 소문자 0x61~0x7A)

| 구간 | 시작 문자 | 시작 헥스 | 끝 문자 | 끝 헥스 |
|---|---|---|---|---|
| 대문자 | `'A'` | 0x41 | `'Z'` | 0x5A |
| 소문자 | `'a'` | 0x61 | `'z'` | 0x7A |

**핵심 공식**: 대문자와 소문자는 정확히 `0x20`(32) 차이만 난다. 즉 `대문자 + 0x20 = 소문자`, `소문자 - 0x20 = 대문자`. `or al, 20h`(비트 5를 강제로 1로) 또는 `and al, 0DFh`(비트 5를 강제로 0으로)가 대소문자 변환 관용구로 자주 등장하는 이유다.

## 화면/코드에서 보이는 징후
- `cmp al, 30h` / `cmp al, 39h` 짝이 함께 보이면 "숫자 문자인지 범위 검사하는 코드"(`isdigit` 유사 로직)로 해석
- `cmp al, 41h` / `cmp al, 5Ah` 또는 `61h`/`7Ah` 짝이 보이면 알파벳 범위 검사(`isalpha`, `isupper`, `islower`)
- `or al, 20h` 또는 `and al, 0DFh`가 알파벳 처리 직후 반복되면 대소문자 변환(`tolower`/`toupper`) 관용구
- 헥스덤프에서 `20`~`7E` 범위 바이트가 연속되면 사람이 읽을 수 있는 ASCII 문자열 구간일 가능성이 높음(`strings` 도구의 판별 기준과 동일)

## 가장 먼저 할 것
작은 헥스 상수(`0x00`~`0x7F` 범위)를 만나면 산술 상수로 단정하기 전에 먼저 이 표에서 해당 문자를 찾아본다. 특히 `cmp`/`sub`/`and`/`or` 연산과 함께 나오는 `0x2F`~`0x3A`, `0x40`~`0x5B`, `0x60`~`0x7B` 근방 값은 문자 범위 검사일 가능성이 매우 높다.

## 단계별 절차
1. 의심되는 상수가 `0x00`~`0x7F` 범위인지 먼저 확인한다(범위를 벗어나면 아스키 문자가 아닐 가능성이 큼).
2. 이 표에서 해당 헥스값에 대응하는 문자를 찾는다.
3. 주변 명령어가 `cmp`/`sub`인지 확인해 "범위 검사"인지 "값 변환"인지 구분한다(예: `sub al, 30h`는 숫자 문자를 정수로 변환).
4. 짝을 이루는 두 비교(예: `0x30`과 `0x39`)가 있으면 그 사이 범위 전체를 검사하는 로직으로 해석한다.
5. IDA/Ghidra에서 상수 표시를 "Char"로 전환해 손 계산 결과와 일치하는지 교차검증한다.

## 명령어/단축키
```python
ord('A')        # 65 (0x41)
chr(0x41)       # 'A'
hex(ord('a'))   # '0x61'
[chr(c) for c in range(0x30, 0x3A)]   # 숫자 문자 전체 나열
```
```bash
man ascii        # Linux/WSL에서 전체 아스키 표 확인 (man-pages 패키지)
```
IDA/Ghidra: 헥스 상수 위에서 우클릭 → "Char" 표시 방식으로 전환하면 아스키 문자로 바로 렌더링해서 보여준다.

## 출력 해석
- `cmp al, 30h` 다음에 `jb`(아래면 분기)와 `cmp al, 39h` 다음에 `ja`(초과면 분기)가 짝지어 있다면, 그 사이(`0x30`~`0x39`)를 벗어나면 실패 처리하는 "숫자인지 검사" 로직이다.
- 대소문자 변환 관용구(`or al, 20h`)를 발견했다면, 그 직전에 이미 알파벳 범위 검사를 통과한 값이라고 가정하고 코드를 읽으면 문맥이 맞아떨어진다.

## 흔한 실수
- `0x41`을 무조건 산술 상수(65)로만 해석하고 문자 `'A'`일 가능성을 놓치는 것 — 특히 XOR 키, 비교값으로 자주 등장한다.
- 대문자/소문자 변환 공식(`±0x20`)을 반대로 기억하는 것 — 소문자가 대문자보다 헥스값이 크다(대문자+0x20=소문자).
- 개행 문자를 플랫폼에 관계없이 항상 `0x0A` 하나로만 생각하는 것 — Windows 텍스트 파일은 보통 `0x0D 0x0A`(CRLF) 조합을 쓴다.
- 아스키 표를 유니코드/UTF-8 멀티바이트 문자에도 그대로 적용하려는 것 — 아스키는 0~127 범위의 1바이트 문자 집합이고, 128 이상의 값은 아스키가 아니라 확장 문자셋이나 UTF-8 멀티바이트 시퀀스의 일부다(REV-0036 참고).

## 막혔을 때 다음 체크
- 문자열이 메모리에 저장되는 방식(ASCII/UTF-8/UTF-16, 널 종료 여부)이 더 궁금하면 → REV-0036 문자열이 메모리에 저장되는 방식 ASCII UTF-8 UTF-16
- 대소문자 변환에 쓰이는 AND/OR 마스크 연산 원리가 헷갈리면 → REV-0026 8비트 16비트 24비트 32비트 64비트 마스크
- 진법 변환 자체가 헷갈리면 → REV-0373 진법 변환(2진 8진 10진 16진) 빠른 참조표

## 미니 예제
간단한 `atoi`류 파싱 루프에서 이 표가 어떻게 쓰이는지 보자.
```asm
loop_start:
movzx   eax, byte ptr [rsi]   ; 현재 문자 하나 로드
cmp     al, 30h                ; '0'(0x30)보다 작은가?
jb      loop_end
cmp     al, 39h                ; '9'(0x39)보다 큰가?
ja      loop_end
sub     al, 30h                ; 문자 코드에서 0x30을 빼서 실제 숫자값 추출
; ... result = result*10 + al 형태로 누적 ...
inc     rsi
jmp     loop_start
loop_end:
```
`cmp al, 30h`와 `cmp al, 39h`가 짝을 이루는 순간 "숫자 문자 범위(`'0'`~`'9'`) 검사"라는 것을 이 표만 봐도 즉시 알 수 있고, 그 뒤의 `sub al, 30h`는 "문자를 실제 정수값으로 변환"하는 표준 관용구임을 바로 확인할 수 있다.

## 관련 글
- REV-0036 — 문자열이 메모리에 저장되는 방식 ASCII UTF-8 UTF-16
- REV-0026 — 8비트 16비트 24비트 32비트 64비트 마스크
- REV-0373 — 진법 변환(2진 8진 10진 16진) 빠른 참조표

## 출처/검증
- ASCII 코드표 전체(제어문자 포함, 0x00~0x7F): ANSI X3.4 / ISO/IEC 646 표준 및 POSIX `man ascii` 참조 문서 기준 (2026-09-09 검증).
- 대소문자 아스키값 0x20 차이 및 `tolower`/`toupper` 비트 연산 관용구: C 표준 라이브러리(`ctype.h`) 구현 관례 기준.
