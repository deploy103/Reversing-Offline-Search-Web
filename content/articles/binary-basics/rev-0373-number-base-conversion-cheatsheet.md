## 한 줄 요약
16진수 한 자리는 정확히 2진수 4자리(니블, nibble)에 대응하므로, 0~15 각각의 2진/8진/10진/16진 표현을 담은 니블 대조표 하나만 외워두면 아무리 긴 16진수라도 자리마다 4비트씩 끊어서 즉시 2진수로 바꿀 수 있다.

## 언제 검색해야 하나
- 디스어셈블리의 헥스 상수(`0x1A`, `0xFF` 등)를 2진수 비트 패턴으로 직접 변환해서 어떤 비트가 켜져 있는지 확인해야 할 때
- 플래그 값이나 권한 비트(`0755`, `PAGE_EXECUTE_READWRITE` 등)가 8진수/16진수로 표기되어 있어 각 자리의 의미를 손으로 풀어야 할 때
- 계산기 없이 그 자리에서 급하게 진법 변환을 해야 하는 CTF/시험 상황일 때
- 2진수 마스크 연산 결과를 검증하기 위해 헥스값을 비트 단위로 쪼개 봐야 할 때

## 핵심 개념
컴퓨터가 다루는 값은 결국 모두 2진수(비트)지만, 사람이 읽기엔 너무 길어서 8진수나 16진수로 축약해 표기한다. 이 축약이 편리한 이유는 8=2^3, 16=2^4이기 때문에 — 8진수 한 자리는 정확히 2진수 3자리, 16진수 한 자리는 정확히 2진수 4자리에 깔끔하게 대응되어, 자릿수 단위로 기계적으로 변환할 수 있기 때문이다(10진수는 2의 거듭제곱이 아니라서 이런 자릿수 대응이 안 되고, 그래서 손 변환이 훨씬 번거롭다).

### 니블(0~15) 대조표 — 진법 변환의 핵심 도구

| 10진수 | 2진수 (4비트) | 8진수 | 16진수 |
|---|---|---|---|
| 0 | 0000 | 0 | 0 |
| 1 | 0001 | 1 | 1 |
| 2 | 0010 | 2 | 2 |
| 3 | 0011 | 3 | 3 |
| 4 | 0100 | 4 | 4 |
| 5 | 0101 | 5 | 5 |
| 6 | 0110 | 6 | 6 |
| 7 | 0111 | 7 | 7 |
| 8 | 1000 | 10 | 8 |
| 9 | 1001 | 11 | 9 |
| 10 | 1010 | 12 | A |
| 11 | 1011 | 13 | B |
| 12 | 1100 | 14 | C |
| 13 | 1101 | 15 | D |
| 14 | 1110 | 16 | E |
| 15 | 1111 | 17 | F |

### 16진수 → 2진수: 자리마다 4비트씩 그대로 치환
16진수 여러 자리를 2진수로 바꿀 때는, **각 16진수 자리를 독립적으로 위 표에서 찾아 4비트씩 이어 붙이면 끝**이다. 자리 사이에 자리올림이나 복잡한 계산이 전혀 필요 없다.

```
0x2F  →  0010 1111   (2 → 0010, F → 1111)
0xA3  →  1010 0011   (A → 1010, 3 → 0011)
```

### 8진수 → 2진수: 자리마다 3비트씩 치환
같은 원리로 8진수는 자리마다 3비트씩 치환한다.

```
0755 (8진수)  →  111 101 101   (7→111, 5→101, 5→101)
```

Linux 파일 권한(`chmod 755` 등)이 8진수인 이유가 바로 이것 — 3비트(rwx) 단위와 8진수 한 자리가 정확히 대응하기 때문이다.

### 10진수는 왜 이 방식이 안 통하는가
10진수는 2의 거듭제곱이 아니므로(10 ≠ 2^n) 자릿수 단위로 기계적으로 쪼개 변환할 수 없다. 10진수를 2진수로 바꾸려면 2로 나눈 나머지를 반복해서 구하는 절차(또는 반대로 2진수를 10진수로 바꾸려면 각 자리에 2의 거듭제곱을 곱해 더하는 절차)가 필요하다 — 그래서 리버싱에서는 되도록 16진수/2진수 사이를 직접 오가고, 10진수는 최종 결과 확인 용도로만 쓰는 습관이 훨씬 빠르다.

```
10진수 173을 2진수로: 173 = 128+32+8+4+1 = 10101101
검산: 0xAD = 1010 1101 → 173  (16진수를 거치면 훨씬 빠르게 검증 가능)
```

### 자주 쓰는 2의 거듭제곱 값 (10진수 대조용)

| 2^n | 값 | 16진수 |
|---|---|---|
| 2^0 | 1 | 0x1 |
| 2^4 | 16 | 0x10 |
| 2^8 | 256 | 0x100 |
| 2^10 | 1024 | 0x400 |
| 2^16 | 65536 | 0x10000 |
| 2^20 | 1048576 | 0x100000 |
| 2^31 | 2147483648 | 0x80000000 |
| 2^32 | 4294967296 | 0x100000000 |

## 화면/코드에서 보이는 징후
- 디스어셈블리에 `and eax, 0Fh`, `test al, 80h` 같은 비트 마스크 상수가 헥스로 표기되어 있는 경우 — 2진수로 풀어보면 어느 비트를 검사하는지 바로 보인다.
- Linux 권한 관련 코드에서 `chmod(path, 0755)`처럼 8진수 리터럴(`0`으로 시작)이 쓰인 경우.
- 플래그 상수(`0x8000000`처럼 특정 비트 하나만 켜진 값)가 옵션/권한 플래그 조합으로 쓰이는 경우.

## 가장 먼저 할 것
변환하려는 값의 진법을 먼저 확정한다(접두사 `0x`=16진수, `0`으로 시작=8진수, 접두사 없음=보통 10진수). 16진수라면 위 니블 표를 자리마다 그대로 대입해 2진수로 풀어쓰는 것이 손 계산의 첫걸음이다.

## 단계별 절차
1. 원본 값의 진법을 표기 형식(`0x`, `0`, 접두사 없음)으로 확정한다.
2. 16진수라면 자리마다 니블 표를 대입해 4비트씩, 8진수라면 자리마다 3비트씩 이어붙여 2진수를 만든다.
3. 완성된 2진수에서 필요한 비트 위치(예: 특정 플래그 비트)를 센다.
4. 10진수로 최종 확인이 필요하면 2진수 각 자리에 2의 거듭제곱을 곱해 더하거나, 파이썬으로 교차검증한다.
5. 결과가 이상하면 자릿수를 8비트(바이트) 단위로 다시 맞춰 앞자리 생략 여부를 확인한다.

## 명령어/단축키
```python
bin(0x2F)        # '0b101111'
oct(0x2F)        # '0o57'
hex(0b101111)    # '0x2f'
int('101111', 2) # 47  (2진 문자열 -> 10진수)
int('2F', 16)    # 47  (16진 문자열 -> 10진수)
format(47, '08b')  # '00101111'  (8자리로 맞춘 2진 표기)
```
```bash
printf '%d\n' 0x2F     # bash에서 헥스를 10진수로
printf '%x\n' 47        # bash에서 10진수를 헥스로
```
IDA: 상수 위에서 우클릭 → "Binary"로 표시 형식 전환하면 즉시 2진수로 볼 수 있다.

## 출력 해석
- `0x2F` = `0010 1111`처럼 4비트씩 묶인 2진수를 얻었다면, 이제 어느 비트가 1인지(여기서는 bit0,1,2,3,5) 바로 셀 수 있다.
- 8진수 `0755`를 3비트씩 풀면 `rwxr-xr-x`(소유자 전체, 그룹/기타는 읽기+실행) 권한 조합과 정확히 대응된다.

## 흔한 실수
- 8진수 리터럴(`0755`)을 10진수 755로 착각하는 것 — C/Python 등 대부분의 언어에서 `0`으로 시작하는 숫자 리터럴은 8진수로 해석된다(Python3는 `0o755`로 명시해야 함, C는 `0755`가 그대로 8진수).
- 16진수를 2진수로 바꿀 때 전체 값을 통째로 나눗셈으로 계산하려는 것 — 자리마다 4비트씩 독립적으로 치환하는 것이 훨씬 빠르고 실수가 없다.
- 2진수 자릿수를 8의 배수(바이트 경계)로 맞추지 않고 앞자리 0을 생략해버려서, 실제 몇 비트짜리 값인지 헷갈리는 것 — 항상 4비트(니블) 또는 8비트(바이트) 단위로 자릿수를 맞춰 표기하는 습관이 필요하다.
- 진법 변환과 엔디안(바이트 순서)을 혼동하는 것 — 진법 변환은 "같은 값을 다른 기수로 표현하는 것"이고 엔디안은 "여러 바이트를 메모리에 배치하는 순서"로 완전히 다른 개념이다(REV-0023, REV-0367 참고).

## 막혔을 때 다음 체크
- 이 값이 signed인지 unsigned인지에 따라 해석이 달라지는 경우가 궁금하면 → REV-0025 Signed와 Unsigned 해석, REV-0370 정수 자료형 최대/최소값 치트시트
- 변환한 2진수로 마스크 연산을 검증하고 싶으면 → REV-0026 8비트 16비트 24비트 32비트 64비트 마스크
- 헥스값을 바이트 순서까지 고려해서 손으로 검증하는 절차가 필요하면 → REV-0367 엔디안이 헷갈릴 때 손으로 검증하는 방법

## 미니 예제
플래그 조합 상수 `0xA5`를 비트 단위로 분석해보자.
```
0xA5  →  자리별 분해: A(1010) 5(0101)  →  1010 0101

비트 위치:  7 6 5 4 3 2 1 0
값:         1 0 1 0 0 1 0 1
```
이 값에서 켜진 비트는 7, 5, 2, 0번이다. 만약 이것이 권한/옵션 플래그 조합(예: bit0=READ, bit2=EXEC, bit5=HIDDEN, bit7=SYSTEM)이라면, `0xA5`는 "READ + EXEC + HIDDEN + SYSTEM이 켜진 조합"이라고 즉시 해석할 수 있다. 이런 분석은 16진수를 통째로 다루려 하면 어렵지만, 니블 대조표로 2진수부터 풀어내면 순식간에 끝난다.
