## 한 줄 요약
`x % N`(상수 N)은 대부분 `DIV`/`IDIV`를 직접 쓰지 않고, N이 2의 거듭제곱이면 `AND` 마스크 한 번으로, 그 외의 상수면 REV-0454에서 다룬 매직 넘버 방식으로 몫을 먼저 구한 뒤 `나머지 = 원래값 - 몫 * N`을 `IMUL`+`SUB`로 계산하는 방식으로 컴파일된다 — 즉 나머지 연산은 거의 항상 "나눗셈 최적화의 부산물"로 함께 나타난다.

## 언제 검색해야 하나
- 소스에 `%`(나머지) 연산이 있어야 할 것 같은데 `DIV`/`IDIV`가 안 보이고, `IMUL` 다음에 `SUB`가 오면서 그 결과가 원래 값에서 무언가를 뺀 형태로 나올 때
- `AND` 명령 하나만으로 나머지가 계산되는 것처럼 보이는데 왜 그런지 이해가 안 될 때
- REV-0454(나눗셈 매직 넘버 패턴)를 이미 본 코드 바로 뒤에 `IMUL`+`SUB`가 추가로 붙어 있어서 "나눗셈 다음에 뭘 더 하는 거지?"라는 의문이 들 때
- 해시 테이블 인덱싱(`hash % table_size`), 순환 버퍼 인덱스(`idx % capacity`) 같은 코드를 분석할 때

## 핵심 개념

### 나머지의 정의와 나눗셈과의 관계
정수 나눗셈에서 `q = x / N`(몫), `r = x % N`(나머지)이라 하면, 정의상 항상 `x = q * N + r`이 성립한다. 이를 뒤집으면 `r = x - q * N`이다. 즉 **몫을 구할 수만 있다면, 나머지는 "몫에 N을 곱해서 원래 값에서 빼는" 한 번의 곱셈과 뺄셈으로 바로 얻을 수 있다.** 그래서 컴파일러는 나머지 연산을 위해 별도의 알고리즘을 쓰지 않고, REV-0454에서 다룬 몫 계산 최적화(매직 넘버 곱셈+시프트, 또는 2의 거듭제곱이면 시프트)를 그대로 재사용한 뒤, 마지막에 `IMUL`(곱)+`SUB`(뺄셈)만 추가한다.

### 2의 거듭제곱 나머지 — AND 마스크 (Unsigned)
나누는 값 N이 2의 거듭제곱(2, 4, 8, 16, ...)이고 **부호 없는(unsigned)** 값이라면, 나머지는 하위 비트를 그대로 떼어내는 것과 같다. 예를 들어 `x % 8`은 "x의 하위 3비트"와 정확히 같다.
```asm
; unsigned x % 8
mov     eax, x
and     eax, 7          ; N-1 = 7 = 0b111, 하위 3비트만 남김
```
`AND`(REV-0055)로 `N-1`을 마스크로 사용하는 이 패턴은 극도로 빠르고 흔해서, 해시 테이블/순환 버퍼 크기를 2의 거듭제곱으로 정하는 실전 관례(`table_size = 1 << k`)의 근본적인 이유이기도 하다.

### 2의 거듭제곱 나머지 — Signed는 단순 AND로 안 된다
**부호 있는(signed)** 정수에서는 음수일 때 단순 `AND`만으로는 C의 나머지 규칙(부호는 피제수 `x`의 부호를 따름, `truncation` 나눗셈과 일관됨)을 만족하지 못한다. 그래서 REV-0454의 signed 2의 거듭제곱 나눗셈과 마찬가지로 바이어스 보정이 들어간 뒤에야 마스킹이 적용된다.
```asm
; signed x % 8
mov     eax, x
cdq                    ; x의 부호를 edx 전체로 확장 (양수면 0, 음수면 -1)
and     edx, 7           ; 음수면 7, 양수면 0
add     eax, edx          ; 바이어스 보정
and     eax, 0FFFFFFF8h   ; 몫 계산용 마스크(하위 3비트 제거)
sub     ecx, eax           ; 원래 x - (보정된 몫*8) = 나머지
```
정확한 명령 순서는 컴파일러/버전에 따라 다르지만, 핵심은 "부호 보정 → 마스킹/시프트 → 원래 값에서 빼기"라는 흐름이 signed 나머지에서는 unsigned보다 한두 단계 더 많다는 것이다.

### 일반 상수 나머지 — 매직 넘버 몫 + IMUL/SUB
N이 2의 거듭제곱이 아니면(예: 10, 3, 7), REV-0454의 매직 넘버 나눗셈으로 몫을 먼저 구하고, 그 몫에 N을 다시 곱해서 원래 값에서 빼는 방식이다.
```asm
; signed x % 10
mov     eax, x
mov     edx, 66666667h
imul    edx
sar     edx, 2
mov     eax, edx
shr     eax, 1Fh
add     eax, edx        ; eax = x / 10  (REV-0454와 완전히 동일한 몫 계산)
imul    eax, eax, 0Ah    ; eax = (x/10) * 10
sub     ecx, eax          ; ecx = 원래 x - (x/10)*10 = x % 10
```
여기서 `IMUL eax, eax, 0Ah`는 "3-오퍼랜드 IMUL" 형태로, `eax = eax * 10`을 한 번에 계산한다(REV-0051 참고). 이 곱셈은 REV-0454의 매직 넘버 곱셈과는 **완전히 다른, 평범한 상수 곱셈**이라는 점에 주의한다 — 몫 계산용 매직 넘버 곱셈과 나머지 계산용 `N` 곱셈을 혼동하지 않아야 한다.

### 레지스터/메모리 효과와 플래그
- `AND`(마스킹)는 결과에 따라 `SF`, `ZF`, `PF`를 세팅하고 `CF`, `OF`를 0으로 클리어한다(REV-0055 참고). 하지만 이 패턴에서는 그 플래그를 후속 로직이 사용하지 않는 경우가 대부분이다.
- `IMUL`/`SUB`도 각각 자신의 플래그 규칙을 따르지만(REV-0051, REV-0048), 나머지 계산 목적에서는 결과 값 자체가 중요하지 나머지 계산 과정에서 세팅된 플래그는 보통 무시된다.
- signed/unsigned 구분이 나머지 연산에서는 나눗셈보다 더 중요하다 — **부호 있는 나머지의 결과 부호는 항상 피제수(x)의 부호를 따른다**(C99 이후 표준 규칙). 예: `-7 % 3 == -1`(3이 아니라), `7 % -3 == 1`. 이 규칙 때문에 signed 나머지는 항상 부호 보정 코드가 따라붙는다.
- 스택/RIP에는 영향이 없다.

### IDA/Ghidra 디컴파일에서 보이는 형태
Hex-Rays와 Ghidra는 이 "몫 계산 + IMUL + SUB" 또는 "AND 마스크" 패턴을 대부분 정확히 `x % N`으로 재인식해서 보여준다. 특히 나눗셈(`x / N`)과 나머지(`x % N`)를 **같은 x, 같은 N에 대해 동시에** 쓰는 코드(`q = x / N; r = x % N;`)는, 컴파일러가 몫 계산 코드를 단 한 번만 만들고 나머지는 그 몫을 재사용해서 계산하도록 합쳐버리는 경우가 많다 — 이때는 디스어셈블리에 `DIV`/`IDIV`나 매직 넘버 블록이 단 한 번만 나타나고, 그 결과가 몫으로도 쓰이고 `IMUL`+`SUB`를 거쳐 나머지로도 쓰인다.

## 화면/코드에서 보이는 징후
```asm
; unsigned 2의 거듭제곱 나머지
mov     eax, x
and     eax, 0Fh        ; x % 16
```
```asm
; signed 일반 상수 나머지 (몫 재사용)
mov     eax, ecx
mov     edx, 66666667h
imul    edx
sar     edx, 2
mov     eax, edx
shr     eax, 1Fh
add     eax, edx         ; eax = ecx / 10 (몫, q)
imul    eax, eax, 0Ah     ; eax = q * 10
sub     ecx, eax           ; ecx = ecx - q*10 = ecx % 10
```
```asm
; 나눗셈과 나머지를 동시에 쓰는 코드
mov     [q], eax          ; 몫 저장
imul    eax, eax, 0Ah
sub     ecx, eax
mov     [r], ecx           ; 나머지 저장
```

## 가장 먼저 할 것
1. `AND` 하나로 끝나는지, 아니면 `IMUL`+`SUB` 조합이 있는지 확인한다 — 전자는 unsigned 2의 거듭제곱 나머지, 후자는 일반 상수 나머지다.
2. `IMUL`+`SUB` 패턴이면, 그 직전에 REV-0454 스타일의 몫 계산 블록(매직 넘버 `IMUL`/`MUL` + `SAR`/`SHR`)이 있는지 확인한다 — 있으면 그 몫을 재사용하는 나머지 계산이다.
3. `SUB`의 두 오퍼랜드 중 어느 쪽이 "원래 값"이고 어느 쪽이 "몫*N"인지 순서를 정확히 확인한다 — 순서가 바뀌면 부호가 반대로 해석된다.

## 단계별 절차

**1) 몫 계산부와 나머지 계산부 분리**

`IMUL eax, eax, N`(N은 원래 나누려던 상수) 직전까지가 몫 계산(REV-0454 패턴), 그 이후 `SUB`까지가 나머지 계산이다. 두 부분을 분리해서 각각 REV-0454의 절차대로 분석한다.

**2) N값 확인**

`IMUL eax, eax, N`의 세 번째 오퍼랜드(즉시값)가 곧 나누는 상수 N이다 — 이건 매직 넘버와 달리 사람이 읽을 수 있는 평범한 10진수/16진수라서 바로 알아볼 수 있다(예: `0Ah` = 10).

**3) 2의 거듭제곱인지 확인**

`IMUL`/`SUB` 없이 `AND`만 있다면, 마스크 값에 1을 더했을 때 2의 거듭제곱이 되는지 확인한다(`AND eax, 0Fh` → `0xF+1=16`, 즉 `% 16`).

**4) signed 여부와 결과 부호 확인**

부호 보정 코드(`CDQ`, `SAR ..., 1Fh` 등)가 있으면 signed이고, 음수 입력에 대해 나머지 부호가 피제수를 따른다는 규칙을 적용해서 해석한다.

## 명령어/단축키
- IDA: `F5`(디컴파일, `%` 연산자로 재인식되는지 확인), `IMUL eax, eax, N`의 N을 더블클릭해서 상수 확인
- Ghidra: Decompile 창 자동 재인식 확인, Listing에서 `imul`+`sub` 연속 패턴을 눈으로 스캔
- Python(오프라인 검증): 여러 x값에 대해 `x % N`을 직접 계산해서 디스어셈블리에서 역산한 값과 일치하는지 대조

## 출력 해석
- IDA가 `x % 10`으로 정확히 복원했다면 신뢰하고 넘어가면 된다.
- `q = x / 10; r = x % 10;`처럼 몫과 나머지가 동시에 변수로 나오면, 어셈블리 레벨에서는 몫 계산이 단 한 번만 있고 나머지는 그 몫을 재사용한 것임을 기억해둔다 — 즉 두 변수가 코드상 별개로 보여도 실제로는 강하게 연결된 계산이다.
- `AND` 결과가 항상 `[0, N-1]` 범위 안에만 있다면 unsigned 2의 거듭제곱 나머지임을 재확인할 수 있다.

## 흔한 실수
- `IMUL`+`SUB` 조합을 REV-0454(나눗셈)와 완전히 별개의 새로운 패턴으로 오인해서, 몫 계산 부분을 다시 처음부터 분석하려 드는 것 — 사실 몫 계산 로직은 REV-0454와 100% 동일하며, 이 글에서 다루는 건 그 뒤에 붙는 `IMUL`+`SUB`뿐이다.
- `AND` 마스크 패턴을 보고 무조건 "비트 플래그 검사"라고 오판하는 것 — 마스크 값이 `2^k - 1`(모든 하위 k비트가 1) 형태이고, 그 결과가 이후 배열 인덱스나 나머지처럼 쓰인다면 나머지 연산일 가능성을 함께 고려해야 한다.
- signed 나머지의 부호 규칙을 잘못 기억하는 것 — `%`의 결과 부호는 **제수(N)가 아니라 피제수(x)의 부호를 따른다**(C99/C++11 이후 표준). `-7 % 3`은 `-1`이지 `2`가 아니다.
- 나머지 계산에 쓰인 `IMUL eax, eax, N`의 `N`을 매직 넘버와 혼동하는 것 — 몫 계산에 쓰인 매직 넘버(예: `0x66666667`)와 나머지 계산에 쓰인 진짜 나누는 값(예: `10`)은 전혀 다른 상수이며 혼동하면 원래 코드를 잘못 재구성하게 된다.

## 막혔을 때 다음 체크
- 몫 계산 부분이 이해가 안 되면 → REV-0454(나눗셈이 곱셈과 시프트로 최적화되는 패턴)를 먼저 읽는다.
- `AND`가 왜 플래그를 세팅하는지, 어떤 플래그인지 헷갈리면 → REV-0055(AND: 마스크와 비트 제거)를 다시 읽는다.
- signed 나머지의 부호 보정 로직이 여전히 헷갈리면 → REV-0053(IDIV), REV-0063(SAR)에서 부호 있는 나눗셈/시프트의 절삭 규칙을 함께 복습한다.
- 실제 N값을 정확히 확정해야 하는데 자신이 없다면 → `IMUL eax, eax, N`의 즉시값을 그대로 신뢰해도 된다(이 값은 매직 넘버가 아니라 평범한 상수이므로 역산이 필요 없다).

## 미니 예제

**예제 1 — 해시 테이블 인덱싱(2의 거듭제곱)**
```c
unsigned int idx = hash % 256;
```
```asm
mov     eax, [hash]
and     eax, 0FFh
```

**예제 2 — 일반 상수 나머지**
```c
int last_digit = n % 10;
```
```asm
mov     eax, ecx
mov     edx, 66666667h
imul    edx
sar     edx, 2
mov     eax, edx
shr     eax, 1Fh
add     eax, edx          ; eax = n / 10
imul    eax, eax, 0Ah
sub     ecx, eax            ; ecx = n % 10
```

**예제 3 — 몫과 나머지를 동시에 쓰는 코드**
```c
int minutes = total_sec / 60;
int seconds = total_sec % 60;
```
```asm
; total_sec / 60 계산 (매직 넘버 생략)
...
mov     [minutes], eax      ; 몫
imul    eax, eax, 3Ch        ; eax = minutes * 60
sub     ecx, eax              ; ecx = total_sec - minutes*60
mov     [seconds], ecx
```

**예제 4 — signed 2의 거듭제곱 나머지 (부호 보정 포함)**
```c
int r = x % 4;   // x가 음수일 수 있음
```
```asm
mov     eax, x
cdq
and     edx, 3
add     eax, edx
and     eax, 0FFFFFFFCh
mov     ecx, x
sub     ecx, eax             ; ecx = x % 4 (부호는 x를 따름)
```

## 관련 글
- REV-0454 — 나눗셈이 곱셈과 시프트로 최적화되는 패턴(Magic Number)
- REV-0055 — AND: 마스크와 비트 제거
- REV-0052 — DIV: Unsigned 나눗셈
- REV-0053 — IDIV: Signed 나눗셈
- REV-0051 — IMUL: Signed 곱셈과 컴파일러 패턴
- REV-0048 — SUB: 뺄셈과 플래그

## 출처/검증
- `x = q*N + r` 나눗셈-나머지 관계 및 컴파일러가 몫 계산을 재사용해 나머지를 유도하는 코드 생성 전략: Henry S. Warren Jr., "Hacker's Delight" 2nd Edition, Chapter 10 기준.
- signed 나머지 결과 부호가 피제수를 따른다는 규칙: ISO C99/C++11 이후 표준의 정수 나눗셈/나머지 연산자 규정 기준.
- `AND`, `IMUL`, `SUB`의 플래그 영향: Intel 64 and IA-32 Architectures Software Developer's Manual, Volume 2 각 명령어 항목 기준.
- 2의 거듭제곱 크기 해시 테이블/순환 버퍼에서 `AND` 마스크로 모듈로를 대체하는 관례는 일반적인 자료구조 구현 및 컴파일러 최적화 관행 기준.
