## 한 줄 요약
리버싱 문제를 풀 때 REV-0018의 9단계 루틴 각각에 걸린 시간을 매번 기록해두면, 여러 문제를 누적한 뒤 "항상 특정 단계에서 유난히 오래 걸린다"는 패턴이 드러나므로 그 단계의 세부 기술을 집중적으로 연습해 실력을 효율적으로 늘릴 수 있다.

## 언제 검색해야 하나
- 여러 문제를 풀어봤지만 실력이 느는 느낌이 안 들고 매번 비슷하게 오래 걸릴 때
- REV-0015(5분 체크리스트)로 순간순간의 막힘은 해결하는데, 장기적으로 어떤 기술이 부족한지 파악이 안 될 때
- 대회 중 시간 배분을 어떻게 해야 할지 감이 안 잡힐 때
- "나는 정적 분석은 빠른데 동적 분석만 가면 느려진다"처럼 막연한 느낌은 있지만 숫자로 확인한 적이 없을 때

## 핵심 개념

### 순간적 체크리스트와 장기적 시간 기록의 차이
REV-0015(5분 체크리스트)는 "지금 이 순간 막혔을 때" 즉각 점검하는 도구다. 반면 이 문서가 다루는 시간 기록은 "문제를 풀 때마다 각 단계 소요 시간을 남겨서, 여러 문제에 걸쳐 반복되는 병목을 찾는" 장기적 회고 도구다. 둘은 목적이 다르므로 함께 써야 한다 — 순간의 막힘은 5분 체크리스트로, 반복되는 패턴은 시간 기록으로 잡는다.

### 왜 병목을 알아야 하는가
리버싱 실력은 "9단계 전체를 골고루 잘하는 것"이 아니라 "어느 한 단계에서 남들보다 유난히 오래 걸리는 것을 없애는 것"으로 빠르게 향상된다. 예를 들어 정찰과 정적 분석은 항상 5분 안에 끝내는데, 매번 "검증 로직 추적" 단계에서 20분 이상 걸린다면, 그 사람에게 필요한 것은 더 많은 문제를 푸는 것이 아니라 xref 사용법과 자주 나오는 검증 패턴(REV-0006, REV-0163)을 집중적으로 복습하는 것이다.

### 무엇을 기록해야 하는가
REV-0018의 9단계(정찰, 형식/보호기법 확인, 정적 분석 지도 그리기, 검증 로직 추적, 정적/동적 재판단, 상수 기록, 로직 복원, 솔버 작성, 제출/정리)마다 시작 시각과 종료 시각을 남긴다. 완벽하게 초 단위로 잴 필요는 없고, 분 단위로만 기록해도 충분히 패턴이 드러난다.

### 기록 방법
REV-0014(리버싱 노트 작성법)에서 다루는 `notes.md`에 표 하나를 추가하는 정도로 충분하다. 별도 도구 없이도 시작할 수 있고, 문제 수가 쌓이면 각 단계의 평균/최댓값을 계산해보는 것만으로 병목이 드러난다.

## 화면/코드에서 보이는 징후
이 문서는 도구 화면의 징후가 아니라 "누적된 기록에서 보이는 패턴"이 핵심이다.
- `notes.md`를 여러 문제에 걸쳐 살펴봤을 때 특정 단계 소요 시간이 항상 다른 단계의 2~3배 이상
- 같은 유형의 문제(예: XOR 기반 검증)인데도 매번 로직 복원 단계에서 시간이 들쭉날쭉
- 정적 분석 단계는 항상 빠르게 끝나는데 동적 분석 전환 판단(REV-0005)에서 매번 머뭇거림

## 가장 먼저 할 것
지금 풀고 있거나 최근에 푼 문제의 `notes.md`를 열어 9단계 중 몇 단계까지 시간을 남겼는지 확인한다. 하나도 기록한 게 없다면 지금부터라도 각 단계 시작 시각만 한 줄씩 적기 시작한다.

## 단계별 절차
1. `notes.md` 맨 위에 표 하나를 만들고 REV-0018의 9단계 이름을 행으로 나열
2. 문제를 풀며 각 단계에 진입할 때 현재 시각(또는 스톱워치 경과 시간)을 기록
3. 문제를 다 풀면(또는 포기하면) 각 단계의 소요 시간을 계산해 표를 채움
4. 이 표를 최소 5~10문제 누적
5. 누적된 표에서 각 단계별 평균/최댓값을 눈으로 비교(엄밀한 통계 도구 없이 손으로 봐도 충분히 드러남)
6. 가장 시간이 오래 걸리는 단계 1~2개를 특정
7. 그 단계에 해당하는 개별 문서(예: 검증 로직 추적이 느리면 REV-0006, REV-0008)를 다시 읽고 그 기술만 별도로 연습
8. 몇 문제 뒤 같은 표를 다시 확인해 그 단계의 시간이 실제로 줄었는지 검증

## 명령어/단축키
```markdown
### 시간 기록 (문제: xor_lock)
| 단계 | 시작 | 종료 | 소요 |
|---|---|---|---|
| 1. 정찰 | 00:00 | 00:02 | 2분 |
| 2. 형식/보호기법 | 00:02 | 00:04 | 2분 |
| 3. 정적 분석 | 00:04 | 00:10 | 6분 |
| 4. 검증 로직 추적 | 00:10 | 00:28 | 18분 |
| 5. 정적/동적 판단 | 00:28 | 00:29 | 1분 |
| 6. 상수 기록 | 병행 | 병행 | - |
| 7. 로직 복원 | 00:29 | 00:35 | 6분 |
| 8. 솔버 작성/검증 | 00:35 | 00:40 | 5분 |
| 9. 제출/정리 | 00:40 | 00:41 | 1분 |
```

## 출력 해석
- 표를 여러 개 누적했을 때 4단계(검증 로직 추적)가 매번 다른 단계의 2배 이상이라면, 이는 "이 사람이 특히 xref/문자열 역추적에 약하다"는 구체적 신호다 — 막연히 "리버싱이 어렵다"가 아니라 훈련할 지점이 명확해진다.
- 특정 단계가 아니라 전체적으로 고르게 오래 걸린다면 병목이 아니라 전반적인 숙련도 문제이므로, REV-0018 루틴 전체를 다시 복습하는 게 더 적절하다.
- 매번 9단계(제출/정리)를 생략하고 있다면, 이 자체가 기록 습관의 병목이므로 우선 그것부터 고친다.

## 흔한 실수
- 시간을 초 단위로 정밀하게 재려다 오히려 그 자체가 부담이 되어 기록을 포기하는 것 — 분 단위 대략치로도 충분하다.
- 딱 한 문제만 기록하고 바로 결론을 내리는 것 — 병목 패턴은 최소 5~10문제는 누적해야 신뢰할 수 있다.
- 병목을 찾은 뒤에도 그 단계를 집중 연습하지 않고 그냥 표만 계속 쌓는 것 — 기록의 목적은 훈련 지점을 찾는 것이지 기록 자체가 아니다.
- 대회 중에 이 기록을 하느라 실제 풀이 시간을 낭비하는 것 — 대회 중에는 시작/종료 시각만 한 줄로 남기고, 분석은 대회가 끝난 뒤에 한다.

## 막혔을 때 다음 체크
- 애초에 9단계 루틴 자체가 헷갈린다 → REV-0018 대회장에서 리버싱 문제 하나를 끝까지 추적하는 실전 루틴
- 노트를 어떻게 정리해야 할지 모르겠다 → REV-0014 리버싱 노트 작성법: 함수 이름 바꾸기와 가설 기록
- 검증 로직 추적 단계가 병목으로 나왔다 → REV-0006 Flag 검증 함수 찾는 가장 흔한 경로, REV-0008 성공/실패 문자열에서 역참조 따라가는 방법
- 로직 복원 단계가 병목으로 나왔다 → REV-0017 솔버를 짜기 전에 직접 로직을 복원하는 순서
- 순간적으로 막혔을 때 대응법이 궁금하다 → REV-0015 막혔을 때 5분 체크리스트

## 미니 예제
5문제를 누적한 뒤의 요약표 예시:
```text
문제1: 4단계 18분 / 나머지 합계 17분
문제2: 4단계 22분 / 나머지 합계 15분
문제3: 4단계 15분 / 나머지 합계 13분
문제4: 4단계 20분 / 나머지 합계 16분
문제5: 4단계 25분 / 나머지 합계 14분
```
5문제 모두에서 "검증 로직 추적"(4단계) 혼자서 전체 시간의 절반 이상을 차지한다. 이 패턴이 확인되면 다음 학습 우선순위는 새로운 알고리즘 패턴을 더 배우는 것이 아니라, xref(X 키)와 문자열 역추적을 더 빠르게 하는 훈련이라는 결론을 얻을 수 있다.

## 출처/검증
- 단계별 시간 기록을 통한 병목 식별 방법론은 일반적인 소프트웨어 엔지니어링의 타임박싱/회고(retrospective) 기법을 CTF 리버싱 워크플로우(REV-0018)에 적용한 것으로, 특정 논문이 아니라 본 위키의 실전 루틴 문서를 기준으로 정리함 (2026-09-09 검증).
