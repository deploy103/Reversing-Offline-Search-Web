## 한 줄 요약
브루트포스가 유효하려면 **키 공간 크기 × 1회 검증 비용**을 계산해서 현실적인 시간(보통 수 분~수 시간) 안에 끝나야 하며, 로직을 완전히 이해하지 못했어도 키 공간이 충분히 작으면(예: 4~6자리 숫자, 알파벳 몇 글자) 굳이 알고리즘을 다 역산하지 않고 브루트포스로 지름길을 낼 수 있다.

## 언제 검색해야 하나
- 검증 로직은 찾았는데 완전히 역산하기가 복잡해서 "그냥 다 넣어봐도 되지 않을까" 싶을 때
- 입력 길이나 문자 종류에 제한이 있어 보여서 경우의 수가 많지 않아 보일 때
- 브루트포스를 시도했는데 너무 오래 걸려서 이게 애초에 틀린 접근이었는지 판단이 필요할 때

## 핵심 개념
브루트포스(완전탐색, 무차별 대입)는 "가능한 모든 입력을 다 시도해서 정답을 찾는" 방법이다. 리버싱에서 로직을 완벽히 이해하고 수학적으로 역산하는 게 이상적이지만, 시간이 제한된 CTF에서는 **키 공간이 충분히 작다면 브루트포스가 압도적으로 빠른 지름길**이 될 수 있다. 문제는 "충분히 작다"를 판단하는 감각이다.

**키 공간(key space) 계산법**: 입력이 가질 수 있는 경우의 수를 계산한다.
- 4자리 숫자 PIN: `10^4 = 10,000`가지.
- 6자리 숫자: `10^6 = 1,000,000`가지.
- 소문자 알파벳 8글자: `26^8 ≈ 2 × 10^11`가지 — 이건 이미 매우 크다.
- 바이트 하나(0~255): `256`가지 — 사실상 즉시 끝난다.
- 32비트 정수 전체: `2^32 ≈ 43억`가지 — 검증 1회가 매우 빠르면(마이크로초 단위) 가능하지만, 느리면 비현실적이다.

**검증 비용**: 한 번의 시도가 얼마나 걸리는지도 중요하다.
- 바이너리를 프로세스로 매번 새로 실행해서 확인하면(`subprocess.run`) 1회당 수십~수백 밀리초가 걸릴 수 있다 — 이러면 10만 번만 돌려도 몇 시간이 걸릴 수 있다.
- 검증 로직을 Python으로 직접 재구현해서 순수 계산만 하면 1회당 마이크로초 단위로 끝나서 수억 번도 몇 분 안에 가능하다.

**대략적인 기준(참고용, 상황에 따라 다름)**:
- 프로세스를 매번 실행하는 방식: 최대 수만~수십만 회 정도가 현실적(몇 분~몇십 분).
- Python으로 로직을 재구현해 순수 계산하는 방식: 수억 회도 가능(몇 분 이내).
- C로 재구현하거나 병렬화: 훨씬 더 큰 공간도 가능.

즉, "브루트포스가 되냐 안 되냐"는 로직의 복잡도가 아니라 **키 공간 크기와 검증 속도의 곱**으로 판단해야 한다. 키 공간이 작으면 로직을 대충만 이해해도(어떤 함수가 맞는지 아닌지만 판별할 수 있으면) 브루트포스로 풀 수 있다.

## 화면/코드에서 보이는 징후
- `scanf("%4d", &pin)`처럼 입력 길이/자리수 제한이 명시적으로 보인다.
- 반복문이 `for (i = 0; i < 6; i++)`처럼 고정된 짧은 길이로 도는 게 보인다 — 각 자리를 독립적으로 브루트포스할 수 있는 구조인지 살펴볼 여지가 있다.
- 검증 함수가 단순 산술(덧셈, XOR, 곱셈) 위주라 Python으로 그대로 옮겨적기 쉬워 보인다.

## 가장 먼저 할 것
검증 함수를 찾은 뒤(F5 디컴파일 코드 확보), 입력의 **길이 제한**과 **문자 종류 제한**을 먼저 확인한다. `scanf` 포맷 문자열(`%4d`, `%20s` 등), 버퍼 크기 선언, 반복문의 경계 조건을 본다.

## 단계별 절차

**1) 입력 형식과 길이 제한 확인**
- `scanf("%4d", ...)` → 정확히 4자리 숫자.
- `char buf[9]; scanf("%8s", buf);` → 최대 8글자 문자열.
- 반복문이 `i < 8`이면 검증 대상이 8바이트/8글자라는 뜻.

**2) 문자 종류(alphabet) 확인**
디컴파일 코드에서 문자 유효성 검사(`isalpha`, `isdigit`, 범위 비교 `'0' <= c && c <= '9'`)가 있는지 확인한다. 있으면 문자 종류가 제한되어 키 공간이 줄어든다(숫자만이면 10가지, 소문자만이면 26가지).

**3) 키 공간 계산**
```
키 공간 = (문자 종류 수) ^ (길이)
```
예: 8자리, 숫자만 → `10^8 = 1억`. 이 정도는 Python 순수 계산이면 수 분 내 가능, 프로세스 재실행이면 부담스럽다.

**4) 자리별로 독립적인지 확인 (매우 중요한 최적화)**
전체를 한 번에 브루트포스하지 않고, **한 글자씩 독립적으로 브루트포스**할 수 있는 구조인지가 결정적이다. 예를 들어 `input[i] ^ key[i] == target[i]`처럼 각 자리가 서로 영향을 안 주고 독립적으로 비교된다면, 8자리 전체를 `256^8`으로 탐색할 필요 없이 **자리마다 256가지만 시도**하면 되므로 `256 × 8 = 2048`번으로 끝난다. 반대로 체크섬처럼 모든 자리가 하나의 값에 영향을 주는(`sum(input) == target`) 구조라면 자리별 독립 탐색이 안 통하고 전체 조합을 봐야 할 수 있다.

**5) 검증 로직을 Python으로 재구현**
브루트포스가 결정됐으면, 매번 실제 바이너리를 실행하지 말고 검증 로직을 그대로 Python 함수로 옮겨서 순수 계산으로 돌린다.
```python
def check(candidate: bytes) -> bool:
    key = bytes([0x1,0x3,0x3,0x7,0xC,0xA,0xF,0xE])
    target = bytes.fromhex("...")  # 추출한 값
    return bytes(c ^ k for c, k in zip(candidate, key)) == target

for i in range(256):
    for pos in range(8):
        ...
```
이 재구현은 [rev-0017-recover-logic-before-solver.md](./rev-0017-recover-logic-before-solver.md)에서 다루는 "로직 복원" 작업과 같은 것이다 — 브루트포스도 결국 로직을 어느 정도 이해해야 가능하다는 점을 기억해야 한다(로직을 전혀 모르면 "검증 성공"을 판별할 방법 자체가 없다).

**6) 실행 시간 가늠**
전체 조합 수를 계산기로 먼저 확인하고, 대략적인 시간을 어림한다. 1억 회 이상이고 자리별 독립 최적화도 안 된다면, 브루트포스보다 로직을 더 분석해서 대수적으로 역산하는 게 낫다.

## 명령어/단축키
```python
# 자리별 독립 브루트포스 예시 (프로세스 재실행 없이 순수 계산)
import itertools, time

start = time.time()
count = 0
for guess in itertools.product(range(256), repeat=4):
    count += 1
    if count % 10_000_000 == 0:
        print(count, time.time() - start)
```
- 실제 바이너리를 매번 실행해야 하는 경우(pwntools 사용): `from pwn import process` 후 `p = process(['./chall']); p.sendline(guess); p.recvline()` — 이 방식은 훨씬 느리므로 자리별 독립 여부를 반드시 먼저 확인한다.

## 출력 해석
- Python으로 1억 번의 단순 XOR 비교를 돌리면 보통 수십 초~수 분 안에 끝난다(하드웨어에 따라 다름). 10억 번을 넘어가면 체감상 오래 걸리기 시작한다.
- 프로세스를 매번 새로 실행하는 방식은 1만 번만 해도 수 분씩 걸릴 수 있다 — 이 방식은 정말 키 공간이 작을 때(수백~수천 가지)만 쓴다.

## 흔한 실수
- 로직을 전혀 이해하지 않은 채 "그냥 무작정 다 돌리면 되겠지"라고 시작해서, 검증 결과를 어떻게 판별할지도 모르는 상태로 시간을 낭비하는 것.
- 자리별 독립 여부를 확인 안 하고 전체 조합(`256^8`처럼 천문학적인 수)을 그대로 브루트포스하려는 것 — 이건 현실적으로 끝나지 않는다.
- 매번 바이너리 프로세스를 새로 실행하는 방식으로 수백만 번을 시도하려는 것 — 반드시 로직을 Python으로 재구현해서 순수 계산으로 돌려야 한다.
- 브루트포스 결과가 여러 개 나왔는데(우연히 조건을 만족하는 잘못된 답) 검증 없이 그대로 제출하는 것 — 로직 이해가 부족하면 거짓 양성(false positive)이 나올 수 있으니, 나온 후보는 실제 바이너리에 다시 넣어 확인한다.

## 미니 예제
검증 로직이 `input[i] ^ 0x13 == target[i]` 형태로 4바이트를 독립적으로 비교한다고 하자. 전체 조합은 `256^4 ≈ 42억`이지만, 자리별 독립이므로 실제로는 자리마다 `256`가지, 총 `256 × 4 = 1024`번만 시도하면 된다.
```python
target = bytes.fromhex("6a7b0c1d")
flag = bytes((t ^ 0x13) for t in target)
print(flag)
```
사실 이 경우는 브루트포스조차 필요 없이 XOR의 역연산(XOR는 자기 자신이 역함수)으로 즉시 계산 가능하다 — 브루트포스는 로직이 이 정도로 간단히 역산되지 않을 때(예: 해시 함수, 비선형 연산)를 위한 차선책이라는 점도 기억해두면 좋다.
