## 한 줄 요약
x64dbg는 무료·오픈소스(GPLv3) Windows용 디버거로, 공식 사이트 x64dbg.com에서 안내하는 snapshots.x64dbg.com(SourceForge 스냅샷 미러)을 통해 **설치 프로그램 없이 압축 파일 하나를 통째로 풀어놓는 방식**으로 설치되며, 완전히 오프라인인 대회 PC에서는 특히 **Microsoft 심볼 서버 접근이 안 된다는 제약**을 미리 인지하고 준비해야 한다.

## 언제 검색해야 하나
- x64dbg를 오프라인 대회용 PC에 미리 준비해두고 싶을 때
- x64dbg 다운로드 페이지가 낯설어서 어디서 받아야 할지 헷갈릴 때
- x32dbg와 x64dbg의 차이, x96dbg가 뭔지 궁금할 때
- 오프라인 상태에서 x64dbg가 뭔가 덜 동작하는 느낌이 들 때(심볼 관련)

## 핵심 개념
x64dbg는 특정 회사가 아니라 오픈소스 커뮤니티(x64dbg 프로젝트, GitHub `x64dbg/x64dbg`)가 관리하는 무료 도구다. 정식 "버전 릴리스"보다는 **매일/매 커밋마다 자동으로 만들어지는 스냅샷(snapshot) 빌드**를 받아 쓰는 것이 표준적인 사용 방식이다.

### 배포 구조
- 공식 홈페이지 x64dbg.com의 Download 버튼은 **snapshots.x64dbg.com**으로 연결되며, 실제 파일은 SourceForge에 올라간다.
- 소스 코드가 필요하면 별도로 source.x64dbg.com(GitHub 저장소)에서 받는다.
- 배포되는 파일은 zip 압축 파일이며, 그 안에 32비트용(`x32\` 폴더, `x32dbg.exe`)과 64비트용(`x64\` 폴더, `x64dbg.exe`)이 함께 들어 있다. 아키텍처를 잘 모르겠으면 `x96dbg.exe`를 실행해서 대상 파일에 맞게 자동으로 선택하게 할 수 있다.
- 설치 프로그램(.msi/.exe installer)이 없다. 원하는 폴더에 압축을 풀면 그대로 실행 가능한 **포터블(portable) 프로그램**이다.

### 오프라인일 때 특히 조심할 점: 심볼 서버
x64dbg는 분석 편의를 위해 Windows 시스템 DLL 등의 디버그 심볼(PDB)을 **Microsoft의 공개 심볼 서버**에서 인터넷으로 내려받아 캐시하는 기능이 있다. 완전히 오프라인인 대회 PC에서는 이 기능이 동작하지 않으므로, `kernel32.dll` 같은 시스템 라이브러리 함수들에 대해 심볼 이름이 붙지 않고 주소만 보일 수 있다. 이는 x64dbg 자체의 문제가 아니라 네트워크가 없어서 생기는 당연한 제약이며, CTF 문제 자체를 분석하는 데는 대개 큰 지장이 없다(문제 바이너리 자체의 심볼은 인터넷과 무관하게 바이너리 안에 있으면 그대로 보인다). 다만 "왜 시스템 DLL 함수 이름이 하나도 안 보이지?"라는 혼란을 예방하기 위해 미리 알아두는 것이 좋다.

## 화면/코드에서 보이는 징후
- 다운로드한 zip을 풀면 최상위에 `x32\`, `x64\`, `x96dbg.exe`, `readme.txt` 등이 보인다.
- `x32dbg.exe`는 32비트(x86) PE 파일 전용, `x64dbg.exe`는 64비트(x64) PE 파일 전용이다. 잘못된 아키텍처의 실행 파일을 열려고 하면 열리지 않거나 오류가 뜬다.
- 오프라인 상태에서 실행하면, 옵션에 따라 시작 시 심볼 다운로드를 시도하다가 타임아웃되는 지연이 발생할 수 있다(대개 몇 초 정도이며 치명적이지 않다).

## 가장 먼저 할 것
아직 인터넷이 되는 PC에서 x64dbg.com → Download 링크를 눌러 snapshots.x64dbg.com(또는 SourceForge)에서 최신 스냅샷 zip을 받는다. 별도의 회원가입이나 라이선스 절차는 없다.

## 단계별 절차

**1) 온라인 상태에서 zip 다운로드**

x64dbg.com에서 Download 버튼 클릭 → snapshots.x64dbg.com으로 이동 → 최신 스냅샷 zip을 받는다(SourceForge 프로젝트 페이지에서 직접 최신 `snapshot_YYYY-MM-DD_HH-MM.zip`을 골라도 된다). 파일 크기는 보통 수십 MB 수준이다.

**2) 필요하면 Visual C++ 재배포 패키지도 함께 준비**

x64dbg는 자체적으로 필요한 구성요소를 대부분 포함하고 있지만, 매우 오래되었거나 초기화가 덜 된 Windows PC라면 Microsoft Visual C++ 재배포 가능 패키지(VC++ Redistributable)가 없어서 실행이 안 되는 경우가 있다. 대회 PC의 상태를 모른다면 최신 x64용 VC++ Redistributable 설치 파일도 함께 받아 USB에 넣어두면 안전하다.

**3) 파일 정리 및 이동**

x64dbg zip(그리고 필요하면 VC++ Redistributable 설치 파일)을 `offline-kit/installers/x64dbg/` 같은 폴더에 모아 USB나 외장 SSD로 옮긴다.

**4) 오프라인 PC에서 압축 해제**

원하는 위치(예: `C:\tools\x64dbg\`)에 zip을 통째로 압축 해제한다. 관리자 권한 설치 과정이 없으므로 일반 사용자 권한으로도 충분하다. 다만 실제 디버깅(다른 프로세스에 붙는 것) 자체는 상황에 따라 관리자 권한 실행이 필요할 수 있다.

**5) VC++ Redistributable 설치(필요시)**

3단계에서 받아둔 재배포 패키지를 설치한다. 이미 정상적인 최신 Windows 환경이라면 대개 생략해도 된다.

**6) 첫 실행**

대상 바이너리의 비트수에 맞춰 `x32dbg.exe` 또는 `x64dbg.exe`를 실행한다. 아키텍처가 헷갈리면 `x96dbg.exe`를 실행해서 파일을 드래그하면 알맞은 쪽으로 안내된다.

**7) 심볼 옵션 확인(선택)**

`Options → Preferences`(또는 Symbols 관련 설정) 메뉴에서 심볼 서버 URL 설정을 확인해 둔다. 완전 오프라인 환경이라면 심볼 다운로드 시도로 인한 지연을 줄이기 위해 심볼 다운로드 기능을 꺼두거나, 최소한 그 지연이 정상이라는 것을 미리 인지해 둔다.

**8) 오프라인 동작 검증**

네트워크를 끊은 상태로 다시 실행해서, 심볼 관련 경고 외에는 정상적으로 프로그램을 열고 브레이크포인트를 걸 수 있는지 확인한다. x64dbg 자체는 라이선스 인증이 없는 오픈소스 도구이므로 이 단계는 대개 무리 없이 통과한다.

## 명령어/단축키
- `x32dbg.exe` : 32비트(x86) 바이너리용 디버거 실행
- `x64dbg.exe` : 64비트(x64) 바이너리용 디버거 실행
- `x96dbg.exe` : 아키텍처 자동 판별 후 알맞은 디버거로 안내
- `File → Open` (또는 실행 파일을 창에 드래그) : 대상 바이너리 열기

## 출력 해석
- 실행 파일을 열었는데 아무 반응이 없거나 즉시 닫히면 아키텍처가 안 맞는 경우(32비트 파일을 x64dbg.exe로 열려고 한 경우 등)일 가능성이 높다.
- 시작 시 상태 표시줄이나 로그에 심볼 다운로드 관련 메시지가 오래 떠 있으면 오프라인 환경에서 심볼 서버 접속을 시도 중인 것이다 — 기다리거나 옵션에서 꺼둔다.
- "필요한 DLL을 찾을 수 없습니다" 류의 Windows 오류가 뜨면 VC++ Redistributable 미설치를 의심한다.

## 흔한 실수
- x64dbg를 "설치 파일이 있어야 한다"고 생각하고 exe 인스톨러를 찾아 헤매는 경우 — 이 도구는 압축 해제만으로 끝나는 포터블 프로그램이다.
- 32비트 크랙미를 `x64dbg.exe`로 열려고 시도하는 경우(또는 그 반대) — 반드시 대상 파일의 비트수에 맞는 실행 파일을 골라야 한다.
- 오프라인 환경에서 심볼이 하나도 안 붙는 걸 보고 "디버거가 고장 났다"고 오해하는 경우 — 네트워크가 없어서 생기는 정상적인 제약이다.
- 관리자 권한 없이 실행해서 일부 프로세스에 붙는 것(attach)이 실패하는 경우 — 필요하면 관리자 권한으로 다시 실행한다.
- 오래된 스냅샷을 여러 번 받아 폴더가 뒤섞이는 경우 — 새 스냅샷은 새 폴더에 풀어서 이전 버전과 섞이지 않게 관리한다.

## 막혔을 때 다음 체크
- 설치는 됐는데 CPU 뷰, 레지스터 창 등 화면 구성이 낯설면 → 동적 분석 카테고리의 브레이크포인트 관련 문서(REV-0169)와 함께 실제로 열어보며 익힌다.
- 단축키를 빠르게 훑고 싶다면 → REV-0281(x64dbg 핵심 단축키와 명령 치트시트)을 참고한다.
- 실제로 크랙미를 하나 풀어보고 싶다면 → REV-0282(x64dbg 10분 실전 워크플로)를 참고한다.
- 정적 분석 도구(IDA/Ghidra)와 병행하고 싶다면 → REV-0274, REV-0277을 참고해 함께 준비해 둔다.

## 미니 예제
대회 전, x64dbg를 오프라인 PC에 준비하는 흐름 예시:

```text
[인터넷 되는 PC]
1. x64dbg.com → Download → snapshots.x64dbg.com 이동
2. 최신 snapshot_YYYY-MM-DD_HH-MM.zip 다운로드
3. (필요시) Microsoft VC++ Redistributable(x64) 설치 파일 다운로드
4. offline-kit/installers/x64dbg/ 폴더에 정리 → USB 복사

[대회용 오프라인 PC]
5. zip을 C:\tools\x64dbg\ 에 압축 해제
6. (필요시) VC++ Redistributable 설치
7. 32비트 문제면 x32dbg.exe, 64비트 문제면 x64dbg.exe 실행
8. 네트워크 끊긴 상태로도 정상 실행/브레이크포인트 설정 확인
   (시스템 DLL 심볼 이름은 안 보일 수 있음 — 정상)
```

## 관련 글
- REV-0274 — IDA 설치와 오프라인 준비
- REV-0277 — Ghidra 설치와 오프라인 준비
- REV-0281 — x64dbg 핵심 단축키와 명령 치트시트
- REV-0282 — x64dbg 10분 실전 워크플로

## 출처/검증
- 다운로드 경로(x64dbg.com → snapshots.x64dbg.com/SourceForge), 배포 형태(설치 프로그램 없는 zip, x32/x64/x96dbg 구성), GPLv3 오픈소스 라이선스는 공식 사이트 x64dbg.com 및 GitHub `x64dbg/x64dbg` 저장소를 기준으로 정리했다(2026-09-08 검증).
- Microsoft 심볼 서버 관련 동작(오프라인 시 심볼 미표시, 지연 발생 가능성)은 디버거의 일반적인 심볼 다운로드 동작 원리에 근거한 설명이며, 정확한 기본 설정값과 타임아웃 동작은 다운로드한 스냅샷 버전의 `Options → Preferences`에서 직접 확인해 재검증할 것을 권장한다.
- 스냅샷 기반 배포 특성상 "최신 버전"의 정확한 기능/화면 구성은 다운로드 시점마다 달라질 수 있으므로, 설치 직후 help.x64dbg.com 또는 동봉된 readme로 재확인하는 것이 안전하다.
