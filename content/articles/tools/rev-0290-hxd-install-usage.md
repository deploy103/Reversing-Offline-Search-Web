## 한 줄 요약
HxD는 독일 개발자 Maël Hörz가 만든 Windows용 무료 헥스/디스크/메모리 에디터로, 화려한 파싱 기능은 없지만 가볍고 빠르며 바이트 검색·수정·비교 같은 기본 작업을 가장 단순하게 처리할 수 있어 CTF에서 "일단 헥스로 몇 바이트만 빨리 보고 고치고 싶을 때" 가장 먼저 여는 도구다.

## 언제 검색해야 하나
- ImHex처럼 무거운 기능 없이, 파일을 열어서 특정 바이트를 빠르게 보고 수정만 하면 될 때
- 파일 안에서 특정 헥스 패턴이나 문자열을 검색하고 싶을 때
- 두 파일을 비교해서 어느 바이트가 다른지 확인하고 싶을 때(패치 전/후 비교 등)
- Windows 실행 중인 프로세스의 메모리를 직접 열어서 값을 확인/수정하고 싶을 때
- 파일의 체크섬(MD5/SHA 등)을 빠르게 계산하고 싶을 때

## 핵심 개념

### HxD는 "가장 단순한 헥스 에디터"의 대표주자
HxD는 1990년대~2000년대부터 이어져 온 전통적인 Windows 헥스 에디터 계보의 대표 도구로, UI가 단순하고 설치 파일이 작으며 동작이 빠르다. 파일 파싱이나 패턴 언어 같은 고급 기능은 없지만, 그만큼 배우는 데 몇 분이면 충분하다. ImHex(REV-0289)가 "구조를 이해하는" 헥스 에디터라면, HxD는 "바이트를 빠르게 보고 고치는" 헥스 에디터로 역할이 나뉜다.

### 파일뿐 아니라 디스크와 메모리도 편집 가능
이름 그대로 파일 편집기만이 아니라 **디스크 에디터**(물리 디스크/파티션을 직접 헥스로 열기)와 **메모리 에디터**(실행 중인 프로세스의 메모리를 열어서 값 확인/수정) 기능도 내장하고 있다. CTF에서는 주로 파일 편집 용도로 쓰지만, 실행 중인 프로세스의 메모리를 빠르게 스캔하고 싶을 때도 유용하다. 단, 디스크 편집은 관리자 권한이 필요하고 Windows Vista 이상에서는 시스템 드라이브에 직접 쓰기가 제한된다.

### 무료이며 재배포가 허용된다
HxD는 개인/상업적 용도 모두 무료이며, 개발사(mh-nexus)는 판매만 금지할 뿐 잡지 부록 CD나 사내 배포 등으로 재배포하는 것을 명시적으로 허용한다. 다만 항상 공식 사이트(`mh-nexus.de`)에서 받는 것이 안전하다 — 제3자 다운로드 포털은 오래된 버전을 제공하거나 백신 오탐을 유발하는 경우가 있다.

## 화면/코드에서 보이는 징후
- 파일을 열면 왼쪽에 오프셋, 가운데에 16진수 바이트, 오른쪽에 아스키 표현이 나란히 보이는 전형적인 헥스 뷰 레이아웃
- 수정한 바이트는 빨간색으로 강조 표시되어 원본과 구분됨
- 파일 하단 상태 표시줄에 현재 커서 오프셋과 선택 범위 크기가 표시됨

## 가장 먼저 할 것
분석하거나 수정할 파일을 HxD에 드래그&드롭한다. `Ctrl+F`로 원하는 헥스 패턴이나 문자열을 검색하고, 필요하면 해당 바이트를 직접 클릭해서 수정한 뒤 `Ctrl+S`로 저장한다.

## 단계별 절차

**1) 공식 다운로드 (인터넷 되는 곳에서, 한 번만)**
- `https://mh-nexus.de/en/hxd/`에서 두 가지 버전 중 선택
  - 설치형(Installer): 표준 설치 프로그램
  - 포터블(Portable): 관리자 권한 없이 USB 등에서 바로 실행 가능한 버전 (HxD 2.3부터 별도 제공)

**2) 오프라인 반입**
- 포터블 버전을 받아두면 대회 PC에서 설치 없이 압축만 풀어 바로 실행 가능해 가장 간편하다
- 설치형을 쓴다면 설치 파일 자체를 USB로 옮겨 대회 PC에서 오프라인 설치

**3) 첫 실행**
- 포터블: 압축을 풀고 `HxD.exe` 더블클릭
- 설치형: 설치 후 시작 메뉴 또는 바탕화면 아이콘 실행

**4) 파일 로드**
- `File → Open` (`Ctrl+O`) 또는 파일을 창에 드래그&드롭
- 여러 파일을 탭으로 동시에 열어 비교 가능

**5) 기본 조작 익히기**
- `Ctrl+F`로 검색(헥스 값 또는 텍스트)
- 원하는 바이트를 클릭 후 직접 타이핑하여 수정
- `Ctrl+S`로 저장(원본을 보존하려면 `File → Save As`로 사본에 저장)

## 명령어/단축키
| 목적 | 단축키 |
|---|---|
| 파일 열기 | `Ctrl+O` |
| 저장 | `Ctrl+S` |
| 다른 이름으로 저장 | `Ctrl+Shift+S` |
| 검색 | `Ctrl+F` |
| 다음 찾기 | `F3` |
| 바꾸기 | `Ctrl+H` |
| 특정 오프셋으로 이동 | `Ctrl+G` |
| 실행 취소 | `Ctrl+Z` |
| 전체 선택 | `Ctrl+A` |
| 선택 영역 복사(헥스 텍스트로) | `Ctrl+Shift+C` |
| 두 파일 비교 | `Analysis → Compare files...` |
| 체크섬 계산 | `Analysis → Checksums/Hashes...` |
| 디스크 열기 | `File → Open disk...` (관리자 권한 필요) |
| 프로세스 메모리 열기 | `Extras → Open RAM` 또는 `Tools → Open process memory` |

## 출력 해석
- 검색(`Ctrl+F`)에서 "Hex-values" 모드로 `4D 5A`를 찾으면 PE 파일의 매직 넘버(`MZ`) 위치를 바로 찾을 수 있다
- 두 파일을 비교(`Compare files`)하면 다른 바이트의 오프셋이 목록으로 나오므로, 패치 전/후 파일을 비교해 "정확히 어느 바이트가 바뀌었는지" 검증할 때 유용하다
- 체크섬 계산 결과(MD5/SHA1/SHA256)는 파일 무결성 확인이나 문제 서버에 제출하는 해시값 계산에 바로 활용 가능

## 흔한 실수
- 원본 파일을 직접 열어 수정하고 `Ctrl+S`로 덮어써서 원본이 사라지는 경우 — 항상 사본을 만들어 작업하는 습관 필요
- 텍스트 검색 시 인코딩(ANSI/UTF-8/UTF-16)을 지정하지 않아 유니코드 문자열을 못 찾는 경우
- 디스크/메모리 편집 기능을 관리자 권한 없이 실행해서 "왜 안 열리지"라고 헷갈리는 경우
- HxD로 구조체를 눈으로 계산하려다 시간을 낭비하는 경우 — 구조 파싱이 필요하면 ImHex(REV-0289)가 더 적합

## 막혔을 때 다음 체크
1. 파일이 안 열리면 다른 프로그램이 해당 파일을 잠그고 있는지(예: 실행 중인 exe) 확인
2. 검색이 안 되면 검색 모드(Text/Hex-values)와 인코딩 설정을 재확인
3. 디스크/메모리 기능이 안 되면 관리자 권한으로 재실행
4. 저장 후 문제가 생기면 실행 취소(`Ctrl+Z`) 이력이 남아있는 동안 되돌리기 시도, 그래도 안 되면 사본 백업 확인

## 미니 예제
```text
1. chall.exe를 HxD에 드래그&드롭
2. Ctrl+F → Hex-values 모드 → "4D 5A" 검색
   → 오프셋 0x0에서 "MZ" 매직 넘버 확인 (정상 PE 파일)
3. 특정 오프셋의 점프 명령어 바이트를 NOP(0x90)으로 교체하고 싶다면
   해당 바이트를 클릭 후 직접 "90"으로 타이핑
4. File → Save As로 patched_chall.exe로 별도 저장(원본 보존)
```
