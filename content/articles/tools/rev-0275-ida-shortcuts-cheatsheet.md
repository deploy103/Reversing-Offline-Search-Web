## 한 줄 요약
IDA를 CTF에서 빠르게 쓰려면 최소한 `F5`(디컴파일), `F2`(브레이크포인트 토글), `F7`/`F8`/`F9`(디버거 진입/오버/실행), `X`(xref), `N`(rename), `G`(주소 이동), `Shift+F12`(strings), `Ctrl+P`(functions), `Y`(타입 지정), `Tab`(pseudocode↔disassembly 전환) 이 12개는 손에 익어야 한다.

## 언제 검색해야 하나
- IDA 단축키를 표로 한눈에 보고 싶을 때
- F7/F8/F9 같은 비슷하게 생긴 디버거 키의 차이가 헷갈릴 때
- N, X, Y처럼 한 글자 단축키가 뭘 하는지 까먹었을 때
- 새 PC/오프라인 환경에서 IDA를 처음 만졌을 때 빠르게 손을 풀고 싶을 때

## 핵심 개념
IDA의 단축키는 크게 세 그룹으로 나뉜다.

1. **정적 분석/탐색용** — 코드를 읽고 이름 붙이고 참조를 추적할 때 쓰는 키(`X`, `N`, `G`, `Y`, `Tab`, `Ctrl+P`, `Shift+F12`).
2. **디컴파일용** — 어셈블리 대신 C 비슷한 코드로 읽을 때 쓰는 키(`F5`).
3. **디버거용** — 실제로 프로그램을 실행시키며 멈추고 한 줄씩 따라갈 때 쓰는 키(`F2`, `F7`, `F8`, `F9`).

대부분의 단축키는 **커서가 디스어셈블리/Pseudocode 창에서 특정 항목(주소, 변수, 함수 이름 등)에 놓여 있을 때** 그 항목을 대상으로 동작한다. 즉 단축키를 누르기 전에 "지금 커서가 어디에 있는지"를 항상 의식해야 한다.

## 화면/코드에서 보이는 징후
아래 표는 별도 설명 없이 바로 참조하는 용도다.

| 단축키 | 동작 | 어디서 쓰나 |
|---|---|---|
| `F5` | 현재 함수를 Pseudocode(C 비슷한 코드)로 디컴파일 | 디스어셈블리에서 함수 안에 커서를 두고 누름 |
| `F2` | 커서 위치에 브레이크포인트 토글(설정/해제) | 디버깅 전, 멈추고 싶은 주소에서 |
| `F7` | Step Into — 디버깅 중 한 줄 실행, `call`이면 함수 안으로 들어감 | 디버거 실행 중 |
| `F8` | Step Over — 디버깅 중 한 줄 실행, `call`이어도 안으로 안 들어가고 통째로 실행 | 디버거 실행 중 |
| `F9` | Continue/Run — 다음 브레이크포인트까지(또는 프로그램 끝까지) 실행 | 디버거 실행 중 |
| `X` | 현재 항목(함수/변수/문자열 등)에 대한 Cross-reference(xref) 목록 표시 | 어디서 이 값을 참조하는지 볼 때 |
| `N` | 현재 항목 이름 바꾸기(Rename) | 함수/변수/라벨 이름을 의미 있게 바꿀 때 |
| `G` | 특정 주소로 바로 이동(Jump to address) | 주소를 알고 있을 때 |
| `Shift+F12` | Strings 창 열기 | 문자열 힌트를 찾을 때 |
| `Ctrl+P` | Functions 창 열기 | 함수 목록 전체를 보고 싶을 때 |
| `Y` | 현재 항목의 타입 지정(Set type) | 변수/함수 시그니처를 수동으로 지정할 때 |
| `Tab` | Pseudocode ↔ 디스어셈블리 전환 | F5로 본 코드와 원본 어셈블리를 대조할 때 |

## 가장 먼저 할 것
지금 이 표를 눈으로 한 번 훑고, 실제 IDA를 열어 아무 함수에서나 `F5` → `Tab` → `X` → `N` 순서로 직접 눌러보며 몸으로 익힌다. 디버거 키(`F2`/`F7`/`F8`/`F9`)는 실제 디버깅 세션을 시작해야 의미가 있으므로, 함수 하나를 디버거로 실행해보면서 따로 연습한다.

## 단계별 절차

**1) F5 — 디컴파일**

디스어셈블리에서 함수 내부에 커서를 두고 `F5`를 누르면 Pseudocode 창이 뜬다. 디컴파일러가 없는 등급(IDA Free 일부 버전 등, REV-0274 참고)에서는 이 키가 동작하지 않을 수 있다.

**2) F2 — 브레이크포인트 토글**

디버거를 붙이기 전이든 후든, 원하는 주소나 코드 줄에 커서를 두고 `F2`를 누르면 빨간 점(브레이크포인트)이 생기거나 없어진다. 다시 누르면 토글된다.

**3) F7/F8 — Step Into vs Step Over**

디버거가 멈춰 있는 상태에서 다음 명령이 `call`일 때, `F7`은 그 함수 내부로 따라 들어가고, `F8`은 함수를 통째로 실행하고 리턴 직후에 멈춘다. 관심 없는 라이브러리 함수(`printf` 등)는 `F8`로 건너뛰고, 검사 로직처럼 중요한 자체 함수는 `F7`로 들어가는 식으로 구분해서 쓴다.

**4) F9 — Continue**

다음 브레이크포인트를 만날 때까지(또는 프로그램이 끝날 때까지) 실행을 이어간다. 첫 브레이크포인트를 걸어둔 뒤 `F9`로 그 지점까지 단숨에 이동하는 용도로 가장 많이 쓴다.

**5) X — xref**

함수 이름, 전역 변수, 문자열 등에 커서를 두고 `X`를 누르면 "이 항목을 어디서 참조하는가" 목록이 뜬다. 목록에서 더블클릭하면 그 위치로 바로 이동한다.

**6) N — rename**

`sub_140001000` 같은 자동 생성 이름을 `check_password` 처럼 의미 있는 이름으로 바꿀 때 쓴다. 이름을 바꾸면 그 이름이 코드 전체에서 한 번에 갱신된다.

**7) G — 주소 이동**

특정 가상 주소(VA)나 RVA를 알고 있을 때 `G`를 누르고 주소를 입력하면 그 위치로 즉시 점프한다.

**8) Shift+F12 — Strings**

바이너리 안의 출력 가능한 문자열을 모아서 보여준다. "Wrong password", "flag{" 같은 힌트성 문자열을 찾을 때 가장 먼저 여는 창이다.

**9) Ctrl+P — Functions**

전체 함수 목록을 이름/주소/크기 순으로 정렬해서 볼 수 있다. 함수가 몇 개인지, 스트립되었는지 파악하는 첫 관문이다.

**10) Y — 타입 지정**

변수나 함수 인자에 커서를 두고 `Y`를 누르면 타입을 수동으로 지정하는 대화상자가 뜬다. IDA가 잘못 추론한 타입(예: `int`인데 실제로는 `char *`)을 바로잡을 때 쓴다.

**11) Tab — Pseudocode/Disassembly 전환**

F5로 연 Pseudocode 창과 원본 디스어셈블리 사이를 즉시 오간다. C 코드로는 이해했지만 실제 어셈블리 명령이 궁금할 때 유용하다.

## 명령어/단축키
| 단축키 | 기능 |
|---|---|
| `F5` | 디컴파일(Pseudocode) |
| `F2` | 브레이크포인트 토글 |
| `F7` | Step Into |
| `F8` | Step Over |
| `F9` | Continue/Run |
| `X` | Cross-reference 보기 |
| `N` | 이름 바꾸기(Rename) |
| `G` | 주소로 이동(Jump) |
| `Shift+F12` | Strings 창 |
| `Ctrl+P` | Functions 창 |
| `Y` | 타입 지정(Set type) |
| `Tab` | Pseudocode ↔ Disassembly 전환 |

## 출력 해석
- `F2`로 건 브레이크포인트는 디스어셈블리 왼쪽 여백에 빨간 점으로 표시된다. 다시 `F2`를 누르면 점이 사라지며 비활성화된다.
- `X`를 눌렀을 때 목록이 비어 있으면(0개) 그 항목을 아무 데서도 참조하지 않는다는 뜻이며, 데드 코드이거나 간접 호출(함수 포인터 등)로만 접근되는 경우일 수 있다.
- `F5`가 회색으로 비활성화되어 있거나 눌러도 반응이 없으면 디컴파일러가 이 아키텍처를 지원하지 않거나 라이선스에 포함되지 않은 것이다(REV-0274의 등급 차이 참고).

## 흔한 실수
- `F7`과 `F8`을 헷갈려서, 라이브러리 함수 내부까지 한 줄씩 따라 들어갔다가 시간을 낭비하는 경우 — 확신 없으면 일단 `F8`로 넘기고, 필요하면 되돌아와 `F7`로 다시 들어간다.
- 커서가 원하는 항목이 아닌 다른 줄에 있는 상태에서 `N`이나 `Y`를 눌러 엉뚱한 항목의 이름/타입을 바꿔버리는 경우 — 항상 커서 위치를 먼저 확인한다.
- `X`(xref)와 `G`(주소 이동)를 혼동해서, 참조 목록이 아니라 주소 입력창이 뜨는 걸 보고 당황하는 경우.
- `Tab`을 아무 창에서나 누르면 다 될 거라 생각하는 경우 — Pseudocode/Disassembly 관계가 성립하는 상황(F5로 연 함수)에서만 의미가 있다.

## 막혔을 때 다음 체크
- 각 단축키가 실제로 어떤 화면 흐름 속에서 쓰이는지 감이 안 잡히면 → REV-0276(IDA 10분 실전 워크플로)에서 실제 예제로 확인한다.
- `F5`/`Tab`을 더 깊게 알고 싶으면 → REV-0146(IDA F5 디컴파일과 Pseudocode 읽기)을 참고한다.
- Graph view에서의 화살표 읽기, 확대/축소 등 추가 조작은 → REV-0150(IDA Graph View에서 분기 읽기)을 참고한다.
- 디버거 관련 키를 더 깊게 알고 싶으면 → REV-0169(브레이크포인트란 무엇인가)를 함께 참고한다.

## 미니 예제
암호 검사 함수를 IDA로 살펴보는 최소 흐름에서 단축키를 어떻게 조합하는지 예시:

```text
1. Ctrl+P 로 Functions 창 → check_flag 비슷한 이름 찾아 더블클릭
2. F5 로 디컴파일 → Pseudocode에서 strcmp 호출 발견
3. Tab 으로 원본 디스어셈블리로 전환 → strcmp 호출 직전 코드 확인
4. strcmp 위에 커서 두고 X → 이 함수를 부르는 다른 곳이 있는지 확인
5. 비교 대상 변수 이름이 v3 처럼 의미 없으면 N 으로 input_buf 등으로 rename
6. F2 로 strcmp 호출 직전에 브레이크포인트 설정
7. 디버거 시작 후 F9 로 거기까지 실행 → F7 로 strcmp 내부까지 확인하거나 F8 로 건너뜀
```

## 관련 글
- REV-0274 — IDA 설치와 오프라인 준비
- REV-0276 — IDA 10분 실전 워크플로
- REV-0142 — IDA에 바이너리 처음 열었을 때 해야 할 것
- REV-0150 — IDA Graph View에서 분기 읽기

## 출처/검증
- 표에 정리된 12개 단축키(F5, F2, F7, F8, F9, X, N, G, Shift+F12, Ctrl+P, Y, Tab)는 Hex-Rays 공식 문서(docs.hex-rays.com) 및 IDA 기본 단축키 구성을 기준으로 정리했으며, 본 지식베이스의 REV-0142/REV-0150 등 기존 IDA 문서에서 이미 검증된 키 매핑과 일치시켰다(2026-09-08 검증).
- IDA는 `Options → Keyboard`(또는 유사 메뉴)에서 단축키를 사용자가 재매핑할 수 있으므로, 실제 설치본에서 커스터마이징된 경우 이 표와 다를 수 있다. 처음 설치한 기본 상태 기준의 단축키임을 전제로 한다.
