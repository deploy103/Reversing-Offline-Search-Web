## 한 줄 요약
x64dbg는 `F9`(실행), `F8`(Step Over), `F7`(Step Into), `F4`(커서까지 실행), `F2`(브레이크포인트 토글), `Ctrl+G`(주소 이동) 같은 단축키와, 화면 하단 **커맨드 바**에 직접 타이핑하는 `bp`, `bpm`, `run`, `dump` 같은 명령어를 함께 쓰는 것이 특징이다.

## 언제 검색해야 하나
- x64dbg 단축키를 표로 한눈에 보고 싶을 때
- F7/F8/F9/F4 같은 비슷한 실행 제어 키가 헷갈릴 때
- 커맨드 바에 뭘 타이핑해야 하는지 모를 때
- 조건부 브레이크포인트나 메모리 브레이크포인트를 걸고 싶은데 방법이 기억 안 날 때

## 핵심 개념
x64dbg의 조작 방식은 크게 두 가지로 나뉜다.

1. **단축키(F-키 중심)** — CPU 창에서 실행 흐름을 제어하는 F2/F4/F7/F8/F9/F12 등. IDA 디버거 단축키와 상당히 비슷하지만 완전히 같지는 않으므로 별도로 외워야 한다.
2. **커맨드 바(command bar)** — 화면 하단의 입력창에 `bp main`처럼 텍스트 명령을 직접 입력해서 실행하는 방식. 단축키로 못 하는 세밀한 제어(조건부 브레이크포인트, 메모리 브레이크포인트, 특정 주소 덤프 등)는 대부분 이 명령어로 처리한다.

CTF 환경에서는 이 두 가지를 섞어 쓰는 것이 표준적이다 — 큰 흐름(실행/정지/스텝)은 F-키로, 세밀한 조건 설정은 명령어로.

## 화면/코드에서 보이는 징후
다음 표는 별도 설명 없이 바로 참조하는 용도다.

### 단축키

| 단축키 | 동작 | 설명 |
|---|---|---|
| `F9` | Run(실행) | 다음 브레이크포인트까지 실행 |
| `F8` | Step Over | 한 줄 실행, `call`도 통째로 넘어감 |
| `F7` | Step Into | 한 줄 실행, `call`이면 내부로 진입 |
| `F4` | Run until selection | 커서가 있는 줄까지 실행(그 줄에 임시 실행) |
| `F2` | Toggle breakpoint | 커서 위치에 브레이크포인트 설정/해제 |
| `F12` | Pause | 실행 중인 프로세스를 강제로 멈춤 |
| `Ctrl+F2` | Restart | 디버깅 대상 프로세스를 재시작 |
| `Ctrl+F9` | Execute till return | 현재 함수의 `ret`까지 실행 |
| `Shift+F9` | Run, skip exceptions | 예외를 프로세스에 넘기며 실행 계속 |
| `Alt+F4` | Close | 디버깅 대상 종료/디버거에서 분리 |
| `Ctrl+G` | Go to expression | 주소/심볼 이름으로 이동 |
| `Space` | Edit instruction | 현재 명령어를 어셈블/패치 |

### 커맨드 바 주요 명령어

| 명령어 | 동작 |
|---|---|
| `bp <주소/이름>` | 소프트웨어 브레이크포인트 설정 (예: `bp main`) |
| `bp <주소>, "<조건>"` | 조건부 브레이크포인트 설정 |
| `bpc <주소>` | 해당 브레이크포인트 삭제 |
| `bpm <주소>` | 메모리 브레이크포인트(접근 시 중단) 설정 |
| `ba <r/w/x> <크기> <주소>` | 하드웨어 브레이크포인트 설정(읽기/쓰기/실행) |
| `run` / `g` | 실행 계속(F9와 동일) |
| `StepInto` / `sti` | Step Into (F7과 동일) |
| `StepOver` / `sto` | Step Over (F8과 동일) |
| `dump <주소>` | Dump 창에서 해당 주소로 이동 |
| `dd <주소>` / `db <주소>` / `dw <주소>` | 지정 주소를 dword/byte/word 단위로 표시 |
| `cmt <주소>, "<텍스트>"` | 해당 주소에 주석 추가 |
| `bookmark <주소>` | 북마크 추가 |

## 가장 먼저 할 것
CPU 창에서 아무 명령어에 커서를 두고 `F2`로 브레이크포인트를 걸어본 뒤, `F9`로 실행해서 거기서 멈추는지 확인한다. 그다음 화면 하단 커맨드 바에 `bp main`을 입력해보며 명령어 방식도 함께 손에 익힌다.

## 단계별 절차

**1) F9 — 실행**

프로그램을 시작하거나, 멈춰 있던 실행을 이어간다. 브레이크포인트가 없으면 프로그램이 끝날 때까지 실행된다.

**2) F2 — 브레이크포인트 토글**

관심 있는 주소(예: 비교 함수 진입점)에 커서를 두고 `F2`를 누르면 그 줄이 빨갛게 표시되며 브레이크포인트가 걸린다. 다시 누르면 해제된다.

**3) F8/F7 — Step Over vs Step Into**

`call` 명령을 만났을 때, 그 함수 내부까지 보고 싶으면 `F7`, 신경 쓰지 않고 넘어가고 싶으면 `F8`을 쓴다. 라이브러리 함수(`printf` 등)는 `F8`로, 검사 로직처럼 직접 만든 함수는 `F7`로 들어가는 것이 일반적이다.

**4) F4 — 커서까지 실행**

여러 줄을 한 줄씩 넘기기 귀찮을 때, 목표 줄에 커서를 두고 `F4`를 누르면 그 줄까지 한 번에 실행된다. 임시 브레이크포인트를 거는 것과 비슷한 효과다.

**5) Ctrl+F9 — 함수 끝까지 실행**

현재 있는 함수의 `ret` 직전까지 단숨에 실행하고 싶을 때 쓴다. `F7`로 들어갔다가 더 볼 게 없다고 판단되면 이 키로 바로 빠져나온다.

**6) Ctrl+G — 주소로 이동**

주소나 심볼 이름(`main`, `kernel32.CreateFileW` 등)을 알고 있을 때 `Ctrl+G`로 즉시 그 위치로 이동한다.

**7) bp 계열 명령어 — 세밀한 브레이크포인트**

커맨드 바에 `bp check_password`처럼 함수 이름으로 브레이크포인트를 걸 수 있고, `bp 0x401230, "eax==1"`처럼 특정 조건에서만 멈추게 할 수도 있다. 메모리 영역에 접근할 때만 멈추고 싶으면 `bpm 0x403000`처럼 메모리 브레이크포인트를 쓴다.

**8) dump / dd / db — 메모리 값 확인**

커맨드 바에 `dump <주소>`를 입력하면 Dump 창이 그 주소로 이동해서 실제 메모리 바이트를 보여준다. 레지스터에 담긴 포인터 값을 우클릭해서 "Follow in Dump"로 이동해도 같은 효과를 얻을 수 있다.

## 명령어/단축키
(위 두 표를 참조. 실전에서 가장 먼저 손에 익혀야 할 최소 세트는 `F9`, `F8`, `F7`, `F2`, `Ctrl+G`, `bp`, `run`이다.)

## 출력 해석
- `F2`로 건 브레이크포인트가 CPU 창 좌측에 빨간 점으로 보이면 정상 등록된 것이다. 반투명하거나 회색이면 비활성화 상태다.
- `bp` 명령 실행 후 커맨드 바 로그(로그 창)에 `Breakpoint at <주소>`류 메시지가 뜨면 성공적으로 설정된 것이고, 오류 메시지가 뜨면 주소/이름을 잘못 입력한 것이다.
- `F9`로 실행했는데 프로그램이 그냥 끝나버리면 브레이크포인트가 실제로 실행되는 경로에 없거나, 조건부 브레이크포인트의 조건이 한 번도 참이 되지 않은 것이다.

## 흔한 실수
- `F7`과 `F8`을 혼동해서 라이브러리 함수 내부까지 한 줄씩 따라 들어가 시간을 낭비하는 경우.
- `F4`(커서까지 실행)와 `F9`(끝까지 실행)를 헷갈려서 원하는 지점을 그냥 지나쳐버리는 경우.
- 브레이크포인트를 안 걸고 `F9`부터 눌러서 프로그램이 그대로 끝까지 실행돼버리는 경우 — 반드시 먼저 `F2`나 `bp`로 정지 지점을 만들어야 한다.
- 조건부 브레이크포인트 문법(`bp <주소>, "<조건>"`)에서 따옴표를 빠뜨리거나 조건식 문법을 틀려서 브레이크포인트가 무조건 걸리는 경우.
- 관리자 권한 없이 실행해서 일부 프로세스에 브레이크포인트가 정상적으로 걸리지 않는 경우.

## 막혔을 때 다음 체크
- 각 단축키/명령어가 실전에서 어떤 순서로 쓰이는지 감이 안 잡히면 → REV-0282(x64dbg 10분 실전 워크플로)에서 실제 예제로 확인한다.
- 브레이크포인트 개념 자체가 헷갈리면 → REV-0169(브레이크포인트란 무엇인가)를 참고한다.
- 설치/오프라인 준비가 아직이면 → REV-0280(x64dbg 설치와 오프라인 준비)을 먼저 확인한다.
- IDA/Ghidra의 정적 분석 결과와 대조하며 디버깅하고 싶으면 → REV-0142, REV-0156 등 정적 분석 문서와 병행한다.

## 미니 예제
암호 검사 함수 진입점(`0x00401230`)을 이미 정적 분석으로 알아낸 상태에서, x64dbg로 실제 값을 확인하는 최소 흐름:

```text
1. x64dbg 실행 후 대상 exe 로드 (기본적으로 진입점에서 멈춰 있음)
2. 커맨드 바에 bp 0x00401230 입력 → Enter
3. F9 로 실행 → 브레이크포인트에서 정지
4. F8 로 한 줄씩 내려가며 strcmp 호출 직전까지 이동
5. strcmp 인자가 담긴 레지스터(RCX/RDX 등) 값을 우클릭 → Follow in Dump
6. Dump 창에서 실제 비교 문자열 확인
7. F7 로 strcmp 내부까지 들어가 보거나, Ctrl+F9 로 바로 리턴까지 실행
```

- 단축키(F9, F8, F7, F4, F2, F12, Ctrl+F2, Ctrl+F9, Shift+F9, Alt+F4, Ctrl+G, Space)와 커맨드 바 명령어(bp, bpc, bpm, ba, run/g, StepInto/sti, StepOver/sto, dump, dd/db/dw, cmt, bookmark)는 x64dbg 공식 문서(help.x64dbg.com) 및 GitHub `x64dbg/x64dbg` 프로젝트를 참고한 다수의 공개 x64dbg 치트시트/입문 자료를 교차 확인해 정리했다(2026-09-08 검증).
- x64dbg는 `Options → Preferences → Shortcuts`에서 단축키를 자유롭게 재지정할 수 있으므로, 이 표는 기본 설정 기준이며 실제 설치본에서 재확인하는 것을 권장한다. 스냅샷 기반 배포 특성상 버전마다 세부 명령어 옵션이 추가/변경될 수 있다.
