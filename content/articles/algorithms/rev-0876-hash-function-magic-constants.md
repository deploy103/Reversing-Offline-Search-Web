## 한 줄 요약
디스어셈블리나 `.rodata`에서 `0x67452301`, `0xEFCDAB89`, `0x98BADCFE`, `0x10325476` 같은 4개 묶음 상수가 보이면 MD5나 SHA-1을, `0x6A09E667`로 시작하는 8개 묶음 상수가 보이면 SHA-256을 의심할 수 있다 — 이 값들은 모두 각 해시 알고리즘의 표준 스펙에 고정된 "초기 해시값(IV)"이다.

## 언제 검색해야 하나
- 디컴파일 코드나 데이터 영역에 32비트 상수 4개 또는 5개, 8개가 나란히 초기화되는 곳을 발견했을 때
- Import 목록에 `MD5Init`, `SHA1Init`, `SHA256_Init`, `CryptCreateHash`, `BCryptHashData` 같은 함수가 있을 때
- 어떤 함수가 입력을 64바이트(512비트) 블록 단위로 나눠서 처리하는 루프 구조를 가질 때
- 알 수 없는 32비트 상수가 "√소수의 소수부"처럼 규칙성 있어 보이는데 정체를 모를 때

## 핵심 개념
암호학적 해시 함수는 시작 전에 고정된 상수(초기 해시값, IV)로 내부 레지스터를 채운다. 이 값들은 무작위가 아니라 표준 문서에 박제된 "nothing-up-my-sleeve" 상수라서, 값 자체가 알고리즘을 특정하는 강력한 지문이 된다.

**MD5 초기값 (RFC 1321, 4개의 32비트 레지스터 A/B/C/D)**
| 레지스터 | 값 (hex) |
|---|---|
| A | `0x67452301` |
| B | `0xEFCDAB89` |
| C | `0x98BADCFE` |
| D | `0x10325476` |

**SHA-1 초기값 (FIPS 180-4, 5개의 32비트 레지스터 H0~H4)**
| 레지스터 | 값 (hex) |
|---|---|
| H0 | `0x67452301` |
| H1 | `0xEFCDAB89` |
| H2 | `0x98BADCFE` |
| H3 | `0x10325476` |
| H4 | `0xC3D2E1F0` |

MD5와 SHA-1은 앞의 4개 값이 완전히 동일하다(SHA-1 설계가 MD4/MD5 계열에서 파생됐기 때문). **다섯 번째 값 `0xC3D2E1F0`의 유무로 MD5(4개)와 SHA-1(5개)을 구분한다.**

**SHA-256 초기값 (FIPS 180-4, 8개의 32비트 레지스터 H0~H7, 첫 8개 소수의 제곱근 소수부에서 유도)**
| 레지스터 | 값 (hex) |
|---|---|
| H0 | `0x6A09E667` |
| H1 | `0xBB67AE85` |
| H2 | `0x3C6EF372` |
| H3 | `0xA54FF53A` |
| H4 | `0x510E527F` |
| H5 | `0x9B05688C` |
| H6 | `0x1F83D9AB` |
| H7 | `0x5BE0CD19` |

SHA-256은 이 8개 초기값 외에도 64개의 라운드 상수(K[0]~K[63], 첫 64개 소수의 세제곱근 소수부)를 쓰는데, 코드 안에 64개짜리 32비트 상수 배열이 있으면 이 K 테이블일 가능성이 높다. SHA-512는 같은 방식이지만 64비트 레지스터 8개(`0x6A09E667F3BCC908`로 시작)를 쓴다.

**바이트 순서(엔디안) 주의**: 메모리에 `mov eax, 67452301h`처럼 즉시값으로 로드되면 그대로 읽으면 되지만, 파일에 리틀엔디안 바이트 나열(`01 23 45 67`)로 저장돼 있으면 반드시 역순으로 읽어야 진짜 값이 나온다.

## 화면/코드에서 보이는 징후
```asm
mov     dword ptr [ctx], 67452301h
mov     dword ptr [ctx+4], 0EFCDAB89h
mov     dword ptr [ctx+8], 98BADCFEh
mov     dword ptr [ctx+0Ch], 10325476h
```
디컴파일:
```c
ctx->h0 = 0x6A09E667; ctx->h1 = 0xBB67AE85; /* ... 8개 ... */
```

## 가장 먼저 할 것
IDA/Ghidra의 상수 검색(`Alt+B` 바이너리 검색 또는 텍스트 검색)으로 `67452301`을 먼저 찾는다. 찾으면 그 근처에 몇 개의 32비트 상수가 더 있는지 세어본다 — 4개면 MD5, 5개면 SHA-1, 8개면(값이 `6A09E667`로 시작) SHA-256이다.

## 단계별 절차
**1) 상수 개수 세기** — 초기화 루틴 하나에 몇 개의 32비트 상수가 연속으로 대입되는지 확인.

**2) 값 대조** — 위 표와 정확히 일치하는지 확인. 순서가 바뀌어 있어도(레지스터 이름만 다르게 매핑) 값 자체는 동일해야 한다.

**3) 블록 크기 확인** — MD5/SHA-1/SHA-256은 모두 64바이트(512비트) 블록 단위로 처리한다. SHA-512류는 128바이트 블록이다.

**4) Python으로 즉시 검증**
```python
import hashlib
print(hashlib.md5(b"test").hexdigest())
print(hashlib.sha1(b"test").hexdigest())
print(hashlib.sha256(b"test").hexdigest())
```
바이너리가 계산한 결과와 Python 표준 라이브러리 결과를 대조하면 알고리즘 식별이 100% 확정된다.

## 명령어/단축키
- IDA: `Alt+B`(바이너리 검색)로 `67 45 23 01`(리틀엔디안 바이트열) 검색
- Ghidra: `Search > Memory` 로 동일 바이트열 검색
- Python: `hashlib.md5/sha1/sha256(...).hexdigest()`

## 출력 해석
- 상수가 4개뿐이고 다섯 번째가 없으면 MD5, `0xC3D2E1F0`까지 5개면 SHA-1.
- 8개에 `0x6A09E667`로 시작하면 SHA-256. 64비트 버전(`0x6A09E667F3BCC908`)이면 SHA-512.
- Python 결과와 바이너리 결과가 다르면 입력 인코딩(UTF-8 vs 다른 인코딩) 또는 솔트 추가 여부를 다시 확인.

## 흔한 실수
- MD5와 SHA-1의 앞 4개 초기값이 동일하다는 걸 모르고 상수만 보고 성급하게 MD5로 단정하는 것 — 다섯 번째 상수(`0xC3D2E1F0`)가 있는지 반드시 확인해야 한다.
- 파일 안의 바이트 나열(`01 23 45 67`)을 그대로 정수로 읽어서 값이 다르다고 착각하는 것 — 리틀엔디안이면 역순으로 읽어야 `0x67452301`이 나온다.
- 이 해시들이 단방향이라는 걸 잊고 해시값에서 원문을 복원하려 시도하는 것 — 목표는 알고리즘 식별이지 역산이 아니며, 이후 전략은 브루트포스나 알려진 평문 대조로 넘어가야 한다.

## 막혔을 때 다음 체크
- 상수가 `0xEDB88320`류라면 해시가 아니라 체크섬 계열 → REV-0877 — CRC 다항식 상수 빠른 참조표.
- 곱셈 상수 `16777619`가 보인다면 → REV-0208 — 16777619 상수가 보일 때 FNV 의심하기.
- 알고리즘을 특정한 뒤 다음에 뭘 해야 할지 전체 흐름이 필요하면 → REV-0885 — 알고리즘 유형별 판별 체크리스트.

## 미니 예제
IDA에서 다음 초기화 코드를 봤다고 하자:
```c
void sha256_init(SHA256_CTX *ctx)
{
    ctx->h[0] = 0x6a09e667;
    ctx->h[1] = 0xbb67ae85;
    ctx->h[2] = 0x3c6ef372;
    ctx->h[3] = 0xa54ff53a;
    ctx->h[4] = 0x510e527f;
    ctx->h[5] = 0x9b05688c;
    ctx->h[6] = 0x1f83d9ab;
    ctx->h[7] = 0x5be0cd19;
}
```
8개의 상수가 정확히 SHA-256 표준값과 일치하므로 이 함수는 SHA-256 초기화 루틴으로 확정된다. Python `hashlib.sha256`으로 즉시 재구현해서 검증 로직을 대조할 수 있다.

## 관련 글
- REV-0877 — CRC 다항식 상수 빠른 참조표
- REV-0208 — 16777619 상수가 보일 때 FNV 의심하기
- REV-0207 — FNV-1과 FNV-1a 해시 패턴
- REV-0885 — 알고리즘 유형별 판별 체크리스트

## 출처/검증
- MD5 초기값(A/B/C/D): RFC 1321, "The MD5 Message-Digest Algorithm" 명세 기준 (2026-09-09 검증).
- SHA-1 초기값(H0~H4): NIST FIPS 180-4, "Secure Hash Standard (SHS)" 명세 기준 (2026-09-09 검증).
- SHA-256 초기값(H0~H7) 및 소수 제곱근 소수부 유도 방식: NIST FIPS 180-4 명세 기준 (2026-09-09 검증).
