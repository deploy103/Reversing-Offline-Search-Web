## 한 줄 요약
"나눗셈처럼 보이는데 실제로는 곱셈으로 구현된" 연산, 또는 두 변수가 몫과 나머지를 주고받으며 값을 스왑하는 루프(`gcd` 계산과 겉보기에 똑같은 구조)를 만났다면, 그건 나머지를 취하는 세계에서 "나누기"에 해당하는 **모듈러 역원(modular inverse)**을 구하는 코드일 가능성이 크다.

## 언제 검색해야 하나
- RSA 관련 코드(REV-0886)에서 개인 지수 `d`를 계산하는 부분을 찾다가, `e`와 `φ(n)`을 입력받아 이상한 루프를 도는 함수를 만났을 때
- Affine 암호(`y = (a*x + b) mod m` 형태)의 복호화 함수인데, `/a`(나눗셈)가 아니라 `* a_inv`(곱셈)로 되어 있어서 이해가 안 될 때
- 두 개의 변수가 계속 자리를 바꾸면서(`t0, t1 = t1, t0 - q*t1` 같은 패턴) 결국 하나가 0이 될 때까지 도는 루프를 봤는데, 단순 GCD 계산이라기엔 결과를 다른 곳에 저장하는 부분이 이상할 때
- `pow(a, m - 2, m)` 형태의 거듭제곱 호출을 발견했는데 왜 지수가 `m - 2`인지 이해가 안 될 때
- 해시나 체크섬 검증 함수에서 "곱셈의 역"을 이용해 원래 값을 복원하려는 듯한 코드가 있을 때

## 핵심 개념

### "나머지 세계"에는 나눗셈이 없다
일반적인 정수 나눗셈 `10 / 3`은 문제없이 계산되지만, 모듈러 연산의 세계(`mod m`)에서는 나눗셈이라는 연산 자체가 정의되어 있지 않다. 대신 "곱했을 때 1이 되는 짝(paired inverse)"을 찾아서 나눗셈 대신 곱셈을 쓴다. 즉, 정수 `a`에 대해 `a * a_inv ≡ 1 (mod m)`을 만족하는 `a_inv`를 모듈러 역원이라 부르고, `b / a mod m`이 필요하면 실제로는 `b * a_inv mod m`을 계산한다. 이 개념이 CTF에 등장하는 이유는 명확하다. RSA의 개인 지수 `d`가 바로 `e`의 모듈러 역원(`e * d ≡ 1 mod φ(n)`)이고, Affine 암호의 복호화 계수도 곱셈 계수 `a`의 모듈러 역원이며, 체크섬/해시 역산에서도 곱셈 단계를 되돌리려면 역원이 필요하다.

### 코드 패턴 1 — 확장 유클리드 호제법(Extended Euclidean Algorithm)
모듈러 역원은 항상 존재하는 게 아니라 `gcd(a, m) = 1`(서로소)일 때만 존재한다. 이걸 확인하면서 동시에 역원까지 구하는 표준 알고리즘이 확장 유클리드 호제법이다. 일반 GCD 계산과 거의 똑같이 생겼지만, **계수를 추가로 추적한다**는 게 결정적 차이다.

```c
// 확장 유클리드 호제법 — 일반 gcd와 겉보기엔 비슷하지만 s, t를 같이 추적한다
int64_t ext_gcd(int64_t a, int64_t b, int64_t *x, int64_t *y) {
    if (b == 0) {
        *x = 1;
        *y = 0;
        return a;
    }
    int64_t x1, y1;
    int64_t g = ext_gcd(b, a % b, &x1, &y1);
    *x = y1;
    *y = x1 - (a / b) * y1;
    return g;
}

int64_t modinv(int64_t a, int64_t m) {
    int64_t x, y;
    int64_t g = ext_gcd(a, m, &x, &y);
    if (g != 1) return -1;              // 역원이 존재하지 않음
    return ((x % m) + m) % m;           // 음수가 나올 수 있으므로 보정
}
```
반복문(비재귀) 버전은 다음처럼 두 쌍의 변수가 나란히 갱신되는 형태로 나타난다.

```c
int64_t modinv_iter(int64_t a, int64_t m) {
    int64_t old_r = a, r = m;
    int64_t old_s = 1, s = 0;
    while (r != 0) {
        int64_t q = old_r / r;
        int64_t tmp_r = old_r - q * r; old_r = r; r = tmp_r;
        int64_t tmp_s = old_s - q * s; old_s = s; s = tmp_s;
    }
    return ((old_s % m) + m) % m;
}
```
디스어셈블리에서 이 패턴을 알아보는 핵심은 **몫(`q = old_r / r`)을 계산한 뒤, 그 몫으로 두 쌍의 변수(`r`/`s`)를 동시에 갱신하며 서로 자리를 바꾼다**는 점이다. 단순 GCD 계산이라면 `r`, `old_r`만 갱신되고 끝나지만, 모듈러 역원 계산은 `s`, `old_s`(때로는 `t`, `old_t`까지 세 쌍)도 똑같은 몫으로 나란히 갱신된다. 이 "여분의 변수 쌍"이 있는지가 GCD와 modinv를 구분하는 가장 확실한 단서다.

### 코드 패턴 2 — 페르마의 소정리를 이용한 지름길
모듈러스 `m`이 소수라면 확장 유클리드 없이 훨씬 간단한 방법이 있다. 페르마의 소정리에 따르면 소수 `p`와 `p`로 나누어떨어지지 않는 `a`에 대해 `a^(p-1) ≡ 1 (mod p)`이므로, 양변에 `a^-1`을 곱하면 `a^(p-2) ≡ a^-1 (mod p)`가 성립한다. 즉 **모듈러 역원을 모듈러 거듭제곱(REV-0886)으로 계산**할 수 있다.

```python
a_inv = pow(a, m - 2, m)   # m이 소수일 때만 성립
```
이 패턴은 코드에서 지수 자리에 `모듈러스 - 2`가 들어가는 형태로 나타난다. IDA/Ghidra 디컴파일에서 `mod_pow(a, m - 2, m)` 같은 호출을 보면, 이건 나눗셈이 아니라 역원을 구하고 있다는 뜻이다. 다만 이 방법은 `m`이 소수일 때만 유효하다 — RSA의 모듈러스 `n = p*q`는 합성수이므로 `φ(n)`을 모듈러스로 쓸 때는 이 지름길을 쓸 수 없고 반드시 확장 유클리드를 써야 한다(왜냐하면 `φ(n)`은 소수가 아니기 때문).

### 어디서 이 패턴을 만나게 되는가
- **RSA 개인키 생성**: `d = modinv(e, φ(n))` — RSA 관련 문제에서 서버 쪽 키 생성 루틴을 리버싱할 때 등장(REV-0886 참고)
- **Affine 암호 복호화**: `y = (a*x + b) mod 26`으로 암호화했다면 복호화는 `x = a_inv * (y - b) mod 26`. 여기서 `a_inv`는 26과 서로소인 `a`에 대한 모듈러 역원
- **해시/체크섬 역산**: `h = h * k mod m` 형태로 값을 누적하는 해시 함수를 역으로 풀 때, 각 단계를 되돌리려면 `k`의 모듈러 역원이 필요
- **선형 합동 생성기(LCG, REV-0891) 역추적**: LCG의 이전 상태를 구할 때도 곱셈 계수의 역원이 필요한 경우가 있음

## 화면/코드에서 보이는 징후
- GCD 계산처럼 보이는 루프인데 변수 쌍이 두 개(`r`/`old_r`, `s`/`old_s`) 이상 나란히 갱신됨
- 함수 이름이나 근처 변수명에 `inv`, `modinv`, `inverse`가 남아있음(strip 안 된 경우)
- 지수 자리에 `mod - 2` 같은 계산식이 들어간 모듈러 거듭제곱 호출
- 나눗셈 연산자가 있어야 할 자리에 곱셈과 나머지 연산만 있음
- 결과값에 대해 `((x % m) + m) % m`처럼 음수를 보정하는 코드가 붙어있음(확장 유클리드는 중간에 음수 계수가 나올 수 있기 때문)

## 가장 먼저 할 것
루프 안에서 몫(`/`)을 구한 뒤 그 몫으로 **두 쌍 이상의 변수**를 동시에 갱신하고 있는지부터 확인한다. 한 쌍만 갱신되면 순수 GCD, 두 쌍 이상이면 확장 유클리드(모듈러 역원)로 거의 확정할 수 있다. 지수 거듭제곱 형태라면 지수가 `모듈러스 - 2`인지 바로 확인한다.

## 단계별 절차
1. 의심되는 함수의 입력 인자 두 개(`a`, `m`)를 확인 — 순서와 의미(어떤 게 나눌 대상이고 어떤 게 모듈러스인지) 파악
2. 루프 내부에서 몫을 계산하는 위치를 찾고, 그 몫으로 몇 개의 변수 쌍이 갱신되는지 셈
3. 변수 쌍이 하나뿐이면 REV-0209(CRC)나 REV-0219(브루트포스 판단)처럼 단순 GCD/공약수 계산일 수 있으니 다른 문맥을 더 확인
4. 두 쌍 이상이면 확장 유클리드로 확정하고, 최종적으로 반환되는 변수(`old_s` 또는 `x`)가 결과임을 확인
5. 결과에 음수 보정(`+ m) % m`)이 있는지 확인 — 있으면 확실히 모듈러 역원 계산 함수
6. 파이썬의 `pow(a, -1, m)`(Python 3.8+) 또는 직접 구현한 `modinv`로 같은 입력을 넣어 값이 일치하는지 검증(REV-0222)
7. 이 역원이 실제로 어디에 쓰이는지(RSA 키 생성? Affine 복호화?) 호출자 함수를 따라가며 최종 목적 확인

## 명령어/단축키
```python
# 파이썬 3.8 이상은 내장 pow로 바로 모듈러 역원 계산 가능
a_inv = pow(a, -1, m)

# 직접 구현 (검증용)
def modinv(a, m):
    g, x, _ = ext_gcd(a, m)
    if g != 1:
        raise ValueError("역원이 존재하지 않음 (gcd != 1)")
    return x % m

def ext_gcd(a, b):
    old_r, r = a, b
    old_s, s = 1, 0
    old_t, t = 0, 1
    while r != 0:
        q = old_r // r
        old_r, r = r, old_r - q * r
        old_s, s = s, old_s - q * s
        old_t, t = t, old_t - q * t
    return old_r, old_s, old_t   # gcd, x, y
```
IDA: 재귀 함수라면 콜 그래프(`Ctrl+X`로 xref 확인)에서 자기 자신을 호출하는지 먼저 체크. Ghidra: Function Graph 뷰에서 루프 안 변수 갱신 순서를 시각적으로 추적.

## 출력 해석
- `ext_gcd`의 첫 반환값(`gcd`)이 1이 아니면 애초에 역원이 존재하지 않는다는 뜻 — 코드에 이 경우를 처리하는 에러 분기가 있는지 확인한다.
- `modinv(a, m) * a % m`을 계산했을 때 1이 나오지 않으면, `a`와 `m`을 반대로 넣었거나 부호 보정을 빠뜨린 것이다.
- RSA 개인 지수 `d`를 구했다면, `pow(pow(m, e, n), d, n) == m`으로 왕복 검증하는 것이 가장 확실하다.

## 흔한 실수
- 확장 유클리드 결과를 그냥 반환해서 음수가 그대로 나오는 것 — 반드시 `((x % m) + m) % m`으로 양수 범위에 맞춰야 한다.
- `gcd(a, m) != 1`인 경우(역원이 없는 경우)를 확인하지 않고 아무 값이나 역원인 것처럼 사용하는 것.
- 페르마 소정리 지름길(`pow(a, m-2, m)`)을 합성수 모듈러스에 그대로 적용하는 것 — `m`이 소수가 아니면 이 공식 자체가 성립하지 않는다.
- RSA 문맥에서 `modinv(e, n)`을 계산해버리는 것 — 실제로는 `modinv(e, φ(n))`이어야 한다. 모듈러스를 `n`과 `φ(n)` 중 무엇으로 쓰는지 반드시 구분해야 한다.

## 막혔을 때 다음 체크
- 이 역원이 RSA 개인 지수 계산에 쓰이는 맥락이라면 → REV-0886 RSA 개념과 간단한 모듈러 거듭제곱 인식하기
- 나눗셈 없이 곱셈만으로 구성된 변환이 애초에 역산 가능한 구조인지 헷갈리면 → REV-0221 역연산 가능한 알고리즘 판단법
- 뽑아낸 알고리즘을 파이썬으로 재현하는 절차가 기억 안 나면 → REV-0222 검증 루틴을 Python으로 그대로 재현하기
- 변환이 단순 덧셈/뺄셈 상수 기반이라 모듈러 역원까지 갈 필요가 없는 경우인지 먼저 확인하려면 → REV-0200 ADD SUB 상수 기반 문자 변환

## 미니 예제
어떤 Affine 암호 복호화 함수를 IDA로 열었더니 다음과 같은 디컴파일 결과가 나왔다고 하자.

```c
int decrypt_char(int y, int a, int b) {
    int a_inv = compute_modinv(a, 26);        // 왜 나눗셈이 아니라 함수 호출이지?
    int x = ((y - b) * a_inv) % 26;
    if (x < 0) x += 26;
    return x;
}
```
`compute_modinv`를 따라가 보니 앞서 설명한 확장 유클리드 형태(몫으로 두 쌍의 변수를 갱신)였다면, 이 함수는 `x = a^-1 * (y - b) mod 26` 공식을 그대로 구현한 Affine 암호 복호화다. 파이썬으로 검증한다.

```python
def ext_gcd(a, b):
    old_r, r = a, b
    old_s, s = 1, 0
    while r != 0:
        q = old_r // r
        old_r, r = r, old_r - q * r
        old_s, s = s, old_s - q * s
    return old_r, old_s

def modinv(a, m):
    g, x = ext_gcd(a, m)
    assert g == 1, "역원 없음"
    return x % m

a, b = 5, 8
a_inv = modinv(a, 26)          # a=5, m=26 -> a_inv = 21
assert (a * a_inv) % 26 == 1   # 검증

def decrypt_char(y):
    return ((y - b) * a_inv) % 26

# 암호문 y=3 (문자 'D')이 있었다면
print(decrypt_char(3))   # 원래 평문 인덱스 복원
```
`(a * a_inv) % 26 == 1`이 성립함을 확인했으므로, 이 역원 값을 그대로 복호화 루프에 대입하면 평문을 복원할 수 있다.

- 페르마의 소정리를 이용한 모듈러 역원 계산(`a^(p-2) mod p`)의 성립 조건(모듈러스가 소수일 것): 표준 정수론 교재(페르마 소정리) 및 RFC 8017(PKCS #1) 배경 설명 기준 (2026-09-09 검증).
- 파이썬 `pow(a, -1, m)` 내장 지원(3.8+): Python 공식 문서 `pow()` 함수 설명 기준 (2026-09-09 검증).
