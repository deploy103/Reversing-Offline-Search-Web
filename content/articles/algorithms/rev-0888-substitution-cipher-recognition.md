## 한 줄 요약
입력의 각 문자를 **키 없이 고정된 1대1 매핑 테이블**로 다른 문자 하나로 바꾸기만 하고, 그 매핑이 문자의 위치나 이전 문자와 무관하게 항상 동일하다면 고전적인 단일 치환 암호(monoalphabetic substitution cipher)를 의심해야 한다.

## 언제 검색해야 하나
- 26바이트(또는 알파벳+숫자 등을 포함한 더 큰 크기)의 상수 배열이 있고, 각 인덱스가 알파벳 순서(`A, B, C, ...`)와 다른 문자로 매핑되어 있을 때
- 입력 문자열을 한 글자씩 순회하며 그 문자를 테이블에서 찾아 인덱스를 구하고, 다른 테이블에서 같은 인덱스의 값을 가져와 치환하는 두 단계 룩업 구조를 만났을 때
- 암호문에서 특정 문자(예: `E`에 대응하는 암호 문자)가 유독 자주 등장하는 것을 발견했을 때 — 평문이 영어라면 빈도 분석이 통할 가능성이 크다는 신호
- 암호화/복호화가 완전히 대칭적인 두 개의 룩업 테이블(정방향/역방향)로 구현되어 있는 걸 봤을 때

## 핵심 개념

### 치환 암호란 무엇인가
치환 암호는 평문의 각 문자를 다른 문자(또는 기호)로 **일관되게** 바꾸는 가장 오래된 암호 방식이다. "일관되게"가 핵심이다 — 평문에 `E`가 몇 번 나오든 항상 같은 암호 문자로 바뀐다. 이 성질 때문에 XOR 반복 변환(REV-0199)이나 Vigenere류 반복 키 암호(REV-0889)와 달리, **암호문 자체의 문자 빈도 분포가 평문의 문자 빈도 분포를 그대로 유지한 채 이름표만 바뀐 것**이 된다. 영어 텍스트에서 `E`가 가장 흔한 글자라는 사실은 변하지 않으므로, 암호문에서 가장 흔한 글자를 찾으면 그게 십중팔구 평문의 `E`에 대응한다 — 이것이 **빈도 분석(frequency analysis)**이다.

### 코드에서 치환 암호가 나타나는 형태
가장 단순한 형태는 룩업 테이블 하나로 끝난다.

```c
// 정방향 치환 테이블 — 인덱스는 평문 문자(A=0..Z=25), 값은 암호 문자
static const char sub_table[26] = {
    'Q','W','E','R','T','Y','U','I','O','P',
    'A','S','D','F','G','H','J','K','L','Z',
    'X','C','V','B','N','M'
};

void encrypt(char *buf, int len) {
    for (int i = 0; i < len; i++) {
        if (isupper(buf[i])) {
            buf[i] = sub_table[buf[i] - 'A'];
        }
    }
}
```
이 코드의 특징은 **인덱스가 위치(`i`)나 이전 상태와 전혀 무관하고, 오직 현재 문자값(`buf[i] - 'A'`)에만 의존**한다는 점이다. XOR/ADD 계열 변환(REV-0199, REV-0200)은 `buf[i] XOR key[i % keylen]`처럼 위치 `i`가 키 선택에 관여하지만, 순수 치환 암호는 위치를 아예 쓰지 않는다. 이 차이가 REV-0215(Lookup Table 기반 변환)의 일반적인 논의와 치환 암호를 구분하는 지점이다 — 치환 암호는 룩업 테이블 변환 중에서도 **알파벳 전체를 다른 알파벳 순열로 재배치한다는 특수성**을 갖는다.

복호화는 정방향 테이블의 역함수, 즉 값과 인덱스를 뒤바꾼 테이블을 쓴다.

```c
// 역방향(복호화) 테이블 — 정방향 테이블에서 자동 생성 가능
static const char inv_table[26];   // inv_table[sub_table[i] - 'A'] = 'A' + i
```
바이너리에 이 역방향 테이블이 **하드코딩되어 별도로 존재**한다면, 정방향 테이블만으로 파이썬에서 직접 역함수를 만들 수 있으므로 굳이 바이너리의 역테이블을 찾을 필요도 없다.

### ROT13/시저류와의 관계
시저 암호(REV-0890)나 ROT13은 치환 암호의 **특수한 부분집합**이다 — 매핑이 "알파벳을 N칸 밀기"라는 하나의 규칙으로 정의되어 있어서 룩업 테이블 없이 산술 연산(`(c - 'A' + N) % 26 + 'A'`)만으로 구현할 수 있다. 반면 일반적인 치환 암호는 26개의 매핑이 서로 **완전히 무작위**라서 산술식으로 표현할 수 없고 반드시 26바이트짜리 테이블이 코드/데이터에 존재해야 한다. 따라서 리버싱 중 "산술 연산만으로 매핑이 되는가, 아니면 반드시 테이블을 참조해야 하는가"를 확인하면 시저류와 일반 치환 암호를 즉시 구분할 수 있다.

### 빈도 분석으로 키 없이 뚫기
치환 암호는 룩업 테이블(즉, 26!가지의 순열 중 하나)이 키 그 자체다. 26!는 천문학적으로 큰 수라 브루트포스(REV-0219)는 불가능하지만, **빈도 분석**은 키를 몰라도 통계적으로 매핑을 추측할 수 있게 해준다. 영어 텍스트의 알려진 문자 빈도 순서는 대략 다음과 같다(높은 빈도부터): `E, T, A, O, I, N, S, H, R, D, L, C, ...`. 암호문에서 문자 빈도를 세어 이 순서와 대응시키면 초기 추측을 만들 수 있고, 이후 흔한 2글자 조합(bigram: `TH`, `HE`, `IN`), 흔한 단어(`THE`, `AND`)의 패턴으로 교정해 나간다.

```python
from collections import Counter

def freq_analysis(ciphertext):
    letters = [c for c in ciphertext.upper() if c.isalpha()]
    counts = Counter(letters)
    # 빈도 높은 순으로 정렬 -> 영어 빈도 순서(ETAOIN...)와 매칭 시도
    return counts.most_common()

ENGLISH_FREQ_ORDER = "ETAOINSHRDLCUMWFGYPBVKJXQZ"
```
이 접근은 완전 자동화보다는 **초기 후보를 좁히고 사람이 확인하며 교정하는** 반자동 도구로 쓰는 게 실전에서 훨씬 효율적이다. CTF에서는 평문이 플래그 형식(`flag{...}`)이나 알려진 접두사를 포함하는 경우가 많아, 그 알려진 부분과 암호문을 대조해 매핑을 즉시 확정할 수 있는 경우도 흔하다(REV-0223 known-plaintext 참고).

## 화면/코드에서 보이는 징후
- 26개(또는 알파벳+숫자+기호를 포함한 더 큰) 항목의 문자 배열이 정확히 알파벳 순서가 아닌 순서로 나열되어 있음
- 문자 변환이 `table[c - 'A']` 형태이고, 인덱스에 루프 변수 `i`나 이전 문자가 전혀 관여하지 않음
- 정방향/역방향 두 개의 테이블이 쌍으로 존재
- 대소문자를 따로 처리하는 분기(`isupper`/`islower`)가 있고, 숫자/기호는 그대로 통과시키는 조건문이 있음

## 가장 먼저 할 것
룩업 테이블을 찾으면 그 26바이트(또는 그 이상)를 그대로 덤프하고, 인덱스가 위치(`i`)와 무관하게 오직 현재 문자에만 의존하는지부터 확인한다. 위치가 관여한다면 이건 치환 암호가 아니라 Vigenere류(REV-0889)이거나 커스텀 알파벳 인코딩(REV-0214)일 가능성이 있다.

## 단계별 절차
1. 문자 변환 루프를 찾고 인덱스 계산식이 `buf[i]`(위치 무관)인지 `key[i % n]`(위치 관여)인지부터 구분
2. 위치 무관이면 참조하는 테이블을 Hex View로 덤프해 26바이트(혹은 해당 알파벳 크기)를 확보
3. 테이블이 산술식(`+N`, `-N`, `%26`)으로 대체 가능한 단순 시프트인지 확인 — 가능하면 REV-0890(시저류)으로 재분류
4. 산술식으로 표현 불가능한 임의 순열이면 표준 치환 암호로 확정
5. 테이블을 파이썬 딕셔너리로 옮기고 역방향 매핑도 함께 생성
6. 암호문에 알려진 접두사(`flag{`)가 있으면 그 부분으로 즉시 매핑 일부를 검증(REV-0223)
7. 알려진 접두사가 없으면 빈도 분석으로 초기 후보를 만들고, 흔한 단어 패턴으로 반복 교정

## 명령어/단축키
```python
# 테이블 기반 치환 암호 복호화
sub_table = "QWERTYUIOPASDFGHJKLZXCVBNM"   # IDA에서 덤프한 순서 그대로
alphabet  = "ABCDEFGHIJKLMNOPQRSTUVWXYZ"

enc_map = dict(zip(alphabet, sub_table))
dec_map = dict(zip(sub_table, alphabet))

def decrypt(ciphertext):
    return "".join(dec_map.get(c, c) for c in ciphertext)
```
IDA: 배열 위에서 `A`(문자열/문자 배열 재해석), Ghidra: Data Type Manager에서 `char[26]`로 캐스팅해 한눈에 순서 확인.

## 출력 해석
- 덤프한 테이블이 알파벳과 정확히 일치하면(`A→A, B→B, ...`) 치환이 아예 없는 항등 함수이거나, 실제 치환 로직이 다른 곳에 있다는 뜻이니 호출 경로를 다시 확인한다.
- 복호화 결과에 사람이 읽을 수 있는 단어가 부분적으로 나타나면 매핑이 맞다는 신호이니, 틀린 나머지 글자는 빈도 분석/단어 유추로 교정한다.
- 대소문자를 구분하지 않고 통으로 처리했는데 결과가 깨진다면, 대문자 테이블과 소문자 테이블이 별도로 존재하는지 다시 확인한다.

## 흔한 실수
- 위치(`i`)가 관여하는 반복 키 암호(REV-0889)를 단순 치환 암호로 오인해서, 매핑 하나로 전체를 복호화하려다 실패하는 것.
- 정방향 테이블과 역방향 테이블을 혼동해서 암호화 테이블로 복호화를 시도하는 것.
- 26!이라는 키 공간 크기만 보고 브루트포스가 불가능하다고 포기하는 것 — 실제로는 빈도 분석이나 known-plaintext로 키 공간 탐색 없이 바로 풀리는 경우가 대부분이다.
- 숫자/기호/공백까지 테이블에 포함된 걸 놓치고 알파벳 26개만 처리해서 일부 문자가 그대로 남는 것.

## 막혔을 때 다음 체크
- 매핑에 문자 위치가 관여한다면 → REV-0889 Vigenere류 반복 키 암호 알아보기
- 매핑이 산술식 하나로 표현 가능한 단순 밀기라면 → REV-0890 시저 암호(Caesar Cipher) 변형 알아보기
- 암호문 일부에서 이미 평문 조각(플래그 형식 등)을 알고 있다면 → REV-0223 Known plaintext와 Flag 형식으로 조건 줄이기
- 이 변환이 근본적으로 역산 가능한지 이론적으로 확인하려면 → REV-0221 역연산 가능한 알고리즘 판단법
- 룩업 테이블 변환 일반론이 더 필요하면 → REV-0215 Lookup Table 기반 변환

## 미니 예제
IDA에서 다음과 같은 디스어셈블리를 봤다고 하자.

```
.rodata:00402000 sub_table db 'Q','W','E','R','T','Y','U','I','O','P'
.rodata:0040200A          db 'A','S','D','F','G','H','J','K','L','Z'
.rodata:00402014          db 'X','C','V','B','N','M'
```
그리고 함수는 다음과 같이 이 테이블을 참조한다.

```c
void encrypt(char *s) {
    for (int i = 0; s[i]; i++) {
        if (s[i] >= 'A' && s[i] <= 'Z') {
            s[i] = sub_table[s[i] - 'A'];   // i는 인덱스 계산에 쓰이지 않음
        }
    }
}
```
인덱스 계산에 `i`가 전혀 관여하지 않으므로 표준 치환 암호로 확정. 파이썬으로 즉시 복호화한다.

```python
sub_table = "QWERTYUIOPASDFGHJKLZXCVBNM"
alphabet  = "ABCDEFGHIJKLMNOPQRSTUVWXYZ"
dec_map = dict(zip(sub_table, alphabet))

ciphertext = "YKQU{ATCG}"   # 예시 암호문
print("".join(dec_map.get(c, c) for c in ciphertext))
```
매핑표를 그대로 반영해 딕셔너리를 만들었으므로, 위 코드는 별도의 빈도 분석 없이 테이블 하나만으로 즉시 평문을 복원한다. 테이블을 확보하지 못한 경우에만 빈도 분석/known-plaintext 절차로 넘어가면 된다.
