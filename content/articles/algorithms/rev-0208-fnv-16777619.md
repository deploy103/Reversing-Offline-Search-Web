## 한 줄 요약
어셈블리나 디컴파일 코드에서 곱셈 상수 `16777619`(헥스로 `0x01000193`)가 보이면, 이는 거의 확실히 **FNV-1 / FNV-1a 해시 알고리즘의 "FNV prime"** 이며, 초기값 `2166136261`(`0x811C9DC5`)과 함께 나타나면 확정적이다.

## 언제 검색해야 하나
- 디컴파일 코드에 `hash = hash * 16777619` 또는 `imul ..., 1000193h` 같은 곱셈이 반복 루프 안에 있을 때
- 어떤 상수가 `0x811C9DC5`(2166136261)로 초기화되는 변수를 발견했을 때
- 문자열/입력을 순회하면서 XOR과 곱셈을 번갈아 하는 루프를 만났을 때 (커스텀 체크섬/검증 함수로 보이는데 알고리즘 이름을 모를 때)

## 핵심 개념
**FNV(Fowler–Noll–Vo) 해시**는 간단하고 빠른 비암호학적 해시 함수로, 파일 무결성 체크, 해시 테이블 키 생성, 그리고 CTF 문제에서 "입력값을 검증하는 체크섬"으로 자주 쓰인다. 구현이 매우 짧아서(루프 하나, 곱셈과 XOR 각 1회) 리버싱 문제에 넣기 좋다는 특징이 있다.

**FNV의 핵심 상수 (32비트 버전)**:
- **FNV offset basis (초기값)**: `2166136261` = `0x811C9DC5`
- **FNV prime (곱셈 상수)**: `16777619` = `0x01000193`

이 두 숫자 중 하나만 봐도 FNV를 강하게 의심할 수 있고, 둘 다 보이면 사실상 확정이다. (64비트 버전은 offset basis `0xCBF29CE484222325`, prime `0x100000001B3`을 쓴다 — 마찬가지로 특징적인 상수라 바로 알아볼 수 있다.)

**FNV-1과 FNV-1a의 차이 (연산 순서만 다름)**:

FNV-1 (곱셈 먼저, XOR 나중):
```
hash = offset_basis
for each byte b in data:
    hash = hash * FNV_prime      # 먼저 곱하고
    hash = hash XOR b            # 그다음 XOR
```

FNV-1a (XOR 먼저, 곱셈 나중 — 실무에서 더 널리 쓰임, 눈사태 효과가 더 좋음):
```
hash = offset_basis
for each byte b in data:
    hash = hash XOR b            # 먼저 XOR하고
    hash = hash * FNV_prime      # 그다음 곱함
```
어셈블리에서 이 둘을 구분하려면, 루프 안에서 `xor`와 `imul`(또는 `mul`) 중 **어느 것이 먼저 나오는지**만 보면 된다.

**곱셈 후 마스킹**: 32비트 FNV는 곱셈 결과를 32비트로 유지해야 하므로(오버플로 시 상위 비트를 자연스럽게 버림), C에서는 `uint32_t` 타입이 자동으로 이를 처리하고, 파이썬으로 재현할 때는 반드시 `& 0xFFFFFFFF`를 곱셈 직후에 걸어야 한다(REV-0026 마스크 참고).

## 화면/코드에서 보이는 징후
- `mov eax, 811C9DC5h` 또는 `mov eax, 2166136261` — 초기화
- `imul eax, 1000193h` 또는 `imul eax, eax, 16777619` — 곱셈
- 위 두 상수가 함께 등장하고, 그 사이에 `xor eax, ...`(입력 바이트)가 루프 안에서 반복
- 디컴파일 결과에 `v1 = (v1 ^ *p) * 16777619;`처럼 곱셈과 XOR이 섞인 한 줄짜리 반복 연산

## 가장 먼저 할 것
IDA에서 이 곱셈 상수(`16777619` 또는 `0x1000193`)를 발견하면, 그 루프 전체를 캡처해서 **XOR과 곱셈의 순서**를 확인한다. 순서만 알면 FNV-1인지 FNV-1a인지 바로 특정되고, 파이썬으로 그대로 재현해서 검증 로직을 우회하거나 정방향으로 값을 계산할 수 있다.

## 단계별 절차

**1) 상수 확인**

디스어셈블리에서 `imul` 오퍼랜드가 `1000193h`(=16777619)인지 계산기로 확인한다. IDA에서 숫자 위에 커서를 놓고 `H`를 눌러 16진/10진을 토글하면 빠르다.

**2) 초기값 확인**

같은 함수 안에서 변수가 `0x811C9DC5`(2166136261)로 초기화되는지 찾는다. 이게 있으면 사실상 FNV로 확정.

**3) FNV-1 vs FNV-1a 판별**

루프 본문을 보고 `xor`가 `imul`보다 먼저 실행되면 FNV-1a, `imul`이 먼저면 FNV-1이다.
```c
// FNV-1a 예시 (디컴파일 결과)
for ( i = 0; i < len; ++i )
{
    hash ^= input[i];          // XOR 먼저
    hash *= 16777619;          // 곱셈 나중
}
```

**4) 파이썬으로 동일 로직 재현**
```python
def fnv1a_32(data: bytes) -> int:
    h = 0x811C9DC5
    for b in data:
        h ^= b
        h = (h * 0x01000193) & 0xFFFFFFFF
    return h

def fnv1_32(data: bytes) -> int:
    h = 0x811C9DC5
    for b in data:
        h = (h * 0x01000193) & 0xFFFFFFFF
        h ^= b
    return h
```

**5) 검증 로직과 대조**

바이너리가 "입력의 FNV 해시가 어떤 목표값과 같으면 Correct"라는 구조라면, 목표값(비교 대상 상수)을 알아내고 이걸로 무엇을 할 수 있는지 판단한다. **FNV는 일반적으로 역산(원문 복원)이 불가능한 단방향 해시**이므로, 목표 해시값과 일치하는 입력을 찾으려면:
- 입력 길이/문자셋이 좁으면 브루트포스(REV-0219 참고)
- 아니면 "정확한 원문"이 아니라 "같은 해시를 만드는 아무 입력"이라도 되는지 문제 조건 확인

## 명령어/단축키
```python
# 빠른 검증용
print(hex(fnv1a_32(b"hello")))   # 특정 라이브러리/문제의 기대값과 대조
```
IDA: `H` (숫자 진법 토글), `Y` (변수 타입 지정으로 uint32_t 명시하면 오버플로 동작이 더 명확히 보임)

## 출력 해석
- 계산된 해시값이 32비트 범위(0 ~ 4294967295)를 벗어나면 마스킹(`& 0xFFFFFFFF`)을 빠뜨린 것이니 다시 확인.
- 바이너리에서 나온 비교 대상 상수와 직접 계산한 해시가 다르면, FNV-1/FNV-1a를 바꿔서 다시 시도하거나, 32비트가 아니라 64비트 버전(다른 상수 세트)일 가능성을 의심.

## 흔한 실수
- FNV-1과 FNV-1a를 구분하지 않고 아무거나 골라 파이썬으로 재현했다가 값이 안 맞아서 "이 알고리즘이 아닌가?"라고 오판하는 것 — 연산 순서만 바꿔보면 대부분 해결된다.
- 32비트 마스크를 빼먹고 파이썬 정수가 계속 커지게 놔두는 것 — 반드시 `& 0xFFFFFFFF`를 곱셈 직후에 명시.
- FNV가 단방향 해시라는 걸 모르고 "해시값에서 원문을 복원하려는" 시도를 하는 것 — 해시는 복원이 아니라 브루트포스/충돌 탐색의 영역이다.
- 초기값 없이 곱셈 상수만 보고 성급하게 FNV라고 단정하는 것 — `16777619`가 우연히 다른 목적으로 쓰였을 수도 있으니, 초기값 `0x811C9DC5`나 루프의 XOR 패턴까지 함께 확인해서 교차검증한다.

## 막혔을 때 다음 체크
- 24비트 마스크(`0xFFFFFF`)와 헷갈린다면 → REV-0026(비트 마스크)에서 F 개수 세는 법 다시 확인.
- CRC 계열과 헷갈린다면 → REV-0209(CRC 계열 알고리즘 흔적 찾기, 예정)와 상수를 비교(CRC32는 보통 `0xEDB88320` 같은 다항식 상수를 테이블로 미리 계산해둔 형태로 나타나 FNV와 패턴이 다르다).
- 해시값 자체를 브루트포스해야 하는 상황이라면 → REV-0219(Brute Force가 가능한 입력 공간 계산, 예정) 참고.

## 미니 예제
IDA에서 다음과 같은 디컴파일 결과를 봤다고 하자:
```c
unsigned int calc_hash(char *s, int len)
{
    unsigned int h = 0x811C9DC5;
    for ( int i = 0; i < len; ++i )
    {
        h = h ^ (unsigned char)s[i];
        h = h * 16777619;
    }
    return h;
}
```
초기값 `0x811C9DC5`와 곱셈 상수 `16777619`, 그리고 `xor`가 `*` 보다 먼저 나오는 순서까지 모두 FNV-1a와 일치한다. 파이썬으로 즉시 재현 가능:
```python
def calc_hash(s: bytes) -> int:
    h = 0x811C9DC5
    for b in s:
        h ^= b
        h = (h * 16777619) & 0xFFFFFFFF
    return h

assert calc_hash(b"test") == calc_hash(b"test")  # 바이너리에서 뽑은 목표값과 비교
```
