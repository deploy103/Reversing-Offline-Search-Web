## 한 줄 요약
검증/변환 루틴을 만났을 때 "이게 해시인지, 암호인지, 단순 인코딩인지, 그냥 커스텀 로직인지" 막막하다면, 이 문서의 체크리스트를 위에서 아래로 훑으며 상수·구조·연산 패턴을 하나씩 대조하면 대부분 몇 분 안에 후보를 좁힐 수 있다.

## 언제 검색해야 하나
- 처음 보는 검증 함수를 만났고, 어디서부터 분석을 시작해야 할지 감이 안 잡힐 때
- 여러 알고리즘 후보(해시? CRC? AES? 커스텀?)가 동시에 떠올라서 우선순위를 정하고 싶을 때
- 개별 알고리즘 문서(FNV, CRC, AES 등)는 읽었지만 "그래서 내 케이스는 어디부터 확인해야 하나" 전체 그림이 필요할 때

## 핵심 개념
알고리즘 식별은 대개 다음 순서로 좁혀나가는 것이 효율적이다: **① 임포트/API 확인 → ② 상수 검색 → ③ 테이블 유무 확인 → ④ 연산 패턴 확인 → ⑤ 입출력 크기 비율 확인.** 상수 하나만 맞아도 대부분 확정되므로, 코드를 한 줄씩 읽기 전에 이 순서로 먼저 훑는 것이 훨씬 빠르다.

### 체크리스트 1 — Import/API부터 확인
- `MD5`, `SHA1`, `SHA256`, `CryptCreateHash`, `BCryptHashData` → 암호학적 해시. REV-0876 참고.
- `crc32`, `RtlComputeCrc32` → CRC 체크섬. REV-0877 참고.
- `BCryptEncrypt`, `CryptEncrypt`, `AES_*`, `EVP_aes_*`, `AESENC`/`AESDEC` 명령어 → AES. REV-0211, REV-0882 참고.
- `RSA_*`, `BCRYPT_RSA_ALGORITHM` → RSA. REV-0881 참고.
- `rand`, `srand`, `random`, `java.util.Random` → PRNG(시드 기반 난수). REV-0883 참고.
- Import가 하나도 없고 전부 직접 구현(인라인 루프)이면 → 체크리스트 2로 이동.

### 체크리스트 2 — 32비트/64비트 상수부터 검색
- `0x67452301`, `0xEFCDAB89`, `0x98BADCFE`, `0x10325476`(+`0xC3D2E1F0`) → MD5/SHA-1. REV-0876.
- `0x6A09E667`로 시작하는 8개 상수 → SHA-256. REV-0876.
- `16777619`(`0x01000193`) / `2166136261`(`0x811C9DC5`) → FNV. REV-0207, REV-0208.
- `0xEDB88320`, `0x04C11DB7`, `0x82F63B78`, `0xA001`, `0x1021` → CRC 계열. REV-0209, REV-0877.
- `63 7C 77 7B` (S-box) 또는 `01 02 04 08...1B 36`(Rcon) → AES. REV-0211, REV-0882.
- `65537`(`0x10001`) → RSA 공개 지수. REV-0881.
- `1103515245`/`12345`, `22695477`/`1`, `214013`/`2531011`, `0x5DEECE66D` → LCG형 PRNG. REV-0883.
- `4D5A`(MZ), `7F454C46`(ELF), `504B0304`(ZIP) 등 → 파일 포맷 매직. REV-0884.
- 위 어디에도 안 걸리면 → 체크리스트 3으로 이동(테이블/구조 기반 판별).

### 체크리스트 3 — 정적 테이블 유무
- **256바이트짜리 배열**이 있고 값이 불규칙 → AES S-box 또는 커스텀 치환 테이블. REV-0211, REV-0214, REV-0215.
- **64자짜리 문자열**(`A-Za-z0-9+/` 류) → Base64(표준 또는 셔플). REV-0212, REV-0879, REV-0880.
- **32자짜리 문자열**(`A-Z2-7`) → Base32. REV-0879.
- **58자짜리 문자열**(`123456789ABCDEF...`, 0/O/I/l 없음) → Base58. REV-0880.
- **85자짜리 문자열**(특수문자 다수 포함) → Ascii85/Base85/Z85. REV-0880.
- **16자짜리 문자열**(`0123456789ABCDEF`) → Hex 인코딩. REV-0213, REV-0879.
- 테이블은 있는데 입력→테이블 인덱스 관계에 산술 규칙이 없음(순수 대입) → 커스텀 치환 테이블. REV-0214.
- 테이블이 아예 없음 → 체크리스트 4로 이동(연산 패턴 기반 판별).

### 체크리스트 4 — 반복 루프의 연산 패턴
- `hash = hash * C ^ byte` 또는 `hash = (hash ^ byte) * C` 형태, 곱셈 상수 하나 + XOR 하나만 반복 → FNV류. REV-0207, REV-0208.
- `crc = table[...] ^ (crc >> 8)` 또는 바이트당 8회 비트 루프 + 다항식 XOR → CRC류. REV-0209, REV-0877.
- `output[i] = input[i] ^ key[i % keylen]`(키 인덱스가 순환) → 반복 키 XOR. 키 길이를 모르면 REV-0878로 먼저 추정, 로직 자체는 REV-0199.
- `v = (v << s) | (v >> (32-s))` 류의 회전 연산 반복 + 특정 상수(`0x9E3779B9`류 델타) → TEA/XTEA. REV-0210.
- `output[i] = table[input[i]]`(산술 규칙 없는 순수 대입) → 치환 테이블. REV-0214.
- 두 개의 중첩 루프가 행렬처럼 인덱싱(`arr[i][j]`, `arr[j][i]`) → 행렬 변환. REV-0217.
- 단순 `add`/`sub`/`shl`/`shr`/`rol`/`ror`/`and`/`xor` 하나만 반복 → REV-0200~REV-0206 각 문서.
- 여기까지도 특정이 안 되면 → 커스텀 알고리즘일 가능성이 높으므로, 역산 가능성(REV-0221)부터 판단하고 REV-0222로 직접 Python 재구현을 시도.

### 체크리스트 5 — 입출력 크기 비율 (인코딩류 최종 확인)
| 입력:출력 비율 | 후보 |
|---|---|
| 1:2 | Hex(Base16) |
| 3:4 | Base64 |
| 4:5 | Ascii85/Base85/Z85 |
| 5:8 | Base32 |
| 가변(나눗셈 기반, 고정 비율 아님) | Base58 |
| 1:1 (길이 불변) | XOR, 치환, 회전, 시프트 등 대칭 변환 계열 |

## 화면/코드에서 보이는 징후
이 체크리스트 자체는 코드 위에서 직접 적용하는 판별 순서이므로, 실제 화면 징후는 각 하위 문서(REV-0207~REV-0223, REV-0876~REV-0884)에 정리된 상수/패턴을 그대로 참고한다.

## 가장 먼저 할 것
검증 함수의 Import 목록부터 확인한다(체크리스트 1). Import가 없다면 함수 안의 32비트/64비트 즉시값을 전부 나열해서 체크리스트 2의 상수표와 대조한다. 이 두 단계만으로도 실무에서 마주치는 알고리즘의 대다수가 식별된다.

## 단계별 절차
**1) 체크리스트 1~5를 순서대로 적용** — 위에서 아래로, 걸리는 즉시 해당 세부 문서로 이동.

**2) 후보가 좁혀지면 세부 문서에서 정확한 상수/공식 대조** — 예: FNV로 좁혀졌으면 REV-0208에서 초기값과 곱셈 상수를 정확히 확인.

**3) Python으로 즉시 재구현해서 검증** — 각 세부 문서의 미니 예제 코드를 그대로 가져와 바이너리의 실제 값과 대조.

**4) 역산 가능 여부 판단** — 알고리즘이 확정되면 이게 애초에 역산 가능한지(REV-0221) 확인하고, 불가능하면 브루트포스(REV-0219)나 알려진 평문(REV-0223) 전략으로 전환.

**5) 전체 로직을 Python으로 재현** — REV-0222 방식으로 검증 루틴 전체를 옮겨서 자동화된 풀이 스크립트를 완성.

## 명령어/단축키
- IDA/Ghidra: `Alt+T`/`Alt+B`(텍스트/바이너리 검색)로 위 상수들을 한 번에 검색
- Python: `hashlib`, `zlib`, `base64`, `Crypto.Cipher.AES` 등 표준/서드파티 라이브러리로 후보를 즉시 검증

## 출력 해석
- 라이브러리로 재구현한 결과가 바이너리 관찰값과 정확히 일치하면 알고리즘 식별 완료.
- 후보를 여러 개 시도했는데 전부 안 맞으면, 상수를 잘못 읽었거나(엔디안 문제) 여러 알고리즘이 조합된 경우(예: XOR 후 Base64)일 수 있으므로 REV-0217(중첩 변환), REV-0223(알려진 평문)로 넘어가서 레이어를 하나씩 벗겨낸다.

## 흔한 실수
- 체크리스트를 순서대로 안 밟고 코드를 처음부터 끝까지 정독하려다 시간을 낭비하는 것 — 상수/Import 검색이 훨씬 빠르다.
- 상수 하나가 우연히 비슷해 보인다고(`16777619`와 `16777215`처럼) 성급하게 확정하는 것 — 반드시 세부 문서의 정확한 값과 자릿수까지 대조해야 한다.
- 여러 변환이 순차적으로 적용된 경우(예: XOR → Base64 인코딩)를 하나의 알고리즘으로 착각하는 것 — 출력이 인쇄 가능한 문자로만 되어 있다면 마지막 단계가 인코딩일 가능성을 먼저 의심하고 그 안쪽 레이어를 별도로 확인해야 한다.
- 식별에는 성공했지만 역산 가능 여부(REV-0221)를 확인하지 않고 무작정 역함수를 구현하려다, 애초에 단방향(해시)이라 불가능한 시도를 반복하는 것.

## 막혔을 때 다음 체크
- 알고리즘은 특정했는데 입력 공간이 너무 커서 막막하면 → REV-0219 — Brute Force가 가능한 입력 공간 계산.
- 두 방향에서 동시에 탐색해야 하는 구조(중간 지점에서 만나는 형태)라면 → REV-0220 — Meet-in-the-middle를 고려할 상황.
- 검증 로직 전체를 Python으로 옮기는 마지막 단계가 필요하면 → REV-0222 — 검증 루틴을 Python으로 그대로 재현하기.

## 미니 예제
어떤 함수에서 다음을 관찰했다고 하자:
1. Import 없음(체크리스트 1 통과 안 됨)
2. `0x811C9DC5`로 초기화되는 변수 발견(체크리스트 2에서 즉시 매치)
3. 루프 안에서 `xor` 다음 `imul ..., 1000193h`

체크리스트 2 단계에서 이미 FNV로 확정되므로, 굳이 체크리스트 3(테이블 확인)이나 4(연산 패턴 전수 조사)까지 갈 필요 없이 바로 REV-0208로 이동해서 FNV-1a 파이썬 구현을 대입하면 된다. 이렇게 체크리스트는 "몇 단계까지 갔는지"가 아니라 "가장 먼저 걸리는 단계에서 즉시 멈추고 이동"하는 것이 핵심이다.

## 관련 글
- REV-0207 — FNV-1과 FNV-1a 해시 패턴
- REV-0208 — 16777619 상수가 보일 때 FNV 의심하기
- REV-0209 — CRC 계열 알고리즘 흔적 찾기
- REV-0211 — AES 테이블 또는 AES API 흔적 찾기
- REV-0876 — 해시 함수 매직 상수 빠른 참조(MD5/SHA1/SHA256 초기값)
- REV-0877 — CRC 다항식 상수 빠른 참조표
- REV-0878 — 흔한 XOR 키 길이 탐지 팁 참조
- REV-0879 — Base64/Base32/Base16 알파벳 빠른 참조
- REV-0880 — 흔한 커스텀 인코딩 알파벳 예시 모음
- REV-0881 — RSA 관련 흔한 상수(e=65537 등) 빠른 참조
- REV-0882 — AES S-Box/Rcon 상수 빠른 참조
- REV-0883 — 흔한 시드 기반 PRNG 상수 빠른 참조(LCG 계수 등)
- REV-0884 — 리버싱에서 자주 보는 매직넘버 모음표
- REV-0221 — 역연산 가능한 알고리즘 판단법
- REV-0222 — 검증 루틴을 Python으로 그대로 재현하기

## 출처/검증
- 본 체크리스트는 REV-0207~REV-0223 및 REV-0876~REV-0884에서 이미 개별 검증된 상수/패턴을 재구성한 요약이며, 별도의 새로운 사실 주장은 포함하지 않는다. 각 항목의 원출처는 해당 개별 문서의 "출처/검증" 절을 참고 (2026-09-09 검증).
