## 한 줄 요약
함수 로직이 중간에 뚝 끊기거나 서로 다른 두 로직이 한 함수 안에 섞여 보인다면 대부분 **함수의 시작/끝 경계를 IDA가 잘못 잡은 것**이며, 문제 지점을 `U`(Undefine)로 되돌린 뒤 정확한 시작 주소에서 `P`(Create function)로 다시 만들거나, `E`(Set function end)/Edit function attributes로 경계를 직접 조정하면 해결되는 경우가 많다 — 단, "분리된 것처럼 보이는 코드"가 실제로는 정상적인 함수 청크(function chunk)일 수도 있으므로 무작정 합치기 전에 먼저 구분해야 한다.

## 언제 검색해야 하나
- 함수의 디스어셈블리/의사코드가 눈에 보기에도 로직 중간에서 뚝 끊기고, RET 없이 다음 함수로 바로 이어질 때
- Functions 창(Ctrl+P)에서 어떤 함수가 몇 바이트짜리 코드 한 줄 수준으로 작거나, 반대로 수천 줄짜리로 비정상적으로 클 때
- 서로 관련 없어 보이는 두 로직 블록이 한 함수 F5 결과 안에 섞여 있을 때
- 함수 이름 옆에 회색으로 다른 함수 이름이 붙어 있거나, Functions 창에 본 적 없는 위치에 같은 함수와 관련된 항목이 여러 개 보일 때(함수 청크 가능성)

## 핵심 개념
IDA의 자동 분석(auto-analysis)은 코드 패턴(표준 프롤로그, CALL 대상, 점프 흐름)을 보고 함수의 시작과 끝을 추정한다. 이 추정이 항상 맞지는 않는다. 대표적으로 함수 경계가 틀어지는 상황은 다음과 같다.

1. **non-returning(반환하지 않는) 함수를 잘못 판단** — `exit`, `abort`, `_assert_fail`처럼 절대 리턴하지 않는 함수를 IDA가 "반환할 수도 있다"고 착각하면, 그 CALL 뒤에 이어지는(사실은 다른 함수의) 코드까지 현재 함수에 억지로 포함시켜 함수가 비정상적으로 커진다. 반대로 실제로는 반환하는 함수를 non-return으로 착각하면 함수가 그 CALL 직후에서 뚝 잘려버린다.
2. **함수 청크(function chunk)** — 컴파일러 최적화(특히 코드 배치 최적화, cold path 분리)는 하나의 논리적 함수를 메모리상 서로 떨어진 여러 조각으로 나눠 배치할 수 있다. IDA는 이런 함수를 "메인 청크(main chunk) + 하나 이상의 꼬리 청크(tail chunk)"로 모델링한다. Functions 창에는 메인 청크만 대표로 나열되고, 꼬리 청크는 별도 색으로 표시되거나 목록에 다르게 나타난다. 이건 **버그가 아니라 정상적인 구조**이므로, "함수가 이상하게 나뉘어 있다"고 해서 무조건 잘못된 것은 아니다.
3. **꼬리 호출(tail call) 최적화** — 함수 끝에서 다른 함수로 `call` 대신 `jmp`로 넘어가는 패턴. IDA가 이걸 별도 함수로의 점프로 제대로 인식하지 못하면, 두 함수의 코드가 하나로 합쳐져 보이거나 반대로 원래 이어져야 할 코드가 분리돼 보인다.
4. **공유 에필로그(shared epilogue)** — 최적화된 컴파일러는 여러 함수의 마지막 정리(에필로그) 코드를 하나로 합쳐서 여러 함수가 같은 RET 지점으로 점프하게 만들기도 한다. 이 경우 IDA가 그 공유 코드를 어느 함수에 귀속시킬지 헷갈려서 경계가 이상해 보일 수 있다.
5. **함수 사이에 끼어든 정렬용 패딩/데이터** — 함수와 함수 사이에 `int3`나 `nop` 정렬 바이트, 혹은 점프 테이블 데이터가 끼어 있는데 IDA가 이를 코드로 착각해 다음 함수 시작 위치를 틀리게 잡는 경우.

## 화면/코드에서 보이는 징후
- 함수 끝이 RET/JMP 같은 자연스러운 종료 명령 없이 그냥 다음 주소의 다른 함수 시작과 맞물려 끝나 있음
- Functions 창(Ctrl+P)에서 함수 크기(Function size 또는 주소 범위)가 극단적으로 작거나(예: 2~3바이트) 극단적으로 큼
- 의사코드(F5) 결과에서 앞부분과 뒷부분의 로직이 전혀 관계없어 보임(사실은 서로 다른 두 함수가 합쳐진 것)
- Functions 창 목록에 같은 이름 계열(`sub_401000`, `sub_401000_0` 등)이나, 함수 이름 뒤에 옅은 색/괄호로 다른 청크 소속이 표시됨 — 이는 청크 구조를 나타내는 정상 표시일 수 있음

## 가장 먼저 할 것
문제로 의심되는 함수의 끝부분(또는 시작부분)으로 이동해서, 정말로 코드가 잘못 잘린 것인지 아니면 정상적인 함수 청크(꼬리 청크)로 이어지는 것인지부터 구분한다. 청크라면 손댈 필요가 없고, 진짜 경계 오류라면 아래 절차로 고친다.

## 단계별 절차

**1) 진짜 경계 오류인지 정상 청크인지 구분**

의심되는 함수에서 Ctrl+P(Functions 창)를 열고 이름을 확인한다. IDA는 함수의 메인 청크와 꼬리 청크를 서로 다르게 표시하므로(버전에 따라 색상/괄호 표기가 다를 수 있음), 목록에서 해당 함수 항목을 더블클릭해 실제로 이어지는 코드인지, 아니면 진짜로 뚝 끊긴 것인지 디스어셈블리를 직접 눈으로 따라가며 확인한다. 함수가 실행되지 않을 코드(쓰레기 바이트) 위에서 끝난다면 진짜 오류다.

**2) 간단한 재생성으로 먼저 시도**

가장 간단한 방법: 함수 시작 주소로 이동(Ctrl+P에서 함수 선택 → Enter) → 그 함수를 삭제(Ctrl+P 목록에서 선택 후 Delete, 또는 함수 시작에서 우클릭 → Delete function) → 커서를 정확한 시작 주소에 놓고 **P**(Create function)로 다시 만든다. 이 방법은 간단한 상황에서 잘 통하지만, 함수에 붙어 있던 주석/이름 등 부가 정보가 날아갈 수 있으므로 중요한 함수라면 주의한다.

**3) 코드가 아닌 바이트부터 정리**

함수 경계가 이상한 원인이 사실 그 안에 정의되지 않은(undefined) 바이트나 잘못 디스어셈블된 데이터가 섞여 있기 때문일 수 있다. 이 경우 먼저 REV-0155 절차대로 `U`(Undefine)로 문제 구간을 되돌리고 `C`(Code)/`D`(Data)로 올바르게 재정의한 다음, 다시 이 글의 절차를 진행한다.

**4) 함수 끝(End) 직접 지정**

함수가 실제보다 짧게 끝났다면, 마지막으로 포함되어야 할 명령어에 커서를 놓고 **E** (Set function end) 를 누른다. 이 명령은 현재 위치까지만 함수에 포함되도록 끝 지점을 자른다. 반대로 함수를 더 늘려야(연장해야) 한다면, 함수 안에서 Edit → Functions → **Edit function**(또는 함수 시작 우클릭 → "Edit function")을 열어 대화상자의 End address 필드를 직접 더 뒤쪽 주소로 수정한다. 단, 새 경계가 다른 함수/청크와 겹치거나 세그먼트 경계를 넘으면 적용되지 않는다.

**5) 두 함수가 하나로 합쳐졌다면 분리**

반대로 원래 두 개여야 할 함수가 하나로 합쳐져 있다면, 두 번째 함수가 실제로 시작하는 주소를 먼저 알아낸다(보통 표준 프롤로그 `push ebp` / `endbr64` 같은 함수 시작 패턴이나, 다른 곳에서 그 주소로의 CALL xref가 있는지로 판단). 그 주소에서 **E**로 앞 함수를 그 직전까지 자르고, 새 시작 주소에서 **P**로 새 함수를 만든다.

**6) non-return 함수 표시 확인**

함수가 특정 CALL 직후에서 이상하게 잘려 있다면, 그 CALL이 부르는 함수가 실제로는 반환하는데 IDA가 non-return으로 잘못 표시했을 가능성이 있다. 그 CALL 대상 함수 위에서 우클릭 메뉴의 "non-returning" 관련 플래그를 확인/해제하고, 원래 함수를 다시 만든다.

**7) 함수 청크(분리된 코드)를 하나로 묶기/떼기**

정상적인 최적화로 코드가 두 곳에 나뉜 게 맞다면(예: 예외 처리용 cold path가 함수 본문과 멀리 떨어진 곳에 있음), 필요할 때 해당 범위를 선택한 뒤 Edit → Functions 하위의 "Append function tail"(꼬리 청크로 추가)이나 "Remove function tail"(꼬리 청크 제거) 명령으로 소속을 조정할 수 있다. 대부분의 경우 IDA 자동 분석이 이미 올바르게 청크를 구성해 놓으므로, 디컴파일 결과가 실제로 이상할 때만 손댄다.

**8) 재분석**

경계를 고친 뒤에는 F5로 디컴파일을 다시 확인하고, 여전히 이상하면 REV-0152(디컴파일러 실패)나 REV-0155(undefined bytes)를 함께 점검한다.

## 명령어/단축키
- `Ctrl+P`: Functions 창 열기(REV-0143 참고)
- `E`: Set function end — 현재 위치까지 함수 끝을 자름
- Edit → Functions → `Edit function`(또는 함수 시작 우클릭 → Edit function): 시작/끝 주소, 이름, 플래그를 대화상자로 직접 편집
- `U`: Undefine — 잘못 정의된 코드/데이터를 되돌림
- `P`: Create function — 커서 위치부터 함수 생성
- Edit → Functions → `Append function tail` / `Remove function tail`: 함수 청크(꼬리 청크) 소속 조정
- 함수 시작 우클릭 → `Delete function`: 함수 정의 삭제(재생성 전 단계)

## 출력 해석
- `Edit function` 대화상자에서 End address를 원하는 값으로 바꿔도 적용이 안 된다면, 그 범위가 다른 함수/청크와 겹치거나 세그먼트 경계를 벗어난다는 뜻이다 — 먼저 그 경계 지점의 다른 함수를 축소하거나 삭제해야 한다.
- Functions 창에서 함수 옆에 표시되는 청크 관련 표기(버전에 따라 다름)는 오류가 아니라 "이 함수는 메모리상 여러 조각으로 나뉘어 있다"는 정보이므로, 무조건 하나로 합칠 필요는 없다.
- E로 자른 후 함수 크기가 여전히 이상하다면, 애초에 자른 위치가 진짜 함수 경계가 아니었을 가능성이 크다 — 다른 함수 시작 패턴(프롤로그)이나 xref를 다시 찾아야 한다.

## 흔한 실수
- 함수 청크(정상적으로 나뉜 코드)를 오류로 착각해서 억지로 하나로 합치려다가 오히려 더 꼬아버리는 것.
- 함수를 삭제(U)만 하고 다시 만들지(P) 않아서 그 구간이 그냥 정의되지 않은 바이트로 남아버리는 것.
- Edit function 대화상자에서 End address를 다른 함수 영역과 겹치게 입력해서 적용이 거부되는데, 왜 안 되는지 모르고 반복 시도하는 것 — 겹치는 함수부터 먼저 정리해야 한다.
- non-return 표시 문제로 함수가 잘렸는데, 원인을 모른 채 계속 E로 끝만 늘렸다가 다음 재분석 때 다시 원래대로 잘리는 것을 반복하는 것 — 근본 원인(non-return 플래그)을 고쳐야 재발하지 않는다.

## 막혔을 때 다음 체크
- 함수 경계는 맞는 것 같은데 디컴파일이 여전히 실패한다면 → REV-0152
- 함수 안에 회색/빨간 `db XX` 정의되지 않은 바이트가 보인다면 → REV-0155(이 문제부터 먼저 해결하는 것이 순서상 맞는 경우가 많음)
- 스택 변수 오프셋이 여전히 이상하다면 → REV-0153
- Functions 창 자체의 열 구성/정렬/필터 사용법이 헷갈린다면 → REV-0143

## 미니 예제
Functions 창에서 `sub_401500`이 겨우 5바이트짜리로 표시되고, 그 바로 뒤 주소에 `sub_401505`라는 이름 없는 함수가 이어져 있다고 하자. `sub_401500`의 마지막 명령어를 보니 `call _exit`이고, 그 CALL 이후 아무 RET 없이 바로 함수가 끝나 있다. 이는 IDA가 `_exit`를 non-return으로 인식하지 못했거나, 반대로 `_exit` 호출 뒤에 실제로는 도달 가능한 코드가 있는데 IDA가 그 경로를 놓친 상황일 수 있다. 이럴 때는 `_exit` 호출 직후 주소로 이동해 그 코드가 실제로 다른 로직(예: 에러 처리 후 복귀)인지 확인하고, 맞다면 `sub_401500`을 Edit function으로 열어 End address를 그 로직이 끝나는 지점(다음 함수 시작 직전)까지 늘려준다. 반대로 그 뒤 코드가 완전히 별개의 함수라면 그대로 두고 이름만 붙여주면 된다.

## 출처/검증
- `E`(Set function end) 단축키, Edit function 대화상자의 시작/끝 주소 편집 제약(다른 청크와 겹칠 수 없음, 세그먼트 경계를 넘을 수 없음 등), "Append function tail" / "Remove function tail" 명령, 그리고 간단 재생성 절차(함수 삭제 후 P로 재생성)는 Hex-Rays 공식 블로그 "Igor's Tip of the Week #127: Changing function bounds"(2024년) 및 공식 문서 "IDA View" 메뉴 레퍼런스 기준이다.
- 함수 청크(메인 청크/꼬리 청크) 개념은 IDA의 오래전부터 존재하는 공식 기능으로, 여러 버전의 공식 문서에서 일관되게 설명된다.
- 다만 Functions 창에서 청크가 정확히 어떤 색/표기로 구분되는지는 IDA 버전과 테마 설정에 따라 달라질 수 있으므로, 실제 화면에서 다르게 보이더라도 당황하지 말고 View → Open subviews → Functions의 열 구성을 직접 확인할 것을 권장한다. 이 글은 실제 설치된 IDA 환경에서 직접 재현 검증하지 못했다.
