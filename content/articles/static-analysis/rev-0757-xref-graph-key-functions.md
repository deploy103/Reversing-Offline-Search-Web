## 한 줄 요약
Call Graph(REV-0166)가 "함수가 함수를 부르는 관계"만 보여주는 반면, Cross Reference Graph(참조 그래프)는 코드→코드뿐 아니라 **코드→데이터, 데이터→코드** 참조까지 한 그림 안에 포함하므로, 전역 변수·문자열·상수 테이블을 매개로 서로 얽혀 있는 진짜 핵심 함수를 콜 그래프만으로는 놓치는 경우까지 찾아낼 수 있다.

## 언제 검색해야 하나
- REV-0166의 콜 그래프로 훑어봤는데도 핵심 로직이 뚜렷하게 안 좁혀질 때, 특히 함수들이 직접 서로를 호출하기보다 **공용 전역 변수**를 통해 간접적으로 상태를 주고받는 구조일 때
- 특정 전역 변수(예: 점수, 상태 플래그, 룩업 테이블)를 읽고 쓰는 모든 함수를 한 번에 찾고 싶을 때
- 함수 포인터 테이블처럼 코드가 데이터를 참조하고, 그 데이터가 다시 다른 코드를 가리키는 간접 호출 구조를 다뤄야 할 때

## 핵심 개념
Cross Reference(교차 참조, XREF)는 "주소 A가 주소 B를 참조한다"는 관계 전체를 뜻하며, 참조의 종류는 크게 두 가지로 나뉜다.

- **코드 참조(Code Xref)**: `call`/`jmp`로 다른 코드 주소를 실행 흐름상 참조. 이것만 모은 것이 REV-0166의 콜 그래프다.
- **데이터 참조(Data Xref)**: 코드가 전역 변수, 문자열, 테이블 같은 데이터 주소를 읽거나 쓰기 위해 참조. 반대로 데이터(예: 함수 포인터 테이블 안의 값)가 코드 주소를 가리키는 경우도 데이터 참조에 포함된다.

Cross Reference Graph는 이 두 종류를 함께 그린 그래프다. IDA에서는 `X` 키(REV-0145)로 여는 Xrefs 목록이 코드/데이터 구분 없이 나열되며, **View → Graphs → Xrefs to/from**을 그래프로 그리면 이 관계가 시각화된다. Ghidra는 함수/데이터 심볼 위에서 우클릭 → **Show References**로 코드+데이터 참조를 함께 확인할 수 있고, 데이터 심볼에는 별도로 **Data Type Manager**와 연동된 참조 정보가 붙는다.

콜 그래프만으로는 "A가 B를 직접 호출하지 않지만, 둘 다 같은 전역 변수 `g_score`를 읽고 쓴다"는 관계가 드러나지 않는다. 하지만 참조 그래프는 `g_score`라는 노드를 중심에 두고 이를 참조하는 모든 함수를 한 번에 보여주므로, "이 변수를 건드리는 함수들이 사실 하나의 상태 머신을 이루고 있다"는 구조를 발견할 수 있다. 이는 REV-0759(Data Xref로 전역 변수 사용처 전부 찾기)와 밀접하게 연결되는 관점이지만, 이 문서는 그 데이터 노드를 포함한 **전체 그래프 형태**로 핵심 함수를 좁히는 데 초점을 둔다.

## 화면/코드에서 보이는 징후
- 콜 그래프(REV-0166)로는 서로 무관해 보이는 함수 여러 개가, 사실 같은 전역 변수나 룩업 테이블을 공유하고 있다.
- 함수 포인터 배열이 데이터 섹션에 있고, 여러 곳에서 이 배열의 인덱스를 계산해 간접 호출(`call [rax*8+table]` 형태)하는 코드가 보인다.
- 특정 문자열/상수를 참조하는 함수가 하나가 아니라 여러 개라 REV-0163/0165 단서만으로는 어떤 함수가 진짜 핵심인지 판단이 안 선다.

## 가장 먼저 할 것
의심되는 전역 데이터(변수, 테이블, 문자열)나 함수 하나를 기준으로 잡고, IDA는 `X`(Xrefs 목록) 또는 View → Graphs → Xrefs to/from, Ghidra는 우클릭 → Show References로 코드/데이터 참조를 모두 나열해본다.

## 단계별 절차
1. 콜 그래프(REV-0166)만으로 부족하다고 판단되면, 의심되는 함수 또는 데이터 심볼 하나를 기준으로 정한다.
2. IDA: 해당 주소에서 `X`를 눌러 코드/데이터 참조 목록을 확인한다. 더 큰 그림이 필요하면 View → Graphs → Xrefs to(누가 나를 참조하는가), Xrefs from(내가 누구를 참조하는가), 또는 User xrefs chart로 결합해서 본다.
3. Ghidra: 심볼 위에서 우클릭 → Show References to(또는 References from)로 목록을 확인하고, 필요하면 Function Call Graph와 나란히 띄워 코드/데이터 참조를 비교한다.
4. radare2: `axt`(코드/데이터 참조 모두 포함, REV-0751)로 텍스트 목록을 얻고, 필요하면 `agf` 등 그래프 명령으로 시각화한다.
5. 참조 목록에서 같은 데이터 노드를 공유하는 함수들을 그룹으로 묶는다.
6. 그룹 안에서 참조 횟수(들어오는 화살표 수)가 유난히 많은 함수/데이터 노드를 "허브"로 표시하고, 반대로 참조가 한 곳뿐인 노드를 "전용 로직" 후보로 표시한다.
7. 최종 후보를 REV-0158/REV-0146으로 정밀 분석하며, 그룹 전체의 역할(예: 상태 머신, 이벤트 핸들러 테이블)을 정리한다.

## 명령어/단축키
- IDA: `X`(Xrefs 목록), View → Graphs → Xrefs to / Xrefs from / User xrefs chart
- Ghidra: 우클릭 → Show References to/from, Window → Function Call Trees(코드 참조 중심)
- radare2: `axt`(xref to), `axf`(xref from), `agf`(현재 함수 그래프를 ASCII로 출력)

## 출력 해석
- 하나의 데이터 노드에 참조가 여러 함수로부터 몰려 있다면, 그 데이터는 프로그램 전역에서 공유되는 상태(state)일 가능성이 크다 — 게임의 점수, 파서의 현재 상태, 전역 설정 플래그 등이 전형적이다.
- 코드 참조는 없고 데이터 참조만 있는 노드(예: 룩업 테이블)는 계산에 쓰이는 상수 데이터일 뿐 실행 로직은 아니다.
- 데이터 참조로 묶인 함수 그룹이 서로 논리적으로 무관해 보인다면, 그 데이터는 단순 전역 버퍼(예: 공용 입력 버퍼)일 수 있으므로 그룹 전체를 하나의 로직으로 오해하지 않도록 주의한다.

## 흔한 실수
- 콜 그래프만 보고 "이 함수들은 서로 무관하다"고 성급히 결론짓는 것 — 데이터를 매개로 한 간접적 연결을 놓칠 수 있다.
- 함수 포인터 테이블을 통한 간접 호출을 코드 참조만으로 찾으려다 실패하는 것 — 이런 구조는 데이터 참조(테이블 자체)까지 함께 봐야 전체 호출 대상을 알 수 있다.
- 참조가 많다고 무조건 핵심 함수라고 단정하는 것 — 로깅, 메모리 할당처럼 범용 유틸리티 데이터/함수도 참조가 많을 수 있다(REV-0166의 흔한 실수와 동일한 함정).
- IDA/Ghidra의 참조 그래프 기능을 켜지 않고 목록(텍스트)만 보다가, 관계가 복잡해지는 순간 손으로 관계도를 그리려 드는 것 — 그래프 기능을 적극 활용하는 것이 훨씬 빠르다.

## 막혔을 때 다음 체크
- 코드 호출 관계만 필요하면 → REV-0166 함수 Call Graph로 핵심 로직 좁히기
- 특정 전역 변수 하나의 모든 사용처만 정밀하게 보고 싶다면 → REV-0759 Data Xref로 전역 변수 사용처 전부 찾기
- radare2로 같은 작업을 커맨드라인에서 하고 싶다면 → REV-0751 radare2로 함수 목록과 XREF 확인하기(afl, axt)
- 재귀/사이클 구조까지 확인하려면 → REV-0758 콜 그래프에서 재귀/사이클 함수 알아보기

## 미니 예제
어떤 문제에서 `g_state`라는 전역 변수를 IDA에서 `X`로 확인했더니, `init_state`, `update_state`, `check_state`, `print_state` 네 함수가 모두 이 변수를 참조하고 있었다. 콜 그래프만 봤을 때는 이 네 함수가 `main`에서 각각 독립적으로 호출되는 것처럼 보여 서로 무관해 보였지만, 참조 그래프로 `g_state`를 중심에 놓고 보니 사실 이 넷이 하나의 상태 머신(초기화→갱신→검증→출력)을 이루고 있다는 것이 드러났다. 이후 분석은 네 함수를 개별로 보지 않고 `g_state` 값의 변화를 따라가는 방식으로 전환해 훨씬 빠르게 로직을 파악할 수 있었다.

## 출처/검증
- 코드 참조와 데이터 참조를 함께 다루는 Cross Reference 개념: IDA 공식 문서(Xrefs, View → Graphs)와 Ghidra 공식 문서(References, Show References) 공통 기준.
- 함수 포인터 테이블을 통한 간접 호출 분석에 데이터 참조가 필요하다는 설명은 두 도구 문서에서 공통적으로 다루는 "indirect call/data reference" 개념을 기준으로 정리했다.
- 이 문서는 실기 화면 재현 없이 공식 문서와 일반적인 사용 패턴을 기준으로 작성되었다(2026-09-09 검증).
