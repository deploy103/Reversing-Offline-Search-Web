## 한 줄 요약
IDA에서 커서를 함수 이름, 전역 변수, 지역/스택 변수, 레지스터 변수, 레이블 위에 놓고 **N**을 누르면 그 항목의 이름을 바꿀 수 있으며, 이 이름은 디스어셈블리 뷰와 Pseudocode(F5) 창, Functions 창, Xrefs 목록에 동시에 반영된다.

## 언제 검색해야 하나
- `sub_401230` 같은 자동 생성된 이름을 의미 있는 이름으로 바꾸고 싶을 때
- Pseudocode 창에서 `v3`, `a1` 같은 변수 이름을 바꾸고 싶은데 방법을 모를 때
- 이름을 바꿨는데 디스어셈블리에는 반영되고 Pseudocode에는 안 보이는(또는 반대) 것 같아 헷갈릴 때
- CTF 문제 풀이 중 "이 함수가 플래그 검증 함수 같다"는 가설을 세우고 나중에 알아보기 쉽게 표시해두고 싶을 때

## 핵심 개념
IDA에서 이름을 붙일 수 있는 대상은 크게 다섯 가지다.

1. **함수 이름** — 디스어셈블리에서 함수 시작 줄(`sub_401230:` 같은 레이블) 또는 Pseudocode 상단의 함수 선언부에 커서를 놓고 N.
2. **전역 변수/데이터** — `.data`, `.bss` 등에 있는 전역 심볼(`dword_40A000` 등)에 커서를 놓고 N.
3. **지역 변수(스택 변수)** — Pseudocode 창에서 `v3`, `a1` 같은 변수 이름에 커서를 놓고 N. 디스어셈블리 뷰에서도 스택 오프셋(`[ebp+8]` 등)에 커서를 놓고 N으로 스택 변수 이름을 바꿀 수 있다.
4. **레지스터 변수** — Hex-Rays가 레지스터 하나를 지역 변수로 취급한 경우(`v1 = eax;` 형태), Pseudocode 창에서만 이름을 바꿀 수 있다. 디스어셈블리 뷰에는 레지스터 자체(`eax`, `rdi`)가 그대로 나오기 때문에, 레지스터에 할당된 변수는 **디스어셈블리에서는 이름을 바꿀 수 없고 Pseudocode 창에서만 가능**하다.
5. **레이블(코드 위치)** — 분기 대상 주소(`loc_401050` 등)에 커서를 놓고 N.

중요한 점은 **디스어셈블리 뷰와 Pseudocode 창이 같은 데이터베이스를 공유**한다는 것이다. 함수 이름, 전역 변수, 스택 변수처럼 IDA 데이터베이스 레벨에 저장되는 이름은 어느 창에서 바꾸든 다른 창에도 즉시(또는 다음 F5 새로고침 시) 반영된다. 다만 레지스터 변수처럼 Hex-Rays가 디컴파일 과정에서만 만들어내는 임시 개념은 Pseudocode 창에만 존재하므로 거기서만 바꿀 수 있다.

큰 함수를 여러 개 리네임할 계획이라면, 매번 F5 디컴파일이 끝나길 기다리는 것보다 **디스어셈블리 뷰에서 먼저 스택 변수와 함수 이름을 정리한 뒤, 마지막에 F5를 눌러 한 번에 Pseudocode를 새로고침**하는 편이 빠르다.

## 화면/코드에서 보이는 징후
- 함수 목록(Functions 창)에 `sub_401230`, `sub_401450`처럼 의미 없는 이름이 잔뜩 나열되어 있다.
- Pseudocode 창의 변수가 `v1`, `v2`, `a1`, `a2`처럼 번호로만 구분된다.
- 문자열 창(Shift+F12)이나 Xrefs 목록에서도 이름을 바꾸지 않은 함수는 여전히 `sub_` 접두사로만 표시된다.

## 가장 먼저 할 것
바꾸려는 대상(함수/전역 변수/지역 변수/레지스터 변수/레이블) 위에 정확히 커서를 놓는다. IDA는 커서가 어떤 토큰 위에 있는지에 따라 다른 대상을 리네임하므로, 줄 전체가 아니라 이름 글자 자체를 클릭하는 것이 중요하다.

## 단계별 절차

**1) 함수 이름 바꾸기**

디스어셈블리 뷰에서 함수 시작 부분(`sub_401230 proc near` 줄 또는 함수 이름 텍스트) 위에 커서를 두고 **N**을 누른다. 또는 Pseudocode 창 맨 위 함수 선언 줄(`int __cdecl sub_401230(...)`)에서 함수 이름 부분에 커서를 놓고 N을 누른다. "Rename" 대화상자(또는 인라인 입력 박스)가 뜨고, 새 이름을 입력하면 즉시 그 함수를 가리키는 모든 CALL 명령어, Xrefs 목록, Functions 창의 표시가 새 이름으로 바뀐다.

**2) 전역 변수 이름 바꾸기**

디스어셈블리에서 전역 데이터 참조(`mov eax, dword_40A000`)의 `dword_40A000` 부분에 커서를 놓고 N. 이 데이터가 정의된 위치(`.data` 섹션 내 실제 주소)로 가서 눌러도 되고, 참조하는 코드 줄에서 눌러도 같은 항목이 리네임된다.

**3) 지역/스택 변수 이름 바꾸기 (디스어셈블리에서)**

함수 프롤로그 부분에서 `[ebp+8]`, `[ebp-0Ch]` 같은 스택 오프셋 표현 위에 커서를 놓고 N을 누르면 그 스택 변수 전체(함수 안에서 그 오프셋을 참조하는 모든 위치)의 이름이 한 번에 바뀐다.

**4) 지역/레지스터 변수 이름 바꾸기 (Pseudocode에서)**

Pseudocode 창에서 `v3`처럼 자동 생성된 변수 이름 위에 커서를 놓고 N. 이름 입력 후 Enter를 누르면 그 변수가 함수 안에서 등장하는 모든 줄에서 한꺼번에 새 이름으로 바뀐다. 이는 스택 변수든 레지스터 변수든 동일하게 동작한다.

**5) 레이블 이름 바꾸기**

분기(JMP/Jcc) 대상 주소인 `loc_401050:` 레이블 위에 커서를 놓고 N. 반복문 안에서 여러 번 점프하는 지점에 `loop_start` 같은 이름을 붙여두면 그래프 뷰나 어셈블리를 읽을 때 훨씬 수월하다.

**6) CTF 트리아지에서 실전 활용**

문자열 창(Shift+F12)에서 `"Correct!"`나 `"wrong flag"` 같은 문자열을 찾고 X(Xrefs)로 그 문자열을 참조하는 함수로 이동했다면, 그 함수가 플래그 검증 로직일 가능성이 높다. 아직 로직을 다 이해하지 못했더라도 함수 이름 위에서 N을 눌러 일단 `check_flag_maybe`처럼 가설을 담은 이름으로 바꿔두면, 이후 이 함수를 호출하는 다른 함수들의 Pseudocode에서도 `check_flag_maybe(...)`로 바로 표시되어 전체 흐름을 훨씬 빠르게 파악할 수 있다. 나중에 로직을 다 이해하면 다시 N을 눌러 `check_flag`처럼 확정된 이름으로 정리하면 된다.

## 명령어/단축키
- **N**: 함수/전역 변수/지역 변수/레지스터 변수/레이블 이름 바꾸기 (디스어셈블리·Pseudocode 공통)
- **Shift+N**(Quick Rename, 최신 버전 Hex-Rays 디컴파일러): 특정 대입/표현식에 등장하는 변수 이름을 문맥에 맞게 자동 전파하는 보조 기능. 버전에 따라 존재하지 않을 수 있으므로 우클릭 메뉴에 "Quick Rename" 항목이 보이는지로 지원 여부를 확인한다.
- 우클릭 → **Rename**: N과 동일한 동작을 메뉴로 실행
- 이름을 지우고 자동 이름으로 되돌리려면 입력란을 빈 문자열로 두고 확인(또는 우클릭 → Rename 후 빈 값 입력)

## 출력 해석
- 이름 입력 후 Enter를 누르면 대화상자가 닫히고 해당 위치의 텍스트가 즉시 새 이름으로 바뀐다. Pseudocode 창이 열려 있다면 F5를 다시 누르지 않아도 대부분 자동으로 갱신되지만, 갱신이 안 된 것처럼 보이면 Pseudocode 창을 클릭한 뒤 F5를 눌러 강제로 새로고침한다.
- 유효하지 않은 이름(공백, 일부 특수문자 포함)을 입력하면 IDA가 그 문자를 자동으로 밑줄(`_`) 등으로 치환하거나 입력 자체를 거부한다. 예를 들어 `check flag`처럼 공백이 들어간 이름은 `check_flag`로 자동 치환되는 식이다. 이름 규칙은 기본적으로 C 식별자 규칙(영문자/숫자/밑줄, 숫자로 시작 불가)을 따른다고 생각하면 안전하다.
- 이미 존재하는 이름과 중복되면 IDA가 경고를 띄우거나 자동으로 접미사를 붙인다. 함수 이름은 데이터베이스 전체에서 고유해야 한다.

## 흔한 실수
- 스택 변수를 바꾸려다가 커서를 명령어의 다른 부분(레지스터, 니모닉)에 놓고 N을 눌러 의도하지 않은 대상이 리네임되는 것 — 반드시 바꾸려는 토큰 정확히 위에 커서를 놓는다.
- 레지스터 변수는 디스어셈블리 뷰에서 리네임이 안 된다는 걸 모르고 계속 시도하는 것 — 레지스터 변수는 Pseudocode 창에서만 이름을 바꿀 수 있다.
- 이름에 한글을 사용하는 것 — IDA 식별자는 기본적으로 ASCII를 기준으로 하므로 한글 이름은 깨지거나 거부될 수 있다. 한글로 메모를 남기고 싶다면 이름 대신 주석(`:` 단축키 또는 우클릭 → Add comment)을 사용한다.
- 함수 이름만 바꾸고 인자 이름(`a1`, `a2`)은 그대로 두는 것 — 함수의 역할을 알아냈다면 인자 이름도 함께 정리해야 나중에 그 함수를 호출하는 다른 코드를 읽을 때 인자의 의미가 바로 보인다.

## 막혔을 때 다음 체크
- N을 눌러도 아무 반응이 없다면 → 커서가 리네임 가능한 토큰(이름/레이블/변수) 위에 정확히 있는지, 혹은 읽기 전용 상태(예: 원격 디버깅 중 특정 뷰)인지 확인한다.
- 이름을 바꿨는데 다른 곳에서는 옛날 이름이 계속 보인다면 → 그 창을 새로고침(F5는 Pseudocode, 디스어셈블리는 보통 자동 갱신)하거나, 애초에 서로 다른 항목(예: 같은 이름의 지역 변수가 다른 함수에도 있는 경우)을 착각한 것이 아닌지 확인한다.
- 함수 이름을 의미 있게 바꾸기 전에 함수의 역할부터 파악하고 싶다면 → REV-0146(F5 디컴파일)과 REV-0145(Xrefs)로 호출 관계와 인자 흐름을 먼저 살펴본다.
- 함수 인자/반환 타입까지 정리하고 싶다면 → REV-0148(Y로 타입 지정하기)로 넘어간다.

## 미니 예제
디스어셈블리에서 다음과 같은 함수가 있다고 하자.

```asm
sub_401230 proc near
    push    ebp
    mov     ebp, esp
    mov     eax, [ebp+8]
    cmp     eax, 1234h
    jz      loc_401250
    ...
```

여기서 함수 이름 `sub_401230` 위에 커서를 놓고 N을 누르고 `check_magic`을 입력하면, 이 함수를 호출하는 다른 모든 곳(예: `call sub_401230`)이 즉시 `call check_magic`으로 바뀐다. 이어서 `[ebp+8]` 위에서 N을 눌러 `input_value`로 바꾸면, 함수 안의 모든 `[ebp+8]` 참조가 `input_value`로 통일된다. Pseudocode(F5)를 열면 다음처럼 보인다.

```c
int __cdecl check_magic(int input_value)
{
    if ( input_value == 0x1234 )
        ...
}
```

## 출처/검증
- N 단축키가 함수/지역 변수/전역 항목/구조체 필드/레이블에 공통 적용된다는 점과 "커서가 있는 항목을 리네임하며, 대상을 판단할 수 없으면 현재 함수를 리네임한다"는 동작: Hex-Rays 공식 문서(Rename 명령어 설명, docs.hex-rays.com) 기준.
- 레지스터 할당 지역 변수는 디스어셈블리가 아닌 Pseudocode 창에서만 리네임 가능하다는 점, 디스어셈블리에서 먼저 이름을 정리한 뒤 F5로 한 번에 새로고침하는 워크플로: Hex-Rays 공식 블로그 "Igor's tip of the week" 시리즈(Renaming and retyping in the decompiler, Renaming registers) 기준.
- Shift+N(Quick Rename)은 비교적 최신 버전(IDA 7.6 전후 자동 리네임 개선과 함께 도입)에 해당하는 기능으로, 구버전에는 없을 수 있으므로 실제 설치된 IDA에서 우클릭 메뉴로 존재 여부를 재확인할 것을 권장한다.
- 이 문서는 2026-09-08 기준 공개된 Hex-Rays 공식 문서/블로그 검색 결과를 바탕으로 작성했으며, 실제 설치된 IDA 버전에서 메뉴/단축키가 다르게 보이면 그 버전의 우클릭 컨텍스트 메뉴를 우선 신뢰할 것.
