## 한 줄 요약
IDA의 **Structures** 서브뷰(`Shift+F9`)에서 구조체를 직접 정의하고, 그 타입을 전역 데이터·Pseudocode 지역 변수·심지어 함수의 스택 프레임에 적용하면 `*(int *)(a1 + 8)` 같은 raw 오프셋 표현이 `a1->hp`처럼 필드 이름으로 바뀌어 코드 흐름을 훨씬 빠르게 이해할 수 있다.

## 언제 검색해야 하나
- 어떤 포인터 변수가 반복적으로 `+0`, `+4`, `+8` 같은 오프셋으로 접근되는데, 이게 하나의 구조체인 것 같아서 필드 단위로 정리하고 싶을 때
- REV-0148(Y로 타입 지정하기)에서 구조체 포인터로 캐스팅하려 했는데, 그 전에 구조체 자체를 어떻게 새로 만드는지 몰라서 막혔을 때
- 함수의 스택 프레임 여러 지역 변수가 사실 하나의 지역 구조체(local struct)인 것 같은데, 어떻게 스택 프레임을 구조체로 묶는지 모를 때
- C 헤더 파일(`.h`)을 갖고 있고, 그 안의 구조체 정의를 IDA에 그대로 가져와 쓰고 싶을 때

## 핵심 개념

### 구조체를 어디서 관리하는가
IDA에서 구조체는 **Structures 서브뷰**(`View → Open subviews → Structures`, 단축키 `Shift+F9`)에서 관리한다. 이 창은 데이터베이스 전역에서 재사용 가능한 구조체 타입의 목록이며, 여기서 만든 구조체는 Pseudocode의 `Y`(Set type, REV-0148) 명령에서 타입 이름으로 바로 참조할 수 있다. 참고로 **Local Types 서브뷰**(`Shift+F1`, REV-0737에서 자세히 다룸)에서도 구조체를 텍스트로 선언할 수 있는데, 두 창은 결국 같은 타입 정보를 공유하지만 Local Types에서 C 문법으로 직접 구조체를 선언하면 정렬(alignment)이 예상과 다르게 처리될 수 있으므로, 패딩이 중요한 구조체는 Structures 창에서 필드를 하나씩 만드는 편이 더 안전하다.

### 새 구조체 만들기
Structures 창에서 `Ins` 키(또는 우클릭 → **Add struct type...**)를 누르면 새 구조체 이름을 입력하는 대화상자가 뜬다. 이름을 정하고 확인하면 빈 구조체가 목록에 추가되고, 그 구조체 안에서 다시 `Ins`(또는 우클릭 → **Add member...**)를 눌러 필드를 하나씩 추가한다. 각 필드는 이름, 타입(예: `int`, `char[16]`, `Player *`처럼 다른 구조체에 대한 포인터도 가능), 필요하면 배열 크기를 지정한다.

### C 헤더로부터 한 번에 가져오기
이미 구조체 정의가 담긴 C 헤더 파일이 있다면, 하나씩 손으로 만들 필요 없이 `File → Load file → Parse C header file...` 메뉴로 헤더 전체를 파싱해서 그 안의 모든 `struct`/`typedef`/`enum` 정의를 한 번에 Local Types(그리고 Structures)에 가져올 수 있다. CTF에서 소스 일부(헤더만)가 제공되는 문제라면 이 방법이 훨씬 빠르다.

### 오프셋 패턴을 보고 구조체 레이아웃 추정하기
소스나 헤더가 전혀 없다면, 디컴파일 결과에서 같은 포인터 변수에 반복적으로 등장하는 오프셋들(`+0`, `+4`, `+8`, `+0xC` 등)을 모아 각 오프셋의 접근 크기(바이트/워드/더블워드인지)와 사용 패턴(비교값, 초기화값)을 보고 필드 타입을 추정한다. 크기가 안 맞는 오프셋 사이에 빈 구간(gap)이 있다면, 그 자리에 `char pad[N]` 같은 채움 필드를 넣어 구조체 전체 크기를 실제 크기(예: `malloc` 호출 인자로 봤던 크기, REV-0654/REV-0655의 힙 청크 크기 참고)와 맞춰야 한다.

### 스택 프레임을 구조체로 다루기
함수 안의 여러 지역 변수가 실제로는 하나의 지역 구조체(예: 파서 상태를 담은 임시 구조체)인 경우, IDA는 함수마다 자동으로 만들어지는 스택 프레임 구조체(디스어셈블리 뷰에서 `Ctrl+K` 또는 함수 헤더 부분 더블클릭으로 열람 가능)를 갖고 있다. 이 스택 프레임 구조체 안에서도 Structures 창과 동일한 방식(`Ins`로 멤버 추가, 필드 타입 지정)으로 필드를 정리할 수 있으며, 서로 인접한 여러 지역 변수를 하나의 하위 구조체로 묶어 넣을 수도 있다.

### 적용까지의 흐름
구조체를 만드는 것 자체는 아직 아무 코드에도 영향을 주지 않는다. 실제로 오프셋 표현을 필드 접근으로 바꾸려면, REV-0148에서 다룬 대로 전역 변수/Pseudocode 변수 위에서 `Y`를 눌러 `구조체이름 *` 형태로 타입을 지정해야 한다. 즉 이 문서(구조체 정의)와 REV-0148(타입 적용)은 항상 짝을 이루는 절차다.

## 화면/코드에서 보이는 징후
- Pseudocode에 `*(int *)(a1 + 8)`, `*(_DWORD *)(a1 + 0x14)`처럼 같은 변수에 대한 반복적인 오프셋 접근이 보인다.
- 디스어셈블리에서 `[eax+0]`, `[eax+4]`, `[eax+8]`처럼 연속된 작은 오프셋들이 한 레지스터 기준으로 반복된다.
- `malloc(0x18)`처럼 고정 크기 할당 직후, 반환된 포인터가 곧바로 여러 오프셋으로 나뉘어 쓰인다.

## 가장 먼저 할 것
문제의 포인터 변수가 참조하는 모든 오프셋과 각 오프셋에서의 접근 크기(바이트/워드/더블워드/쿼드워드)를 먼저 종이나 메모장에 나열한다. 이 목록이 구조체 필드 목록의 초안이 된다.

## 단계별 절차
1. `Shift+F9`로 Structures 창을 연다.
2. `Ins`(또는 우클릭 → **Add struct type...**)로 새 구조체 이름(예: `Player`)을 만든다.
3. 만든 구조체를 더블클릭해 안으로 들어간 뒤, `Ins`(또는 우클릭 → **Add member...**)로 앞서 정리한 오프셋 순서대로 필드를 하나씩 추가한다. 오프셋 사이에 빈틈이 있으면 `char pad_N[크기]` 형태의 채움 필드로 메운다.
4. 이미 C 헤더가 있다면 3번 과정 대신 `File → Load file → Parse C header file...`로 헤더를 통째로 불러온다.
5. 구조체가 완성되면, 실제로 적용할 전역 변수/Pseudocode 변수 위에서 `Y`를 누르고 `Player *`처럼 포인터 타입으로 지정한다(REV-0148).
6. 스택 지역 변수 여러 개를 하나의 구조체로 묶고 싶다면, 함수 디스어셈블리에서 `Ctrl+K`(스택 프레임 보기)를 눌러 자동 생성된 프레임 구조체를 열고, 같은 방식으로 필드를 정리하거나 하위 구조체를 삽입한다.
7. F5를 다시 눌러(또는 자동 갱신을 기다려) Pseudocode가 필드 이름 기준으로 바뀌었는지 확인한다.

## 명령어/단축키
- `Shift+F9`: Structures 서브뷰 열기
- Structures 창에서 `Ins`: 새 구조체 추가(구조체 목록에서) 또는 새 멤버 추가(구조체 안에서)
- 우클릭 → **Add struct type...** / **Add member...**: `Ins`와 동일한 동작을 메뉴로 실행
- `File → Load file → Parse C header file...`: C 헤더 전체를 구조체/typedef/enum으로 일괄 가져오기
- 함수 디스어셈블리에서 `Ctrl+K`: 현재 함수의 스택 프레임 구조체 열기
- `Y`: 전역/지역 변수에 구조체 포인터 타입 적용(REV-0148)

## 출력 해석
- 구조체를 만들고 필드를 추가하면 Structures 창에 오프셋, 크기, 타입, 이름이 표로 정리되어 보인다 — 이 표의 오프셋 열이 실제 메모리 레이아웃과 일치하는지 항상 재확인한다.
- Pseudocode에서 변수에 구조체 포인터 타입을 적용한 뒤 `field_8`처럼 자동 생성된 이름이 보인다면, 그 필드에 아직 의미 있는 이름을 붙이지 않은 것이다 — Structures 창으로 돌아가 이름을 정리한다.
- 구조체 전체 크기가 실제 할당 크기(`malloc` 인자 등)와 다르면 필드 배치나 패딩 계산이 잘못된 것이므로 오프셋 목록을 다시 검토해야 한다.

## 흔한 실수
- 오프셋 사이의 빈틈(패딩)을 무시하고 필드를 딱 붙여서 만들어, 이후 필드들의 오프셋이 실제와 어긋나는 것.
- Local Types 창에서 C 문법으로 구조체를 선언했는데 컴파일러의 실제 정렬 규칙과 안 맞아서(예: 원래 1바이트 정렬로 컴파일된 구조체) 필드 오프셋이 밀리는 것 — 이런 경우 REV-0737에서 다루는 `#pragma pack` 관련 주의사항을 참고해야 한다.
- 구조체는 만들었는데 REV-0148의 `Y` 단계를 빼먹어서 실제 코드에는 여전히 raw 오프셋만 보이는 것.
- 필드 타입을 크기만 맞추고(`int`) 실제 의미(포인터인지 플래그 비트필드인지)는 무시해서, 나중에 다시 봤을 때 필드 이름과 실제 쓰임이 안 맞는 것.

## 막혔을 때 다음 체크
- 구조체는 만들었는데 실제로 변수에 적용하는 방법이 헷갈린다면 → REV-0148 IDA Y로 타입 지정하기
- 구조체 정렬/패딩 문제로 Local Types와 Structures 결과가 다르게 나온다면 → REV-0737 IDA Local Types 창 활용하기
- 매직 넘버가 섞인 필드가 있다면 → REV-0735 IDA에서 Enum을 정의해서 매직넘버를 이름으로 바꾸기
- 구조체 참조 표기 자체를 빠르게 요약해서 보고 싶다면 → REV-0721 IDA 구조체(Structure) 정의 빠른 참조

## 미니 예제
다음과 같이 raw 오프셋으로만 보이는 Pseudocode가 있다고 하자.

```c
int __cdecl sub_401500(int a1)
{
  if ( *(int *)(a1 + 8) > 100 )
    *(int *)(a1 + 12) = 0;
  return *(int *)(a1 + 8);
}
```

`Shift+F9`로 Structures 창을 열고 `Ins`로 `Player`라는 이름의 새 구조체를 만든 뒤, 그 안에서 다시 `Ins`를 세 번 눌러 `int id`(오프셋 0), `int hp`(오프셋 4), `int mp`(오프셋 8)... 처럼 필드를 채운다(이 예제에서는 오프셋 8과 12가 쓰였으므로 `id`, `hp` 뒤에 오프셋 8=`mp`, 오프셋 12=`atk` 순으로 정리한다고 가정). 구조체가 완성되면 `a1` 위에서 `Y`를 누르고 `Player *`를 입력한다.

```c
int __cdecl sub_401500(Player *a1)
{
  if ( a1->mp > 100 )
    a1->atk = 0;
  return a1->mp;
}
```

## 출처/검증
- Structures 서브뷰(`Shift+F9`)와 `Add struct type...`/`Add member...`(단축키 `Ins`) 조작: Hex-Rays 공식 사용자 가이드(Subviews, Types 문서) 기준.
- `File → Load file → Parse C header file...`로 C 헤더의 구조체/typedef/enum을 일괄 가져오는 기능: Hex-Rays 공식 문서(Types) 기준.
- Local Types에서 C 문법으로 구조체를 선언할 때 정렬(alignment) 처리가 Structures 창과 다르게 동작할 수 있다는 실전 팁: 리버싱 실무 블로그에서 반복적으로 언급되는 caveat이며, 정확한 재현 조건은 IDA 버전에 따라 다를 수 있어 실제 환경에서 재확인이 필요하다.
- 함수 스택 프레임 구조체를 `Ctrl+K`로 여는 동작: Hex-Rays 공식 단축키 레퍼런스 기준.
