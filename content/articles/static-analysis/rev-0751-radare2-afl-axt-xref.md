## 한 줄 요약
radare2에서 `afl`로 전체 함수 목록을 뽑아 크기·이름 기준으로 후보를 추리고, 그 후보 주소에 커서를 옮긴 뒤 `axt`로 "누가 이 함수를 호출하는가(xref to)"를 확인하는 두 명령의 조합만으로, GUI 없이도 큰 바이너리에서 핵심 로직 위치를 상당히 빠르게 좁힐 수 있다.

## 언제 검색해야 하나
- SSH로 접속한 서버나 GUI가 없는 CTF 환경에서 radare2만으로 분석해야 하는데, 함수가 너무 많아 `afl` 결과만 봐서는 어디부터 봐야 할지 모를 때
- 특정 함수(예: 문자열 비교, 암호화 루프)를 발견했는데, 이 함수가 프로그램의 어느 지점에서 호출되는지 GUI의 더블클릭 없이 커맨드라인으로 확인해야 할 때
- IDA의 Xrefs(REV-0145)나 Ghidra의 XREF(REV-0160) 개념을 radare2 커맨드라인에서 그대로 재현하고 싶을 때

## 핵심 개념
radare2의 명령 체계는 접두 문자로 계열이 나뉜다(REV-0292). `a`로 시작하는 명령은 analysis(분석) 계열이며, 그중 `afl`과 `axt`는 "함수를 찾고, 그 함수의 참조 관계를 추적한다"는 하나의 워크플로우로 이어진다.

- **`afl`(Analyze Function List)**: `aaa`로 분석이 끝난 뒤 발견된 모든 함수를 주소, 실행 블록 수, 바이트 크기, 이름 순으로 나열한다. IDA/Ghidra의 Functions 창(REV-0143, REV-0159)과 정확히 같은 정보다. 함수가 strip되어 이름이 `fcn.00401234` 형태로만 보여도, 크기와 블록 수는 여전히 유효한 단서다 — 반복문이 있는 알고리즘 함수는 블록 수가 많고, 단순 wrapper 함수는 블록 수가 1~2개로 적다.
- **`axt`(Xref To, addr xref to)**: 현재 커서(seek 위치)가 가리키는 주소를 **누가 참조하는지** 나열한다. 코드에서 `call`로 호출하는 경우뿐 아니라, 데이터로 주소 값을 참조하는 경우(함수 포인터 테이블 등)까지 포함한다. IDA에서 `X` 키(REV-0145)를 눌렀을 때 나오는 "Xrefs to" 목록과 동일한 정보를 커맨드라인으로 얻는 것이다.
- **`axf`(Xref From)**: 반대로 현재 함수/주소가 **누구를 참조하는지**를 보여준다. `axt`와 짝을 이뤄 "누가 나를 부르고, 나는 누구를 부르는가"를 양방향으로 확인할 수 있다.

이 두 명령을 오가면 별도의 그래프 뷰 없이도 REV-0166에서 다루는 콜 그래프의 핵심 정보(들어오는 화살표/나가는 화살표)를 텍스트로 재구성할 수 있다. 큰 바이너리에서 GUI를 켤 여유가 없을 때 특히 유용하다.

## 화면/코드에서 보이는 징후
- `afl` 결과가 수십~수백 줄로 스크롤이 끝없이 이어진다.
- 함수 이름이 전부 `fcn.XXXXXXXX` 형태로 strip되어 있어 이름만으로는 역할을 짐작할 수 없다.
- 특정 함수 주소는 찾았는데, 그 함수가 `main`에서 직접 호출되는지 아니면 다른 헬퍼 함수를 거쳐 간접적으로 호출되는지 커맨드라인에서 바로 확인이 안 된다.

## 가장 먼저 할 것
`aaa`로 분석을 끝낸 뒤 `afl`을 실행하고, 출력을 블록 수/크기 기준으로 눈으로 훑어 상위 몇 개 후보(반복문이 있을 법한 크기, 즉 너무 작지도 너무 크지도 않은 함수)를 추린다. 그다음 후보 주소로 `s`(seek) 이동해 `axt`로 호출 경로를 확인한다.

## 단계별 절차
1. `r2 -A ./chall`로 파일을 열며 자동 분석까지 마친다.
2. `afl`로 전체 함수 목록을 확인한다. 필요하면 `afl~size`처럼 grep 필터(radare2 내부 `~` 연산자)를 걸어 특정 크기 이상 함수만 추릴 수 있다.
3. 후보 함수 이름 또는 주소로 `s <주소또는이름>`(예: `s main`, `s fcn.00401234`)을 실행해 커서를 옮긴다.
4. `axt`를 실행해 이 함수를 호출하는 위치 목록을 확인한다. 결과에 여러 줄이 나오면 각 줄의 호출 지점 주소로 다시 `s`해서 문맥을 확인할 수 있다.
5. 반대로 이 함수가 무엇을 호출하는지 보려면 `axf`를 실행한다.
6. `pdf`로 해당 함수 전체를 디스어셈블해 실제 로직을 확인하고, 필요하면 `f`(flag)로 이름을 붙여 이후 세션에서 알아보기 쉽게 만든다.
7. 후보가 여러 개면 2~6을 반복하며 좁혀 나가고, 최종적으로 REV-0165(상수 검색)나 문자열 단서와 교차검증한다.

## 명령어/단축키
```
r2 -A ./chall
[0x...]> afl
[0x...]> afl~1000     ; 대략적인 크기 필터(문자열 필터 문법 예시)
[0x...]> s main
[0x...]> axt
[0x...]> axf
[0x...]> pdf
[0x...]> f myname @ 0x00401234
```

## 출력 해석
- `afl` 출력의 각 줄은 `주소 블록수 크기 이름` 순서다. 블록 수가 1이면 분기가 거의 없는 단순 함수, 블록 수가 두 자릿수 이상이면 반복문/조건문이 많은 함수라는 신호다.
- `axt` 결과 줄은 보통 `CALL 0x주소 함수이름` 형태로 나온다. 이 주소가 `main` 근처거나 REV-0163/0164로 이미 찾아둔 검증 로직 근처라면, 지금 보고 있는 함수가 그 검증 로직의 하위 헬퍼일 가능성이 높다.
- `axt` 결과가 아예 없다면(참조하는 곳이 없다면) 해당 함수는 어디서도 직접 호출되지 않는다는 뜻이다 — 죽은 코드이거나, 함수 포인터로 간접 호출되어 정적 분석만으로는 참조가 안 잡힌 경우일 수 있다.

## 흔한 실수
- `aaa`를 생략하고 `afl`을 쳐서 함수가 하나도 안 나오는 것을 파일 문제로 오해하는 것(REV-0291 참고).
- `axt`와 `axf`를 헷갈려서 반대 방향의 참조를 확인하는 것 — `axt`는 "나를 부르는 곳(to me)", `axf`는 "내가 부르는 곳(from me)"이다.
- 커서(`s`)를 함수 시작 주소가 아닌 함수 중간 어딘가로 옮긴 채 `axt`를 실행해서 빈 결과를 받는 것 — `axt`는 정확히 그 주소를 참조하는 곳만 찾으므로, 함수 시작 주소(심볼 이름 그대로)로 이동했는지 확인해야 한다.
- strip된 바이너리에서 `fcn.XXXXXXXX` 이름만 보고 후보를 포기하는 것 — 이름이 없어도 크기·블록 수·`axt`/`axf` 관계만으로 충분히 후보를 추릴 수 있다.

## 막혔을 때 다음 체크
- radare2 명령어 자체가 처음이라면 → REV-0291 radare2 설치와 첫 명령
- 전체 명령어를 표로 다시 보고 싶다면 → REV-0292 radare2 명령어 치트시트
- 텍스트가 아니라 그림으로 호출 관계를 보고 싶다면 → REV-0752 radare2 비주얼 모드(V)로 그래프 보기
- afl/axt로도 후보가 안 좁혀지면 상수 기반 접근으로 전환 → REV-0165 상수 검색으로 알고리즘 찾기

## 미니 예제
```
$ r2 -A ./chall
[0x00001060]> afl
0x00001060    1 42   entry0
0x00001149    3 120  main
0x000011c9    6 210  fcn.000011c9
[0x00001060]> s fcn.000011c9
[0x000011c9]> axt
main 0x1189 [CALL] call fcn.000011c9
[0x000011c9]> pdf
```
`afl`에서 블록 수 6짜리 함수가 눈에 띄어 `s`로 이동한 뒤 `axt`를 쳤더니 `main`에서 한 번만 호출된다는 것이 확인됐다. 호출 지점이 하나뿐이라는 것은 이 함수가 범용 유틸리티가 아니라 특정 목적(검증/계산)을 위해 만들어졌을 가능성을 시사한다.

## 출처/검증
- `afl`, `axt`, `axf` 명령의 동작과 출력 형식: radare2 공식 문서 "The Radare2 Book"(https://book.rada.re) 명령어 참조 기준.
- IDA Xrefs(`X` 키), Ghidra XREF와 개념적으로 동일하다는 대응 관계는 세 도구 공식 문서에서 공통으로 설명하는 "cross reference" 개념을 기준으로 정리했다.
- 이 문서는 실기 재현 없이 공식 문서와 일반적으로 통용되는 사용 패턴을 기준으로 작성되었으며, 버전에 따라 출력 포맷이 다를 수 있어 실제 세션에서 `afl?`, `axt?`로 도움말을 한 번 더 확인하는 것을 권장한다(2026-09-09 검증).
