## 한 줄 요약
IDA에서 커서를 함수, 전역 데이터, 또는 Pseudocode 안의 지역 변수 위에 놓고 **Y**를 누르면 그 항목의 C 스타일 타입(함수 원형, 데이터 타입, 변수 타입)을 직접 선언할 수 있으며, 이는 디컴파일 결과가 얼마나 읽기 쉽게 보이는지를 결정하는 가장 강력한 명령 중 하나다.

## 언제 검색해야 하나
- Pseudocode에서 함수 인자가 `a1`, `a2`, `a3`처럼 나오는데 실제로는 구조체 포인터 같아서 필드로 보고 싶을 때
- 어떤 변수가 `*(int *)(a1 + 8)`처럼 raw 오프셋으로만 보여서 구조체인지 배열인지 판단하기 어려울 때
- 함수를 호출하는 쪽에서 인자 개수/타입이 이상하게 표시될 때 (호출된 함수의 원형이 잘못 추론된 경우)
- 전역 데이터가 `byte_40A000`처럼 단순 바이트로만 보이는데 실제로는 배열이나 구조체일 것 같을 때

## 핵심 개념
Y는 커서 위치에 있는 항목의 **종류에 따라 다른 대화상자**를 연다.

1. **함수 이름 위에서 Y** — "Edit function"(또는 함수 프로토타입 편집기, 버전에 따라 "Function signature" 등으로 표기) 대화상자가 열린다. 여기서 반환 타입, 함수 이름, 인자 타입/개수, 호출 규약(`__cdecl`, `__stdcall`, `__fastcall`, `__thiscall`, `__usercall` 등)을 C 선언 형태로 직접 입력한다. 예: `int __cdecl sub_401230(char *a1, int a2)`.
2. **전역 데이터 위에서 Y** — 그 주소를 특정 타입(정수 크기, 배열, 구조체, 포인터 등)으로 재정의한다. 예를 들어 `byte_40A000`를 `char[64]`로 바꾸면 IDA가 그 영역을 64바이트짜리 배열로 다시 표시한다.
3. **Pseudocode 안의 지역 변수 위에서 Y** — 그 변수의 타입을 즉시 바꾼다. 예를 들어 `int a1`을 `char *a1`으로 바꾸면, 그 변수를 사용하는 모든 줄이 정수 연산이 아니라 포인터 역참조/문자열 연산으로 다시 표시된다. 구조체 포인터 타입을 지정하면 `*(int *)(a1 + 8)` 같은 raw 오프셋 표현이 `a1->field_8`처럼 필드 접근으로 바뀌어 훨씬 읽기 쉬워진다.

**왜 함수 원형을 정확히 맞추는 게 중요한가**: Hex-Rays 디컴파일러는 함수 본문뿐 아니라 그 함수를 호출하는 모든 지점의 표시도 함수 원형을 기준으로 만든다. 만약 IDA가 인자 개수를 잘못 추론했다면(너무 많거나 너무 적게), 호출하는 쪽 코드에서 인자가 누락되거나 엉뚱한 값이 인자처럼 표시되는 문제가 생긴다. Y로 함수 원형을 정확히 지정하면 이 문제가 즉시 해결되고, 그 함수를 호출하는 모든 곳의 Pseudocode가 다시 계산되어 올바르게 표시된다. REV-0151(Positive SP Value 경고)이나 REV-0153(Stack Pointer 분석이 틀렸을 때)처럼 스택 분석이 꼬이는 문제도 근본 원인이 호출 규약/인자 개수 오판인 경우가 많은데, 이때 해결 수단이 바로 Y다.

**왜 구조체로 캐스팅하는 게 중요한가**: 리버싱 초보자가 흔히 저지르는 실수는 이 단축키의 존재를 몰라서 `*(int *)(a1 + 8)`, `*(int *)(a1 + 0xC)` 같은 raw 오프셋 표현을 손으로 하나하나 계산하며 읽는 것이다. 만약 구조체 레이아웃을 이미 알고 있거나(예: `struct Player { int hp; int mp; ... }`) IDA의 Local Types에 그 구조체를 미리 정의해뒀다면, 변수를 `Player *`로 Y 지정하는 순간 모든 오프셋이 `a1->hp`, `a1->mp`처럼 필드 이름으로 자동 변환되어 표시된다. 이는 코드를 읽는 속도와 정확도를 크게 높여준다.

Y로 지정한 타입은 IDA 데이터베이스에 저장되며, 지역 변수/전역 변수의 색은 보통 사용자가 직접 지정한 타입은 파란색, IDA가 추론한(확정되지 않은) 타입은 회색으로 구분해서 보여준다(테마에 따라 색상은 다를 수 있음). 이 색 구분으로 "내가 확정한 정보"와 "IDA의 추측"을 구분할 수 있다.

## 화면/코드에서 보이는 징후
- Pseudocode에서 함수 인자가 실제 코드 흐름과 안 맞게 너무 많거나 적게 표시된다.
- `*(int *)(a1 + 8)`, `*(_DWORD *)(a1 + 0x14)`처럼 포인터 연산 + 오프셋 표현이 반복적으로 나온다.
- 함수를 호출하는 여러 곳에서 인자 자리에 이상한 캐스팅(`(int)&unk_...`)이나 정체불명의 값이 표시된다.
- 전역 변수가 실제로는 문자열/배열인데 `byte_40A000`, `byte_40A001`처럼 한 바이트씩 따로 이름 붙어 있다.

## 가장 먼저 할 것
바꾸려는 대상(함수 이름/전역 데이터/Pseudocode 지역 변수) 위에 커서를 정확히 놓고, 먼저 그 대상이 실제로 어떤 크기와 구조를 가지는지 대략 파악한다(오프셋 접근 패턴을 보고 몇 바이트짜리 구조체인지 가늠하거나, 함수 호출부의 인자 push/mov 개수를 세어 인자 개수를 가늠).

## 단계별 절차

**1) 함수 원형 지정하기**

디스어셈블리 또는 Pseudocode에서 함수 이름 위에 커서를 놓고 **Y**를 누른다. "Edit function" 계열 대화상자가 열리고, 텍스트 입력란에 현재 추론된 원형(예: `int __cdecl sub_401230(int, int)`)이 채워져 있다. 이를 지우고 실제 원형을 C 선언 형태로 입력한다.

```
int __cdecl check_flag(char *input, int len)
```

확인을 누르면 함수 본문과 이 함수를 호출하는 모든 지점의 Pseudocode가 새 원형 기준으로 다시 표시된다.

**2) 호출 규약이 안 맞을 때**

만약 실제 어셈블리에서 인자를 넘기는 레지스터/스택 순서가 IDA 기본 추론과 다르다면(예: 최적화된 코드에서 비표준 레지스터 사용), 원형 앞에 `__usercall`을 붙이고 각 인자 뒤에 `@<레지스터명>`을 명시하는 방식도 있다. 이는 고급 사용법이므로 처음에는 표준 호출 규약(`__cdecl`, `__stdcall`, `__fastcall`)부터 시도하고, 그래도 안 맞으면 REV-0153(Stack Pointer 분석이 틀렸을 때)을 참고한다.

**3) 전역 데이터 타입 재정의하기**

전역 데이터 위에 커서를 놓고 Y를 누르면 타입 입력란이 뜬다. 배열이면 `char[64]`, 구조체 포인터면 `Player *`처럼 입력한다. 구조체 자체가 아직 정의되어 있지 않다면, 먼저 Local Types 창(Shift+F1 또는 View → Open subviews → Local Types)에서 `struct Player { int hp; int mp; };` 형태로 구조체를 정의해둔 다음 Y로 그 타입을 적용한다.

**4) Pseudocode 지역 변수 타입 바꾸기**

Pseudocode 창에서 변수(`a1`, `v3` 등) 위에 커서를 놓고 Y를 누른다. 작은 입력란이 뜨고 새 타입(예: `Player *`, `char *`, `unsigned int`)을 입력하면 Enter로 즉시 적용된다. 그 변수가 쓰인 모든 줄이 새 타입 기준으로 다시 표시된다.

**5) 구조체 캐스팅으로 오프셋 정리하기**

`*(int *)(a1 + 8)`처럼 나오는 변수가 있다면, 그 오프셋들을 모아 어떤 구조체인지 추정한 뒤 Local Types에 구조체를 만들고, 해당 변수를 그 구조체의 포인터 타입으로 Y 지정한다. 그러면 `a1->field_8`처럼 표시되고, 필드 이름도 다시 N으로 바꿔서 의미 있게 정리할 수 있다.

## 명령어/단축키
- **Y**: 함수/전역 데이터/지역 변수 타입 지정 (디스어셈블리에서는 "Set item type"에 대응, Pseudocode에서는 "Set type"에 대응 — 명칭은 다르지만 둘 다 Y 하나로 실행됨)
- **Shift+F1** 또는 View → Open subviews → **Local Types**: 구조체/열거형을 미리 정의해두는 창
- 우클릭 → **Set type...** / **Edit function...**: Y와 동일한 동작을 메뉴로 실행
- Pseudocode에서 우클릭 → **Convert to struct*** 계열 명령(버전에 따라 이름이 다를 수 있음): 오프셋 접근 패턴을 자동으로 구조체 후보로 제안해주는 기능도 있으니 존재 여부를 우클릭 메뉴에서 확인해볼 것

## 출력 해석
- 타입 입력란에 문법이 틀린 C 선언을 입력하면(예: 괄호가 안 맞거나 존재하지 않는 타입 이름을 사용하면) 입력란 테두리가 빨간색으로 표시되거나 확인 시 에러 메시지가 뜬다. 이 경우 입력한 선언을 다시 확인한다.
- 타입 적용 후 함수 본문의 변수 색이 파란색(사용자 지정 확정 타입)으로 바뀌었다면 정상적으로 적용된 것이다. 여전히 회색이라면 적용이 안 됐거나 다른 항목을 지정한 것이니 다시 확인한다.
- 구조체 포인터로 지정했는데 필드가 `field_0`, `field_4`처럼 자동 생성된 이름으로만 보인다면, 구조체 정의 자체에 의미 있는 필드 이름을 아직 안 붙인 것이다. Local Types에서 구조체를 다시 열어 필드 이름을 정리한다.

## 흔한 실수
- Y 단축키의 존재 자체를 모르고 `*(int *)(a1 + 8)` 같은 표현을 손으로 오프셋 계산해가며 읽는 것 — 구조체를 정의하고 Y로 캐스팅하면 훨씬 빠르고 정확하다.
- 함수 원형을 바꿨는데 호출 규약을 실제와 다르게 지정해서(`__stdcall`인데 `__cdecl`로 지정 등) 오히려 인자 표시가 더 이상해지는 것 — REV-0151에서 다루는 SP 경고가 이런 경우에 뜰 수 있다.
- 전역 변수 타입을 너무 작게 지정해서(예: 실제로는 구조체인데 `int`로만 지정) 뒤쪽 필드들이 별도의 이름 없는 바이트로 계속 남는 것.
- 타입을 지정한 후 F5로 새로고침하지 않고 예전 화면을 계속 보며 "안 바뀌었다"고 착각하는 것 — Pseudocode 창을 클릭 후 F5를 눌러 확인한다.
- Local Types에 구조체를 정의하지 않고 바로 `Player *`처럼 존재하지 않는 타입 이름을 입력해서 에러가 나는 것 — 구조체는 먼저 정의부터 해야 한다.

## 막혔을 때 다음 체크
- 함수 원형을 바꿔도 호출부 표시가 이상하다면 → REV-0153(Stack Pointer 분석이 틀렸을 때)에서 다루는 호출 규약/스택 정리 방식 문제를 의심한다.
- 애초에 이 함수가 SP 경고(REV-0151)를 띄우고 있었다면 → 원형을 고치는 것이 그 경고의 해결책일 수 있다.
- 어떤 구조체인지 감이 안 잡힌다면 → REV-0146(F5 디컴파일)로 돌아가 그 변수가 어디서 만들어지고(malloc 크기 등) 어떻게 쓰이는지부터 다시 추적한다.
- 타입을 지정했는데도 여전히 raw 오프셋이 보인다면 → 지정한 타입이 실제로 적용됐는지(파란색 표시 여부) 확인하고, 안 됐다면 입력한 C 선언 문법을 다시 점검한다.

## 미니 예제
다음처럼 IDA가 구조체를 인식하지 못한 상태의 Pseudocode가 있다고 하자.

```c
int __cdecl sub_401500(int a1)
{
  if ( *(int *)(a1 + 8) > 100 )
    *(int *)(a1 + 12) = 0;
  return *(int *)(a1 + 8);
}
```

Local Types에서 다음 구조체를 정의한다.

```c
struct Player
{
  int id;
  int hp;
  int mp;
};
```

Pseudocode에서 `a1` 위에 커서를 놓고 **Y**를 눌러 `Player *`를 입력하면 다음처럼 바뀐다.

```c
int __cdecl sub_401500(Player *a1)
{
  if ( a1->hp > 100 )
    a1->mp = 0;
  return a1->hp;
}
```

이후 함수 이름 위에서 N을 눌러 `heal_check` 등으로 정리하면 코드의 의도가 훨씬 분명해진다.

- REV-0147 — IDA 함수 변수 이름 N으로 바꾸기
- REV-0151 — IDA Positive SP Value Has Been Detected 경고
- REV-0153 — IDA Stack Pointer 분석이 틀렸을 때

## 출처/검증
- Y가 함수 위에서는 함수 프로토타입 편집기를, Pseudocode 지역 변수 위에서는 Set type 명령을 여는 동일 단축키라는 점, 함수 원형 편집기가 "classic free-text one-line editor"와 "multi-line editor"를 오갈 수 있다는 최신 변경 사항: Hex-Rays 공식 릴리스 노트(IDA 8.5, 9.0) 및 공식 문서(Functions 메뉴, Set type 명령 설명, docs.hex-rays.com) 검색 결과 기준.
- Set type이 반환 타입/인자/호출 규약을 바꿀 수 있고, 캐스팅 자체는 대상 이름을 바꾸지 않는다는 점, 사용자 지정 타입과 추론된 타입을 색으로 구분해 표시한다는 점: 위와 동일한 Hex-Rays 공식 문서 검색 결과 기준.
- 이 문서는 2026-09-08 기준 검색 가능한 공식 문서/릴리스 노트 요약을 근거로 작성했다. Hex-Rays 문서 사이트 구조가 최근 개편되어 일부 개별 페이지 URL이 이동/삭제된 상태였으므로, 정확한 현재 메뉴 문구는 실제 설치된 IDA 버전의 우클릭 컨텍스트 메뉴로 반드시 재확인할 것.
