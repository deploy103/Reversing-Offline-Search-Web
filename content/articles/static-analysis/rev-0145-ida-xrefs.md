## 한 줄 요약
`X` 키는 커서가 있는 함수/데이터/문자열을 **"누가 참조(호출/읽기/쓰기/점프)하는지"** 보여주는 "Xrefs to" 목록을 열어주는 단축키로, IDA에서 "이 문자열을 쓰는 함수가 뭐지?", "이 함수를 누가 호출하지?" 같은 질문에 답하는 가장 기본적이고 강력한 도구다.

## 언제 검색해야 하나
- 특정 함수를 "누가 호출하는지" 알고 싶을 때
- 특정 전역 변수/문자열을 "누가 읽거나 쓰는지" 알고 싶을 때
- Strings 창에서 흥미로운 문자열을 찾은 뒤, 그걸 실제로 사용하는 코드로 넘어가고 싶을 때
- 어떤 함수가 프로그램 전체에서 몇 번이나 호출되는지, 즉 얼마나 핵심적인 함수인지 감을 잡고 싶을 때

## 핵심 개념
IDA는 분석 과정에서 코드와 데이터 사이의 모든 참조 관계, 즉 **cross-reference(xref, 상호 참조)**를 자동으로 기록한다. 예를 들어 `call sub_401000` 명령어가 있으면, IDA는 "이 주소에서 sub_401000으로의 코드 참조(call)가 있다"는 정보를 양쪽에 모두 저장한다. 이 정보 덕분에 특정 주소에 커서를 놓고 `X`를 누르면 **"이 주소를 참조하는 모든 곳"**의 목록을 즉시 볼 수 있다. 이것이 바로 **"Xrefs to"**(이 지점으로의 참조들)이다.

- **Xrefs to (이 지점을 참조하는 것들)** — `X` 키로 여는 기본 목록. "누가 나를 부르는가/읽는가/쓰는가"를 보여준다. 함수에서 누르면 "누가 이 함수를 호출하는가", 전역 변수/문자열에서 누르면 "누가 이 데이터를 읽거나 쓰는가"를 알 수 있다.
- **Xrefs from (이 지점이 참조하는 것들)** — 반대 방향으로, "내가 누구를 부르는가/누구를 읽고 쓰는가"를 보여준다. IDA View 화면 자체에서 함수 코드를 읽으면서 각 `call`/`lea`/`mov` 명령어를 하나씩 따라가는 것과 비슷한 정보지만, 별도로 한 지점에서 "내가 나가는 참조가 몇 개나 있는지"를 목록으로 모아 보고 싶을 때 유용하다. 메뉴 경로나 단축키는 버전에 따라 다를 수 있으므로(예: 우클릭 메뉴의 "Jump to xref"류 항목), 필요하면 커서를 각 명령어 위에 놓고 개별적으로 확인하는 방식이 가장 확실하다.

"Xrefs to" 목록 창에는 보통 다음과 같은 컬럼이 표시된다.

- **Direction** — 참조의 방향(예: 위쪽 코드에서 오는지, 아래쪽에서 오는지 등, "Up"/"Down"으로 표시되는 경우가 흔하다).
- **Type** — 참조의 종류. 코드 참조라면 `Call`(함수 호출), `Jump`(점프), `Ordinary flow`(순차 실행) 등으로, 데이터 참조라면 `Read`(읽기), `Write`(쓰기), `Offset`(주소 자체를 값으로 사용, 예: `lea`로 포인터를 얻는 경우) 등으로 구분된다.
- **Address** — 그 참조가 발생하는 소스 위치(즉, 참조하는 명령어/데이터의 주소).
- **Text** — 그 주소에 있는 실제 코드/데이터 한 줄(디스어셈블리 텍스트).

이 네 컬럼만 읽을 줄 알면, "누가 어디서 어떤 방식으로 이 지점을 사용하는지"를 한 번에 파악할 수 있다.

## 화면/코드에서 보이는 징후
- 함수 이름이나 데이터 라벨 위에 커서를 놓고 `X`를 누르면 "Xrefs to <이름>" 제목의 작은 목록 창이 뜬다.
- 참조가 딱 하나뿐이면 목록 창이 뜨는 대신 바로 그 위치로 이동하는 경우도 있다(참조가 유일하면 목록을 띄울 필요가 없기 때문).
- 목록 각 행 앞에 화살표나 아이콘으로 코드/데이터 참조를 구분해서 보여주는 경우가 많다.
- 디스어셈블리 화면에서 함수 이름 왼쪽에 `; sub_401000+1A ↑o` 같은 주석이 자동으로 붙어 있기도 한데, 이는 IDA가 참고용으로 남긴 "이 값은 다른 곳에서도 참조된다"는 힌트다.

## 가장 먼저 할 것
궁금한 함수 이름/전역 변수/문자열 위에 커서(캐럿)를 놓고 바로 `X`를 눌러본다. 목록이 뜨면 Address와 Text 컬럼만 먼저 훑어 "어떤 함수 안에서, 어떤 명령어로" 참조되는지 파악한다.

## 단계별 절차

**1) 대상 위에 커서 놓기**

디스어셈블리(IDA View)나 Strings/Functions 창에서 확인하고 싶은 함수 이름, 전역 변수, 문자열 라벨 위에 커서를 놓는다. 목록 창(Strings, Functions)에서 항목을 선택한 상태에서도 `X`가 동작하는 경우가 많다.

**2) X로 Xrefs to 목록 열기**

`X`를 누른다(메뉴 경로로는 `View → Open Subviews → Cross references`, 또는 우클릭 → `Jump to xref` 계열도 유사한 목적으로 쓰인다). 참조가 여러 개면 목록 창이 뜨고, 하나뿐이면 바로 그 위치로 이동할 수 있다.

**3) 목록 읽기**

Direction/Type/Address/Text 네 컬럼을 확인한다. Type이 `Call`이면 "이 함수를 실제로 호출하는 코드"이고, `Read`/`Write`면 "이 데이터를 읽거나 쓰는 코드"다. Text 컬럼을 보면 그 줄의 실제 명령어를 목록에서 바로 읽을 수 있어, 하나하나 이동해보지 않아도 대략적인 맥락을 파악할 수 있다.

**4) 원하는 참조로 이동**

목록에서 원하는 행을 더블클릭하거나 선택 후 `Enter`를 누르면, IDA View가 그 참조가 발생한 정확한 주소로 이동한다. 이 위치를 감싸는 함수를 확인하면 "이 함수가 대상을 실제로 사용하는 곳"이 된다.

**5) 필요하면 반복 추적**

이동한 함수 자체를 또 다른 함수가 호출하는지 궁금하면, 그 함수 이름 위에서 다시 `X`를 눌러 한 단계 더 위로(호출 체인을 거슬러) 추적할 수 있다. 이렇게 반복하면 "이 체크 로직이 결국 `main`에서부터 어떻게 도달하는가" 같은 전체 흐름을 손으로 그려볼 수 있다.

## 명령어/단축키
- `X` : 커서 위치(함수/데이터/문자열)에 대한 "Xrefs to" 목록 열기
- `Enter` 또는 더블클릭 : 목록에서 선택한 참조 위치로 이동
- `View → Open Subviews → Cross references` : 메뉴로 같은 기능 접근
- `Esc` (또는 `Ctrl+-`에 해당하는 뒤로가기) : 이동 이력에서 이전 위치로 돌아가기 — xref로 여러 번 이동한 뒤 원래 자리로 돌아올 때 유용

## 출력 해석
- Type이 `Call`인 xref가 여러 개 있다는 것은 그 함수가 프로그램 여러 곳에서 재사용되는 공용 함수(유틸리티성)라는 뜻일 수 있다.
- 특정 문자열/함수에 대한 xref가 **정확히 1개**뿐이라면, 그 지점이 프로그램 로직상 유일한 진입 경로라는 뜻이므로 분석 우선순위가 높다.
- xref가 **0개(목록이 비어 있음)**라면, 코드에서 직접 참조되지 않는 데이터이거나(예: 디버그 정보, 사용되지 않는 문자열), 또는 함수 포인터 테이블/점프 테이블처럼 **간접 참조**를 통해서만 쓰이고 있어 IDA가 정적으로 그 연결을 발견하지 못했을 가능성이 있다. 이 경우 동적 분석(디버거로 실제 실행 흐름 확인)이 필요할 수 있다.
- Type이 `Offset`으로 표시되는 참조는 그 주소 자체를 값(포인터)으로 사용한다는 뜻이며, 함수 포인터 배열이나 콜백 테이블에서 자주 나타난다.

## 흔한 실수
- `X`를 눌렀는데 목록이 안 뜨고 바로 어딘가로 이동해버려서 "안 열렸다"고 착각하는 경우 — 참조가 하나뿐이면 목록 없이 바로 이동하는 것이 정상 동작이다. `Esc`(뒤로가기)로 원위치한 뒤 다시 확인하면 된다.
- Xrefs to(누가 나를 참조하는가)와 Xrefs from(내가 누구를 참조하는가)을 헷갈려서, 호출자를 찾으려다가 반대로 자기 자신이 호출하는 함수 목록을 보고 있는 경우.
- xref 목록의 Text 컬럼만 보고 실제 코드 맥락(그 위/아래 몇 줄)을 확인하지 않은 채 성급하게 판단하는 경우 — 반드시 Enter로 이동해서 실제 함수 흐름을 눈으로 확인해야 한다.
- 간접 호출(레지스터를 통한 `call rax` 등)이나 함수 포인터 테이블 때문에 xref가 비어 있는 상황을 "이 함수는 안 쓰인다"고 성급히 결론짓는 경우 — 실제로는 쓰이지만 IDA가 정적으로 못 찾은 것일 수 있다.

## 막혔을 때 다음 체크
- xref가 하나도 없는데 분명히 쓰일 것 같은 함수/데이터라면 → 함수 포인터 테이블이나 vtable, 콜백 등록 코드가 근처에 있는지 확인하고, 필요하면 디버거로 실행 중 실제 호출 여부를 관찰한다.
- 함수를 찾았는데 그 안 로직을 더 편하게 읽고 싶다면 → REV-0146(F5 디컴파일과 Pseudocode 읽기)로 넘어간다.
- 문자열에서부터 xref를 따라가는 전체 흐름이 처음이라면 → REV-0144(IDA Strings 창과 Shift+F12)를 먼저 읽고 이 문서와 이어서 실습한다.
- 여러 단계를 거슬러 올라가다 어디까지 왔는지 헷갈리면 → `Ctrl+P`(Functions 창, REV-0143)에서 현재 함수 이름을 검색해 전체 그림에서의 위치를 다시 확인한다.

## 미니 예제
"비밀번호 검사 함수(`sub_401520`)를 누가 호출하는지" 거슬러 올라가는 흐름:

```text
1. sub_401520 함수 이름 위에 커서 놓고 X
2. Xrefs to 목록에 Type=Call, Address=0x401700, Text="call sub_401520" 한 줄 표시
3. Enter로 0x401700 이동 → 이 위치가 sub_401810(예: 메뉴 처리 함수) 안에 있음을 확인
4. sub_401810 이름 위에서 다시 X → 이번엔 Type=Call 항목이 하나, Address가 WinMain 근처
5. 결국 WinMain → sub_401810 → sub_401520 순서로 호출된다는 흐름을 손으로 재구성 완료
```

## 출처/검증
- Xrefs to 목록의 컬럼 구성(Direction/Type/Address/Text)과 `X` 단축키 동작은 Hex-Rays 공식 문서 및 공개 IDA 단축키 레퍼런스(docs.hex-rays.com/user-guide/configuration/shortcuts)를 기준으로 정리했다(2026-09-08 검증).
- Xrefs from(반대 방향 참조 확인) 관련 정확한 메뉴명/단축키는 버전마다 표기가 다를 수 있어, 실제 설치된 IDA에서 우클릭 메뉴를 직접 확인해서 재검증할 것을 권장한다.
