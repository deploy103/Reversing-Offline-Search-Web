## 한 줄 요약
"Simple and Swap"(Bronze 3)은 드림핵 CTF Season 7 Round #22(Div2)에도 리버싱 카테고리 문제로 등재되어 있고 코인 구매형 공식 write-up이 존재하는 것까지 확인되지만, 공개 인터넷에서 상세 로직을 다루는 write-up은 찾지 못했다. 이름 자체가 "간단한 것과 교환(swap) 연산"을 직접 가리키므로, 입력값의 두 부분(바이트, 변수, 배열 원소 등)을 서로 맞바꾼 뒤 비교하는 구조로 추정하는 것이 가장 자연스러운 출발점이다.

## 언제 검색해야 하나
- "Simple and Swap"을 열었는데 코드 안에서 두 변수의 값을 맞바꾸는 `XCHG` 인스트럭션이나 임시 변수를 쓴 교환 로직이 보일 때
- Bronze 3 난이도인데 배열의 원소들이 서로 자리를 바꾸는 로직(정렬과 유사하지만 정렬은 아닌)이 보여서 어떻게 되돌려야 할지 감이 안 잡힐 때
- 이름의 "simple"과 실제 코드의 복잡함이 안 맞는 것 같아서 다른 사람의 접근법을 참고하려 할 때

## 핵심 개념
검색 결과 "Simple and Swap"이라는 이름의 드림핵 리버싱 문제가 CTF Season 7 Round #22(Div2)에 존재하고, 20 코인짜리 Official Writeup이 있다는 것까지 확인되었다. 하지만 그 write-up의 실제 내용(로직, 상수, 풀이 스크립트)은 로그인 없이 열람할 수 없어 확인하지 못했다. 아래 내용은 이름에서 유추한 일반적 접근법이다.

"swap"이라는 단어가 프로그래밍에서 의미하는 것은 명확하다 — 두 값의 위치를 맞바꾸는 연산이다. 어셈블리 수준에서는 `XCHG` 인스트럭션(REV-0043)으로 직접 구현되거나, 임시 변수를 거쳐 `tmp = a; a = b; b = tmp;` 형태의 세 줄짜리 코드로 컴파일되는 것이 일반적이다. "Simple"이 함께 붙어 있으므로, 교환 연산 자체는 한 번 또는 소수의 횟수만 일어나고 그 뒤에 간단한 비교가 이어지는 구조로 추정할 수 있다.

이런 유형의 문제에서 흔히 쓰이는 설계는 다음과 같다.

- 입력 문자열/배열의 특정 인덱스 쌍(예: 0번째와 마지막, 또는 짝수/홀수 인덱스)을 서로 교환한 뒤, 그 결과를 정답 배열과 비교한다.
- 교환이 한 번이 아니라 여러 번 반복되는 루프(예: 배열을 뒤집는 것과 같은 효과)로 구현되어 있을 수도 있다. 이 경우 최종 결과는 원본 배열의 순서를 반전시킨 것과 동일하므로, 검증 통과를 위한 입력은 목표 배열을 다시 반전시키면 얻을 수 있다.
- 교환 연산 자체가 대칭적(swap을 두 번 하면 원래대로 돌아옴)이라는 성질을 이용하면, 목표 값에서 같은 교환 연산을 거꾸로 한 번 더 적용하는 것만으로 원래 입력을 복원할 수 있는 경우가 많다.

## 화면/코드에서 보이는 징후
- 디스어셈블리에 `XCHG` 인스트럭션이 직접 보이거나, 세 줄짜리 임시 변수 교환 패턴(`MOV`, `MOV`, `MOV`)이 반복됨
- 배열 인덱스 두 개를 변수로 받아 그 위치의 값을 맞바꾸는 함수(`swap(a, b)` 형태)가 별도로 분리되어 있을 수 있음
- 교환이 루프 안에서 반복되며 인덱스가 점점 가운데로 좁혀지는 패턴(배열 반전과 유사)이 보일 수 있음

## 가장 먼저 할 것
`main`에서 교환이 몇 번 일어나는지, 어떤 인덱스 쌍을 대상으로 하는지 먼저 표로 정리한다. 교환이 한 번인지 반복(루프)인지 구분하는 것이 이후 역산 전략을 결정하는 핵심이다.

## 단계별 절차
1. IDA/Ghidra에서 교환 관련 함수/인스트럭션(`XCHG` 또는 3줄 임시변수 패턴) 위치 확인
2. 교환 대상이 되는 인덱스/변수 쌍이 고정인지, 루프로 반복되는지 확인
3. 교환 이후 비교되는 목표 값(하드코딩된 배열/문자열) 확인
4. 교환이 대칭 연산이라는 성질을 이용해 목표 값에 같은 교환을 거꾸로 적용해 원래 입력값 복원
5. 복원한 입력값을 실제 바이너리에 넣어 검증

## 명령어/단축키
```text
IDA: Alt+G(구조체/전역 검색은 아니지만) → 그래프 뷰(Space)로 루프 구조 확인
x64dbg: 교환 함수 호출 전후로 F2 브레이크포인트를 걸어 두 값이 실제로 뒤바뀌는지 레지스터/메모리 창에서 확인
```

## 출력 해석
교환 연산은 성질상 짝수 번 반복하면 원상복구되고 홀수 번이면 한 번 교환된 상태로 남는다. 루프 반복 횟수를 세어 짝/홀 여부를 먼저 확인하면 역산 방향을 잘못 잡는 실수를 줄일 수 있다.

## 흔한 실수
- 교환이 한 번뿐이라고 예단하고 실제로는 루프로 반복되는 교환을 놓치는 것
- 교환의 대칭성(같은 연산을 다시 적용하면 원상복구)을 활용하지 않고 처음부터 새로운 방정식을 세워 복잡하게 접근하는 것
- `XCHG`가 인스트럭션 수준에서 안 보인다고 "교환 로직이 없다"고 단정하는 것 — 컴파일러가 임시 변수를 쓰는 3줄짜리 `MOV` 패턴으로 바꿔놓는 경우가 흔함

## 막혔을 때 다음 체크
- `XCHG` 인스트럭션 자체의 동작이 헷갈리면 → REV-0043 XCHG: 두 값 교환
- 배열 반전/뒤섞기 같은 구조 전체가 궁금하면 → REV-0216 배열 셔플 검증(이 저장소 algorithms 카테고리)과 유사한 접근이 필요할 수 있음
- 정적 분석만으로 안 풀리면 → REV-0805 정적분석만으로 도저히 안 풀릴 때 동적으로 전환하는 기준

## 미니 예제
```python
# 교환이 대칭 연산이라는 성질을 이용한 역산 스킷치(구조 예시, 실제 인덱스/값 아님)
target = list(b"targetvalue")
target[0], target[-1] = target[-1], target[0]  # 문제와 동일한 교환을 한 번 더 적용
print(bytes(target))
```
이 예제는 "swap"이라는 이름에서 유추한 대칭 연산 역산 방식을 보여주는 일반적 예시이며, 실제 "Simple and Swap" 바이너리의 정확한 인덱스나 값이 아니다.
