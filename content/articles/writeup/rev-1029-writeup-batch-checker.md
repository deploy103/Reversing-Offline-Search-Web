## 한 줄 요약
"Batch Checker"는 IDA/Ghidra로 열 수 있는 PE나 ELF가 아니라 Windows `.bat`(배치) 스크립트 자체가 난독화되어 배포되는 문제로, 리버싱 대신 "난독화된 배치 문법을 한 줄씩 해독"하는 정적 코드 리딩이 핵심이며, 실제로 이 문제 제작에 쓰인 것으로 확인된 난독화 도구는 Python으로 작성된 배치 난독화 스크립트다.

## 언제 검색해야 하나
- 드림핵 카테고리가 "reversing, misc"로 같이 표시된 "Batch Checker"를 열었는데 실행 파일이 아니라 `.bat`/`.cmd` 텍스트 파일이 나와서 어떻게 다뤄야 할지 모를 때
- 배치 파일을 열어봤는데 `%~`, `set`, `call`, `%variable:~0,1%` 같은 문법이 뒤섞여서 눈으로 읽기 힘들 때
- IDA/Ghidra를 켜야 하는 문제인지, 아니면 그냥 텍스트 에디터로 봐야 하는 문제인지부터 헷갈릴 때

## 핵심 개념
Windows 배치 스크립트(`.bat`, `.cmd`)는 컴파일되지 않는 인터프리터 언어이므로, 바이너리 리버싱과는 완전히 다른 접근이 필요하다. 그런데 배치 문법 자체가 원래도 읽기 불편한 데다(변수 확장 규칙이 복잡하고, `delayed expansion`, `for /f`, `call` 재귀 호출 등 기괴한 트릭이 많다), 문제 제작자가 여기에 **의도적인 난독화**를 추가하면 사람이 눈으로 읽기 거의 불가능한 수준이 된다.

이 문제의 제작에 사용된 것으로 공개적으로 확인된 도구는 "배치 난독화 스크립트"로, Python으로 작성되어 원본 `.bat` 파일을 변환해 문제 파일을 만든다. 일반적으로 배치 난독화는 다음과 같은 기법을 조합한다.

- 변수명을 의미 없는 임의 문자열로 바꿔치기(사람이 읽어서 의도를 짐작하기 힘들게)
- `set` 명령으로 문자열을 여러 조각으로 나눠 저장한 뒤 나중에 이어붙이기(문자열 조각화)
- `%var:~start,length%` 문자열 슬라이싱 구문을 남용해 원래 명령어 문자열을 조립
- `^`(캐럿) 이스케이프 문자나 특수문자를 끼워 넣어 눈으로 읽을 때 헷갈리게 하기
- 실제 실행할 명령을 문자열로 조립한 뒤 `call` 또는 `%var%`로 간접 실행

따라서 이 문제를 풀 때는 "어셈블리를 읽는" 리버싱이 아니라 "난독화된 스크립트를 손으로/도구로 되돌리는" 디옵스퓨케이션(deobfuscation) 작업이 된다.

## 화면/코드에서 보이는 징후
- 파일 확장자가 `.bat` 또는 `.cmd`이고, 메모장으로 열면 알아볼 수 없는 변수명과 `%...%` 치환이 가득함
- 같은 줄에 `set` 명령이 여러 번 반복되며 짧은 문자열 조각을 계속 이어붙이는 패턴이 보임
- `setlocal enabledelayedexpansion`이 선언되어 있고, 이후 `!var!` 형태의 지연 확장 변수가 자주 쓰임
- 최종적으로 조립된 문자열을 `%결과변수%` 형태로 그대로 실행하거나 `call`로 넘기는 줄이 있음

## 가장 먼저 할 것
파일을 실행하기 전에 반드시 텍스트 에디터(메모장, VS Code 등)로 먼저 열어서 내용을 읽는다. 배치 스크립트는 그 자체로 소스코드이므로, 실행하지 않고도 로직을 다 볼 수 있다는 게 바이너리 리버싱과 가장 큰 차이다. 다만 스크립트 안에 파일을 삭제하거나 시스템을 변경하는 위험한 명령이 숨어 있을 수 있으므로, 정체를 파악하기 전에는 스냅샷을 뜬 가상머신 등 격리된 환경에서만 실행해야 한다.

## 단계별 절차
1. `.bat` 파일을 텍스트 에디터로 열어 전체 구조를 훑는다(파일 크기가 크지 않으므로 전체를 다 읽을 수 있다).
2. `set` 명령으로 정의되는 변수들을 순서대로 노트에 옮겨 적어, 각 변수가 최종적으로 어떤 문자열이 되는지 손으로 계산한다.
3. `%var:~start,length%` 같은 문자열 슬라이싱이 보이면, 원본 변수 값에서 해당 구간만 잘라내 계산한다.
4. 지연 확장(`!var!`)이 쓰였다면, 반복문(`for`)이나 조건문(`if`) 안에서 값이 실행 시점에 계속 바뀔 수 있다는 점을 감안해 순서대로 추적한다.
5. 손으로 추적하기 너무 복잡하면, 위험한 명령(`del`, `format`, 네트워크 호출 등)이 없는지 먼저 확인한 뒤, 격리된 환경에서 `echo` 명령으로 바꿔 실행해보며 각 단계에서 실제로 조립되는 문자열을 화면에 출력시켜 확인한다.
6. 최종적으로 사용자 입력과 비교되는 정답 문자열이나 플래그 조립 로직을 찾는다.

## 명령어/단축키
```bat
:: 위험한 명령을 실행 대신 화면 출력으로 바꿔 확인하는 트릭
:: 예: call %cmd% 대신 echo %cmd% 로 바꿔서 실제로 무엇이 실행될지 미리 본다
echo %결과변수%

:: 배치 디버깅에 유용한 옵션
@echo on   rem 스크립트 맨 위 @echo off를 지우거나 on으로 바꾸면 각 줄이 실행되며 그대로 화면에 출력됨
```
Python으로 유사 로직을 재현해 문자열 조립을 검증하고 싶다면, 변수 슬라이싱은 `var[start:start+length]`로 그대로 옮겨 계산할 수 있다.

## 출력 해석
`echo`로 바꿔서 확인한 결과, 최종적으로 실행되려던 명령이 단순한 문자열 비교(`if "%input%"=="정답"`)라면 그 정답 문자열이 곧 플래그이거나 플래그의 일부다. 조립된 문자열이 또 다른 배치 코드 조각이라면(즉, 코드가 코드를 생성하는 다단계 난독화라면) 그 조각을 다시 같은 방식으로 풀어야 한다.

## 흔한 실수
- 배치 파일을 무작정 더블클릭해서 실행하는 것 — 난독화된 스크립트 안에 무엇이 있는지 모르는 상태로 실행하면 시스템에 원치 않는 변경이 생길 수 있다. 반드시 먼저 읽고, 격리된 환경에서만 실행한다.
- `set` 변수 이어붙이기를 손으로 계산하다가 순서를 헷갈려서 잘못된 최종 문자열을 얻는 것 — 노트에 각 변수의 현재 값을 표로 정리하며 진행하는 것이 안전하다.
- 지연 확장(`!var!`)과 일반 확장(`%var%`)의 차이를 무시하고 텍스트를 순서 그대로 해석하는 것 — 지연 확장은 그 줄이 "실행되는 시점"의 값을 쓰므로 반복문 안에서는 결과가 다르게 나올 수 있다.
- 이 문제를 PE 바이너리 리버싱 문제처럼 생각해서 IDA로 열려고 시도하는 것 — 파일이 텍스트 스크립트라는 것부터 확인해야 한다.

## 미니 예제
난독화의 느낌을 보여주는 단순화된 예시다(실제 문제 파일의 코드가 아니라 배치 난독화의 일반적인 기법을 보여주는 가상의 코드).
```bat
@echo off
setlocal enabledelayedexpansion
set a=fl
set b=ag
set c=%a%%b%
set /p input=Enter password:
if "%input%"=="%c%_1234" (
    echo Correct!
) else (
    echo Wrong.
)
```
이 예시에서 `a`와 `b`를 이어붙이면 `flag`가 되고, 최종 비교 대상은 `flag_1234`이다. 실제 "Batch Checker" 문제는 여기에 문자열 슬라이싱, 지연 확장, 다단계 조립까지 겹쳐서 훨씬 복잡하게 만들어져 있을 것으로 추정되지만, 풀이 원리는 "각 변수의 최종 값을 순서대로 손으로 계산한다"는 점에서 동일하다.
