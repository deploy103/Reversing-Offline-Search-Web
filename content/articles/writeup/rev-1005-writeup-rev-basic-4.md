## 한 줄 요약
rev-basic-4는 앞선 rev-basic-0(REV-1001)의 구조를 그대로 가져오되 검증 함수 이름이 `Compare_str()`처럼 좀 더 명시적으로 붙어 있는 변형으로 보이며, 이 글에서는 공개된 상세 write-up이 부족한 만큼 구체적인 정답을 확정하지 않고 "검증 함수를 찾아 비교 대상을 추출하는" 일반적인 절차를 중심으로 설명한다.

## 언제 검색해야 하나
- 드림핵 rev-basic-4를 열었는데 지금까지의 rev-basic 문제들과 비슷한 느낌인데 검증 함수 이름이 `sub_...` 대신 `Compare_str` 같은 이름으로 보일 때
- 다른 rev-basic 문제들의 write-up을 참고하려는데 rev-basic-4만 정리된 글이 잘 안 보여서 스스로 절차를 세워야 할 때
- rev-basic 시리즈를 순서대로 풀다가 4번째 문제에서 "이전 문제와 뭐가 다른지"를 비교하며 접근하고 싶을 때

## 핵심 개념
공개적으로 검색되는 자료 중에는 이 문제를 자세히 단계별로 다룬 완결된 블로그 글을 찾지 못했다. 다만 rev-basic 시리즈 전체가 공유하는 공통 골격은 명확하다: 실행 시 `Input : ` 같은 문구를 출력하고 사용자 입력을 받은 뒤, 내부 검증 함수 하나를 호출해 그 반환값에 따라 `Correct` 또는 `Wrong`을 출력한다. 검증 함수의 내부 구현만 문제마다 다르며, 지금까지 REV-1001~REV-1004에서 본 것처럼 크게 "직접 문자열 비교(strcmp)", "문자 단위 하드코딩 비교", "배열 인덱스 비교(스트라이드 함정 포함)", "XOR과 산술이 섞인 수식" 네 가지 패턴이 반복해서 나타난다.

일부 검색 결과에서는 이 문제의 검증 함수가 `Compare_str()`처럼 이름이 붙어 있고, 저장된 문자열과 사용자 입력을 하나씩 비교한다는 설명이 나왔지만, 그 설명이 다른 rev-basic 문제(특히 XOR과 `2*i`가 섞인 수식)와 뒤섞여 인용된 것으로 보여 이 문제만의 확실한 수식이라고 단정하기 어렵다. 따라서 이 글에서는 특정 수식이나 정답 문자열을 확정적으로 제시하지 않고, 문제를 마주쳤을 때 스스로 검증 로직의 종류를 판별하는 절차를 안내하는 데 집중한다.

## 화면/코드에서 보이는 징후
- 실행하면 이전 rev-basic 문제들과 마찬가지로 입력 대기 문구가 출력되고, 임의 문자열 입력 시 `Wrong`이 출력된다.
- `main`을 디컴파일하면 입력 함수 호출 다음에 검증 함수 하나를 호출하고, 반환값이 참일 때만 `Correct`를 출력하는 구조가 보인다.
- 검증 함수 이름이 `sub_주소` 형태일 수도 있고, 심볼 정보가 남아 있다면 `Compare_str` 같은 이름이 그대로 보일 수도 있다.

## 가장 먼저 할 것
DIE로 파일 종류를 확인하고 실제로 실행해 입출력 문구를 확인한다. 그다음 IDA로 `main`을 F5로 디컴파일해 검증 함수를 찾아 그 안으로 들어간다. 이 단계에서 코드를 보고 "이게 strcmp인지, if 문 여러 개인지, for 루프+배열인지, XOR/산술 수식이 섞여 있는지"를 먼저 분류하는 것이 이후 절차를 결정한다.

## 단계별 절차
1. DIE로 파일 확인, 실행해 입출력 문구 확인.
2. IDA에서 `main`을 F5로 디컴파일, 검증 함수 호출부 확인.
3. 검증 함수 내부로 진입해 F5로 디컴파일.
4. 코드 형태를 REV-1001~REV-1004에서 본 네 가지 패턴(직접 비교/문자 단위 비교/배열 스트라이드/XOR+산술) 중 어느 것에 가까운지 분류한다.
5. 문자열 리터럴이 그대로 보이면 REV-1001 절차를, 하드코딩된 숫자 `if` 문이 이어지면 REV-1002 절차를, 배열과 루프가 보이면 REV-1003·REV-1004 절차를 그대로 적용해본다.
6. 어떤 패턴에도 딱 맞지 않는다면 Hex View로 실제 데이터 값을 먼저 확인하고, 비교식을 종이에 그대로 옮겨 적은 뒤 역산 가능 여부를 REV-0221 기준으로 판단한다.
7. 도출한 후보 문자열을 실제로 입력해 `Correct`가 나오는지 반드시 검증한다.

## 명령어/단축키
- IDA: `F5`(디컴파일), 데이터/문자열 더블클릭(참조 위치 이동), Hex View에서 원본 바이트 확인.
- DIE: 실행 파일 드래그 앤 드롭으로 헤더/컴파일러 확인.

## 출력 해석
검증 함수의 반환형이 `bool` 또는 `int`이고 0/1만 반환한다면, `main`에서 이 반환값을 `if (result)` 형태로 검사해 `Correct`/`Wrong`을 나누는 것이 rev-basic 시리즈의 공통 패턴이다. 반환값이 어떤 조건에서 1이 되는지만 정확히 추적하면 되고, 그 조건 안의 세부 연산이 문제마다 달라질 뿐이다.

## 흔한 실수
- 확실하지 않은 온라인 정보를 검증 없이 그대로 정답이라 믿고 제출 시도를 반복하는 것 — 이 글에서도 확정되지 않은 정보는 확정처럼 서술하지 않았다.
- 이전 rev-basic 문제와 겉모습이 비슷하다고 해서 검증 함수 내부까지 똑같을 것이라 가정하고 코드를 안 열어보는 것.
- 검증 함수 이름에 심볼이 남아 있다고 해서 그 이름만 보고 로직을 짐작하고 실제 디컴파일 코드를 확인하지 않는 것.

## 막혔을 때 다음 체크
- 직접 문자열 비교 패턴이 궁금하면 REV-1001(rev-basic-0)을 본다.
- 문자 단위 하드코딩 비교 패턴이 궁금하면 REV-1002(rev-basic-1)를 본다.
- 배열 인덱스 접근 폭 함정이 궁금하면 REV-1003(rev-basic-2)를 본다.
- XOR과 산술이 섞인 수식 역산이 궁금하면 REV-1004(rev-basic-3)를 본다.
- 다음 문제인 rev-basic-5의 인접 바이트 합산 패턴은 REV-1006을 참고한다.

## 미니 예제
아래는 이 시리즈에서 반복적으로 나타나는 "검증 함수 분류표"를 의사코드로 정리한 것이다. 실제 rev-basic-4의 코드가 아니라, 문제를 마주쳤을 때 먼저 대조해볼 수 있는 체크리스트다.

```text
검증 함수 안에 strcmp(...) 호출이 있다        -> REV-1001 패턴
검증 함수 안에 if (*(a1+i) != 상수) 가 반복    -> REV-1002 패턴
검증 함수 안에 for 루프 + 배열 비교, 캐스팅 다름 -> REV-1003 패턴
검증 함수 안에 XOR과 곱셈/덧셈이 함께 있음      -> REV-1004 패턴
```
