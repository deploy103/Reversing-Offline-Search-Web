## 한 줄 요약
드림핵 Silver 4 "Secure Mail"은 IDA로 열 PE/ELF 바이너리가 아니라 브라우저에서 실행되는 난독화된 HTML/JavaScript이며, 비밀번호는 6자리 생년월일(YYMMDD) 형식이라는 문제 설명의 힌트를 바탕으로 검증 함수를 정적으로 완전히 해독하는 대신 브라우저 콘솔에서 후보 값을 전부 넣어보는 무차별 대입으로 접근하는 것이 실전적인 풀이다.

## 언제 검색해야 하나
- 드림핵 문제인데 실행 파일이 아니라 `.html` 파일 하나가 주어져서 IDA/Ghidra로 열 대상이 없어 당황스러울 때
- 페이지 소스를 열어보니 `_0x9a220`, `_0x1a2b` 같은 16진수 이름의 함수/변수가 가득해서 눈으로 읽기가 거의 불가능할 때
- 로그인 버튼이나 "확인" 버튼을 누르면 특정 함수가 실행되는데, 그 함수가 맞으면 `document.write`로 뭔가를 출력하고 틀리면 `alert("Wrong")` 같은 걸 띄우는 구조를 확인했을 때
- 알고리즘을 완전히 역산하기보다 "그냥 다 넣어보면 되지 않을까"를 고민하고 있을 때

## 핵심 개념

### 웹 기반 리버싱과 네이티브 리버싱의 차이
이 문제는 컴파일된 바이너리가 아니라 브라우저가 그대로 해석하는 JavaScript다. 따라서 어셈블리를 읽을 필요가 없는 대신, 사람이 읽기 어렵게 변수/함수 이름을 16진수 형태(`_0x9a220`)로 바꾸고 문자열을 배열/함수 뒤에 숨기는 JS 난독화 도구(예: obfuscator.js류)의 결과물을 상대해야 한다. IDA의 Xref 대신 브라우저 개발자 도구(F12)의 Sources 탭, 콘솔(Console), 이벤트 리스너 확인 기능을 쓰는 것이 이 부류 문제의 기본 도구다.

### 검증 함수의 겉모습
버튼 클릭 이벤트에 연결된 `_0x9a220(pass.value)` 형태의 호출이 핵심이다. 이 함수 내부는 문자열 배열 난독화, 함수 하나로 여러 연산을 처리하는 디스패치 구조 등이 섞여 있어서 로직을 한 줄씩 눈으로 따라가기가 매우 피곤하다. 다만 실행 결과의 두 갈래는 명확히 구분된다 — 검증에 실패하면 `Wrong`류의 알림/함수가 호출되고, 성공하면 `document.write(...)`로 플래그 관련 내용을 페이지에 직접 그려 넣는다.

### 완전 역산 대신 입력 공간을 좁혀 브루트포스하는 전략
문제 설명(비밀번호는 6자리 생년월일)이 입력 형식에 대한 강한 힌트를 준다. `YYMMDD` 형식이라면 연도 2자리(00~99), 월 2자리(01~12), 일 2자리(01~31)의 조합으로 나올 수 있는 값은 많아야 대략 99 × 12 × 31 ≈ 36,800가지 수준이라 완전 탐색이 순식간에 끝난다. 즉 검증 함수의 내부 로직(어떤 해시/치환을 쓰는지)을 완벽히 이해하지 않아도, "그 함수에 문자열을 넣으면 참/거짓을 돌려준다"는 사실만 알면 브라우저 콘솔에서 함수를 직접 호출하는 반복문으로 정답을 찾아낼 수 있다.

### 콘솔에서 검증 함수를 직접 호출할 때의 함정
`_0x9a220`이 실패 시 `alert()`를 호출하도록 되어 있다면, 반복문 안에서 알림창이 뜨는 순간 스크립트 실행이 멈춰버려서(브라우저가 `alert`을 동기적으로 처리) 자동화된 대입이 매번 막힌다. 이를 피하려면 `window.alert`를 아무 것도 하지 않는 함수로 미리 덮어써서(`window.alert = function(){}`) 실패 알림이 흐름을 막지 못하게 만든 뒤 반복문을 돌려야 한다.

## 화면/코드에서 보이는 징후
- 페이지 소스나 개발자 도구 Sources 탭에 알아볼 수 없는 `_0xXXXXX` 이름의 변수/함수가 대량으로 보인다.
- "확인" 버튼에 `onclick="_0x9a220(pass.value)"` 또는 이벤트 리스너로 같은 함수가 연결되어 있다.
- 틀린 값을 넣으면 `Wrong`이라는 알림창이 뜨고, 맞는 값을 넣으면 페이지 내용이 `document.write`로 바뀐다.
- 문제 설명에 "비밀번호는 6자리 생일"이라는 문구가 있어 입력 형식이 좁게 제한되어 있음을 알 수 있다.

## 가장 먼저 할 것
F12로 개발자 도구를 열고 Console 탭에서 검증 함수 이름(`_0x9a220` 등, 실제 파일에서 확인한 이름)을 직접 타이핑해 존재를 확인한다. 전역 스코프에 노출된 함수라면 `typeof _0x9a220`이 `"function"`으로 나온다. 그다음 아무 값이나 넣어 `_0x9a220("123456")`처럼 직접 호출해보고 반환값이나 화면 변화를 관찰한다.

## 단계별 절차
1. 페이지를 로컬로 저장하거나 브라우저에서 열고 F12로 개발자 도구를 연다.
2. Sources 탭에서 전체 스크립트를 pretty-print(중괄호 { } 아이콘)로 정렬해 최소한 함수 경계를 눈으로 구분할 수 있게 만든다.
3. 필요하면 스크립트를 통째로 복사해 de4js 같은 오프라인/로컬 JS 정리 도구에 붙여넣어 변수명은 그대로지만 들여쓰기와 상수 폴딩이 정리된 형태로 다시 본다.
4. "확인" 버튼의 이벤트 핸들러를 찾아 실제로 호출되는 검증 함수 이름을 확정한다.
5. Console에서 `window.alert = function(){};`을 실행해 실패 알림이 코드 흐름을 막지 않게 만든다.
6. 문제 설명의 "6자리 생일" 힌트에 맞춰 연도(00-99)×월(01-12)×일(01-31) 3중 반복문을 짜고, 두 자리씩 0으로 패딩한 문자열을 검증 함수에 넣어 반환값/성공 여부를 확인한다.
7. 성공 조건(예: 반환값이 true, 또는 특정 DOM 변화가 감지됨)을 만족하는 조합을 찾으면 반복문을 멈추고 그 값을 실제 입력창에 넣어 최종적으로 `document.write`가 실행되는 것을 확인한다.

## 명령어/단축키
```javascript
// 개발자 도구 콘솔에서
window.alert = function(){};   // 실패 알림이 흐름을 막지 않도록 무력화

for (let y = 0; y < 100; y++) {
  for (let m = 1; m <= 12; m++) {
    for (let d = 1; d <= 31; d++) {
      const cand = String(y).padStart(2, '0')
                  + String(m).padStart(2, '0')
                  + String(d).padStart(2, '0');
      if (_0x9a220(cand)) {           // 실제 검증 함수 이름으로 교체
        console.log('FOUND:', cand);
      }
    }
  }
}
```
- F12 — 개발자 도구 열기
- Ctrl+Shift+K(파이어폭스) / Ctrl+Shift+J(크롬) — 콘솔만 바로 열기
- Sources 탭의 `{}` 아이콘 — 코드 예쁘게 정렬(pretty-print)

## 출력 해석
- 콘솔에 `FOUND: 000101` 같은 값이 찍히면 그 문자열이 실제 입력창에 넣을 정답 후보다. 여러 개가 나올 수 있으므로 각각 실제 입력창에 넣어 최종 `document.write` 결과가 플래그처럼 보이는지 확인한다.
- 검증 함수가 `true/false`가 아니라 `undefined`나 예외를 던진다면, 그 함수가 내부에서 DOM 요소(`pass`, 특정 id)를 직접 참조하고 있어서 콘솔에서 직접 호출할 때 해당 요소가 없어 실패하는 것일 수 있다 — 이때는 실제 입력창(`document.getElementById('pass').value = cand`)에 값을 넣고 버튼 클릭을 코드로 트리거(`btn.click()`)하는 방식으로 바꿔야 한다.
- 알림창이 계속 뜨면서 반복문이 멈춘다면 `window.alert` 오버라이드가 실행 전에 원래 함수가 이미 참조를 캐시해뒀을 가능성이 있으니, 페이지를 새로고침한 직후 가장 먼저 오버라이드 코드를 실행해야 한다.

## 흔한 실수
- 난독화된 JS를 어셈블리처럼 한 줄씩 손으로 완전히 해독하려다 시간을 다 쓰는 것 — 입력 공간이 충분히 좁으면 브루트포스가 훨씬 빠르다.
- `alert`를 막지 않고 반복문을 돌려서 첫 번째 실패에서 스크립트가 멈춰버리는 것을 못 깨닫고 "왜 콘솔이 응답이 없지"라며 헤매는 것.
- 검증 함수가 전역이 아니라 클로저 내부에 숨어 있어 콘솔에서 이름으로 직접 호출이 안 되는 경우를 고려하지 않는 것 — 이때는 버튼 클릭 이벤트 자체를 코드로 발생시키는 우회가 필요하다.
- 6자리를 무조건 "날짜"로만 보고 자릿수 패딩을 틀리게 하는 것(예: 5월을 "5"로 넣어서 실제로는 "05"가 필요한 경우 계속 실패로 나옴).
