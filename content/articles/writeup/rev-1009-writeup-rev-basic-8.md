## 한 줄 요약
rev-basic-8은 입력 문자열의 각 바이트에 -5를 곱해 8비트로 자른 값을 미리 저장된 정답 배열과 비교하는 rev-basic 시리즈 문제로, "곱하기" 연산이라는 것만 확인하면 후보값 0~255를 모두 대입하는 소규모 브루트포스로 원래 입력을 그대로 복원할 수 있다.

## 언제 검색해야 하나
- 드림핵 rev-basic-8을 IDA로 열었는데 `sub_140001000` 같은 이름 없는 함수 안에서 반복문이 입력값에 어떤 상수를 곱하고 있는 것처럼 보일 때
- `byte_140003000`처럼 `.rodata`/`.data` 영역에 있는 고정 배열과 변환된 입력값을 바이트 단위로 비교하는 구조를 발견했을 때
- "Input : "을 출력한 뒤 아무 문자열을 넣어도 항상 "Wrong"만 나오는 rev-basic 계열 문제에서 다음에 뭘 해야 할지 막막할 때

## 핵심 개념
드림핵 rev-basic 시리즈(rev-basic-0부터 순서대로 이어지는 연습용 크랙미 묶음)는 공통적으로 "사용자 입력을 어떤 규칙으로 변환한 뒤 하드코딩된 배열과 비교해서 Correct/Wrong을 출력"하는 구조를 가진다. rev-basic-8의 차이점은 그 변환 규칙이 단순 XOR나 덧셈이 아니라 **곱셈**이라는 점이다. 검증 함수는 입력 바이트 하나를 가져와 정수 -5를 곱하고, 그 결과를 8비트(`unsigned __int8`)로 잘라낸 값을 목표 배열의 같은 인덱스 값과 비교한다. 모든 자리가 일치해야 통과다.

곱셈 기반 검증은 이론적으로 "모듈러 역원(modular inverse)"을 구하면 역연산이 가능하다. -5를 256으로 나눈 나머지는 251이고, 251과 256은 서로소이므로 확장 유클리드 알고리즘으로 역원을 구할 수 있다(직접 계산하면 251 × 51 ≡ 1 (mod 256)이 성립한다). 즉 목표 바이트에 51을 곱해 8비트로 자르면 원래 입력 바이트가 나온다는 뜻이다. 다만 참고한 원문 풀이 작성자는 이 역연산 접근을 시도했지만 도중에 포기했다고 밝혔고, 대신 후보값 0부터 255까지를 모두 대입해 `(-5 * candidate) & 0xFF`가 목표 바이트와 같아지는 값을 찾는 전형적인 바이트 단위 브루트포스로 문제를 해결했다. 검증 구간이 21바이트(0x15) 정도로 작기 때문에 전체 탐색 공간은 21 × 256번의 비교밖에 되지 않아 순식간에 끝난다.

## 화면/코드에서 보이는 징후
- 실행하면 "Input : " 프롬프트가 뜨고 아무 값이나 넣으면 "Wrong"만 반복 출력
- IDA에서 `main`을 F5로 디컴파일하면 입력 버퍼를 받은 뒤 이름 없는 서브함수(`sub_140001000` 류) 호출 결과로 분기하는 `if` 문 하나만 보임
- 서브함수 내부에 `for (i = 0; i < 0x15; i++)` 형태의 루프와 `(unsigned __int8)(input[i] * -5)` 같은 캐스팅 곱셈식이 보임
- 비교 대상이 함수 안이 아니라 `.rodata` 근처에 고정 배열(`byte_140003000` 류)로 따로 정의되어 있음

## 가장 먼저 할 것
문자열 창(Shift+F12)에서 "Correct"와 "Wrong"을 먼저 찾고, 그 문자열을 참조하는 코드 위치로 Xref(Ctrl+X)를 따라가 검증 함수의 정확한 시작 주소를 확인한다. 그 다음 검증 함수를 F5로 디컴파일해서 비교 로직이 "더하기"인지 "곱하기"인지부터 구분한다. rev-basic-8은 곱하기이므로 XOR류 문제(REV-0199)와는 접근 방식이 다르다는 점을 여기서 확정해야 한다.

## 단계별 절차
1. Windows PowerShell에서 바이너리를 직접 실행해 "Input :" 프롬프트와 Wrong 출력을 확인한다.
2. IDA로 열고 `main`을 F5로 디컴파일해 입력을 받는 부분과 검증 함수 호출부를 찾는다.
3. 검증 함수(`sub_140001000`)를 F5로 디컴파일해 반복 횟수(0x15 = 21)와 곱셈 상수(-5)를 정확히 읽는다.
4. 비교 대상 배열(`byte_140003000`)을 Hex View나 IDA의 Export data 기능으로 21바이트 그대로 뽑아낸다.
5. Python으로 각 목표 바이트에 대해 0~255 전체를 대입해 `(candidate * -5) & 0xFF == target`을 만족하는 후보를 찾는 스크립트를 작성한다.
6. 21개 바이트 각각의 정답 후보를 이어붙여 완성된 입력 문자열을 만든다.
7. 복원한 문자열을 바이너리에 다시 입력해 "Correct"가 뜨는지 검증한다.

## 명령어/단축키
```text
IDA: Shift+F12 (문자열 창), Ctrl+X (Xref), F5 (디컴파일)
```
```python
target = [...]  # byte_140003000에서 뽑은 21바이트
answer = bytearray()
for t in target:
    for c in range(256):
        if ((c * -5) & 0xFF) == t:
            answer.append(c)
            break
print(bytes(answer))
```

## 출력 해석
브루트포스 스크립트가 21바이트를 모두 채우면 바로 사람이 읽을 수 있는 ASCII 문자열이 나온다. 만약 후보가 여러 개 나오거나 하나도 안 나온다면 곱셈 상수(-5)나 반복 횟수(0x15)를 잘못 읽었을 가능성이 크므로 디컴파일 결과를 다시 확인해야 한다. 참고한 원문 풀이에서 실제로 복원된 값은 `Did_y0u_brute_force?`였다.

## 흔한 실수
- `(input[i] * -5)`를 부호 있는 정수 그대로 비교해서 목표 배열 값과 안 맞는 것처럼 보이는 것 — 반드시 `& 0xFF`로 8비트로 잘라야 한다.
- 곱셈 상수 -5를 뺄셈(-5를 더하기)으로 착각해 REV-0200류 덧셈 역연산 공식을 그대로 적용하는 것.
- 모듈러 역원 계산을 시도하다가 확장 유클리드 계산이 복잡해 보여서 포기하는 것 — 검증 구간이 짧을 땐 굳이 역원을 구하지 않고 0~255 전체 대입으로도 충분하다.

## 막혔을 때 다음 체크
- 곱셈 기반 검증의 수학적 원리(모듈러 역원)가 헷갈리면 → REV-0887 모듈러 역원(Modular Inverse)이 코드에 나타나는 패턴
- 이 브루트포스가 시간 안에 끝날 탐색인지 판단하는 기준이 필요하면 → REV-0219 Brute Force가 가능한 입력 공간 계산
- 애초에 이 변환이 역연산 가능한 구조인지 판단하는 절차가 궁금하면 → REV-0221 역연산 가능한 알고리즘 판단법
- 같은 rev-basic 시리즈의 다른 문제 접근법이 필요하면 → REV-1010 [Write-up] rev-basic-9

## 미니 예제
검증 함수를 의사코드로 재구성하면 다음과 같다.
```c
int check(char *input) {
    for (int i = 0; i < 0x15; i++) {
        unsigned __int8 v = (unsigned __int8)(input[i] * -5);
        if (v != byte_140003000[i]) return 0;
    }
    return 1;
}
```
이 구조에서 `input[i]`를 모르는 상태로 `v`(목표값)만 알고 있으므로, `v`를 만들어내는 `input[i]` 후보를 0~255 중에서 찾는 것이 풀이의 전부다.
