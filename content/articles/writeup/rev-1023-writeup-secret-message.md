## 한 줄 요약
드림이가 이미지를 자체 제작한 런렝스(run-length) 계열 인코딩으로 암호화해 둔 문제로, 인코더 바이너리(`prob`)를 정적 분석해 인코딩 규칙을 파악한 뒤 그 역함수를 파이썬으로 구현해 원본 이미지를 복원하면 그 안에서 플래그를 얻을 수 있다.

## 언제 검색해야 하나
- secret message 문제에서 받은 `.enc` 파일이 표준 이미지 포맷 시그니처와 맞지 않아 이미지 뷰어로 바로 열리지 않을 때
- 같이 제공된 인코딩 프로그램(`prob` 등)을 열어봤는데 반복되는 바이트를 특별하게 처리하는 루프가 보일 때
- "이미지 복원 + 자체 인코딩 리버싱" 조합의 문제를 처음 만나 어디서부터 시작해야 할지 감이 안 잡힐 때

## 핵심 개념

### 문제 구성
secret message는 인코딩 프로그램(원본 실행 파일), 그 프로그램으로 원본 이미지를 인코딩한 결과 파일(`.enc`), 그리고 복원에 성공했을 때 결과를 볼 수 있는 이미지 뷰어 스크립트(`imageviewer.py`)로 구성된다. 즉 목표는 "`.enc` 파일을 원본 이미지 바이트로 되돌려서 imageviewer.py로 열면 플래그가 보인다"는 것으로 명확하다.

### 자체 제작 런렝스 인코딩 추정 구조
인코딩 프로그램을 IDA로 열어 핵심 루프를 분석하면, 표준 zlib/PNG 압축이 아니라 직접 구현한 단순한 반복 압축 방식이 쓰였다는 것을 알 수 있다. 이런 방식의 일반적인 동작은 다음과 같이 재구성할 수 있다. 입력 바이트를 하나씩 그대로 출력에 쓰다가, 같은 값이 연속으로 두 번 나오는 순간을 감지하면 그 뒤에 남은 반복 횟수(이미 쓴 두 개를 제외한 나머지 개수)를 숫자 한 바이트로 기록하고, 실제 반복되는 나머지 바이트들은 인코딩된 스트림에 쓰지 않고 건너뛴다. 예를 들어 원본이 `X Y Y Y Y Z`(Y가 4번 반복)라면, 인코더는 `X`를 쓰고, `Y`를 두 번 쓴 뒤(연속 2회 감지), 남은 반복 2회를 나타내는 카운트 바이트 `0x02`를 쓰고, 마지막으로 `Z`를 쓴다. 즉 6바이트였던 원본이 `X Y Y 0x02 Z` 5바이트로 줄어든다.

### 디코더 재구현
디코더는 이 규칙을 반대로 적용한다. 인코딩된 스트림을 한 바이트씩 읽다가, 방금 읽은 바이트가 바로 앞에 쓴 바이트와 같으면(연속 2회 감지) 다음에 오는 바이트는 데이터가 아니라 "추가로 몇 번 더 반복해야 하는가"를 나타내는 카운트로 해석하고, 그 개수만큼 같은 바이트를 출력에 추가로 채운다. 위 예시라면 `X Y Y 0x02 Z`를 읽어 `X`, `Y`, `Y`를 그대로 쓰고, 연속 2회를 감지했으니 다음 바이트 `0x02`를 카운트로 읽어 `Y`를 2번 더 채우고(`Y Y Y Y` 완성), 마지막 `Z`를 써서 원본 `X Y Y Y Y Z`를 정확히 복원한다.

## 화면/코드에서 보이는 징후
- 인코딩 프로그램 디스어셈블리에 이전 바이트(prev)를 저장해 뒀다가 현재 바이트와 비교하는 루프
- 비교 결과가 같을 때만 별도의 카운터 변수를 증가/기록하는 분기
- `.enc` 파일을 hexdump 했을 때 이미지 포맷 매직 넘버(BMP의 `42 4D`, PNG의 `89 50 4E 47` 등)가 전혀 안 보이고 대신 반복 바이트+숫자 패턴이 눈에 보임

## 가장 먼저 할 것
`.enc` 파일을 hexdump/xxd로 먼저 훑어보며 "같은 바이트가 두 번 연속된 뒤 이상한 한 바이트가 오고, 그 다음 다른 데이터가 이어지는" 패턴이 반복되는지 눈으로 확인한다. 이 패턴이 보이면 런렝스 계열 인코딩을 강하게 의심할 수 있고, 이후 인코딩 프로그램 분석은 그 의심을 확인하는 작업이 된다.

## 단계별 절차
1. 제공된 인코딩 프로그램을 IDA로 열어 `main`과 핵심 인코딩 함수를 찾는다.
2. 함수 내부에서 "이전 값과 비교", "같으면 카운트 처리" 로직을 찾아 정확한 조건과 바이트 순서를 확인한다.
3. `.enc` 파일 앞부분을 hexdump로 열어 분석한 로직이 실제 데이터와 맞는지 손으로 한 번 검증한다.
4. 분석한 인코딩 로직의 정확한 역함수를 Python으로 작성한다(위 개념 설명의 디코더 로직 참고).
5. `.enc` 파일 전체에 디코더를 적용해 `.raw` 파일을 만든다.
6. 제공된 `imageviewer.py`로 `.raw` 파일을 열어 이미지를 확인하고, 이미지 안에 보이는 문자열/그림에서 플래그를 얻는다.

## 명령어/단축키
```bash
xxd secretMessage.enc | head -20
python3 decode.py     # 직접 작성한 디코더 스크립트 실행
python3 imageviewer.py secretMessage.raw
```

## 출력 해석
디코더를 돌린 결과 파일 크기가 원본 이미지의 예상 크기(가로x세로x채널 수 등)와 맞아떨어지면 디코딩이 올바르게 됐다는 신호다. 크기가 안 맞으면 카운트 바이트의 의미(전체 반복 횟수인지, 추가 반복 횟수인지)를 반대로 해석했을 가능성이 크므로 그 부분부터 다시 검토한다.

## 흔한 실수
- 카운트 바이트를 "전체 반복 횟수"로 해석해야 하는데 "추가 반복 횟수"로(또는 반대로) 잘못 해석하는 것 — 작은 예시를 손으로 직접 인코딩/디코딩해보며 검증해야 한다.
- 연속 2회 감지 조건을 놓쳐서 반복이 1회만 있어도 카운트 바이트가 있다고 착각하는 것.
- 디코딩된 `.raw` 파일에 표준 이미지 헤더가 없어서 일반 이미지 뷰어로 바로 열려고 하다가 실패하는 것 — 문제에서 제공하는 전용 `imageviewer.py`를 반드시 사용해야 한다.

## 막혔을 때 다음 체크
- 커스텀 인코딩을 분석해 검증 로직을 파이썬으로 재현하는 일반적 방법이 필요하면 REV-0222 검증 루틴을 Python으로 그대로 재현하기를 본다.
- REP 계열 명령어로 반복되는 데이터를 다루는 어셈블리 패턴이 헷갈리면 REV-0080 REP 프리픽스를 본다.
- 비슷하게 "변형된 데이터를 원래대로 되돌리는" 접근이 필요한 다른 문제는 REV-1021 [Write-up] Recover를 참고한다.

## 미니 예제
```python
def decode(enc_bytes):
    out = bytearray()
    i = 0
    while i < len(enc_bytes):
        b = enc_bytes[i]
        out.append(b)
        if len(out) >= 2 and out[-2] == b:
            i += 1
            count = enc_bytes[i]
            out.extend([b] * count)
        i += 1
    return bytes(out)

# XYY0x02Z -> XYYYYZ
print(decode(bytes([0x58, 0x59, 0x59, 0x02, 0x5A])))
```
이 스크립트는 위에서 재구성한 "연속 2회 감지 + 카운트 바이트" 규칙을 그대로 코드로 옮긴 것이며, 실제 문제의 `.enc` 파일에도 같은 원리가 적용되는지는 직접 hexdump로 검증해야 한다.
