## 한 줄 요약
rev-basic-3은 `byte_140003000[i] == (i XOR input[i]) + 2*i` 형태의 수식으로 검증하는 유형이며, XOR의 자기 역원 성질(`A XOR B = C`이면 `C XOR B = A`)을 이용해 `input[i] = i XOR (byte_140003000[i] - 2*i)`로 정리하면 바로 역산된다.

## 언제 검색해야 하나
- 드림핵 rev-basic-3 검증 함수에서 `^`(XOR)과 `2 * i`가 함께 섞인 식을 만났는데 어떻게 손으로 풀어야 할지 막막할 때
- 배열 값과 입력값 사이에 단순 비교가 아니라 산술 연산이 끼어 있어서, 앞선 rev-basic-0~2 문제처럼 그냥 값을 읽기만 해서는 답이 안 나올 때
- "역연산이 가능한 구조인지 아닌지"부터 판단이 안 서서 시간을 낭비하고 있을 때

## 핵심 개념
지금까지의 rev-basic 문제들은 "저장된 값을 그대로 읽거나(strcmp), 하드코딩된 숫자와 비교하거나(char-by-char), 배열 접근 방식만 헷갈리게(stride)" 만드는 수준이었다면, rev-basic-3부터는 실제로 산술/논리 연산이 검증 로직에 들어간다. 검증 함수는 입력 길이만큼(이 문제는 0x18 = 24바이트) 루프를 돌며, 각 인덱스 `i`에 대해 미리 정해진 배열 `byte_140003000[i]`의 값이 `(i XOR 입력[i]) + 2*i`와 같은지 확인한다. 하나라도 다르면 즉시 실패로 끝난다.

이 식을 손으로 역산하려면 연산 순서를 정확히 지켜야 한다. 원래 식은 `배열값 = (i XOR 입력) + 2*i`이므로, 먼저 양변에서 `2*i`를 빼서 `배열값 - 2*i = i XOR 입력`을 만들고, 그다음 XOR의 성질을 이용해 양변에 다시 `i`를 XOR하면 `입력 = i XOR (배열값 - 2*i)`가 된다. 뺄셈을 먼저 하고 XOR을 나중에 해야 하며, 순서를 반대로 하면 전혀 다른 값이 나온다는 점이 이 문제의 핵심 함정이다. 이런 "역연산 가능한 선형 식 + XOR" 조합은 REV-0221에서 다루는 역연산 판단법과 REV-0199의 XOR 역산 개념을 그대로 적용할 수 있는 사례다.

## 화면/코드에서 보이는 징후
- 실행 흐름은 이전 문제들과 동일: `Input : ` → `%256s` 입력 → 검증 함수 → `Correct`/`Wrong`.
- 검증 함수 디컴파일 결과에 `for (i = 0; i < 0x18; ++i) { if (byte_140003000[i] != (i ^ a1[i]) + 2 * i) return 0i64; }` 형태의 코드가 보인다.
- `byte_140003000`라는 이름의 전역 바이트 배열이 24개 값으로 채워져 있다.

## 가장 먼저 할 것
DIE로 파일 확인 후 IDA에서 검증 함수를 F5로 디컴파일해 정확한 수식과 반복 횟수(`0x18` = 10진수 24)를 확인한다. 수식을 확인했다면 종이나 메모장에 먼저 "배열값 = (i XOR 입력) + 2*i" 형태로 정확히 옮겨 적고, 그다음에 역산 공식을 유도한다. 손으로 24개를 직접 계산하기보다는 바로 파이썬 스크립트로 넘어가는 것이 실수를 줄인다.

## 단계별 절차
1. DIE로 파일 확인, 실행해 입출력 문구 확인.
2. IDA에서 `main` → 검증 함수 진입, F5로 디컴파일해 정확한 수식과 반복 횟수를 확인.
3. `byte_140003000`를 더블클릭해 데이터 위치로 이동, Hex View에서 24개의 바이트 값을 순서대로 읽어 리스트로 만든다.
4. 수식 `배열값 = (i XOR 입력) + 2*i`을 `입력 = i XOR (배열값 - 2*i)`로 정리한다.
5. 파이썬으로 `i`를 0부터 23까지 돌리며 각 값을 계산하고 `chr()`로 변환한다.
6. 만들어진 24글자 문자열을 실행 파일에 입력해 `Correct`가 나오는지 검증한다.

## 명령어/단축키
- IDA: `F5`(디컴파일), 데이터 이름 더블클릭 후 Hex View에서 바이트 확인.
- Python: 아래 미니 예제와 같은 짧은 스크립트로 전체 배열을 한 번에 역산.

## 출력 해석
`(i ^ a1[i]) + 2 * i`에서 `^`는 비트 단위 XOR을 의미하고, `+`는 그 결과에 `2*i`를 더하는 일반 정수 덧셈이다. 연산자 우선순위상 `^`가 `+`보다 먼저 계산되므로 코드에 쓰인 순서 그대로 "먼저 XOR, 그다음 더하기"가 맞다. 역산할 때는 이 순서를 반대로 뒤집어 "먼저 빼기, 그다음 XOR"을 해야 한다는 점이 중요하다. 만약 순서를 헷갈려 XOR을 먼저 풀어버리면 전혀 다른 문자가 나온다.

## 흔한 실수
- 연산 순서를 무시하고 `(배열값 XOR i) - 2*i`처럼 XOR과 뺄셈 순서를 바꿔서 역산해 틀린 문자가 나오는 것.
- `2 * i`에서 `i`가 0부터 시작한다는 것을 깜빡하고 1부터 시작해서 전체 결과가 한 인덱스씩 밀리는 것.
- 배열 크기(0x18 = 24)를 16진수 그대로 10진수처럼 읽어 18바이트만 처리하고 마는 것.
- 파이썬에서 뺄셈 결과가 음수가 될 수 있다는 것을 고려하지 않고 그대로 `chr()`에 넣어 오류가 나거나 이상한 문자가 나오는 것(바이트 값이므로 `& 0xFF`로 8비트로 맞춰줘야 안전하다).

## 막혔을 때 다음 체크
- XOR 없이 배열 접근 폭만 헷갈리는 형태라면 REV-1003(rev-basic-2)을 먼저 복습한다.
- 비슷하게 XOR과 상수가 섞인 형태가 또 나온다면 REV-1005(rev-basic-4)도 유사한 구조일 가능성이 있으니 비교해서 본다.
- XOR 역산 자체의 원리가 헷갈리면 REV-0057(XOR 연산)과 REV-0199(XOR 반복 변환 역산)를 먼저 본다.

## 미니 예제
```python
# byte_140003000에서 읽은 24개의 값이라고 가정
table = [...]  # Hex View에서 읽은 실제 24바이트

flag = ''
for i, v in enumerate(table):
    ch = (v - 2 * i) & 0xFF
    ch ^= i
    flag += chr(ch)

print(flag)
```
`(v - 2*i) & 0xFF`로 먼저 8비트 범위로 맞춘 뒤 `i`를 XOR하면, 코드에 쓰인 `(i ^ input) + 2*i`를 정확히 반대로 되돌린 값이 나온다.
