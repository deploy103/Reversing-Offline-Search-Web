## 한 줄 요약
rev-basic-6은 입력 문자를 인덱스로 사용해 256개짜리 치환 배열 `b`를 조회하고, 조회한 값을 또 다른 고정 배열 `a`와 비교하는 이중 테이블 구조라서, 값을 직접 계산하는 게 아니라 "배열 `a`의 각 값이 배열 `b`에서 몇 번째 위치에 있는지"를 거꾸로 검색해야 정답이 나온다.

## 언제 검색해야 하나
- 드림핵 rev-basic-6에서 입력 문자가 그대로 비교되는 게 아니라 어떤 배열의 "인덱스"로 쓰이는 것 같은데, 그다음에 뭘 해야 할지 모를 때
- 코드에 256개짜리 배열과 18개(또는 다른 길이)짜리 배열 두 개가 동시에 나와서 어느 게 입력이고 어느 게 정답 기준인지 헷갈릴 때
- x64dbg로 함수 이름 없이 주소만 보면서 분석하다가 흐름을 놓쳤을 때

## 핵심 개념
지금까지의 문제들은 입력 문자에 산술/논리 연산을 적용한 결과를 정답 배열과 비교했다. rev-basic-6은 연산 대신 "조회(lookup)"를 쓴다. 코드는 입력 문자열의 `i`번째 문자를 인덱스로 삼아 256개짜리 배열 `b`(치환 테이블, 코드에서는 특정 메모리 주소로 표시됨)의 `b[입력[i]]` 값을 읽어온다. 그리고 이 값을 정답 길이(0x12 = 18)만큼의 고정 배열 `a`의 `a[i]`와 비교해서, 일치하면 다음 문자로 넘어가고 불일치하면 실패한다.

이 구조에서는 입력 문자 자체가 배열 `b`의 인덱스이기 때문에, `a[i]`와 `b`를 알고 있어도 "`b`의 어느 인덱스에서 그 값이 나왔는지"를 찾아야 원래 입력 문자를 알 수 있다. 즉 `b`를 순방향으로 조회하는 게 아니라, `a[i]`와 값이 같은 원소를 `b` 안에서 순차 탐색(0~255까지 검사)해 그 인덱스 번호를 찾아내는 역방향 탐색이 필요하다. 이는 REV-0907에서 다루는 "두 배열이 서로를 참조하며 변환하는 이중 테이블 패턴"과 REV-0215의 Lookup Table 기반 변환의 실제 예시다.

## 화면/코드에서 보이는 징후
- 실행 흐름은 이전 문제들과 동일: `Input : ` → 입력 → `Correct`/`Wrong`.
- 디스어셈블리/디컴파일에서 사용자 입력 바이트를 그대로 다른 배열의 오프셋으로 사용하는 코드(`movzx`로 바이트를 읽은 뒤 그 값을 다시 다른 배열 주소에 더해서 참조하는 형태)가 보인다.
- 함수에 이름이 없고(스트립되었거나 IDA가 이름을 못 붙인 경우) 주소로만 식별되는 경우가 많아, 어셈블리 수준에서 두 배열의 크기(하나는 256개, 하나는 18개)를 직접 확인해야 한다.

## 가장 먼저 할 것
DIE로 파일 확인 후, x64dbg에서 문자열 참조로 `Input : ` 위치를 찾아 검증 함수로 진입한다. 함수에 이름이 없다면 먼저 두 개의 배열이 각각 몇 바이트인지(하나는 256바이트짜리 치환 테이블, 하나는 정답 길이만큼의 짧은 배열)를 어셈블리에서 확인해 어느 쪽이 "치환 테이블"이고 어느 쪽이 "정답 기준값"인지 구분한다.

## 단계별 절차
1. DIE로 파일 확인, 실행해서 입출력 문구 확인.
2. x64dbg에서 문자열 참조 검색으로 `Input : ` 출력 위치를 찾고, `Correct`/`Wrong` 분기 직전의 `call`로 진입.
3. 함수 내부에서 입력 바이트가 어떤 배열의 인덱스로 쓰이는지(즉 `movzx` 등으로 읽은 값을 다시 주소 계산에 사용하는 지점) 확인.
4. 256바이트 치환 배열(`b`)과 18바이트 정답 기준 배열(`a`)을 각각 덤프해 파이썬 리스트로 옮긴다.
5. 파이썬에서 `a`의 각 값에 대해 `b.index(값)`(또는 직접 반복문으로 순차 탐색)을 수행해 원래 입력 문자를 하나씩 복원한다.
6. 복원된 18개의 인덱스 값을 `chr()`로 변환해 문자열을 만든다.
7. 실제로 입력해 `Correct`가 나오는지 검증한다.

## 명령어/단축키
- x64dbg: 우클릭 → Search for → String references, `F2`(브레이크포인트), `F7`/`F8`(Step Into/Over), Dump 창에서 배열 주소로 이동(Ctrl+G)해 바이트 값 확인.
- Python: `b.index(v)` 또는 `[i for i, x in enumerate(b) if x == v]`로 값이 몇 번째 인덱스에 있는지 탐색.

## 출력 해석
`b[input[i]] == a[i]`가 모든 `i`에서 성립해야 통과라는 것은, "입력 문자를 인덱스로 넣었을 때 나오는 치환값이 미리 정해진 기준값과 같아야 한다"는 의미다. `b`가 1:1 치환(같은 값이 중복되지 않는 순열)이라면 `a[i]`에 대응하는 인덱스는 정확히 하나만 존재하므로, 순차 탐색으로도 항상 유일한 답을 찾을 수 있다.

## 흔한 실수
- `a`와 `b`의 역할을 반대로 이해해서, `a`를 치환 테이블로 보고 `b`를 인덱스로 조회하려는 것 — 어느 배열이 256개짜리(치환 테이블)이고 어느 게 정답 길이만큼(18개)인지 크기를 먼저 확인해야 한다.
- `b`에 중복된 값이 있을 수 있다는 가능성을 고려하지 않고 `index()` 결과 하나만 믿었다가, 실제로는 여러 인덱스 중 하나만 정답인 경우를 놓치는 것(이 문제의 `b`가 순열이라면 문제 없지만, 항상 확인하는 습관이 필요하다).
- 어셈블리에서 배열 인덱싱에 쓰이는 레지스터 크기(바이트 단위 `movzx`인지, 워드/더블워드인지)를 잘못 읽어 인덱스 계산이 틀리는 것.
- 함수 이름이 없다고 해서 분석을 포기하는 것 — 이름이 없어도 배열 크기와 참조 패턴만으로 충분히 로직을 재구성할 수 있다.

## 미니 예제
```python
a = [...]   # 정답 기준 배열(18개)
b = [...]   # 256개짜리 치환 테이블

flag = ''
for target in a:
    idx = b.index(target)  # b[idx] == target 이 되는 idx를 찾는다
    flag += chr(idx)

print(flag)
```
`b.index(target)`는 파이썬 리스트에서 특정 값이 처음 나타나는 위치를 찾아주는 함수이며, `b`가 순열(치환) 테이블이라는 전제하에 이 방식으로 항상 유일한 원래 문자를 복원할 수 있다.
