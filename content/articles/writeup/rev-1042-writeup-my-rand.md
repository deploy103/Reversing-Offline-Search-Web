## 한 줄 요약
"my rand"(Bronze 2)는 드림핵 CTF Season 7 Round #14(Div2)에도 리버싱 카테고리 문제로 등재되어 있고 코인 구매형 공식 write-up이 존재하는 것까지 확인되지만, 상세 로직을 다루는 공개 write-up은 찾지 못했다. 이름 그대로 "직접 구현한(my) 난수 생성기"를 분석해 그 출력을 예측하거나 역산하는 문제로 추정된다. "randzzz"(REV-1047, Silver 4)라는 이름이 비슷한 별개의 드림핵 문제도 존재하므로 혼동하지 않아야 한다.

## 언제 검색해야 하나
- "my rand"를 열었는데 표준 `rand()`/`srand()`가 아니라 직접 구현한 것처럼 보이는 난수 생성 함수가 있어서 예측 방법이 막막할 때
- 검색 결과에 이름이 비슷한 "randzzz"라는 다른 드림핵 문제가 섞여 나와서 헷갈릴 때
- 프로그램이 무작위 값을 생성해 그 값을 맞추라고 요구하는데, 매 실행마다 값이 달라지는 것처럼 보여서 무작위성을 깨는 방법이 필요할 때

## 핵심 개념
검색으로 확인한 사실은 "my rand"가 드림핵 CTF Season 7 Round #14(Div2)에 리버싱 카테고리 문제(코인 구매형 Official Writeup 존재)로 등장한다는 것이다. 검색 과정에서 "randzzz"라는 유사한 주제의 다른 드림핵 문제(Season 4 Round #4, Div2 — `get_flag()`를 호출하기 위해 난수를 맞추는 문제)도 함께 발견되었는데, 이는 별도의 문제이며 이 저장소에서는 REV-1047로 따로 다룰 예정이므로 "my rand"와 섞어서 서술하지 않는다.

"my rand"라는 이름에서 "my"가 강조하는 것은 표준 라이브러리의 `rand()`가 아니라 문제 제작자가 직접 구현한 난수 생성 로직일 가능성이다. 이런 유형의 문제에서 일반적으로 나타나는 설계와 대응 전략은 다음과 같다.

- 직접 구현한 PRNG가 선형 합동 생성기(LCG, `x = (a*x + c) mod m` 형태)라면, 연속된 출력값 몇 개만 관찰해도 계수 `a`, `c`, `m`을 역산할 수 있다(REV-0891, REV-0883 참고).
- `srand(time(NULL))`처럼 시드를 현재 시간으로 초기화하고 표준 `rand()`를 그대로 쓰는 경우라면, 실행 시점의 대략적인 시간 범위 안에서 가능한 시드를 모두 시도해보는 무차별 대입이 유효하다(REV-0893, REV-0894 참고).
- 난수처럼 보이지만 실제로는 결정적인 값(예: 특정 전역 변수, 카운터)을 단순히 뒤섞어 출력하는 "가짜 난수"일 수도 있다. 이 경우는 REV-0331에서 다루는 "같은 입력인데 다르게 보이는 결과"에 해당할 수 있다.

Bronze 2라는 난이도를 고려하면, Mersenne Twister처럼 복잡한 PRNG보다는 LCG나 시간 기반 시드처럼 비교적 접근하기 쉬운 구조일 가능성이 높다고 추정할 수 있으나, 이는 확정된 사실이 아니다.

## 화면/코드에서 보이는 징후
- 매 실행마다 다른 값이 출력되거나 요구되는데, 프로그램 내부에 자체 구현한 것으로 보이는 난수 함수(곱셈, 시프트, XOR 연산으로 상태를 갱신하는 짧은 함수)가 존재
- `time`, `srand`, `rand` 등의 표준 API가 import되어 있는지 여부로 표준 라이브러리 기반인지 직접 구현인지 구분 가능
- 상태 변수(시드) 하나를 계속 갱신하며 그 값에서 일부 비트만 뽑아 출력값으로 쓰는 구조

## 가장 먼저 할 것
Import 목록에서 `rand`, `srand`, `time`이 있는지 먼저 확인한다. 있다면 표준 PRNG 예측 전략(REV-0893, REV-0894)을 적용하고, 없다면 자체 구현된 PRNG 함수를 찾아 그 갱신 공식을 수식으로 옮겨 적는다.

## 단계별 절차
1. Import 목록으로 표준 `rand`/`srand` 사용 여부 확인
2. 표준 라이브러리 기반이면 시드가 고정값인지 `time(NULL)` 기반인지 확인 후 REV-0893/REV-0894 절차 적용
3. 자체 구현이면 상태 갱신 함수를 찾아 `x_{n+1} = f(x_n)` 형태의 수식으로 정리
4. 연속된 출력값을 실행/디버깅으로 몇 개 수집해 계수(LCG라면 a, c, m)를 역산
5. 역산한 공식으로 다음 출력값을 예측하거나, 필요한 특정 값이 나오는 시드/입력을 계산

## 명령어/단축키
```text
IDA: Imports 탭에서 rand/srand/time 검색
x64dbg: 난수 함수 호출 직후 반환값(EAX/RAX)을 여러 번 기록해 수열 패턴 확인
Python: 수집한 수열로 LCG 계수 역산(연립방정식 또는 확장 유클리드 알고리즘 활용)
```

## 출력 해석
연속된 몇 개의 출력값 사이에 일정한 배율/증가값 관계가 보인다면 LCG일 가능성이 높다(REV-0891). 값들이 훨씬 불규칙하다면 Mersenne Twister류(REV-0892)이거나 해시 기반일 수 있으므로 접근법을 바꿔야 한다.

## 흔한 실수
- "randzzz"(REV-1047)와 이름이 비슷하다는 이유로 그 문제의 풀이 방향을 그대로 "my rand"에 적용하는 것 — 서로 다른 문제임
- 자체 구현 PRNG를 표준 `rand()`로 착각해 표준 라이브러리 기준 시드 역산 공식을 그대로 대입하는 것
- 출력값을 한두 개만 보고 패턴을 단정해 계수 역산에 필요한 최소 샘플 수를 채우지 않는 것

## 막혔을 때 다음 체크
- 자체 구현 PRNG가 선형 합동 생성기처럼 보이면 → REV-0891 LCG(Linear Congruential Generator) 기반 난수 알아보기, REV-0883 흔한 시드 기반 PRNG 상수 빠른 참조
- 시드가 `rand()`/`srand()` 표준 조합이라면 → REV-0893 rand()/srand() 시드 기반 문제 접근법
- 시드가 시간 기반이라면 → REV-0894 시간 기반 시드(seed = time())를 역산하는 접근
- 어떤 알고리즘 유형인지부터 판단이 안 되면 → REV-0885 알고리즘 유형별 판별 체크리스트
