## 한 줄 요약
섹션 엔트로피 값이 7.5~8.0에 가까워서 패킹을 의심했는데 Detect It Easy가 패커 시그니처를 찾지 못한다면, 실제로는 **패킹이 아니라 압축된 리소스(아이콘, 이미지, ZIP으로 묶인 데이터), 암호화된 설정 파일, 또는 이미 컴파일된 압축 라이브러리 데이터**가 특정 섹션에 들어 있어서 그 섹션만 엔트로피가 높게 나오는 것일 가능성이 크다.

## 언제 검색해야 하나
- PE-bear나 다른 분석 도구에서 특정 섹션(주로 `.rsrc`, `.data`, 또는 커스텀 이름의 섹션)의 엔트로피 값이 7.5 이상으로 나오는데, Detect It Easy로 스캔했을 때 알려진 패커/프로텍터 시그니처가 전혀 안 잡힐 때
- `.text`(코드) 섹션은 정상적인 엔트로피(보통 6.0 전후)를 보이는데, 다른 섹션 하나만 유독 높게 나올 때
- IDA로 열었을 때 코드는 정상적으로 함수가 잘 인식되는데도 엔트로피 경고만 계속 신경 쓰일 때
- "엔트로피가 높으면 무조건 패킹"이라고 배웠는데 실제 사례에서는 그렇지 않아 헷갈릴 때

## 핵심 개념

### 엔트로피는 "패킹 여부"가 아니라 "데이터의 무작위성"을 재는 지표다
섀넌 엔트로피(Shannon entropy)는 어떤 데이터 블록 안의 바이트 값 분포가 얼마나 균등하게 퍼져 있는지를 0~8 사이의 값으로 나타낸다(8에 가까울수록 모든 바이트 값이 골고루 나타나 예측하기 어렵다는 뜻). 압축된 데이터와 암호화된 데이터는 원리상 바이트 분포가 균등해지도록 만들어지므로 둘 다 엔트로피가 높게 나온다. 즉 **엔트로피가 높다는 것은 "압축되었거나 암호화된 데이터가 있다"는 뜻이지, "실행 파일 전체가 패커로 감싸여 있다"는 뜻이 정확히 일치하는 것은 아니다.**

### 정상적인 프로그램에서도 특정 섹션만 엔트로피가 높을 수 있는 경우
- **`.rsrc` 섹션에 PNG/JPEG 아이콘, 압축된 리소스가 포함된 경우**: 이미지 포맷 자체가 이미 압축되어 있으므로 엔트로피가 높다. 이는 패킹과 무관한 정상적인 현상이다.
- **애플리케이션이 자체적으로 ZIP, 7z 등의 압축 라이브러리를 내장하고 그 데이터를 리소스나 별도 섹션에 박아 둔 경우**: 예를 들어 설치 프로그램이 압축된 설치 데이터를 리소스에 통째로 넣어두면 그 섹션의 엔트로피는 매우 높지만, 이는 설치 프로그램의 정상적인 설계다.
- **암호화 라이브러리를 사용하는 프로그램이 내장된 인증서, 키, 또는 암호화된 설정 파일을 리소스로 갖고 있는 경우**: 암호화된 데이터 역시 엔트로피가 높다.
- **이미 컴파일 타임에 압축된 서드파티 라이브러리 데이터(폰트, 사운드 등)를 정적으로 링크한 경우**.

### 패킹과 구별하는 실전 기준
패킹된 실행 파일은 보통 다음 특징을 "함께" 보인다. 이 중 엔트로피 하나만 높고 나머지가 정상이라면 패킹이 아닐 가능성이 크다.
- 코드 섹션(`.text`)의 엔트로피까지 비정상적으로 높다(정상 컴파일된 코드는 엔트로피가 대략 5.5~6.5 범위인 경우가 많다).
- Import Table의 함수 개수가 비정상적으로 적다(패커가 원본 IAT를 감췄기 때문).
- Entry Point가 표준 컴파일러 스텁이 아니라 낯선 코드를 가리킨다.
- Detect It Easy가 알려진 패커/프로텍터 시그니처를 찾아낸다(이것이 가장 직접적인 증거다).

## 화면/코드에서 보이는 징후
- PE-bear의 섹션 목록에서 `.rsrc` 또는 유사한 데이터 섹션 하나만 엔트로피 막대가 빨간색/높은 값으로 표시되고, `.text`는 정상 범위로 표시된다.
- Detect It Easy 결과 창에 "Packer" 항목이 비어 있거나 컴파일러 이름(예: "Microsoft Visual C/C++")만 정상적으로 표시된다.
- 리소스 뷰어(Resource Hacker 등)로 `.rsrc`를 열어보면 실제로 PNG/ICO/JPEG 형식의 이미지나 ZIP 시그니처(`PK\x03\x04`)로 시작하는 바이너리 데이터가 들어 있다.
- IDA에서 함수 개수, Strings 창의 문자열 개수가 정상적인 프로그램 수준으로 풍부하다.

## 가장 먼저 할 것
엔트로피가 높게 나온 섹션이 정확히 어느 섹션인지부터 확인한다. 코드 섹션(`.text`)인지 리소스/데이터 섹션(`.rsrc`, `.data`)인지에 따라 해석이 완전히 달라진다.

## 단계별 절차
1. PE-bear 또는 Detect It Easy의 섹션별 엔트로피 뷰에서, 높게 나온 섹션의 이름과 크기를 정확히 확인한다.
2. 해당 섹션이 `.rsrc`라면, Resource Hacker나 PE-bear의 리소스 뷰어로 내용을 직접 열어본다. PNG(`\x89PNG`), JPEG(`\xFF\xD8\xFF`), ZIP(`PK\x03\x04`) 같은 알려진 매직 바이트로 시작하면 정상적인 압축 포맷 데이터일 뿐이다.
3. `.text` 섹션의 엔트로피도 함께 확인한다. `.text`가 정상 범위(대략 5.5~6.5)라면 패킹이 아니라고 볼 근거가 강해진다. `.text`까지 높다면 다시 패킹을 의심해야 한다.
4. Detect It Easy로 "Deep scan" 옵션까지 켜서 다시 스캔해본다 — 얕은 스캔에서는 놓친 시그니처를 심층 스캔에서 잡아내는 경우가 있다.
5. Import Table 항목 개수와 Strings 창의 문자열 풍부함을 확인한다. 둘 다 정상적으로 많다면 패킹이 아니라는 결론에 무게가 실린다.
6. 그래도 확신이 안 서면, 실제로 x64dbg에서 잠깐 실행해보고 Entry Point 코드가 정상적인 컴파일러 스텁(`push ebp` 계열 프롤로그, CRT 초기화 API 호출)인지 직접 눈으로 확인한다.

## 명령어/단축키
- PE-bear: 파일 열기 → 좌측 트리 `Section Headers` → 각 섹션 행에 표시되는 Entropy 값 확인
- Detect It Easy: 파일 드래그 앤 드롭 → 우측 상단 "Options" → Deep scan 체크 → 재스캔
- Resource Hacker: 파일 열기 → 좌측 트리에서 리소스 타입별로 확인, 이미지 리소스는 미리보기 지원
- 매직 바이트 확인: HxD로 해당 섹션 오프셋을 열어 첫 4~8바이트 직접 확인

## 출력 해석
- `.rsrc` 섹션만 높고 `.text`가 정상이며 Import Table도 풍부하다면 → 패킹이 아니라 리소스 자체가 압축/암호화된 정상 케이스다.
- `.text`와 `.rsrc` 모두 높고 Import Table이 빈약하다면 → 패킹일 가능성이 높다.
- Deep scan 후에도 패커 시그니처가 전혀 안 잡히고, Entry Point 코드가 정상 컴파일러 스텁으로 보인다면 → 패킹이 아니라고 결론 내려도 무방하다.

## 흔한 실수
- 섹션 이름과 관계없이 파일 전체의 평균 엔트로피 하나만 보고 "패킹됐다"고 단정하는 것 — 반드시 섹션별로 나눠서 봐야 한다.
- `.rsrc`에 이미지가 들어 있는 것을 발견하고도 "그래도 혹시 모르니" 언패킹 도구를 이것저것 시도하며 시간을 낭비하는 것.
- Detect It Easy를 얕은 스캔 한 번만 돌리고 결과가 없다고 바로 결론짓는 것 — Deep scan을 한 번 더 시도해보는 것이 안전하다.
- 반대로 패커 시그니처가 실제로 잡혔는데도 "리소스 때문일 것"이라고 넘겨짚고 무시하는 것 — 시그니처가 잡혔다면 그것이 가장 강한 증거이므로 우선한다.

## 막혔을 때 다음 체크
- `.text` 섹션까지 높게 나온다면 → REV-0228(Entropy가 높은 Section의 의미)로 돌아가 기본 판단 기준을 다시 확인한다.
- 여전히 패킹인지 판단이 애매하다면 → REV-0964(패킹 여부 판단이 애매해서 시간을 낭비할 때)를 참고한다.
- Import Table 개수를 어떻게 판단해야 할지 모르겠다면 → REV-0229(Import가 거의 없는 PE를 봤을 때)를 참고한다.

## 미니 예제
```text
1) PE-bear로 setup.exe 열기
   -> .text  entropy 6.1 (정상 범위)
   -> .rdata entropy 5.3
   -> .rsrc  entropy 7.92 (높음, 패킹 의심)
2) Detect It Easy Deep scan 실행 -> Packer: (없음), Compiler: Microsoft Visual C++ 2019
3) Resource Hacker로 .rsrc 내부 확인
   -> RCDATA 리소스 하나가 4.2MB, 첫 4바이트가 "PK\x03\x04"(ZIP 시그니처)
4) 설치 프로그램이 설치 데이터 전체를 ZIP으로 압축해 리소스에 내장한 것으로 확인
   => 패킹이 아니라 정상적인 설치 프로그램 구조로 결론
```

## 관련 글
- REV-0228 — Entropy가 높은 Section의 의미
- REV-0964 — 패킹 여부 판단이 애매해서 시간을 낭비할 때
- REV-0961 — 패커 시그니처는 잡히는데 도구가 자동 언패킹을 실패할 때

## 출처/검증
- 섀넌 엔트로피의 정의와 압축/암호화 데이터가 높은 엔트로피를 보이는 원리: 정보 이론의 표준 정의(Shannon, "A Mathematical Theory of Communication") 및 Detect It Easy/PE-bear 등 분석 도구의 엔트로피 계산 방식 설명 문서 기준(2026-09-09 검증).
- 리소스 섹션에 포함되는 이미지/압축 포맷의 매직 바이트: 각 포맷의 공개 명세(PNG, JPEG, ZIP 파일 포맷 스펙) 기준.
