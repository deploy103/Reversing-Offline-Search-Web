## 한 줄 요약
VMProtect나 Themida 같은 상용 프로텍터는 압축이 아니라 코드 가상화·다중 안티 디버깅·안티 덤프를 겹겹이 쌓아 만든 제품이라 ASPack식 "OEP 찾고 덤프"가 통하지 않으며, CTF/실무 맥락에서는 완전한 언패킹을 목표로 삼기보다 "정말 언패킹이 필요한가"부터 재질문하는 것이 현실적인 첫 단계다.

## 언제 검색해야 하나
- DIE 또는 entry point 코드 패턴으로 `VMProtect`, `Themida`, `WinLicense`, `Enigma Protector` 등이 식별되었을 때
- x64dbg를 붙이자마자 프로세스가 즉시 종료되거나 이상 동작할 때
- entry point 코드가 짧은 압축 해제 루프가 아니라 반복적인 "핸들러 디스패치" 구조(가상 머신 인터프리터처럼 보이는 코드)로 되어 있을 때
- "언패킹에 며칠씩 걸린다"는 이야기를 듣고 다른 접근법이 없는지 찾고 있을 때

## 핵심 개념

### 상용 프로텍터는 "패커"가 아니라 "프로텍터"다
UPX/ASPack/PECompact/MPRESS는 실행 파일 크기를 줄이는 것이 목적인 순수 압축기(REV-0939~0941)다. 반면 VMProtect, Themida, WinLicense, Enigma Protector 같은 상용 제품은 목적 자체가 "리버싱을 최대한 어렵게 만드는 것"이다. 이들은 보통 다음을 동시에 제공한다.

- **코드 가상화(Code Virtualization)**: 원본 x86/x64 명령어를 자체 바이트코드로 변환하고, 그 바이트코드를 해석 실행하는 커스텀 VM을 심는다(REV-0947 참고). 원본 명령어는 디스어셈블리에서 아예 사라진다.
- **다중 레이어 안티 디버깅**: `IsDebuggerPresent`, PEB 체크(REV-0235/REV-0236) 수준을 훨씬 넘어서 커널 드라이버 탐지, 타이밍 체크(REV-0237), 하드웨어 브레이크포인트 탐지, VM/샌드박스 탐지(REV-0238)까지 결합한다.
- **안티 덤프(Anti-Dump)**: 메모리 덤프 자체를 방해하는 기법(섹션 권한을 실행 직전에만 잠깐 풀었다 잠그기, 실행 중 코드 재암호화 등, REV-0950 참고)을 적용한다.
- **가상 머신 여러 개, OEP 여러 개**: 진짜 OEP로 한 번에 점프하지 않고, 여러 개의 가짜 점프/가짜 VM 진입을 거치게 만들어 "찾았다고 생각한 OEP가 사실은 또 다른 스텁"인 경우가 흔하다.

이런 이유로 REV-0227/REV-0944에서 다루는 "pushad 찾기 → OEP 점프 확인 → 덤프" 절차는 상용 프로텍터 앞에서는 사실상 작동하지 않는다. 해당 절차는 순수 압축 패커를 전제로 한 것이다.

### 현실적인 대응 우선순위
CTF나 실무에서 상용 프로텍터를 만났을 때 실제로 도움이 되는 순서는 다음과 같다.

1. **이 문제가 정말 "완전한 언패킹"을 요구하는가부터 재확인한다.** 대부분의 CTF는 프로텍터 자체를 뚫는 것이 아니라 그 안의 로직(비밀번호 비교, 키 생성 알고리즘 등)을 알아내는 것이 목표다. 완전히 언패킹된 깨끗한 실행 파일을 만들 필요 없이, 프로텍터가 씌워진 채로 동적 분석(API 후킹, 메모리 브레이크포인트, 특정 문자열 참조 위치 찾기)만으로 답을 얻을 수 있는 경우가 많다.
2. **공개된 언패커/버전 정보를 먼저 찾는다.** VMProtect/Themida는 워낙 유명해서 특정 구버전에 대한 공개 연구(학회 발표, 블로그, 오래된 언패커 프로젝트)가 존재하는 경우가 있다. 다만 최신 버전은 계속 강화되므로 기대 수준을 낮게 잡아야 한다.
3. **동적 분석 우선 전략으로 전환한다.** 문자열이 나타나는 순간, 특정 API가 호출되는 순간에 브레이크포인트를 걸어 그 시점의 레지스터/메모리 상태만 관찰하는 방식은 완전한 언패킹 없이도 가능한 경우가 많다.
4. **팀/시간 예산을 정한다.** 실무 악성코드 분석이든 CTF든, 상용 프로텍터 완전 우회는 숙련자도 며칠이 걸릴 수 있는 작업이다. "이 문제/샘플에 얼마나 시간을 쓸 가치가 있는가"를 먼저 판단하는 것이 비효율적인 삽질을 막는다.

## 화면/코드에서 보이는 징후
- DIE가 `VMProtect x.x`, `Themida/WinLicense x.x` 등을 명시적으로 표시(다만 최신 버전은 시그니처를 숨기려 해서 "Unknown" 또는 오탐이 나올 수도 있음)
- entry point 코드가 반복적인 `switch`형 디스패치 구조(핸들러 테이블 인덱싱)로 보임 — 일반 함수처럼 안 보이고 거대한 하나의 루프
- x64dbg를 붙이자마자 프로세스가 즉시 종료되거나, 타이틀바 조작·하드웨어 브레이크포인트 삭제 같은 이상 동작 발생
- 문자열이 `.rodata`/`.rdata`에 평문으로 거의 없고, 실행 중에만 잠깐 복호화되어 나타남

## 가장 먼저 할 것
DIE로 어떤 제품/버전인지부터 정확히 식별한다. 그 다음 "이 CTF 문제/샘플에서 진짜 필요한 것이 완전한 언패킹인가, 아니면 특정 로직 하나만 알면 되는가"를 먼저 판단한다. 후자라면 동적 분석 우선 전략(REV-0953의 5분 판단 절차와 연결)으로 바로 전환하는 것이 훨씬 실용적이다.

## 단계별 절차
1. DIE로 프로텍터 제품/버전 식별
2. 문제/샘플의 목표가 "로직 파악"인지 "완전 언패킹"인지 구분
3. 로직 파악이 목표라면: 목표 문자열/API에 대한 참조를 동적으로 추적(메모리 브레이크포인트, API 후킹)
4. 완전 언패킹이 불가피하다면: 공개된 해당 버전 전용 연구/도구가 있는지 먼저 검색
5. 없다면 코드 가상화 개념(REV-0947)과 안티 디버깅 우회를 단계적으로 학습하며 접근 — 이는 별도의 심화 과정임을 인지
6. 시간 예산을 정하고, 초과 시 동적 분석으로 전략 전환

## 명령어/단축키
- DIE: `File → Open`으로 프로텍터 시그니처 확인
- x64dbg: 프로세스가 즉시 종료될 경우 `Options → Preferences`에서 안티 디버깅 관련 스텔스 옵션(TitleBar 숨기기, PEB BeingDebugged 패치 등) 활성화 후 재시도
- 메모리 브레이크포인트: 문자열/버퍼 주소에 `Set Memory Breakpoint on Access`로 접근 시점 포착

## 출력 해석
- x64dbg가 붙자마자 프로세스가 사라진다면 프로세스 생성 초기 단계에서부터 강력한 안티 디버깅이 걸려 있다는 뜻이다. 이 경우 REV-0235/REV-0236의 기초 우회로는 부족할 수 있다.
- 코드가 거대한 `switch`형 디스패처로 보이는데 개별 case가 매우 단순한 연산(레지스터 하나 더하기 등)만 반복한다면 이는 코드 가상화 VM 핸들러일 가능성이 매우 높다(REV-0947).

## 흔한 실수
- 상용 프로텍터를 만났는데도 UPX/ASPack용 절차(pushad 찾기)를 그대로 시도하며 시간을 낭비하는 것.
- "완전히 언패킹해야만 분석할 수 있다"고 단정하고 동적 분석 우회 전략을 처음부터 배제하는 것.
- 최신 버전 VMProtect/Themida를 개인 학습 목적으로 몇 시간 안에 완전히 뚫을 수 있을 것이라 기대하는 것 — 실제로는 전문 연구자도 오랜 시간을 들이는 작업이다.
- 상업적 크랙 목적으로 접근하는 것 — 이 저장소의 범위는 CTF/교육/방어적 리버싱이며 상용 소프트웨어 라이선스 우회는 다루지 않는다.

## 막혔을 때 다음 체크
- 코드 가상화 구조 자체를 더 이해하고 싶다면 → REV-0947 코드 가상화(Code Virtualization) 개념 소개
- 디버거가 붙자마자 종료된다면 → 안티 디버깅 개념(REV-0235, REV-0236, REV-0239) 재확인
- 안티 덤프 때문에 메모리 덤프가 깨진다면 → REV-0950 Anti-Dump 기법(덤프 방지) 개념 소개
- 시간 대비 효율을 재판단하고 싶다면 → REV-0953 패킹/난독화 여부를 실전에서 5분 안에 판단하는 절차

## 미니 예제
```text
DIE 결과: "VMProtect v3.x -> VMProtect Software"

전략 A (로직 파악 목표):
  1. 목표 문자열("Correct!", "Wrong password" 등)에 메모리 접근 브레이크포인트
  2. 그 시점 콜스택 역추적으로 비교 로직 근처 확인
  3. 완전 언패킹 없이 답 도출

전략 B (완전 언패킹 목표, 고난도):
  1. 코드 가상화 핸들러 패턴 학습(REV-0947)
  2. 안티 디버깅 레이어 하나씩 우회
  3. 시간이 오래 걸릴 수 있음을 인지하고 진행
```
대부분의 CTF 상황에서는 전략 A가 훨씬 실용적이다.

## 관련 글
- REV-0947 — 코드 가상화(Code Virtualization) 개념 소개
- REV-0950 — Anti-Dump 기법(덤프 방지) 개념 소개
- REV-0953 — 패킹/난독화 여부를 실전에서 5분 안에 판단하는 절차
- REV-0235 — IsDebuggerPresent 우회 개념
- REV-0236 — PEB BeingDebugged 검사 우회 개념
- REV-0239 — Exception 기반 안티디버깅 기초

## 출처/검증
- VMProtect/Themida/WinLicense/Enigma Protector가 코드 가상화, 다중 안티 디버깅, 안티 덤프를 결합한 상용 제품이라는 설명은 각 제품의 공식 제품 소개 페이지 및 다수의 공개 리버싱/malware 분석 컨퍼런스 발표 자료에서 공통적으로 확인되는 내용을 기준으로 정리했다.
- "완전 언패킹보다 동적 분석 우선"이라는 실전 전략은 다수의 CTF 라이트업과 리버싱 교육 자료에서 반복적으로 권장되는 접근법을 요약한 것이다(2026-09-09 검증).
