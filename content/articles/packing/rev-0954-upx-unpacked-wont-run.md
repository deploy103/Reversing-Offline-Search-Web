## 한 줄 요약
`upx -d`가 "Unpacked 1 file"이라고 성공 메시지를 띄웠는데도 결과 파일이 실행되지 않는다면, 대부분은 UPX 자체의 실패가 아니라 원본 파일이 **UPX 버전과 다르게 수정(변형/이중 패킹/파일 손상)되어 있어서** 압축 해제 로직이 헤더 일부를 잘못 복원했기 때문이다.

## 언제 검색해야 하나
- `upx -d packed.exe`를 실행했을 때 에러 없이 끝났는데, 생성된 파일을 실행하면 아무 창도 뜨지 않거나 즉시 사라질 때
- 언패킹된 파일을 더블클릭하면 "이 앱을 열 수 없습니다" 또는 "%1은(는) 올바른 Win32 응용 프로그램이 아닙니다" 메시지가 뜰 때
- 원본 패킹된 파일은 잘 실행되는데, `upx -d` 결과물만 실행이 안 될 때
- Detect It Easy로 언패킹 후 파일을 다시 열었을 때 PE 구조 자체가 이상하다고 표시될 때

## 핵심 개념
UPX는 원본 실행 파일을 압축한 뒤, PE 헤더의 섹션 정보(`.text`, `.rdata`, `.rsrc` 등)를 `UPX0`, `UPX1` 같은 자체 섹션으로 재구성하고, 압축 해제 스텁 코드를 심어 새 파일을 만든다. `upx -d`는 이 반대 과정을 수행해서 원래의 섹션 레이아웃과 엔트리 포인트를 복원하려고 시도한다.

문제는 이 복원 과정이 "UPX가 원본을 압축했을 때 기록해 둔 메타데이터"에 전적으로 의존한다는 점이다. 다음과 같은 경우 이 메타데이터가 깨지거나 UPX가 잘못 해석해서, 압축은 풀리지만 **PE 구조가 실행 가능한 상태로 완전히 복원되지 않는다.**

1. **파일이 UPX로 패킹된 후 추가로 수정되었다** — 예를 들어 리소스 에디터로 아이콘을 바꿨거나, 다른 도구로 섹션을 덧붙였다면 UPX가 기록해 둔 오프셋과 실제 파일 오프셋이 어긋난다.
2. **이중 패킹(다른 패커 위에 UPX를 덧씌우거나, UPX 위에 다른 패커를 덧씌운 경우)** — `upx -d`는 UPX 레이어 한 겹만 벗겨내므로, 그 아래 여전히 다른 패커의 스텁이 남아 있어 정상 실행 파일이 아니다.
3. **UPX 버전 불일치** — CTF 문제 출제자가 특정 버전의 UPX로 패킹했는데, 로컬에 설치된 UPX가 다른(특히 더 최신이거나 더 오래된) 버전이면 내부 포맷 해석 방식의 미세한 차이 때문에 복원이 어긋날 수 있다.
4. **의도적인 방어 장치(anti-unpack)** — 일부 크랙미/챌린지는 UPX 헤더의 특정 필드를 수동으로 조작해서(예: 체크섬 필드를 일부러 깨뜨리거나, 매직 넘버는 유지하되 섹션 크기 필드만 변경) `upx -l`/`upx -d`가 겉보기엔 동작하는 것처럼 보이지만 실제로는 잘못된 결과를 내놓도록 만들어 둔 경우도 있다.

## 화면/코드에서 보이는 징후
- `upx -d` 명령 출력이 `Unpacked 1 file` 로 정상 종료된 것처럼 보인다.
- 결과 파일 크기는 원본보다 커졌지만(압축 해제 후 정상적인 크기 증가), 더블클릭하면 반응이 없거나 즉시 종료된다.
- Detect It Easy로 언패킹 결과 파일을 다시 열었을 때 "Unknown" 또는 헤더 파싱 경고가 뜬다.
- PE-bear로 열었을 때 섹션 테이블의 `VirtualAddress`/`RawSize` 값이 서로 겹치거나, 엔트리 포인트 주소가 어느 섹션에도 속하지 않는 것으로 보인다.

## 가장 먼저 할 것
언패킹된 파일을 실행하기 전에, 먼저 그 파일을 Detect It Easy로 다시 스캔해서 "정말 UPX 흔적이 완전히 사라졌는지", 그리고 PE 헤더가 유효한 구조로 보이는지부터 확인한다. 이 단계를 건너뛰고 바로 실행해서 원인 추측에 시간을 쓰지 않는 것이 중요하다.

## 단계별 절차
1. `upx -V`로 로컬 UPX 버전을 확인하고, 가능하면 최신 안정 버전으로 다시 시도한다. 이미 최신이라면 구버전(예: 3.9x)도 함께 시도해본다 — 버전 간 미세한 차이로 복원 결과가 달라지는 경우가 실제로 있다.
2. 언패킹 전에 원본 파일을 다시 Detect It Easy로 스캔해서, 정말 "UPX"만 단독으로 잡히는지 확인한다. 다른 패커 이름이 함께 뜨거나 "Unknown" 항목이 섞여 있으면 이중 패킹을 의심한다(REV-0960 참고).
3. `upx -d -o unpacked.exe packed.exe` 처럼 출력 파일명을 명시적으로 지정해서, 원본 파일을 덮어쓰지 않고 결과를 따로 확인한다.
4. 결과 파일을 PE-bear 또는 Detect It Easy로 다시 열어 섹션 테이블, 엔트리 포인트, Import Table이 정상적으로 파싱되는지 확인한다.
5. 여전히 실행이 안 되면 `upx -d`에 의존하지 않고, x64dbg로 원본 패킹된 파일을 직접 실행해 OEP까지 도달한 뒤 수동으로 메모리 덤프를 뜨는 방식(REV-0227)으로 전환한다. 자동 도구가 실패하는 순간부터는 수동 절차가 더 신뢰할 수 있다.

## 명령어/단축키
```text
upx -V                          # 설치된 UPX 버전 확인
upx -l packed.exe                # 패킹 정보(원본 크기, 압축률 등) 확인, 실제 복원 없이 미리보기
upx -d -o unpacked.exe packed.exe  # 출력 파일명을 지정해 언패킹
upx -d -f packed.exe              # 강제(force) 모드로 재시도
```
- Detect It Easy: 파일을 드래그해서 열고 좌측 하단 결과 확인, "Deep scan"으로 더 정밀하게 재스캔
- PE-bear: 파일 열기 후 좌측 트리에서 Section Headers 클릭해 RawSize/VirtualSize 확인

## 출력 해석
- `upx -l`에서 압축률(`Ratio`)이 정상적인 범위(대략 30~60%)로 나오면 UPX가 파일 구조를 올바르게 인식했다는 뜻이다. 이 값이 비정상적으로 낮거나(거의 압축 안 됨) 명령이 오류를 내면 애초에 UPX 표준 포맷이 아닐 가능성이 크다.
- `upx -d` 후 파일 크기가 원본 패킹 파일보다 커졌다면 압축 해제 자체는 일어난 것이다. 문제는 "커졌다"가 아니라 "구조가 올바른가"이므로 크기만 보고 성공을 판단하면 안 된다.
- PE-bear에서 엔트리 포인트가 어떤 섹션에도 속하지 않는다고 표시되면, 헤더 복원이 실패한 결정적 증거다.

## 흔한 실수
- `upx -d`의 종료 메시지가 "성공"이라고 나온 것만 보고 바로 실행해버려서, 왜 실행이 안 되는지 원인을 UPX 바깥(안티바이러스, 권한 문제 등)에서 찾으려 헤매는 것.
- 이중 패킹 가능성을 확인하지 않고 `upx -d`를 반복 실행하는 것 — UPX 레이어가 한 겹뿐이라면 두 번째 실행은 "not packed" 오류만 반복된다.
- 로컬 UPX 버전이 오래되었거나 너무 최신이라는 점을 의심하지 않고, 같은 버전으로만 계속 재시도하는 것.
- 결과 파일을 원본 파일명으로 덮어써서, 실패했을 때 원본 패킹 파일로 되돌아갈 수 없게 만드는 것 — 항상 `-o`로 별도 파일명을 지정해야 한다.

## 막혔을 때 다음 체크
- 언패킹된 덤프 자체가 x64dbg/IDA에서 크래시를 낸다면 → REV-0955(언패킹한 덤프가 크래시가 날 때)를 참고한다.
- Detect It Easy 결과에 패커가 두 개 이상 겹쳐 보인다면 → REV-0960(멀티레이어 패킹)을 참고한다.
- Import Table이 텅 비어 있다면 → REV-0958(Import Table이 언패킹 후에도 비어있을 때)을 참고한다.
- 애초에 UPX가 맞는지부터 의심된다면 → REV-0225(UPX인지 확인하는 법)로 돌아가 확인한다.

$ upx -l packed.exe

위처럼 `upx -l`의 압축률과 `upx -d`의 결과가 정상적으로 보여도, 실제 실행은 실패할 수 있다. 이 경우 Detect It Easy로 `unpacked.exe`를 다시 스캔해 PE 헤더가 유효한지부터 확인해야 한다.

## 관련 글
- REV-0225 — UPX인지 확인하는 법
- REV-0227 — 수동 언패킹 개념 OEP와 Dump
- REV-0955 — 언패킹한 덤프가 크래시가 날 때
- REV-0958 — Import Table이 언패킹 후에도 비어있을 때
- REV-0960 — 여러 겹으로 패킹된(Multi-layer) 바이너리를 만났을 때

## 출처/검증
- UPX 명령행 옵션(`-l`, `-d`, `-o`, `-f`)과 압축 해제 동작 방식: UPX 공식 문서(github.com/upx/upx, `upx --help` 및 프로젝트 README) 기준 (2026-09-09 검증).
- 이중 패킹/헤더 변형 시 UPX 복원이 실패할 수 있다는 점은 다수의 공개 리버싱 교육 자료와 UPX 프로젝트 이슈 트래커에서 공통적으로 보고되는 현상을 일반화한 것으로, 실제 원인은 샘플마다 다를 수 있어 개별 검증이 필요하다.
