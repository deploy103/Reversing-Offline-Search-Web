## 한 줄 요약
지역 변수는 함수가 호출될 때마다 새로 만들어지는 스택 프레임 안에 있으므로 `[rbp-N]`처럼 현재 프레임 기준 상대 주소로 접근하고, 전역 변수는 프로그램이 로드되는 동안 항상 같은 위치(.data/.bss)에 있으므로 `[rip+심볼]`(x64) 같은 고정된 절대/RIP-상대 주소로 접근한다 — 이 "주소가 프레임마다 바뀌는가, 항상 같은가"의 차이가 전역/지역을 구분하는 가장 확실한 단서다.

## 언제 검색해야 하나
- 변수 두 개가 같은 함수 안에서 쓰이는데 하나는 `[rbp-8]` 식으로, 다른 하나는 `[rip+0x2f50]` 식으로 접근되어 왜 방식이 다른지 궁금할 때
- IDA/Ghidra가 어떤 변수를 `off_404040`, `dword_404040` 처럼 고정 주소 이름으로 표시하고 다른 변수는 그냥 `var_4`, `local_18`로 표시할 때 그 의미 차이가 헷갈릴 때
- 재귀 호출이나 여러 스레드 상황에서 "이 변수는 호출마다 다른 값을 가질 수 있는가"를 판단해야 할 때
- 함수를 벗어나도 값이 유지되는 변수를 찾아야 하는데 스택 기반 주소만 보고 다 지역 변수로 오해하고 있을 때

## 핵심 개념
지역 변수는 함수의 스택 프레임(`rbp` 또는 `rsp` 기준) 안에 생성되므로, 함수가 다시 호출되면 완전히 새로운 메모리 위치에 새 값으로 만들어진다. 반면 전역 변수는 실행 파일의 `.data`(초기값 있음) 또는 `.bss`(초기값 0) 섹션에 컴파일 시점부터 고정된 위치를 가지며, 프로그램이 종료될 때까지 그 주소가 바뀌지 않는다.

```c
int g_counter = 100;      /* 전역 변수: .data 섹션에 고정 위치 */

void bump(void) {
    int local = 5;         /* 지역 변수: 현재 호출의 스택 프레임 안 */
    g_counter += local;
}
```

x86-64, `-O0`, Intel 문법(PIE 환경, RIP 상대 주소):

```asm
bump:
    push    rbp
    mov     rbp, rsp
    mov     DWORD [rbp-4], 5          ; local = 5   -- 스택 프레임 기준 상대주소 [rbp-4], 호출마다 새로 생김
    mov     eax, DWORD [rbp-4]        ; eax = local
    add     eax, DWORD [rip+g_counter] ; eax += g_counter -- RIP 상대지만 실제로는 고정된 절대 위치를 가리킴
    mov     DWORD [rip+g_counter], eax ; g_counter = eax   -- 같은 고정 위치에 다시 씀
    pop     rbp
    ret
```

`local`은 `[rbp-4]`로 접근되며, `bump()`를 다시 호출하면 `rbp` 자체가 그때그때 다른 스택 프레임을 가리키므로 `local`의 실제 메모리 주소도 매번 달라진다. 반면 `g_counter`는 `[rip+g_counter]`로 접근되는데, 이는 "현재 명령어 주소에서 상대적으로 몇 바이트 떨어진 위치"라는 뜻이지만 그 결과로 계산되는 절대 주소는 프로그램이 로드된 이후 항상 동일하다 — 즉 `bump()`를 백 번 호출해도 `g_counter`는 항상 같은 메모리 셀을 가리킨다.

## 화면/코드에서 보이는 징후
- `[rbp-N]`, `[rbp+N]`, `[rsp+N]` 형태(프레임/스택 포인터 상대) → 지역 변수 또는 인자
- `[rip+심볼]`(x64) 또는 고정된 숫자 주소 리터럴(x86, 예: `[0x404040]`) → 전역 변수, `static` 변수, 문자열 리터럴 등
- IDA/Ghidra에서 `var_`, `local_`, `arg_` 접두사가 붙은 이름은 스택 기반(지역), `off_`, `dword_`, `byte_`, `qword_` 등 주소 기반 이름은 고정 위치(전역/정적)
- 여러 함수에서 같은 심볼(`[rip+g_counter]`)을 공유해서 접근하면 그 변수는 전역이라는 확실한 증거

## 가장 먼저 할 것
문제의 변수가 `rbp`/`rsp` 상대 오프셋으로 접근되는지, 아니면 고정 심볼/주소로 접근되는지부터 확인한다. 여러 함수가 똑같은 고정 주소를 공유해서 읽고 쓴다면 그 변수는 반드시 전역(또는 static)이다.

## 단계별 절차
1. 변수 접근 명령어의 주소 표현이 `rbp`/`rsp` 기반인지 `rip`(또는 고정 리터럴) 기반인지 구분한다.
2. `rip` 기반이라면 IDA/Ghidra에서 그 심볼로 더블클릭 이동해 `.data`/`.bss` 섹션에 있는지 확인한다.
3. 그 심볼을 다른 함수들도 참조하는지 Xref(교차 참조, IDA `X` 키)로 확인해 전역 여부를 재검증한다.
4. `rbp`/`rsp` 기반 변수는 함수 진입/종료 시 스택 프레임과 함께 생성/소멸되므로, 함수 밖에서는 그 주소가 의미가 없다는 점을 기억하고 분석 범위를 그 함수 안으로 한정한다.

## 명령어/단축키
- IDA: 주소 위에서 `X`(Xref to) — 여러 함수가 참조하면 전역 확정. 심볼 더블클릭으로 `.data`/`.bss` 위치 확인
- Ghidra: 심볼 위에서 우클릭 → References To, Data Type Manager에서 섹션 확인
- GDB: `info address 변수명`으로 전역 변수의 고정 주소 확인, `p &local_var`로 지역 변수의 현재 호출에서의 스택 주소 확인(재호출 시 값이 바뀌는지 비교)
- x64dbg: 심볼 창에서 `.data`/`.bss` 섹션 매핑 확인, 스택 창에서 `rbp` 기준 오프셋 직접 관찰

## 출력 해석
같은 `[rip+g_counter]` 표현이 여러 함수에서 반복해 나타난다면, 그 값은 함수 호출과 무관하게 공유되는 상태(전역 상태)라는 뜻이다. 반대로 `[rbp-4]`는 함수가 실행되는 동안에만 유효한 임시 저장소이며, 함수가 `ret`으로 끝나 스택 프레임이 해제되면 그 값도 의미를 잃는다(다만 메모리 자체가 즉시 지워지는 건 아니므로 디버거로 여전히 읽을 수는 있다 — 다만 신뢰할 수 없는 값이다).

## 흔한 실수
- `[rbp-N]` 오프셋 숫자가 같다고 해서 서로 다른 함수의 지역 변수를 같은 변수로 착각하는 것 — 오프셋은 함수마다 독립적으로 재사용된다.
- PIE 바이너리에서 `[rip+심볼]`을 보고 "주소가 실행마다 바뀌니 전역이 아니다"라고 오해하는 것 — ASLR로 로드 베이스 자체는 바뀌어도, 그 베이스에 대한 상대 위치(오프셋)는 항상 고정이며 같은 실행 안에서는 절대 주소도 고정이다.
- `static` 지역 변수를 지역 변수라고 생각해서 `[rbp-]`로 접근할 거라 예상하는 것 — 실제로는 전역처럼 `[rip+]`로 접근된다(REV-1076 참고).
- 함수 인자(`[rbp+N]`, 인텔 스택 프레임 관례상 양수 오프셋인 경우 등)를 지역 변수와 혼동하는 것 — 인자도 스택 기반이지만 호출자가 넘겨준 값이라는 출처가 다르다.

## 막혔을 때 다음 체크
- `[rbp-]`가 아닌데도 함수 안에서 선언된 변수처럼 보인다면 → REV-1076 static 지역 변수가 어셈블리에서 보이는 패턴
- 이 전역 변수가 다른 함수에서 재귀적으로 계속 갱신되는 형태라면 → REV-1066 재귀 함수가 어셈블리/스택에서 보이는 패턴(예정)
- 전역/지역 구분의 더 자세한 배경 지식이 필요하면 → REV-0353 전역 변수와 지역 변수를 메모리 위치로 구분하는 법

## 미니 예제
두 함수가 같은 전역 변수를 공유하는 모습을 보면 전역 여부가 명확해진다.

```c
int g_total = 0;

void add_one(void) {
    g_total = g_total + 1;
}

void add_ten(void) {
    g_total = g_total + 10;
}
```

```asm
add_one:
    push    rbp
    mov     rbp, rsp
    mov     eax, DWORD [rip+g_total]   ; g_total 읽기
    add     eax, 1
    mov     DWORD [rip+g_total], eax   ; g_total 쓰기
    pop     rbp
    ret

add_ten:
    push    rbp
    mov     rbp, rsp
    mov     eax, DWORD [rip+g_total]   ; add_one과 완전히 같은 심볼(같은 고정 위치)을 가리킴
    add     eax, 10
    mov     DWORD [rip+g_total], eax
    pop     rbp
    ret
```

`add_one`과 `add_ten` 두 함수가 서로 다른 스택 프레임을 갖고 있음에도 정확히 같은 `[rip+g_total]` 심볼을 공유한다는 사실이, 이 값이 두 함수 호출 사이에 계속 유지되는 전역 상태라는 것을 증명한다.

## 출처/검증
- 전역 변수가 `.data`/`.bss` 섹션에 고정 배치되고 지역 변수가 스택 프레임 안에 배치되는 규칙: ELF/PE 실행 파일 섹션 구조 및 System V AMD64 ABI(스택 프레임 관례) 기준.
- x64 PIE 환경에서 전역 변수 접근이 `RIP`-상대 주소로 인코딩되는 방식: Intel 64 and IA-32 Architectures Software Developer's Manual(RIP-relative addressing) 기준 (2026-09-10 검증).
