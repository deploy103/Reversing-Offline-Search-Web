## 한 줄 요약
IDA의 Strings 창(`Shift+F12`)은 기본 설정상 5자 이상의 8비트 ASCII(`C`-style) 문자열만 스캔하고 UTF-16(`C16`, "Unicode C-style") 문자열은 기본적으로 켜져 있지 않을 수 있으므로, Strings 창에서 `Setup...`(단축키 `Ctrl+U`)을 열어 "Unicode C-style (16 bits)" 항목을 체크하고 다시 스캔하면 대부분 해결된다.

## 언제 검색해야 하나
- Windows GUI 프로그램(`L"문자열"` 형태의 와이드 문자열을 많이 쓰는 프로그램)인데 `Shift+F12`로 연 Strings 창에 결과가 이상하게 적을 때
- 코드에서 분명히 `lea rdx, aHello`처럼 문자열을 참조하는 것 같은데, Strings 창을 아무리 찾아도 해당 문자열이 안 보일 때
- 디스어셈블리에서 문자열로 보이는 데이터 영역(예: `.rdata`)에 바이트가 있는데 IDA가 이를 문자열로 인식하지 못하고 그냥 숫자 배열로 보여줄 때

## 핵심 개념
IDA의 Strings 창은 데이터베이스 전체를 스캔해서 "문자열처럼 보이는" 바이트 시퀀스를 찾아 목록으로 보여주는 기능이다. 이 스캔은 다음 두 가지 조건에 의해 결과가 제한된다.

1. **문자열 종류(타입) 필터**: IDA는 `C-style(0 종료)`, `Unicode(UTF-16)`, `Pascal 스타일(1바이트 길이 접두사)`, `Delphi 스타일(4바이트 길이 접두사)` 등 여러 문자열 인코딩 스타일을 인식할 수 있지만, 기본 설정에서는 이 중 일부만 켜져 있다. 특히 **기본값은 8비트 ASCII, 5자 이상인 `C`-style 문자열만 스캔**하도록 되어 있어, `L"..."` 형태로 컴파일된 UTF-16 문자열(Strings 창에서는 `C16` 타입으로 표시됨)은 기본 설정으로는 목록에 나타나지 않는다.
2. **최소 길이 필터**: 기본 최소 길이(대개 5자)보다 짧은 문자열은 스캔 대상에서 제외된다. Windows API 이름(`"OK"`, `"Yes"` 등 아주 짧은 UI 문자열)이 이 때문에 누락될 수 있다.

Windows API는 대부분 ANSI(`A` 접미사, 예: `MessageBoxA`)와 유니코드(`W` 접미사, 예: `MessageBoxW`) 두 버전이 존재하고, 최신 Visual Studio 기본 프로젝트 설정은 유니코드(`W` 계열)를 기본으로 사용한다. 따라서 요즘 컴파일된 프로그램일수록 문자열 대부분이 UTF-16(`C16`)으로 저장되어 있을 가능성이 높고, 이 설정을 켜지 않으면 정말 중요한 문자열 대부분을 놓치게 된다.

## 화면/코드에서 보이는 징후
- Strings 창에 결과가 몇 개 없거나, 있는 것들도 짧은 심볼/경로 문자열뿐이고 프로그램 UI에 나오는 문자열(메시지 박스 텍스트 등)이 안 보임
- IDA Imports 탭에 `MessageBoxW`, `LoadStringW`, `lstrcpyW` 같은 `W` 접미사(와이드 문자) 함수가 많이 보임 — 이는 이 프로그램이 UTF-16 문자열을 주로 사용한다는 강력한 신호
- `.rdata` 섹션을 헥스 뷰로 보면 각 문자가 2바이트씩(`48 00 65 00 6C 00 6C 00 6F 00` = "Hello") 배치되어 있는데, IDA가 이를 문자열로 인식하지 않고 단순 데이터로 보여줌

## 가장 먼저 할 것
1. Strings 창(`Shift+F12`)을 연다.
2. 창 안에서 마우스 우클릭 → `Setup...`(또는 단축키 `Ctrl+U`)을 선택한다.
3. 문자열 타입 목록에서 `Unicode C-style (16 bits)`(또는 유사 명칭, IDA 버전에 따라 "Unicode" 항목)에 체크한 뒤 `OK`를 누른다. IDA가 데이터베이스를 다시 스캔하며 UTF-16 문자열이 새로 목록에 추가된다.

## 단계별 절차
**1) Setup 대화상자 열기**
- Strings 창이 비어 있거나 결과가 적을 때는 우선 `Ctrl+U`(또는 우클릭 → Setup)로 설정 창을 연다.

**2) 필요한 문자열 타입 켜기**
- 최소한 `C-style (0 종료)`와 `Unicode(16bit) C-style`은 항상 함께 켜두는 것이 좋다. Delphi로 만들어진 프로그램을 분석 중이라면 `Pascal 스타일`, `Delphi 스타일`(4바이트 길이 접두사)도 추가로 켜야 문자열이 보인다.
- 최소 길이(minimum length)도 함께 확인해, 짧은 UI 문자열까지 보고 싶다면 5보다 작은 값(예: 2~3)으로 낮춘다. 다만 너무 낮추면 의미 없는 노이즈 문자열이 대량으로 섞여 나올 수 있으니 필요에 따라 조절한다.

**3) 재스캔 및 확인**
- 설정을 바꾸면 IDA가 자동으로 다시 스캔한다. 큰 바이너리라면 시간이 좀 걸릴 수 있다. 특정 범위만 다시 스캔하고 싶다면 원하는 영역을 선택한 뒤 Strings 관련 명령을 실행하면 범위가 한정된다.
- 새로 나타난 `C16` 타입 문자열들을 확인한다. `Type` 컬럼에 `C`(8비트)와 `C16`(16비트)이 구분되어 표시된다.

**4) 여전히 안 보이는 문자열 처리**
- 특정 문자열이 Setup을 다 켰는데도 안 보인다면, 그 데이터가 IDA에게 아직 "코드"로 인식되어 있거나 이미 다른 데이터 타입(배열 등)으로 정의되어 있어서일 수 있다. 이 경우 해당 주소로 직접 이동(`Ctrl+G`)한 뒤, `Alt+A`(Make Array를 통한 ASCII 문자열 만들기, 혹은 우클릭 → `Text String`)로 강제로 유니코드 문자열로 재정의해줄 수 있다.
- 문자열이 XOR 등으로 암호화되어 저장되어 있어서 원래부터 "문자열처럼 안 생긴" 경우도 있다. 이 경우는 Strings 창 설정 문제가 아니라 별도의 복호화 추적이 필요하다.

## 명령어/단축키
- `Shift+F12`: Strings 창 열기
- `Ctrl+U` 또는 우클릭 → `Setup...`: 문자열 타입/최소 길이 설정
- `Alt+A`(또는 우클릭 → `Text String`): 특정 주소를 문자열로 강제 재정의
- `Ctrl+G`: 특정 주소로 이동

## 출력 해석
- Strings 창의 `Type` 컬럼이 `C`이면 8비트(ASCII/UTF-8 계열) 문자열, `C16`이면 16비트(UTF-16, 이른바 "와이드 문자열")다.
- `Length` 컬럼은 문자 개수(바이트 수가 아님)를 나타내므로, UTF-16 문자열은 실제 차지하는 바이트 수가 `Length × 2`(널 종료 바이트 포함 시 조금 더) 정도가 된다는 점을 감안해야 한다.

## 흔한 실수
- Setup에서 유니코드를 켜지 않은 채로 "이 프로그램은 문자열이 거의 없다"고 성급하게 결론짓는 것. 최신 Windows GUI 프로그램은 오히려 대부분의 문자열이 UTF-16이다.
- 최소 길이를 너무 낮춰서 의미 없는 바이트 나열까지 문자열로 대량 표시되어, 정작 찾아야 할 문자열을 노이즈 속에서 놓치는 것.
- 코드 영역에 있는 문자열(코드 중간에 인라인으로 박혀 있는 짧은 텍스트)은 Strings 창 스캔 대상에서 애초에 제외되는 경우가 있다는 점을 모르고 계속 Strings 창만 붙잡고 있는 것. 이런 경우는 해당 코드 영역을 직접 눈으로 훑어보거나 xref를 따라가야 한다.

## 막혔을 때 다음 체크
- ASCII/UTF-16 문자열 구조 자체가 헷갈린다면 → REV-0128(Windows 문자열 ASCII와 UTF-16 찾기)을 먼저 읽는다.
- 문자열은 찾았는데 이게 리소스 섹션 안의 문자열 테이블이라 다르게 접근해야 한다면 → REV-0613(리소스 문자열 테이블이 안 보일 때)을 확인한다.
- API 이름만으로 기능을 추측하고 싶다면 → REV-0138(API 이름으로 함수 기능 추측)을 확인한다.

## 미니 예제
`sample.exe`를 IDA로 열고 `Shift+F12`를 눌렀더니 문자열이 12개밖에 안 나왔다. `Ctrl+U`로 Setup을 열어보니 `Unicode C-style (16 bits)` 항목이 체크 해제되어 있었다. 이를 체크하고 `OK`를 누르자 재스캔 후 문자열이 200개 넘게 나타났고, 그중에는 `MessageBoxW` 호출 직전에 `lea rdx, aInvalidPasswor`(예: `"Invalid Password!"`)로 참조되는 실제 검증 실패 메시지도 포함되어 있었다. 이 문자열을 더블클릭해 `X`로 교차 참조를 확인하면, 곧바로 비밀번호 비교 로직이 있는 함수로 이동할 수 있다.

## 출처/검증
- IDA Strings 창의 기본 설정이 5자 이상 8비트 `C`-style 문자열만 스캔하며, `Ctrl+U`(Setup)에서 "Unicode C-style (16 bits)" 등 문자열 타입을 추가로 켤 수 있다는 점은 Hex-Rays 공식 문서(Strings 관련 문서, "Igor's Tip of the Week" 블로그 시리즈) 기준이다.
- 최신 Windows 프로그램이 `W` 접미사 유니코드 API를 기본으로 사용하는 경향과 이에 따른 UTF-16 문자열 비중 증가는 Win32 API의 ANSI/유니코드 이중 체계에 대한 일반적인 사실이다(2026-09-08 기준 서술).
